# Cleanup, platform and delivery skills (#456-#560)

Fixing problem phone footage, fitting each short-video platform, thumbnails and final export settings, with a source for every item.
Researched 2026-10-24 via agent-reach (Exa) web search. Every ffmpeg command below was run once on a 3 s 640x360 30 fps test clip
(ffmpeg 6.1.1, testsrc2 + sine; vertical tests on a 360x640 copy) and is marked "(ran OK locally, <time>)"; times are for that tiny clip, so compare them with each other, not with real footage.

## Cleanup & repair

456. **Spot variable frame rate** — compare the declared and achieved rate: if `r_frame_rate` and `avg_frame_rate` differ, the clip is VFR (one phone clip declared 60 and delivered 30.13). Here: `ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate,avg_frame_rate -of default=nw=1 in.mp4` (ran OK locally, 0.06 s). [FastDrop, https://developers.fastdrop.io/guides/variable-frame-rate] [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/change-framerate/, 2026-04-08]
457. **Check the real frame timestamps of WhatsApp clips** — a WhatsApp clip reported r_frame_rate 28.4 while really being about 12 fps (134 frames in 11 s), so read the per-frame pts instead of trusting the header. Here: `ffprobe -v error -select_streams v:0 -show_entries frame=pts_time -of csv=p=0 in.mp4` (ran OK locally, 0.17 s). [repo: CLAUDE.md "Client phone-video edits"]
458. **Why VFR breaks edits** — players follow each frame's timestamp, but tools that count frames and assume a fixed rate place things wrongly, so sound slides away from picture or the timeline stutters. [FastDrop, https://developers.fastdrop.io/guides/variable-frame-rate] [O'Reilly "Adobe Premiere Pro", https://www.oreilly.com/library/view/adobe-premiere-pro/9781681986883/compend_8-3.xhtml, 2021-03-04]
459. **Make a constant-frame-rate copy before the first cut** — convert once, then edit the copy; treat it as a test: if the CFR copy stays in sync, VFR was the cause. Here: `ffmpeg -i in.mp4 -fps_mode cfr -r 30 -c:v libx264 -crf 18 -c:a copy cfr.mp4` (ran OK locally, 0.45 s). [Uncompressed.io, https://uncompressed.io/guides/variable-frame-rate-video-problems] [TextOps skills sync-repair, https://github.com/TextOps/textops-skills/blob/main/media-fixing-and-repair/references/sync-repair.md]
460. **Test one clip before converting the whole project** — keep the original untouched, make one CFR sample and check duration, audio channels, cadence and sync side by side before relinking. [DaVinci Resolve Club, https://davinciresolveclub.com/davinci-resolve-variable-frame-rate/, 2026-09-23] [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/variable-framerate-to-constant/, 2026-06-30]
461. **Re-encode VFR footage as new masters** — for the least pain in an editor, transcode VFR clips one generation (ProRes 422 for editing speed, or high-bitrate H.264). [ProVideo Coalition (Jeff Greenberg), https://www.provideocoalition.com/tool-tip-tuesday-for-adobe-premiere-pro-variabe-frame-rates-kill-timelines/, 2025-08-12]
462. **Change frame rate with the fps filter** — `fps=N` drops or duplicates frames by timestamp (e.g. 60 to 30 for social). Here: `ffmpeg -i in.mp4 -vf fps=30 -c:v libx264 -crf 18 -c:a copy out.mp4` (ran OK locally, 0.39 s). [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/change-framerate/, 2026-04-08] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps]
463. **Interpolate every low-fps phone clip to 30 fps** — motion-interpolate all clips (not only slow-mo ones) with scene-change detection off, or 1x shots look choppy. Here: `ffmpeg -i in.mp4 -vf minterpolate=fps=60:mi_mode=mci:mc_mode=aobmc:vsbmc=1:scd=none -c:v libx264 -crf 18 out.mp4` (ran OK locally, 5.54 s, the slowest common fix after nlmeans). [repo: CLAUDE.md "Client phone-video edits"] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate]
464. **Know the minterpolate modes** — `mi_mode=dup` repeats frames, `blend` averages neighbours, `mci` is motion-compensated; with mci, `mc_mode=aobmc` adapts block weights to cut oversmoothing (default obmc). [ayosec FFmpeg filter docs, https://ayosec.github.io/ffmpeg-filters-docs/8.1/Filters/Video/minterpolate.html]
465. **Fast, cheaper interpolation with blend** — blend mode is faster but lower quality than mci. Here: `ffmpeg -i in.mp4 -vf minterpolate=fps=60:mi_mode=blend -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.57 s, about 10x faster than mci). [ffmpeg-engineering-handbook, https://github.com/endcycles/ffmpeg-engineering-handbook/blob/main/docs/advanced/speed.md] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate]
466. **Smooth slow motion** — interpolate first, then stretch timestamps, then set the output rate. Here: `ffmpeg -i in.mp4 -an -vf "minterpolate=fps=60:mi_mode=mci:mc_mode=aobmc:vsbmc=1,setpts=2.0*PTS,fps=30" -c:v libx264 -crf 15 slow.mp4` (ran OK locally, 5.57 s); fast hand motion smears a little. [repo: CLAUDE.md "Editing a phone video into a professional edit" step 2] [ffmpeg-engineering-handbook, https://github.com/endcycles/ffmpeg-engineering-handbook/blob/main/docs/advanced/speed.md]
467. **Slow the audio with chained atempo** — atempo's minimum is 0.5, so chain it for 0.25x. Here: `ffmpeg -i in.mp4 -filter_complex "[0:v]setpts=4.0*PTS[v];[0:a]atempo=0.5,atempo=0.5[a]" -map "[v]" -map "[a]" out.mp4` (ran OK locally, 0.93 s). [ffmpeg-engineering-handbook, https://github.com/endcycles/ffmpeg-engineering-handbook/blob/main/docs/advanced/speed.md] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atempo]
468. **Stabilize in two passes with vid.stab (pass 1: detect)** — the first pass writes per-frame motion to a .trf file and outputs no video. Here: `ffmpeg -i in.mp4 -vf vidstabdetect=shakiness=5:accuracy=15:result=tr.trf -f null -` (ran OK locally, 0.27 s). [Paul Irish, https://paulirish.com/2021/video-stabilization-with-ffmpeg-and-vidstab/, 2021-04-30] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect]
469. **Pass 2: transform, then sharpen** — vidstabtransform reads the .trf and compensates; vid.stab's authors say to add unsharp in the second pass. Here: `ffmpeg -i in.mp4 -vf vidstabtransform=input=tr.trf:smoothing=10:zoom=0:optzoom=1,unsharp=5:5:0.8:3:3:0.4 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.86 s). [georgmartius/vid.stab, https://github.com/georgmartius/vid.stab] [Rainnic, https://rainnic.altervista.org/en/how-stabilize-video-using-ffmpeg-and-vidstab] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform]
470. **Tune smoothing** — `smoothing=10` uses 21 frames (10 past, 10 future) to low-pass camera motion; higher is smoother but limits pans, and 0 simulates a static camera. [ayosec FFmpeg filter docs, https://ayosec.github.io/ffmpeg-filters-docs/9.0/Filters/Video/vidstabtransform.html]
471. **Hide the shaking black borders** — `optzoom=2` zooms in and out to keep borders out of view; or set a fixed `zoom=5` (105%). [tk-sls.de, https://tk-sls.de/wp/4018, 2022-08-30]
472. **Both stabilization passes must see the same frames** — the .trf has one entry per frame in order, so never put fps, minterpolate, select, mpdecimate, trim or -r before vidstabtransform unless the same filter ran before vidstabdetect ("not enough transforms found" warning). Here: when also interpolating, put `minterpolate=fps=48,` in front of both passes. [georgmartius/vid.stab, https://github.com/georgmartius/vid.stab]
473. **Drop duplicated frames before stabilizing** — duplicates read as zero motion and give a regular jerk; remove them with mpdecimate in both passes. Here: `ffmpeg -i in.mp4 -vf mpdecimate,setpts=N/FRAME_RATE/TB -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.45 s). [georgmartius/vid.stab, https://github.com/georgmartius/vid.stab] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mpdecimate]
474. **Deinterlace before stabilizing** — vid.stab treats each frame as progressive, so interlaced fields confuse the motion analysis. [georgmartius/vid.stab, https://github.com/georgmartius/vid.stab]
475. **One-pass quick fix: deshake** — built-in, always available, but the two-pass vid.stab gives superior results. Here: `ffmpeg -i in.mp4 -vf deshake -c:v libx264 -crf 18 out.mp4` (ran OK locally, 1.05 s). [tanersener/vid.stab, https://github.com/tanersener/vid.stab] [Greg Zaal, https://blog.gregzaal.com/2014/05/30/camera-stabilisation-with-ffmpeg/, 2014-05-30] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake]
476. **Stronger deshake** — raise the maximum shift `rx`/`ry` (default 16, up to 64) and keep `edge=mirror`. [eliteai.tools ffmpeg-stabilization skill, https://eliteai.tools/agent-skills/ffmpeg-stabilization-360] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake]
477. **Warp Stabilizer smoothness** — default Smooth Motion; try 50-75% smoothness, or Result: No Motion for a locked-off look. [Adobe Help, https://helpx.adobe.com/ee/premiere-pro/how-to/stabilize-handheld-footage.html]
478. **No Motion costs sharpness** — the tripod look zooms in the most, so the image gets softer; Position/Scale/Rotation method can reduce artifacts. [Larry Jordan, https://larryjordan.com/articles/stabilize-shaky-video-footage-using-adobe-premiere-pro/, 2023-01-04]
479. **Stabilize only the shaky part** — split the clip and stabilize the problem section; it is faster and touches less footage. [Shotkit, https://shotkit.com/stabilize-video-premiere-pro/, 2023-06-28]
480. **Crop vs fill edges** — Auto Crop is always sharp but smaller; Full Frame fills edges with AI interpolation and may blur them; more strength means more crop or artifacts. [Topaz Labs docs, https://docs.topazlabs.com/topaz-video/filters/stabilization]
481. **Recognise rolling shutter (jello)** — CMOS sensors read line by line, so fast pans or subjects skew, wobble and bend straight lines. [Adobe, https://www.adobe.com/creativecloud/video/discover/rolling-shutter-effect.html] [MIT Computational Photography, https://people.csail.mit.edu/fredo/comp-photo-book/12-video-05-video-stabilization-and-rolling-shutter-correction.html]
482. **Repair rolling shutter** — Premiere's Rolling Shutter Repair: raise the rate until skewed lines are vertical (DSLRs about 50-70%, iPhone near 100%) and set the scan direction for a rotated phone. [Adobe Help, https://helpx.adobe.com/premiere-pro/using/rolling-shutter-repair.html]
483. **Prevent jello when shooting** — lower the maximum shutter little by little until it eases (watch for exposure side effects). [Hanwha Vision support, https://support.hanwhavision.com/hc/en-us/articles/34554733883801-Jello-effect-in-camera-video-Rolling-shutter]
484. **Identify what "interlaced" really is first** — true interlaced (every moving frame combed) needs deinterlacing; telecined film needs inverse telecine; deinterlacing progressive material throws detail away. [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace] [renomath.org, https://renomath.org/video/linux/interlace/]
485. **Classify frames with idet** — it counts TFF, BFF and progressive frames over a moving section. Here: `ffmpeg -i in.mp4 -vf idet -f null -` (ran OK locally, 0.14 s; on our synthetic progressive test clip it still reported 49 TFF / 30 BFF / 11 progressive, so confirm combing by eye). [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#idet]
486. **Deinterlace with yadif** — a high-quality deinterlacer, and the one in an accepted ffmpeg-for-YouTube answer. Here: `ffmpeg -i in.mp4 -vf yadif=mode=0 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.56 s). [mpv issue #12478, https://github.com/mpv-player/mpv/issues/12478, 2023-09-25] [Video StackExchange (Gyan), https://video.stackexchange.com/questions/24479/how-to-encode-for-youtube-with-ffmpeg] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#yadif]
487. **Prefer bwdif for less shimmer** — yadif and bwdif are ffmpeg's two best deinterlacers; bwdif handles text shimmer better. Here: `ffmpeg -i in.mp4 -vf bwdif=mode=send_field -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.91 s). [mpv issue #12478, https://github.com/mpv-player/mpv/issues/12478, 2023-09-25] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bwdif]
488. **Deinterlace before YouTube** — YouTube wants progressive uploads: 1080i60 becomes 1080p30. [YouTube Help, https://support.google.com/youtube/answer/1722171?hl=en]
489. **Decide whether to denoise** — noise eats bitrate; remove digital/low-light noise and compression residue, keep film grain, and use the least denoise that works because it always costs detail. [Encode Wiki, https://encode.wiki/tools/filtering/denoise]
490. **Fast denoise: hqdn3d** — spatial + temporal smoothing; light setting for webcam or slightly noisy video. Here: `ffmpeg -i in.mp4 -vf hqdn3d=4:3:6:4.5 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.75 s). [TextOps skills visual-quality, https://github.com/TextOps/textops-skills/blob/main/media-fixing-and-repair/references/visual-quality.md] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#hqdn3d]
491. **Raise only luma_spatial for stronger hqdn3d** — the other three values derive from it (hqdn3d=8 equals 8:6:12:9); large values blur. [Codec Wiki, https://codecs.wiki/docs/filtering/denoise]
492. **Precise but slow denoise: nlmeans** — far slower and more precise than hqdn3d. Here: `ffmpeg -i in.mp4 -vf nlmeans=s=3:p=7:r=15 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 18.47 s, about 25x hqdn3d). [Encode Wiki, https://encode.wiki/tools/filtering/denoise] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#nlmeans]
493. **Temporal-only denoise: atadenoise** — adaptive temporal averaging; threshold A reacts to abrupt changes, B to continuous ones (defaults 0.02 / 0.04). Here: `ffmpeg -i in.mp4 -vf atadenoise -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.50 s). [ayosec FFmpeg filter docs, https://ayosec.github.io/ffmpeg-filters-docs/9.0/Filters/Video/atadenoise.html] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atadenoise]
494. **Order and balance of noise reduction** — temporal first and gently, a little spatial after; remove chroma noise aggressively and luma noise sparingly, or the picture turns waxy. [Addaly, https://addaly.com/learn/video-editing/noise-and-sharpening]
495. **Strong denoise on high-ISO phone video blurs** — users tried nlmeans, bm3d, hqdn3d, dctdnoiz and more on ISO 3200 phone footage and all blurred at strengths that removed the noise. [Stack Overflow, https://stackoverflow.com/questions/74831282/remove-video-noise-from-video-with-ffmpeg-without-producing-blur-scale-down-ef, 2022-12-17]
496. **Prevent noise at the shoot** — high ISO (above about 800), heavy compression and brightening underexposed clips cause most noise: shoot with more light and lower ISO. [Storyblocks, https://www.storyblocks.com/resources/tutorials/denoise-video-in-premiere-pro, 2025-07-09]
497. **Smooth frame-to-frame brightness jumps: deflicker** — moving-average luminance filter (size 2-129, default 5) for timelapse-style flicker. Here: `ffmpeg -i in.mp4 -vf deflicker=size=5:mode=am -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.53 s). [ayosec FFmpeg filter docs, https://ayosec.github.io/ffmpeg-filters-docs/8.1/Filters/Video/deflicker.html] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deflicker]
498. **deflicker does not fix mains-light banding** — a 1/30 s shutter under 50 Hz lights gave bands that deflicker could not remove. [Video StackExchange, https://video.stackexchange.com/questions/23384/remove-flickering-due-to-artificial-light-with-ffmpeg, 2018-02-09]
499. **Prevent light flicker** — artificial lights pulse at twice the mains rate: on 60 Hz use 30/60 fps, on 50 Hz (Europe and most of Asia) use 25/50 fps and a matching shutter. [Boris FX, https://borisfx.com/blog/how-to-stop-light-flickering-in-your-videos/, 2024-06-04] [RED, https://www.reddigitalcinema.com/red-101/flicker-free-video-tutorial]
500. **Rolling LED bands need a plugin** — Flicker Free: try a preset, then a higher Time Radius for slow bands, then Time Step; watch for ghosting on camera motion. [Digital Anarchy, https://digitalanarchy.com/blog/video-editing-plugins/deflickering-videos-with-rolling-bands-caused-by-light-problems-often-leds-with-examples-in-davinci-resolve-premiere-pro-after-effects-final-cut-pro/]
501. **Fix exposure before stylizing** — correct under/over exposure first; for an overexposed shot lower Highlights, Shadows and Saturation. Here: `ffmpeg -i in.mp4 -vf eq=brightness=0.06:contrast=1.1:gamma=1.2:saturation=1.1 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.45 s). [Adobe Learn, https://www.adobe.com/learn/after-effects/web/repair-video, 2023-05-24] [Adobe Learn, https://www.adobe.com/learn/premiere-pro/web/color-correct-unusable-footage, 2023-05-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#eq]
502. **Lift a dark clip with a curve** — curves presets give quick tone changes. Here: `ffmpeg -i in.mp4 -vf curves=preset=lighter -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.68 s). [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#curves]
503. **Clipped SDR highlights cannot be recovered** — where no detail remains, build separate exposure planes with windows, darken the blown sky, and treat hot skin instead. [Mixing Light, https://mixinglight.com/color-grading-tutorials/fixing-over-exposure-in-standard-dynamic-range-sdr-footage/, 2024-10-03]
504. **Brightening reveals noise** — grading an underexposed shot can worsen noise; sometimes bringing the shadows down hides it. [Adobe Video x Film Riot, https://www.youtube.com/watch?v=jYvO3QQUzrg, 2024-10-24]
505. **Pick a grade on a real frame** — compare 2-3 candidates with HyperFrames grade-compare, then apply the winner to every clip. Here: `npx hyperframes grade-compare --for frame.png --grades grades.json`. [repo: CLAUDE.md "Editing a phone video into a professional edit" step 4]
506. **Upscale with lanczos** — lanczos is the best-quality (slowest) scaler; bicubic is a balance, bilinear fastest. Here: `ffmpeg -i in.mp4 -vf scale=1920:1080:flags=lanczos -c:v libx264 -crf 18 out.mp4` (ran OK locally, 3.13 s). [WaveSpeed Blog, https://wavespeed.ai/blog/posts/blog-how-to-upscale-enhance-video-quality-ffmpeg/, 2026-02-10] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scale]
507. **Upscaling adds no detail** — export at the content's native resolution: 720p to 1080p only grows the file. [OpenClip, https://openclip.app/guides/video-encoding-guide]
508. **Sharpen after upscaling with CAS** — Contrast Adaptive Sharpen, `strength` 0-1 (default 0). Here: `ffmpeg -i in.mp4 -vf scale=1920:1080:flags=lanczos,cas=strength=0.5 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 3.26 s, only +0.13 s over the scale alone). [ayosec FFmpeg filter docs, https://ayosec.github.io/ffmpeg-filters-docs/9.0/Filters/Video/cas.html] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#cas]
509. **Classic sharpen: unsharp** — luma matrix size and amount, chroma left alone here. Here: `ffmpeg -i in.mp4 -vf unsharp=5:5:1.0:5:5:0.0 -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.58 s). [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#unsharp] [ffmpeg-forge FILTERS.md, https://github.com/parth181195/ffmpeg-forge/blob/master/docs/FILTERS.md]
510. **AI upscale when lanczos is not enough** — Real-ESRGAN models do 2x/4x super-resolution (rebuild edges and texture) and DnCNN-type models denoise, at far higher compute cost. [npuscale, https://github.com/ikeno-web/npuscale] [revid on PyPI, https://pypi.org/project/revid/]
511. **Vertical clip on a 16:9 canvas: blurred fill** — place a blurred, scaled copy of the same footage behind the original instead of black pillar bars. [Shotstack, https://shotstack.io/learn/blur-sides-vertical-video/] [Stack Overflow, https://stackoverflow.com/questions/30789367/ffmpeg-how-to-convert-vertical-video-with-black-sides-to-video-169-with-blur]
512. **Landscape clip into 9:16 with blurred fill** — fit the whole wide frame and fill above/below with an enlarged blurred copy, nothing cropped. Here: `ffmpeg -i in.mp4 -filter_complex "[0:v]scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,boxblur=20:2[bg];[0:v]scale=1080:-2[fg];[bg][fg]overlay=(W-w)/2:(H-h)/2" -c:v libx264 -crf 18 -c:a copy out.mp4` (ran OK locally, 3.23 s). [VideoToolery, https://videotoolery.com/resize/blur-video-background] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#boxblur]
513. **Or crop to fill 9:16** — cropping keeps the frame full but loses the sides. Here: `ffmpeg -i in.mp4 -vf "crop=ih*9/16:ih,scale=1080:1920:flags=lanczos" -c:v libx264 -crf 18 -c:a copy out.mp4` (ran OK locally, 1.57 s). [FlexClip, https://www.flexclip.com/learn/fill-in-sides-of-vertical-video.html] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#crop]
514. **Never burn bars into a YouTube upload** — YouTube frames the video itself; letterbox/pillarbox bars or padding interfere with its dynamic player. [YouTube Help, https://support.google.com/youtube/answer/4603579?hl=en] [YouTube Help, https://support.google.com/youtube/answer/6375112]
515. **Find the direction of an A/V offset** — clap test: sound after the action means audio is late; check stream start_time, but only playback proves sync. Here: `ffprobe -v error -show_entries stream=codec_type,start_time -of default=nw=1 in.mp4` (ran OK locally, 0.07 s). [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/audio-video-sync/, 2026-04-08]
516. **Shift streams without re-encoding: -itsoffset** — open the file twice, offset one input, map video from one and audio from the other. Here: `ffmpeg -i in.mp4 -itsoffset 0.2 -i in.mp4 -map 0:v -map 1:a -c copy out.mp4` (audio 0.2 s later; ran OK locally, 0.06 s). [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/audio-video-sync/, 2026-04-08]
517. **Delay audio in milliseconds: adelay** — delays only (cannot move audio earlier); `all=1` applies to every channel. Here: `ffmpeg -i in.mp4 -af adelay=200:all=1 -c:v copy out.mp4` (ran OK locally, 0.10 s). [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/audio-video-sync/, 2026-04-08] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adelay]
518. **Fixed offset vs growing drift** — a constant offset is shifted once; a gap that keeps growing is not fixed by manual alignment (often VFR, see above). [Wondershare Recoverit, https://recoverit.wondershare.com/video-repair/audio-video-out-of-sync.html]
519. **Rule out Bluetooth before "fixing" sync** — Bluetooth headphones add playback delay; check on built-in speakers first. [Descript Help, https://help.descript.com/add-and-manage-media/ts-av-issues]
520. **Repair clipped audio** — lower the gain first, then de-clip, because rebuilt peaks rise above 0 dB. Here: `ffmpeg -i in.mp4 -af volume=-3dB,adeclip -c:v copy out.mp4` (ran OK locally, 0.22 s). [salivity ffmpeg articles, https://salivity.github.io/ffmpeg/article/repair-audio-clipping-with-f-fmpeg-adeclip-filter] [iZotope, https://www.izotope.com/community/blog/how-to-fix-audio-clipping, 2022-01-12] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adeclip]
521. **Clean a clip's existing voice instead of replacing it** — remove noise, music and background so only the person's voice remains. Here: `library/tools/clean_voice.py` (skill clean-video-voice). [repo: CLAUDE.md "Voice and songs with words"]

## Platform & retention

532. **Strong hooks share five traits** — motion from frame one, a specific subject, an open loop, a promise kept, and on-screen text for sound-off viewers. [Click Pop, https://www.clickpop.ai/guides/hooks-for-the-first-three-seconds, 2026-10-14]

## Thumbnails

557. **One clear idea: face, contrast, few words** — vidIQ's 500 breakout videos: 69% had a face, 56% high contrast, 89% at least one; text mostly five words or fewer. [vidIQ, https://vidiq.com/blog/post/youtube-thumbnail-design-tips/, 2026-07-14]
558. **Faces are table stakes, text is an edge** — of 2,960 thumbnails, 84% of breakouts and 82% of underperformers had a face; 86.6% of breakouts had text, best at 4-6 words. [Eden, https://eden.so/blog/what-makes-a-good-youtube-thumbnail/]
559. **Expression intensity matters** — face thumbnails averaged 6.8% CTR vs 4.1% without; neutral faces gave almost no advantage. [CTRpilot, https://ctrpilot.com/blog/youtube-thumbnail-study-1000-videos, 2025-09-15]
560. **YouTube's own design tips** — rule of thirds, readable font, not too complex, image as large as possible; refresh old thumbnails. [YouTube Help, https://support.google.com/youtube/answer/12340300?hl=en]
561. **Face size and layout** — face fills about 30-50% of the frame, two dominant colours, one focal element; no logos bottom-right where the duration badge sits. [social-media-skills youtube-thumbnail, https://github.com/charlie947/social-media-skills/blob/main/skills/youtube-thumbnail/SKILL.md]
562. **Check at small size** — shrink to about 200 px wide to catch illegible text; white text with a black outline over a saturated background stays readable. [Polimake, https://polimake.com/en-us/kb/video-thumbnails, 2025-01-24]
563. **Sizes** — YouTube recommends 3840x2160 for videos and 2160x3840 for Shorts (min width/height 640 px), JPG or PNG; Shorts thumbnails 9:16. [YouTube Help, https://support.google.com/youtube/answer/72431?hl=en] Classic size 1280x720 under 2 MB. [Adobe Express, https://www.adobe.com/express/discover/sizes/youtube] Here: `ffmpeg -ss 1.5 -i in.mp4 -frames:v 1 -vf scale=1280:720:flags=lanczos -q:v 2 thumb.jpg` (ran OK locally, 0.11 s). [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scale]
564. **Instagram cover size** — recommended cover 420x654 px (1:1.55). [Instagram Help, https://help.instagram.com/1038071743007909]
565. **Test & Compare (A/B)** — up to 3 titles/thumbnails; winner judged on watch time share; results take days to 2 weeks; if no winner, the first upload stays. [YouTube Help, https://support.google.com/youtube/answer/16391400?hl=en] [YouTube Help, https://support.google.com/youtube/answer/13861714?hl=en]
566. **Make test variants really different** — more different thumbnails finish faster; background colour changes moved CTR most (18-25%), then expression (12-18%), text (8-15%), small layout tweaks under 3%. [YouTube Help, https://support.google.com/youtube/answer/13861714?hl=en] [ThumbnailCreator, https://www.thumbnailcreator.com/insights/ab-testing-thumbnail-results, 2025-01-01]
567. **A/B tests are close to a coin flip** — 460 real tests: median stopped after 20.5 h and the original still showed in 45% of settled tests. [TubeAI, https://tubeai.app/blog/youtube-thumbnails/youtube-thumbnail-ab-test]

## Delivery & export

568. **CRF = quality target** — x264 0-51, lower is better; sane 18-28, default 23; x265 default 28. [slhck CRF Guide, https://slhck.info/video/2017/02/24/crf-guide.html, 2017-02-24]
569. **Preset = speed vs size** — ultrafast to placebo; use the slowest you have patience for; with CRF the preset barely changes quality, mostly file size. [Stack Overflow, https://stackoverflow.com/questions/14306205/do-ffmpeg-h264-compression-presets-affect-the-video-quality] [beandog wiki, https://dvds.beandog.org/doku.php?id=x264]
570. **Two-pass when the file size is fixed** — 2-pass VBR hits a target average bitrate. Here: `ffmpeg -y -i in.mp4 -c:v libx264 -b:v 3000k -pass 1 -an -f mp4 /dev/null && ffmpeg -i in.mp4 -c:v libx264 -b:v 3000k -pass 2 -c:a aac -b:a 128k out.mp4` (ran OK locally, 0.27 s + 0.41 s). [ffmpeg.media, https://www.ffmpeg.media/articles/transcoding-crf-vs-bitrate-codecs-presets, 2024-04-25]
571. **YouTube recommended settings** — MP4, H.264 High profile, progressive, 2 consecutive B-frames, closed GOP of half the frame rate, CABAC, VBR, 4:2:0, native frame rate; AAC-LC or Opus. [YouTube Help, https://support.google.com/youtube/answer/1722171?hl=en]
572. **YouTube SDR bitrates** — 1080p 8 Mbps (12 at 48-60 fps), 1440p 16/24, 4K 35-45/53-68; audio 128 kbps mono, 384 stereo, 512 for 5.1. [YouTube Help, https://support.google.com/youtube/answer/1722171?hl=en] [The Post Flow, https://thepostflow.com/post-production/post-production-workflows/export-settings-youtube-instagram-tiktok/, 2026-07-18]
573. **YouTube ffmpeg line** — CRF 18, max 2 B-frames, keyframes every half second, AAC 48 kHz stereo, faststart. Here: `ffmpeg -i in.mp4 -vf format=yuv420p -c:v libx264 -preset slow -crf 18 -profile:v high -bf 2 -g 15 -c:a aac -b:a 384k -ar 48000 -movflags +faststart out.mp4` (ran OK locally, 0.65 s). [Video StackExchange (Gyan), https://video.stackexchange.com/questions/24479/how-to-encode-for-youtube-with-ffmpeg] [YouTube Help, https://support.google.com/youtube/answer/1722171?hl=en]
574. **Instagram Reels API specs** — MOV/MP4, no edit lists, moov atom at front; H.264 or HEVC, progressive, closed GOP, 4:2:0; 23-60 fps; max 1920 px wide; VBR up to 25 Mbps; AAC 48 kHz, 128 kbps; 3 s-15 min; 300 MB. [justin.searls.co, https://justin.searls.co/posts/a-script-to-validate-videos-for-the-instagram-api/, 2025-02-14]
575. **Instagram re-encodes** — it encodes 1080p to about 5 Mbps internally, so uploading far higher only costs bandwidth. [FormatDrop, https://formatdrop.com/guides/compress-video-for-instagram, 2025-01-01]
576. **One vertical preset for Reels/TikTok/Shorts** — 1080x1920, 30 fps (60 for action), H.264 (or HEVC), 8-12 Mbps, AAC 48 kHz (192 kbps), loudness about -14 LUFS. Here: `ffmpeg -i in.mp4 -vf scale=1080:1920:flags=lanczos,format=yuv420p -r 30 -c:v libx264 -preset slow -crf 18 -maxrate 12M -bufsize 24M -c:a aac -b:a 192k -ar 48000 -movflags +faststart out.mp4` (ran OK locally, 3.69 s; 5.1 Mbps on the test clip). [HEVCut, https://hevcut.com/guides/best-export-settings-reels-tiktok-shorts] [Addaly, https://addaly.com/learn/video-editing/export-settings-per-destination]
577. **HEVC option** — HEVC is accepted by the Reels API and one guide prefers it when supported, otherwise H.264. Here: `ffmpeg -i in.mp4 -c:v libx265 -crf 24 -c:a aac -b:a 192k -movflags +faststart out.mp4` (ran OK locally, 0.9 s). [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx265] [HEVCut, https://hevcut.com/guides/best-export-settings-reels-tiktok-shorts] [justin.searls.co, https://justin.searls.co/posts/a-script-to-validate-videos-for-the-instagram-api/, 2025-02-14]
578. **TikTok upload specs** — 1080x1920 recommended (360-4,096 px per side accepted), MP4/WebM/MOV, up to 4 GB. [Socialync, https://www.socialync.io/tools/video-specs] [PostProxy, https://www.postproxy.dev/blog/instagram-reels-vs-tiktok-vs-youtube-shorts-publishing-via-api/]
579. **faststart** — moves the moov atom (playback index) to the front so web players start before the whole file downloads; remux without re-encoding. Here: `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4` (ran OK locally, 0.07 s). [Pixplicity Cookbook, https://code.pixplicity.com/ffmpeg/faststart/] [FFmpeg-cvslog, https://ffmpeg.org/pipermail/ffmpeg-cvslog/2013-August/067635.html]
580. **WhatsApp compresses hard** — standard quality is 480p and HD is 720p; status videos go to 360p/480p by connection; send as a document to avoid compression. [NEWS.am TECH, https://tech.news.am/en/news/1967, 2023-08-25] [Gadgets To Use, https://gadgetstouse.com/blog/2024/01/23/upload-high-quality-video-photo-whatsapp-status/, 2024-01-23] [The Verge (archived), https://web.archive.org/web/20210719070155/www.theverge.com/2021/7/9/22569744/whatsapp-image-video-compression-quality-updates, 2021-07-09]
581. **Deliver a WhatsApp copy too** — full quality file plus a CRF 23 copy. Here: `ffmpeg -i in.mp4 -c:v libx264 -crf 23 -preset slow -c:a aac -b:a 160k -movflags +faststart out.mp4` (ran OK locally, 0.62 s). [repo: CLAUDE.md "Editing a phone video into a professional edit" step 8] (Users report already-well-encoded H.264 under about 16 MB for 30 s may skip WhatsApp's re-encode. [Reddit r/whatsapp, https://www.reddit.com/r/whatsapp/comments/yahj8l/sending_hires_videos_as_inline_media/, 2022-10-22])
582. **Washed-out export = tagging problem** — primaries, transfer and matrix tags tell players how to read pixels; a wrong or missing tag makes blacks grey without changing a pixel. [mediacodec.dev, https://mediacodec.dev/wiki/colour-spaces-and-washed-out-video/] [Avid KB, https://kb.avid.com/pkb/articles/en_US/Knowledge/Washed-out-or-crushed-luminance-levels-in-Media-Composer-or-your-exported-file]
583. **Tag bt709 explicitly** — these flags only tag, they do not convert pixels. Here: `ffmpeg -i in.mp4 -c:v libx264 -crf 18 -colorspace bt709 -color_primaries bt709 -color_trc bt709 -color_range tv out.mp4` (ran OK locally, 0.45 s; ffprobe then showed bt709/bt709/bt709, range tv). [salivity ffmpeg articles, https://salivity.github.io/ffmpeg/article/how-to-set-libx-264-color-description-in-f-fmpeg] [Stack Overflow, https://stackoverflow.com/questions/61834623/how-to-use-ffmpeg-colorspace-options, 2020-10-24]
584. **Tag inside the filter graph with setparams** — sets the colour properties on the frames. Here: `ffmpeg -i in.mp4 -vf setparams=colorspace=bt709:color_primaries=bt709:color_trc=bt709:range=tv -c:v libx264 -crf 18 out.mp4` (ran OK locally, 0.43 s). [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setparams]
585. **Check the source tags first** — if they are filled in and plausible, preserve them; HD is BT.709, DVD BT.601. Here: `ffprobe -v error -select_streams v:0 -show_entries stream=pix_fmt,color_range,color_space,color_transfer,color_primaries -of default=nw=1 in.mp4` (ran OK locally, 0.08 s). [Encode Wiki, https://encode.wiki/guides/preserve-color-and-hdr]
586. **yuv420p for the web** — most browsers support only yuv420p (Chrome is the exception). [ORI Encoding Guidelines, https://academysoftwarefoundation.github.io/EncodingGuidelines/Encodeh264.html]
587. **AAC bitrate by content** — speech 64 kbps, general soundtrack 128 kbps, music 192-256 kbps per stereo pair. Here: `-c:a aac -b:a 192k -ar 48000` (used in the vertical preset above). [mediacodec.dev, https://mediacodec.dev/wiki/audio-codecs/] [pkglog AAC guide, https://pkglog.com/en/blog/audio-codec-aac-complete-guide/, 2026-07-20]
588. **Normalise loudness for social** — target about -14 LUFS (our client reels aimed near -16) and verify with ebur128. Here: `ffmpeg -i in.mp4 -af loudnorm=I=-14:TP=-1.5:LRA=11 -c:v copy out.mp4` (ran OK locally, 0.20 s; ebur128 then read I = -14.0 LUFS). [Addaly, https://addaly.com/learn/video-editing/export-settings-per-destination] [repo: CLAUDE.md "Client phone-video edits"] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#loudnorm]
589. **Set frame rate from the timeline, not the preset** — a "YouTube 1080p" preset can carry 29.97 and silently convert a 25p edit; also check the resolution field. [Addaly, https://addaly.com/learn/video-editing/export-settings-per-destination]
590. **Don't export 4K for Shorts/Reels** — platforms downscale to 1080p anyway. [HEVCut, https://hevcut.com/guides/best-export-settings-reels-tiktok-shorts]
