## H.264 with libx264

4401. **CRF +6 halves the size** — the CRF scale is exponential: +6 gives roughly half the bitrate/file size, -6 roughly double. Use it to jump to a size you want in one step. **How:** encode once, then move CRF by 6 to halve or double: `ffmpeg -y -i in.mp4 -c:v libx264 -crf 29 -c:a copy half.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4402. **10-bit x264 has a 0-63 quantizer scale** — the 0-51 CRF scale applies only to 8-bit x264; a 10-bit build uses 0-63, and the ffmpeg console shows yuv420p (8-bit) or yuv420p10le (10-bit). 8-bit is more common among distributors. **How:** check what you encode in the log line, or force 10-bit: `ffmpeg -y -i in10.mkv -c:v libx264 -pix_fmt yuv420p10le -crf 20 out10.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4403. **List x264 presets and tunes from your own build** — ffmpeg can print every preset and tune your libx264 knows. It prints the lists and then stops with an encoder error; that is expected. **How:** `ffmpeg -hide_banner -f lavfi -i nullsrc -c:v libx264 -preset help -f mp4 - 2>&1 | grep Possible; true` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4404. **Placebo is not worth it** — placebo helps at most ~1% over veryslow; veryslow helps ~3% over slower, slower ~5% over slow, slow 5-10% over medium. **How:** stop at veryslow (or slow when time is short); never use placebo. [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4405. **Preset time cost** — for a 2-pass 1080p example: medium to slow costs ~40% more time, slower ~100% more, veryslow 280% of medium; fast saves ~10%, faster ~25%, ultrafast ~55% at much lower quality. **How:** plan render time from these ratios before a batch export. [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4406. **tune animation for cartoons** — animation tuning uses higher deblocking and more reference frames; good for cartoons and flat-colour motion graphics. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -tune animation -crf 20 -c:a copy anim.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4407. **tune grain to keep film grain** — grain tuning preserves the grain structure in old, grainy film material. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -tune grain -crf 18 -c:a copy grain.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4408. **tune stillimage for slideshows** — stillimage tuning is for slideshow-like content. **How:** photo slideshows and podcast still-image videos: `ffmpeg -y -loop 1 -framerate 2 -i cover.jpg -i in.wav -c:v libx264 -tune stillimage -crf 18 -c:a aac -shortest -pix_fmt yuv420p still.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/YouTube, checked 2026-10-24]
4409. **tune fastdecode for weak players** — fastdecode allows faster decoding by disabling certain filters. **How:** for old phones/TV boxes that stutter: `ffmpeg -y -i in.mp4 -c:v libx264 -tune fastdecode -crf 20 -c:a copy fd.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4410. **tune zerolatency for live** — zerolatency is for fast encoding and low-latency streaming. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -preset veryfast -tune zerolatency -f mpegts zl.ts` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4411. **Leave -profile alone unless a device needs it** — x264 picks the profile itself; set baseline or main only for old devices, or to match other files before the concat demuxer. -profile:v is incompatible with lossless and high444 does not work as a profile setting. **How:** only for an old device: `ffmpeg -y -i in.mp4 -c:v libx264 -profile:v main -crf 20 -c:a copy main.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4412. **High 4:2:2 Intra profile** — high422 with -g 1 -pix_fmt yuv422p10le gives High 4:2:2 Intra Profile (an intra-only 10-bit 4:2:2 H.264). **How:** `ffmpeg -y -i in10.mkv -c:v libx264 -profile:v high422 -g 1 -pix_fmt yuv422p10le -crf 12 intra422.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4413. **Lossless H.264** — use -qp 0 (or -crf 0 with High 4:4:4 Predictive); High 10 does not support lossless. Use ultrafast for speed or veryslow for size. Most non-FFmpeg players can't decode lossless. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -preset ultrafast -qp 0 lossless.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4414. **RGB sources: libx264rgb for true lossless** — if lossless output does not look lossless, the RGB to YUV conversion is the cause; libx264rgb accepts packed RGB. **How:** `ffmpeg -y -i frames/img_%04d.png -c:v libx264rgb -qp 0 rgb_lossless.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4415. **x264-params overrides a preset** — preset values can be overridden with -x264-params key=value pairs (x264opts is deprecated); the wiki warns tweaking is usually a waste of time. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -preset slow -crf 22 -x264-params keyint=123:min-keyint=20 -c:a copy kp.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4416. **Simulated CBR for broadcast-style TS** — x264 has no true CBR; simulate it with nal-hrd=cbr plus equal -b:v/-minrate/-maxrate and a -bufsize. nal-hrd cbr is not allowed in MP4, so write TS. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -x264-params nal-hrd=cbr -b:v 1M -minrate 1M -maxrate 1M -bufsize 2M cbr.ts` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4417. **Capped CRF (VBV) for streaming** — -crf with -maxrate and -bufsize targets the CRF but raises it when the rate would exceed the cap; libx264 does not strictly hold the max, use two-pass for a perfect cap. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -crf 23 -maxrate 1M -bufsize 2M -c:a copy capped.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4418. **Two-pass with a cap** — average bitrate plus maxrate/bufsize in two passes gives the tightest control. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -b:v 1M -maxrate 1M -bufsize 2M -pass 1 -an -f mp4 /dev/null && ffmpeg -y -i in.mp4 -c:v libx264 -b:v 1M -maxrate 1M -bufsize 2M -pass 2 -c:a aac capped2p.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4419. **MiB to kbit/s for a size target** — bitrate = size / duration; 200 MiB x 8388.608 / 600 s = ~2796 kbit/s total, minus audio (e.g. 128) for the video rate. 1 kbit is 1000 bit, hence 8388.608 not 8192. **How:** compute it before pass 1: `python3 -c "print(round(200*8388.608/600-128))"` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4420. **Two-pass gives no better quality than CRF** — the FAQ says two-pass is not better quality than CRF; it only hits a file size more accurately. **How:** use CRF unless a size or bitrate is required. [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4421. **First pass segfault fix** — if -an in pass 1 gives a segfault or a broken file, drop -an and add -vsync cfr to the first pass. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -b:v 1M -pass 1 -vsync cfr -f null /dev/null` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4422. **Name the two-pass log** — -passlogfile sets the log prefix (default ffmpeg2pass, file PREFIX-N.log) so parallel two-pass jobs don't overwrite each other. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -b:v 800k -pass 1 -passlogfile jobA -an -f null /dev/null && ls jobA-0.log` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Video-Options, checked 2026-10-24]
4423. **Test settings on a slice first** — encode a random section with -ss and -t/-to to judge settings quickly. **How:** `ffmpeg -y -ss 0.5 -t 1 -i in.mp4 -c:v libx264 -crf 20 -an slice.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4424. **yuv420p for QuickTime and dumb players** — QuickTime and most players only decode YUV 4:2:0 H.264, so add -pix_fmt yuv420p when the source is 4:2:2/4:4:4 or RGB. **How:** `ffmpeg -y -i in10.mkv -c:v libx264 -pix_fmt yuv420p -crf 20 qt.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/YouTube, checked 2026-10-24]
4425. **Force IDR keyframes** — forced-idr makes forced I-frames IDR frames, so they are true random-access points. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -force_key_frames 0,1 -forced-idr 1 -an idr.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4426. **Open GOP with -flags -cgop** — flags -cgop disables closed GOP (similar to x264 --open-gop). Platforms that need closed GOP (X, YouTube) should not get it. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -flags -cgop -an opengop.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4427. **CAVLC for very old decoders** — coder vlc disables CABAC (same as --no-cabac). **How:** only for very old hardware; YouTube asks for CABAC. `ffmpeg -y -i in.mp4 -c:v libx264 -profile:v baseline -coder vlc -an cavlc.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24] [YouTube Help, https://support.google.com/youtube/answer/1722171?hl=en, checked 2026-10-24]
4428. **Set the H.264 level** — the private -level option takes a level IDC name like 3.1 or 4.1. **How:** for Apple-compatible HLS variants (High 4.1): `ffmpeg -y -i in.mp4 -c:v libx264 -profile:v high -level 4.1 -an l41.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24] [Apple Developer, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
4429. **Limit B-frames with -bf** — bf maps to x264 bframes (B-frames between I and P). **How:** YouTube's spec is 2 consecutive B-frames: `ffmpeg -y -i in.mp4 -c:v libx264 -bf 2 -an bf2.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24] [YouTube Help, https://support.google.com/youtube/answer/1722171?hl=en, checked 2026-10-24]
4430. **Fixed GOP: -g plus -keyint_min plus no scenecut** — g = max GOP, keyint_min = min GOP, sc_threshold = scene change threshold; fixed GOPs make segment cuts exact. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -g 30 -keyint_min 30 -sc_threshold 0 -an fixedgop.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#dash-2, checked 2026-10-24]
4431. **Access unit delimiters** — aud=1 adds access unit delimiters; some broadcast and Blu-ray chains want them. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -x264-params aud=1 -an aud.ts` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4432. **Blu-ray compatible x264** — bluray-compat is a shorthand for bluray-compat=1 force-cfr=1. **How:** full Blu-ray authoring needs more (see the wiki's Blu-ray page). `ffmpeg -y -i in.mp4 -c:v libx264 -bluray-compat 1 -an bd.264` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.264, checked 2026-10-24]
4433. **Print SSIM after encoding** — -ssim 1 makes libx264 print SSIM stats at the end. Here x264 warned that SSIM with psy on is invalid, so turn psy off for the measurement run. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -ssim 1 -psy 0 -an -f null - 2>&1 | grep -i ssim` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx264_002c-libx264rgb, checked 2026-10-24]
4434. **Intra-only H.264 for frame-accurate review** — with -g 1 -bf 0 every frame is an I-frame, so scrubbing backwards is easy; needs a lower CRF (7-11 in the VFX test). **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -g 1 -bf 0 -crf 9 -pix_fmt yuv420p -an review.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VFX, checked 2026-10-24]
4435. **CRF 19 for review copies** — in the VFX wiki's tests CRF 19 gave very good movies at small size that play on ordinary laptops; playback trouble eased from CRF 15 up. **How:** `ffmpeg -y -i in.mp4 -c:v libx264 -crf 19 -pix_fmt yuv420p -c:a copy daily.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VFX, checked 2026-10-24]

## H.265/HEVC with libx265

4436. **x265 CRF 28 ~ x264 CRF 23** — x265's default CRF 28 should look like x264 CRF 23 at about half the size; the max is always 51, even 10-bit. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -crf 28 -preset medium -c:a aac -b:a 128k hevc.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4437. **x265 savings grow with resolution** — libx265 saves around 25-50% over libx264 at the same quality, most at 1080p and above. **How:** prefer HEVC for 1080p/4K masters to platforms that accept it. [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4438. **Preset changes the size at the same CRF** — CRF values differ by preset: veryslow at one CRF may be bigger than ultrafast but better per bit. **How:** compare presets at equal file size, not equal CRF. [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4439. **x265 two-pass uses x265-params pass** — for libx265 the -pass option does not apply; use -x265-params pass=1 / pass=2. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -b:v 600k -x265-params pass=1 -an -f null /dev/null && ffmpeg -y -i in.mp4 -c:v libx265 -b:v 600k -x265-params pass=2 -c:a aac h265_2p.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4440. **Lossless HEVC** — use -x265-params lossless=1 (no -crf 0 needed); the log shows a lossless compression ratio. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params lossless=1 -an hevc_ll.mkv 2>&1 | grep -i lossless` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24] [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4441. **All-intra HEVC** — use -g 1 (ffmpeg 4.3+) for intra-only HEVC. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -g 1 -crf 20 -an hevc_intra.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4442. **hvc1 tag for Apple** — add -tag:v hvc1 so Final Cut/Apple players accept the HEVC file. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -crf 24 -tag:v hvc1 -c:a copy apple_hevc.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4443. **Main 10 for 10-bit HEVC** — x265 10-bit profiles include main10 and main422-10; 8-bit main and main444-8. **How:** `ffmpeg -y -i in10.mkv -c:v libx265 -pix_fmt yuv420p10le -profile:v main10 -crf 22 m10.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libx265, checked 2026-10-24]
4444. **x265 tunes** — x265 tunes: psnr, ssim, grain, zero-latency, fast-decode, animation; generally not required. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -tune animation -crf 24 -an h265anim.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/H.265, checked 2026-10-24]
4445. **tune grain turns on rc-grain** — rc-grain minimises QP fluctuations and removes pulsing of grain; it is enabled by --tune grain, which is the recommended way. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -tune grain -crf 22 -an h265grain.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4446. **x265 keyint default 250** — x265 keyint defaults to 250; -1 is one keyframe at the start, 1 is all-intra; set min-keyint equal for a fixed interval. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params keyint=60:min-keyint=60:scenecut=0 -an h265gop.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4447. **x265 open GOP is on by default** — x265 allows non-IDR I-slices by default (--open-gop). Turn it off when a platform needs closed GOP. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params no-open-gop=1 -an closedgop.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24] [X Developer docs, https://docs.x.com/x-api/media/quickstart/best-practices, checked 2026-10-24]
4448. **x265 B-frames default 4** — x265 --bframes defaults to 4 (0-16); 0 forces low-latency P/I only. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params bframes=0 -an h265nob.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4449. **x265 level and tier** — --level-idc sets the minimum decoder level (as 5.1 or 51); it can force VBV on CRF encodes. high-tier is default enabled, used only if needed. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params level-idc=4:no-high-tier=1 -an h265l4.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4450. **x265 VBV in CRF mode needs both values** — in CRF mode both vbv-bufsize and vbv-maxrate (kbit) are needed; VBV also turns on emergency denoising when QP > 51. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -crf 24 -x265-params vbv-maxrate=2000:vbv-bufsize=4000 -an h265vbv.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4451. **x265 strict-cbr** — strict-cbr keeps ABR within ~5% of target, prioritising bitrate over quality, useful for short segments. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -b:v 800k -x265-params strict-cbr=1:vbv-maxrate=800:vbv-bufsize=1600 -an h265cbr.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4452. **aq-mode 3 against banding in dark 8-bit** — x265 aq-mode 3 biases to dark scenes and is recommended for 8-bit or low-bitrate 10-bit encodes to prevent banding/blocking. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -crf 24 -x265-params aq-mode=3 -an h265aq3.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4453. **Repeat headers for raw HEVC streams** — --repeat-headers emits VPS/SPS/PPS at every keyframe, for when no container holds the headers. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params repeat-headers=1 -an rh.hevc` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4454. **Drop the x265 info SEI for bit-exact tests** — --info (default on) writes encoder version and settings into the stream; it can make bitstreams differ between builds. Turn off for regression tests. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params info=0 -an noinfo.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4455. **Zones: more bits for one scene** — --zones start,end,b=multiplier (or q=QP) changes bitrate for frame ranges; later zones win. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -crf 24 -x265-params zones=0,29,b=1.5 -an zones.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]
4456. **x265 picture hash SEI** — --hash 1/2/3 writes MD5/CRC/checksum SEI so a decoder can validate pictures and detect data loss. **How:** `ffmpeg -y -i in.mp4 -c:v libx265 -x265-params hash=1 -an hashsei.mp4` (tested here 2026-10-24) [x265 docs, https://x265.readthedocs.io/en/master/cli.html, checked 2026-10-24]

## AV1 (SVT-AV1, libaom, rav1e)

4457. **SVT-AV1 CRF default 35** — libsvtav1 CRF is the default rate control; ffmpeg range 0-63 (default 35). The upstream guide says crf=30 is a good 1080p start. **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -crf 35 -c:a copy svt.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24] [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Ffmpeg.md, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libsvtav1, checked 2026-10-24]
4458. **SVT-AV1 presets 0-13** — higher presets are faster; 13 is only for debugging; 4-6 is a common quality/time trade-off; 10+ for fast/realtime. **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -preset 10 -crf 35 -c:a copy svt_fast.mp4` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24] [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Ffmpeg.md, checked 2026-10-24]
4459. **SVT-AV1 personal-archive line** — the upstream example: preset 5, crf 32, -g 240, 10-bit, tune=0 (subjective), film-grain=8. **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -preset 6 -crf 32 -g 240 -pix_fmt yuv420p10le -svtav1-params tune=0:film-grain=8 -c:a copy svt_home.mkv` (tested here 2026-10-24) [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Ffmpeg.md, checked 2026-10-24]
4460. **Film-grain level by content** — film-grain 1-50 denoises and re-synthesises grain at decode; ~8 for normal live action, 10-15 very grainy, 4-6 for 2D animation; omit if no grain. SVT-AV1 1.7.0 here warned that film grain above preset 6 is for debugging only. **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -preset 6 -crf 35 -svtav1-params film-grain=8 -an fg.mkv` (tested here 2026-10-24) [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Ffmpeg.md, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4461. **Keep detail with film-grain-denoise=0** — film-grain-denoise=0 encodes the original frames instead of the denoised ones, to avoid detail loss at high grain levels. **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -preset 6 -crf 35 -svtav1-params film-grain=10:film-grain-denoise=0 -an fg0.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24] [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Parameters.md, checked 2026-10-24]
4462. **SVT-AV1 keyframe interval** — SVT-AV1's default keyint is short (2-3 s per the wiki, ~5 s in current docs); the wiki suggests up to 5 s or more, e.g. -g 150 for 30 fps. **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -crf 35 -g 150 -an svtgop.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24] [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Parameters.md, checked 2026-10-24]
4463. **SVT-AV1 fast-decode** — fast-decode=1 makes bitstreams cheaper to decode (not effective on every preset). **How:** `ffmpeg -y -i in.mp4 -c:v libsvtav1 -crf 35 -svtav1-params fast-decode=1 -an svtfd.mkv` (tested here 2026-10-24) [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Ffmpeg.md, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4464. **SVT-AV1 lossless needs v3.0** — lossless is supported since SVT-AV1 v3.0.0 via svtav1-params lossless=1. Our build is v1.7.0: ffmpeg printed 'Error parsing option lossless: 1.' and still exited 0 with a lossy file, so read the log, not the exit code. **How:** needs SVT-AV1 >= 3.0 (missing); check: `ffmpeg -y -i in.mp4 -c:v libsvtav1 -crf 35 -svtav1-params lossless=1 -an ll.mkv 2>&1 | grep 'Error parsing'` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4465. **SVT-AV1 max bitrate in CRF** — mbr (kbps) caps bitrate for CRF encodes in SVT-AV1's parameter list (current docs; check your version). **How:** needs a newer SVT-AV1 if 1.7.0 rejects it. `ffmpeg -y -i in.mp4 -c:v libsvtav1 -crf 35 -svtav1-params mbr=2000 -an svtmbr.mkv` (tested here 2026-10-24) [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Parameters.md, checked 2026-10-24]
4466. **Pipe to SvtAv1EncApp for a newer SVT** — if ffmpeg's SVT is too old, pipe y4m into the standalone encoder, then mux audio back. **How:** needs SvtAv1EncApp (missing): `ffmpeg -i in.mkv -map 0:v:0 -pix_fmt yuv420p10le -f yuv4mpegpipe -strict -1 - | SvtAv1EncApp -i stdin --preset 5 --crf 32 -b out.ivf` [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/Docs/Ffmpeg.md, checked 2026-10-24]
4467. **libaom constant quality** — libaom-av1 -crf (0-63) is constant quality; CRF 23 ~ x264 CRF 19. Before ffmpeg 4.3 also add -b:v 0. **How:** `ffmpeg -y -i in.mp4 -c:v libaom-av1 -crf 30 -cpu-used 8 -row-mt 1 -an aom.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4468. **libaom constrained quality** — -crf with a non-zero -b:v gives constrained quality (quality target with a ceiling). **How:** `ffmpeg -y -i in.mp4 -c:v libaom-av1 -crf 30 -b:v 2000k -cpu-used 8 -an aomcq.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4469. **libaom speed with cpu-used** — -cpu-used 0-8 (default 1) trades speed and quality; -row-mt 1 plus tiles uses more cores. **How:** `ffmpeg -y -i in.mp4 -c:v libaom-av1 -crf 30 -cpu-used 8 -row-mt 1 -tiles 2x1 -an aomfast.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libaom_002dav1, checked 2026-10-24]
4470. **libaom keyframes every 10 s max** — libaom's default max keyframe interval is 9999 frames (slow seeking); up to 10 s is reasonable: -g 300 at 30 fps. **How:** `ffmpeg -y -i in.mp4 -c:v libaom-av1 -crf 30 -cpu-used 8 -g 300 -an aomg.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4471. **AV1 10-bit stays in Main profile** — AV1 Main profile includes 10-bit, so yuv420p10le is safe for hardware decoders; 4:4:4 needs High, 12-bit Professional. **How:** `ffmpeg -y -i in10.mkv -c:v libaom-av1 -crf 30 -cpu-used 8 -pix_fmt yuv420p10le aom10.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/AV1, checked 2026-10-24]
4472. **libaom grain synthesis** — denoise-noise-level enables grain synthesis in libaom (0 = off). **How:** `ffmpeg -y -i in.mp4 -c:v libaom-av1 -crf 30 -cpu-used 8 -denoise-noise-level 10 -an aomgrain.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libaom_002dav1, checked 2026-10-24]
4473. **rav1e speed and params** — librav1e has speed 0-10, qp 0-255 and rav1e-params. **How:** `ffmpeg -y -i in.mp4 -c:v librav1e -speed 10 -qp 100 -an rav1e.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#librav1e, checked 2026-10-24]

## VP9 and WebM

4475. **VP9: never leave out -b:v** — the default libvpx-vp9 settings without -b:v give mediocre quality. **How:** always give a bitrate or -crf with -b:v 0. [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4476. **VP9 constant quality needs -b:v 0** — constant quality needs -crf plus -b:v 0 exactly; CRF 0-63, 15-35 recommended, 31 for 1080p. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -crf 31 -b:v 0 -deadline good -cpu-used 4 -c:a libopus vp9.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4477. **VP9 two-pass constant quality** — two-pass is the recommended libvpx-vp9 method, because some quality features only run in 2-pass; -b:v 0 -crf N in both passes. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -b:v 0 -crf 30 -pass 1 -an -f null /dev/null && ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -b:v 0 -crf 30 -pass 2 -cpu-used 4 -c:a libopus vp9_2p.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4478. **VP9 first pass speed is fixed** — for VP9 -speed 0-4 give the same first-pass speed and results; above 4 the first pass goes single-core and slower, so omit -speed in pass 1. **How:**  [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4479. **VP9 constrained quality** — -crf with a non-zero -b:v bounds the bitrate; easy clips behave like CQ, hard clips like VBR. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -crf 30 -b:v 2000k -cpu-used 4 -an vp9cq.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4480. **VP9 CBR** — set -minrate, -maxrate and -b:v to the same value. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -minrate 1M -maxrate 1M -b:v 1M -cpu-used 4 -an vp9cbr.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4481. **Lossless VP9** — -lossless 1 enables lossless libvpx-vp9. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -lossless 1 -cpu-used 4 -an vp9ll.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4482. **VP9 deadline good, not best** — deadline good is the recommended default; ffmpeg docs say best is poorly named, slow and may be worse than good; realtime for live. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -crf 33 -b:v 0 -deadline realtime -cpu-used 8 -an vp9rt.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libvpx, checked 2026-10-24]
4483. **VP9 row-mt** — -row-mt 1 enables row-based multithreading (off by default in libvpx 1.7); gains grow with resolution. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -crf 33 -b:v 0 -row-mt 1 -cpu-used 4 -an vp9mt.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4484. **VP9 4:2:0 for players** — 4:2:2/4:4:4 sources may give output some players can't handle; force -pix_fmt yuv420p. **How:** `ffmpeg -y -i in10.mkv -c:v libvpx-vp9 -pix_fmt yuv420p -crf 33 -b:v 0 -cpu-used 4 vp9_420.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4485. **VP9 tune-content screen** — tune-content: default, screen, film. **How:** for screen recordings: `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -crf 33 -b:v 0 -tune-content screen -cpu-used 4 -an vp9screen.webm` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#libvpx, checked 2026-10-24]
4486. **WebM audio is Opus or Vorbis** — WebM takes Vorbis or Opus; the default WebM audio encoder is libopus. **How:** `ffmpeg -y -i in.mp4 -c:v libvpx-vp9 -crf 33 -b:v 0 -cpu-used 5 -c:a libopus -b:a 96k webm_opus.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/HighQualityAudio, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VP9, checked 2026-10-24]
4487. **Cues at the front of WebM/MKV** — -movflags +faststart does nothing for Matroska; use -cues_to_front 1. **How:** `ffmpeg -y -i vp9.webm -c copy -cues_to_front 1 vp9_front.webm` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/YouTube, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#matroska, checked 2026-10-24]

## Mezzanine and intermediate codecs (ProRes, DNxHR, FFV1, MJPEG)

4488. **Use prores_ks, not prores/prores_aw** — the VFX wiki found prores_ks the best of ffmpeg's ProRes encoders and the only one with 4444; colour from prores and prores_ks looked the same. **How:** `ffmpeg -y -i in10.mkv -c:v prores_ks -profile:v 3 -pix_fmt yuv422p10le -c:a pcm_s16le hq.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VFX, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#ProRes, checked 2026-10-24]
4489. **ProRes profile names** — prores_ks profiles: proxy, lt, standard, hq, 4444, 4444xq (0-5). **How:** `ffmpeg -y -i in10.mkv -c:v prores_ks -profile:v lt -pix_fmt yuv422p10le lt.mov` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#ProRes, checked 2026-10-24]
4490. **ProRes 4444 with alpha** — 4444 profiles take yuva444p10le; alpha_bits 0/8/16 (0 disables alpha coding); 4444 and 4444 XQ are the only ProRes with alpha. **How:** `ffmpeg -y -f lavfi -i testsrc2=s=320x180:r=30 -t 1 -vf format=yuva444p10le -c:v prores_ks -profile:v 4444 -alpha_bits 16 alpha4444.mov` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#ProRes, checked 2026-10-24] [Apple ProRes White Paper (April 2022), https://www.apple.com/final-cut-pro/docs/Apple_ProRes.pdf, checked 2026-10-24]
4491. **ProRes qscale 9-13** — in the VFX wiki's tests -qscale:v 9-13 was a good size/quality balance (11 a good bet, 9 a bit better; 5 or less when space is no problem; 0 best, 32 worst). **How:** `ffmpeg -y -i in10.mkv -c:v prores_ks -profile:v 3 -qscale:v 11 -pix_fmt yuv422p10le q11.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VFX, checked 2026-10-24]
4492. **vendor apl0** — -vendor apl0 makes QuickTime/Final Cut treat the file as made by Apple's encoder. **How:** `ffmpeg -y -i in10.mkv -c:v prores_ks -profile:v 3 -vendor apl0 -pix_fmt yuv422p10le apl0.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VFX, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#ProRes, checked 2026-10-24]
4493. **ProRes speed: raise bits_per_mb** — prores_ks honours frame size limits; detailed frames take longer. A higher bits_per_mb (profiles use 200-2400, max 8000) speeds it up. **How:** `ffmpeg -y -i in10.mkv -c:v prores_ks -profile:v 3 -bits_per_mb 2400 -pix_fmt yuv422p10le bpm.mov` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#ProRes, checked 2026-10-24]
4494. **ProRes target rates at 1080p29.97** — Apple targets: 4444 XQ ~500 Mbps, 4444 ~330, 422 HQ ~220, 422 ~147, 422 LT ~102, Proxy ~45 Mbps. **How:** use these to estimate disk space for a delivery. [Apple ProRes White Paper (April 2022), https://www.apple.com/final-cut-pro/docs/Apple_ProRes.pdf, checked 2026-10-24]
4495. **ProRes GB per hour** — Apple's table: 1920x1080 30p 422 HQ = 220 Mb/s = 99 GB/hr; 3840x2160 30p 422 HQ = 884 Mb/s = 398 GB/hr; 1080 30p Proxy = 45 Mb/s = 20 GB/hr. **How:** budget storage from the table before exporting a master. [Apple ProRes White Paper (April 2022), https://www.apple.com/final-cut-pro/docs/Apple_ProRes.pdf, checked 2026-10-24]
4496. **ProRes is VBR with a ~10% ceiling** — ProRes varies bits per frame around a target; the maximum is about 10% above the target bits per frame. **How:**  [Apple ProRes White Paper (April 2022), https://www.apple.com/final-cut-pro/docs/Apple_ProRes.pdf, checked 2026-10-24]
4497. **ProRes HQ for Vimeo** — Vimeo accepts H.264, ProRes 422 HQ or HEVC, and suggests ProRes if H.264 shows quality issues and you have storage. **How:** `ffmpeg -y -i in10.mkv -c:v prores_ks -profile:v hq -pix_fmt yuv422p10le -c:a aac -b:a 320k -ar 48000 vimeo_hq.mov` (tested here 2026-10-24) [Vimeo Help, https://help.vimeo.com/hc/en-us/articles/12426043233169-Video-and-audio-compression-guidelines, checked 2026-10-24]
4498. **DNxHR profiles in ffmpeg** — the dnxhd encoder here lists dnxhr_lb, dnxhr_sq, dnxhr_hq, dnxhr_hqx and dnxhr_444; pixel formats yuv422p, yuv422p10le, yuv444p10le, gbrp10le. **How:** `ffmpeg -hide_banner -h encoder=dnxhd` (tested here 2026-10-24)
4499. **DNxHR HQ (8-bit 4:2:2)** — the dnxhr_hq profile takes yuv422p (8-bit 4:2:2). **How:** `ffmpeg -y -i in.mp4 -c:v dnxhd -profile:v dnxhr_hq -pix_fmt yuv422p -c:a pcm_s16le dnxhr_hq.mov` (tested here 2026-10-24)
4500. **DNxHR HQX (10-bit)** — the dnxhr_hqx profile takes yuv422p10le (10-bit 4:2:2). **How:** `ffmpeg -y -i in10.mkv -c:v dnxhd -profile:v dnxhr_hqx -pix_fmt yuv422p10le dnxhr_hqx.mov` (tested here 2026-10-24)
4501. **Photo JPEG review movies** — Photo JPEG plays on any OS; only qscale matters and should be 1; fine up to ~1K, struggles at 2K+. **How:** `ffmpeg -y -i in.mp4 -c:v mjpeg -q:v 1 -pix_fmt yuvj422p -an pjpeg.mov` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/VFX, checked 2026-10-24]
4502. **FFV1 is the archive codec** — FFV1 is lossless and a good choice for archiving and preservation; the Library of Congress made FFV1 v3 in Matroska a Preferred Format in Dec 2023. **How:** `ffmpeg -y -i in10.mkv -c:v ffv1 -level 3 -g 1 -slicecrc 1 -slices 24 -c:a copy archive.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/FFV1, checked 2026-10-24] [Library of Congress blog, https://blogs.loc.gov/thesignal/2023/12/embracing-ffv1-matroska-container-preferred/, checked 2026-10-24]
4503. **FFV1 archival settings** — for archival use GOP 1 (error resilience, frames lost independently) and slice CRC on; two-pass may win back size. **How:** `ffmpeg -y -i in10.mkv -c:v ffv1 -level 3 -coder 1 -context 1 -g 1 -slices 24 -slicecrc 1 ffv1_arch.mkv` (tested here 2026-10-24) [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/FFV1, checked 2026-10-24]

4616. **One still per second** — -fps_mode cfr -r 1 writes one image per second. **How:** `ffmpeg -y -i in.mp4 -fps_mode cfr -r 1 stills/img-%03d.jpeg` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#image2_002c-image2pipe, checked 2026-10-24]
4617. **Name frames by PTS** — -frame_pts 1 puts the timestamp in the file name (use with -copyts). **How:** `ffmpeg -y -i in.mp4 -copyts -frame_pts 1 -frames:v 3 pts/%d.png && ls pts` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#image2_002c-image2pipe, checked 2026-10-24]

## Checksums and QC

4621. **Decoded-content hash with -f hash** — the hash muxer hashes all decoded frames (SHA-256 default; MD5, CRC32, adler32...), ignoring timestamps: proves two files decode to the same picture/sound. **How:** `ffmpeg -v error -i in.mp4 -f hash -hash md5 -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#hash-1, checked 2026-10-24]
4622. **Per-stream hash** — streamhash prints one hash per stream, so audio and video can be checked separately. **How:** `ffmpeg -v error -i in.mp4 -map 0 -f streamhash -hash sha256 -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#streamhash-1, checked 2026-10-24]
4623. **Frame-by-frame MD5** — framemd5 writes an MD5 per packet with dts/pts/duration/size, to find the first differing frame. **How:** `ffmpeg -v error -y -i in.mp4 -f framemd5 frames.md5 && head -12 frames.md5 | tail -2` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#framemd5-1, checked 2026-10-24]
4624. **Per-frame SHA-256** — framehash defaults to SHA-256 per packet. **How:** `ffmpeg -v error -y -i in.mp4 -f framehash -hash sha256 fh.txt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#framehash-1, checked 2026-10-24]
4625. **Compare stream-copied packets** — with -c copy, framemd5 hashes the coded packets, so a remux can be checked against the original. Here a remux with use_editlist 0 shifted every timestamp but kept every hash, so compare the stream index + hash columns only. **How:** `ffmpeg -v error -y -i in.mp4 -c copy -f framemd5 a.md5 && ffmpeg -v error -y -i yt.mp4 -c copy -f framemd5 b.md5 && diff <(grep -v '^#' a.md5 | cut -d, -f1,6 | sort) <(grep -v '^#' b.md5 | cut -d, -f1,6 | sort) && echo SAME` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#framemd5-1, checked 2026-10-24]
4626. **Lossless round-trip proof** — encode FFV1/lossless and compare the decoded hash with the source's. **How:** `ffmpeg -v error -i in10.mkv -f hash -hash md5 - > s.txt && ffmpeg -v error -y -i in10.mkv -c:v ffv1 -level 3 rt.mkv && ffmpeg -v error -i rt.mkv -f hash -hash md5 - > r.txt && cmp s.txt r.txt && echo LOSSLESS` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#hash-1, checked 2026-10-24] [FFmpeg Wiki, https://trac.ffmpeg.org/wiki/Encode/FFV1, checked 2026-10-24]
4627. **Quick CRC** — the crc muxer prints one Adler-32 over all decoded frames; framecrc one per packet. **How:** `ffmpeg -v error -i in.mp4 -f crc -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#crc-1, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#framecrc-1, checked 2026-10-24]
4628. **Decode test with -f null** — the null muxer writes nothing: decode a file fully to find errors (add -benchmark for speed). **How:** `ffmpeg -v error -benchmark -i in.mp4 -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#null, checked 2026-10-24]
4629. **Whole-file checksum list for deliveries** — a sha256sum manifest next to the files lets the client verify the transfer. **How:** `sha256sum in.mp4 in.wav > SHA256SUMS && sha256sum -c SHA256SUMS` (tested here 2026-10-24)
4630. **Count keyframe spacing** — list keyframe packet times to check GOP length matches the spec. **How:** `ffprobe -v error -select_streams v:0 -show_entries packet=pts_time,flags -of csv=p=0 fixedgop.mp4 | grep K | head -3` (tested here 2026-10-24)
4631. **Check faststart (moov before mdat)** — trace the top-level atoms: moov must come before mdat for progressive playback. **How:** `ffprobe -v trace -i yt.mp4 2>&1 | grep -oE "type:'(moov|mdat)'" | head -2` (tested here 2026-10-24)
4632. **Confirm profile, level, pix_fmt** — read profile, level, pix_fmt and B-frames before sending to a platform. **How:** `ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,profile,level,pix_fmt,has_b_frames,r_frame_rate -of default=nw=1 l41.mp4` (tested here 2026-10-24)

## Archive and broadcast

4633. **Bit-exact output for reproducible files** — -bitexact enables bitexact mode for muxers/encoders (no version strings), so reruns can be byte-compared. **How:** `ffmpeg -y -i in.wav -c:a pcm_s16le -bitexact -fflags +bitexact be1.wav && ffmpeg -y -i in.wav -c:a pcm_s16le -bitexact -fflags +bitexact be2.wav && cmp be1.wav be2.wav && echo IDENTICAL` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
4634. **MPEG-TS service names** — mpegts metadata service_provider/service_name (defaults FFmpeg / Service01) plus service_id, PIDs. **How:** `ffmpeg -y -i in.mp4 -c copy -mpegts_service_id 0x0101 -mpegts_pmt_start_pid 0x1500 -mpegts_start_pid 0x150 -metadata service_provider=FireCraft -metadata service_name=Promo bc.ts` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#mpegts-1, checked 2026-10-24]

## Missing tools

- **SVT-AV1 >= 3.0 / SvtAv1EncApp** — our ffmpeg links SVT-AV1 1.7.0, which has no lossless mode and no standalone CLI here. Free option: build SVT-AV1 from source (BSD 3-Clause Clear License), https://gitlab.com/AOMediaCodec/SVT-AV1 (licence file https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/master/LICENSE.md, checked 2026-10-24).
- **libfdk_aac (HE-AAC v1/v2)** — the native aac encoder makes AAC-LC only. libfdk_aac is marked non-free (its licence is not GPL-compatible), so no prebuilt ffmpeg has it and it must be compiled yourself; source and notes: https://trac.ffmpeg.org/wiki/Encode/AAC (checked 2026-10-24). For HLS above 64 kbit/s, AAC-LC is what Apple asks for anyway.
- **GPU encoders (NVENC/AMF/QSV)** — no GPU in this container, so h264_nvenc/av1_amf lines from the wiki can't run here; CPU encoders above cover every delivery.
