# Restoration and repair on CPU
Scope: low-fps/VFR phone clips, interpolation, upscaling, denoise, deblock/deband, deinterlace and inverse telecine, stabilisation, lens/geometry, flicker, corrupt or truncated files, VHS and old film (not colour looks).
Researched 2026-10-24 via agent-reach (Exa) web search, official docs and local tests.

Tests ran on synthetic 2 s clips (640x360 testsrc2 with noise, interlace, telecine, shake, barrel, VFR and damage added) with the local ffmpeg 6.1.1; `in.mp4` stands for the clip. The current ffmpeg docs describe a newer ffmpeg, so where 6.1 differed it is noted. Tools marked "(missing)" were downloaded or built only in the scratchpad for the test; see Missing tools.


## Diagnose the damage first

1281. **Count variable-delta frames with vfrdet** — vfrdet reports how many frames had a variable vs constant pts delta, plus min/max/average delta when any varied. **How:** Run it before choosing a CFR target: `ffmpeg -i in.mp4 -vf vfrdet -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vfrdet, checked 2026-10-24]
1282. **Equal rate fields do not prove CFR** — r_frame_rate is only a base-rate guess and avg_frame_rate an estimate; equal values do not prove constant frame rate, so read the decoded frame times across the clip and do not pick the target from the average alone. **How:** Dump every frame time and compare neighbours: `ffprobe -v error -select_streams v:0 -show_frames -show_entries frame=best_effort_timestamp_time -of csv=p=0 in.mp4` (tested here 2026-10-24) [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/variable-framerate-to-constant/, checked 2026-10-24]
1283. **Per-frame log with showinfo** — showinfo prints, per frame, n, pts_time, interlace mode i (P/T/B), iskey, picture type (I/P/B) and plane checksums, mean and stdev, without changing the video. **How:** Use it to see keyframes, field flags and odd timestamps around a damaged spot: `ffmpeg -i in.mp4 -vf showinfo -f null - 2>&1 | grep pts_time | head` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#showinfo, checked 2026-10-24]
1284. **List duplicated frames with mpdecimate debug** — There is no "dupedetect" filter; mpdecimate at loglevel debug prints a drop/keep line with pts_time for every frame it considers a duplicate. **How:** Count or grep the drop lines: `ffmpeg -i in.mp4 -vf mpdecimate -loglevel debug -an -f null - 2>&1 | grep -c ' drop '` (tested here 2026-10-24) [Stack Overflow, https://stackoverflow.com/questions/51273508/reporting-duplicated-frames-with-ffmpeg, checked 2026-10-24] [Stack Overflow, https://stackoverflow.com/questions/37088517, checked 2026-10-24]
1285. **Find frozen stretches with freezedetect** — freezedetect logs freeze_start/duration/end when the picture shows no significant change for duration d (default 2 s) against noise tolerance n (default -60 dB / 0.001). **How:** Lower d to catch short freezes: `ffmpeg -i in.mp4 -vf freezedetect=n=-60dB:d=0.5 -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#freezedetect, checked 2026-10-24]
1286. **Find black dropouts with blackframe** — blackframe reports frames where at least amount % (default 98) of pixels are below threshold (default 32), with frame number and timestamp, and exports lavfi.blackframe.pblack. **How:** Needs loglevel info or higher: `ffmpeg -i in.mp4 -vf blackframe=amount=98:threshold=32 -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blackframe, checked 2026-10-24]
1287. **Spot tape dropouts with signalstats TOUT** — signalstats stat=tout flags temporal outliers, pixels unlike their same-field neighbours, such as video dropouts, head clogs or tape tracking problems in digitised analog video. **How:** Read the per-frame TOUT value: `ffprobe -v error -f lavfi -i "movie=in.mp4,signalstats=stat=tout" -show_entries frame_tags=lavfi.signalstats.TOUT -of csv=p=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#signalstats-1, checked 2026-10-24]
1288. **Spot dropout concealment with signalstats VREP** — stat=vrep finds vertical line repetition; uncommon in analog captures, so in digitised tape it can mean a dropout compensator concealed damage. **How:** Same probe, VREP tag: `ffprobe -v error -f lavfi -i "movie=in.mp4,signalstats=stat=vrep" -show_entries frame_tags=lavfi.signalstats.VREP -of csv=p=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#signalstats-1, checked 2026-10-24]
1289. **Highlight out-of-broadcast-range pixels** — signalstats out=brng paints pixels outside legal broadcast range in the chosen colour (default yellow). **How:** Render one marked frame to look at: `ffmpeg -i in.mp4 -vf signalstats=out=brng:color=red -frames:v 1 brng.png` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#signalstats-1, checked 2026-10-24]
1290. **Log per-frame brightness and change (YAVG, YDIF)** — signalstats logs YAVG (average luma) and YDIF (average difference to the previous frame) per frame, among YMIN/YMAX, U/V and saturation stats. **How:** Read both for a flickering clip, before and after a fix: `ffprobe -v error -f lavfi -i "movie=in.mp4,signalstats" -show_entries frame_tags=lavfi.signalstats.YAVG,lavfi.signalstats.YDIF -of csv=p=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#signalstats-1, checked 2026-10-24]
1291. **Score blockiness with blockdetect** — blockdetect measures blocking artifacts without changing frames (no-reference measure by Muijs and Kirenko); period_min/max set the grid search range, default 3-24. **How:** Docs example searches periods 8-32: `ffmpeg -i in.mp4 -vf blockdetect=period_min=8:period_max=32 -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blockdetect-1, checked 2026-10-24]
1292. **Score blur with blurdetect** — blurdetect measures blurriness (Marziliano no-reference metric); block_width/height/pct limit it to the most significant blocks. **How:** Docs example: 80% of the most significant 32x32 blocks: `ffmpeg -i in.mp4 -vf blurdetect=block_width=32:block_height=32:block_pct=80 -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blurdetect-1, checked 2026-10-24]
1293. **Measure spatial and temporal information (siti)** — siti computes ITU-T P.910 SI/TI scores (a legacy implementation of a superseded edition); print_summary=1 prints summary stats. **How:** Docs command: `ffmpeg -i in.mp4 -vf siti=print_summary=1 -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#siti-1, checked 2026-10-24]
1294. **Telecine shows up as repeated fields in idet** — In idet's summary, telecine appears as Top or Bottom "Repeated Fields" in roughly two of every five frames; true interlaced video combs every moving frame instead. **How:** Run idet over a moving section and read the Repeated Fields line: `ffmpeg -i in.mp4 -vf idet -an -f null - 2>&1 | grep -E "Repeated|frame detection"` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/ivtc, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#idet, checked 2026-10-24]
1295. **Per-frame idet verdicts** — idet sets per-frame metadata (single/multiple current_frame, repeated.current_frame); the docs inspect the first 360 frames with metadata=print. **How:** Docs command: `ffmpeg -i in.mp4 -filter:v idet,metadata=mode=print -frames:v 360 -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#idet, checked 2026-10-24]
1296. **Clean wrong interlace flags with idet** — analyze_interlaced_flag=N makes idet check the interlaced flag on N frames; an accurate flag is kept, an inaccurate one is cleared, a cheap way to clean the flag. **How:** Place it before a deint=interlaced deinterlacer: `ffmpeg -i in.mp4 -vf idet=analyze_interlaced_flag=20,yadif=deint=interlaced -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#idet, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#yadif-1, checked 2026-10-24]
1297. **Do not trust container field flags** — Flags are often wrong (especially DVD rips); deinterlacing with the wrong field order makes motion step backward and forward, so when idet and the container disagree, test both orders on a pan and keep the smooth one. **How:** Read the stream flag, then compare with idet: `ffprobe -v error -select_streams v:0 -show_entries stream=field_order -of csv=p=0 in.mp4` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace, checked 2026-10-24] [claude-mods restoration.md, https://github.com/0xdarkmatter/claude-mods/blob/main/skills/ffmpeg-ops/references/restoration.md, checked 2026-10-24]
1298. **Find black borders with cropdetect** — cropdetect prints recommended crop values for the non-black area; limit (default 24) is the black threshold, round (default 16; 2 for even sizes), skip initial frames (default 2). **How:** Docs pattern with metadata print: `ffmpeg -i in.mp4 -vf cropdetect=limit=24:round=2,metadata=mode=print -an -f null - 2>&1 | grep crop= | tail -1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#cropdetect, checked 2026-10-24]
1299. **Find an embedded picture with cropdetect mvedges** — mode=mvedges finds the playing video from motion vectors plus edge pixels; motion vectors come from mestimate or from the decoder with -flags2 +export_mvs. **How:** Docs command: `ffmpeg -i in.mp4 -vf mestimate,cropdetect=mode=mvedges,metadata=mode=print -an -f null - 2>&1 | grep crop= | tail -1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#cropdetect, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mestimate, checked 2026-10-24]
1300. **Reset cropdetect when a logo spoils it** — reset_count=N restarts detection after N frames; useful when channel logos distort the detected area (0 = never reset, keep the largest area). **How:** `ffmpeg -i in.mp4 -vf cropdetect=reset_count=30,metadata=mode=print -an -f null - 2>&1 | grep -c crop=` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#cropdetect, checked 2026-10-24]
1301. **Bounding box of non-black pixels** — bbox prints the box containing all luma values above min_val (default 16). **How:** `ffmpeg -i in.mp4 -vf bbox=min_val=16 -an -f null - 2>&1 | grep -m1 x1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bbox, checked 2026-10-24]
1302. **Scene-change scores with scdet** — scdet sets lavfi.scd.score per frame and logs cuts above threshold (good values 8-14, default 10); sc_pass=1 passes only the scene-change frames. **How:** `ffmpeg -i in.mp4 -vf scdet=threshold=10 -an -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scdet-1, checked 2026-10-24]
1303. **Stop at the first error: -xerror** — -xerror makes ffmpeg stop and exit on error, so a corrupt file fails fast instead of being decoded through. **How:** Exits non-zero on our damaged test TS (that is the point): `ffmpeg -xerror -v error -i in.ts -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1304. **Exit code 69 when too many frames fail** — -max_error_rate sets the fraction of failed frame decodes (0-1, default 2/3) above which ffmpeg returns exit code 69; processing still continues. **How:** `ffmpeg -max_error_rate 0.0 -v error -i in.ts -f null -; echo exit=$?` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1305. **Strict damage check: -err_detect explode** — The err_detect decoder flags include crccheck, bitstream, buffer and explode (abort decoding on minor error detection); careful/compliant/aggressive tighten what counts as an error. **How:** Here (ffmpeg 6.1) it still exited 0 on a damaged TS while logging the errors, so read the log, or use -xerror for a non-zero exit: `ffmpeg -v error -err_detect explode -i in.ts -f null -` (tested here 2026-10-24) [ffmpeg-codecs docs, https://ffmpeg.org/ffmpeg-codecs.html#Codec-Options, checked 2026-10-24]
1306. **Abort when nothing gets written** — -abort_on empty_output stops when no packets reached the muxer; empty_output_stream does it per output stream. **How:** `ffmpeg -abort_on empty_output -i in.mp4 -c copy out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1307. **Show only what changed between frames: tmix -1 2 -1** — Docs example tmix=frames=3:weights="-1 2 -1":scale=1 shows only temporal differences (weights -1 3 -1 is a simple temporal convolution). **How:** `ffmpeg -i in.mp4 -vf "tmix=frames=3:weights=-1 2 -1:scale=1" -c:v libx264 -crf 18 diff.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]

## Variable frame rate and timestamps

1308. **Keep phone timestamps as they are: -fps_mode passthrough** — -fps_mode passthrough passes each frame with its demuxer timestamp; cfr duplicates/drops to an exact rate; vfr passes frames but drops ones that would share a timestamp; auto (default) picks cfr or vfr by muxer. **How:** `ffmpeg -i in.mp4 -fps_mode passthrough -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1309. **CFR conversion cannot bring back missing pictures** — Converting VFR to CFR only duplicates or drops frames; it cannot restore lost pictures or work out the right lip sync. If original and copy are off by the same fixed amount, changing the frame rate will not fix it. **How:** Compare start, middle and end of the original and a short CFR test copy in the same player first. [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/variable-framerate-to-constant/, checked 2026-10-24]
1310. **VFR to CFR with audio kept on the same timeline** — Put fps=<rate> on the video chain and aresample=async=1 on the audio chain: fps alone gives constant video beside audio that still has the recorder's hole in it; async=1 fills holes with silence and trims overlaps. **How:** Source-given filtergraph: `ffmpeg -i in.mp4 -filter_complex "[0:v]fps=25[v];[0:a]aresample=async=1[a]" -map "[v]" -map "[a]" -c:v libx264 -crf 18 -c:a aac out.mp4` (tested here 2026-10-24) [afmpeg how-to, https://afmpeg.phpboyscout.uk/how-to/get-a-constant-frame-rate/, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#aresample-1, checked 2026-10-24]
1311. **What the number in aresample=async means** — async=1 only inserts silence or trims samples; values above 1 also allow stretching/squeezing by up to that many samples per second; inserting/trimming starts when the gap exceeds 0.1 s (min_hard_comp default). In MP4 a clock-speed mismatch may not show in timestamps, so async cannot fix it. **How:** `ffmpeg -i in.mp4 -af aresample=async=1000 -c:v copy out.mp4` (tested here 2026-10-24) [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/fix-audio-drift/, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#aresample-1, checked 2026-10-24]
1312. **Growing drift is a speed problem, not an offset** — If audio matches at the start and gets worse toward the end, it is drift; -itsoffset only shifts by a fixed amount. Measure the gap near the end and correct the audio speed: 0.5 s late at 600 s gives (600+0.5)/600 = 1.00083. **How:** `ffmpeg -i in.mp4 -af atempo=1.00083 -c:v copy out.mp4` (tested here 2026-10-24) [FFmpeg Cookbook, https://ffmpeg-cookbook.com/en/articles/fix-audio-drift/, checked 2026-10-24]
1313. **Drop duplicate frames and keep the audio** — mpdecimate removes near-duplicate frames; with variable-rate output the remaining frames keep their timestamps, so the audio stays usable (the answer used -vsync vfr, now -fps_mode vfr). **How:** `ffmpeg -i in.mp4 -vf mpdecimate -fps_mode vfr -c:v libx264 -crf 18 -c:a copy out.mp4` (tested here 2026-10-24) [Stack Overflow, https://stackoverflow.com/questions/37088517, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1314. **Cut frozen parts out of a video-only clip** — mpdecimate plus setpts=N/FRAME_RATE/TB rebuilds smooth timestamps after the duplicates are gone; mpdecimate works only on video, so drop the audio or it goes out of sync. **How:** `ffmpeg -i in.mp4 -vf mpdecimate,setpts=N/FRAME_RATE/TB -an out.mp4` (tested here 2026-10-24) [Video SE, https://video.stackexchange.com/questions/28631/remove-frozen-parts-from-a-corrupted-video, checked 2026-10-24] [Stack Overflow, https://stackoverflow.com/questions/37088517, checked 2026-10-24]
1315. **Tune mpdecimate thresholds** — A frame is dropped when no 8x8 block differs by more than hi (default 64*12) and no more than frac (default 0.33) of blocks differ by more than lo (default 64*5); one user detected duplicates more aggressively with hi=64*32:lo=64*24:frac=0.05. **How:** `ffmpeg -i in.mp4 -vf mpdecimate=hi=64*32:lo=64*24:frac=0.05 -fps_mode vfr -an out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mpdecimate, checked 2026-10-24] [Stack Overflow, https://stackoverflow.com/questions/37088517, checked 2026-10-24]
1316. **Limit how many frames mpdecimate may drop in a row** — max (mode 0) sets the maximum consecutive drops when positive, or the minimum interval between drops when negative; keep ignores that many similar frames before dropping starts. **How:** `ffmpeg -i in.mp4 -vf mpdecimate=max=2:keep=1 -fps_mode vfr -an out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mpdecimate, checked 2026-10-24]
1317. **Periodic duplicates: decimate, not mpdecimate** — mpdecimate is heuristic and may skip some duplicates; decimate removes exactly one frame per cycle, so it suits only regularly repeating duplicates (one user had 1 duplicate after every 5 good frames). decimate needs CFR input. **How:** cycle=N drops one frame in every N: `ffmpeg -i in.mp4 -vf decimate=cycle=6 -an -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [Stack Overflow, https://stackoverflow.com/questions/37088517, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#decimate-1, checked 2026-10-24]
1318. **decimate on partly duplicated footage** — decimate mixed=1 says only part of the input needs decimating; the output then becomes variable frame rate. **How:** `ffmpeg -i in.mp4 -vf decimate=mixed=1 -an -c:v libx264 -crf 18 out.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#decimate-1, checked 2026-10-24]
1319. **Pad the start when video begins after audio** — fps start_time=0 assumes the first PTS is 0, padding the beginning with copies of the first frame when video starts after audio, or trimming negative-PTS frames. **How:** `ffmpeg -i in.mp4 -vf fps=fps=30:start_time=0 -c:v libx264 -crf 18 -c:a copy out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
1320. **fps rounding and the last frame** — fps round chooses PTS rounding (zero, inf, down, up, near = default); eof_action=pass passes the last frame through if the input duration has not been reached. **How:** `ffmpeg -i in.mp4 -vf fps=fps=30:round=near:eof_action=pass -an -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
1321. **Named rates in fps: ntsc, pal, film, ntsc_film** — fps accepts source_fps, ntsc (30000/1001), pal (25), film (24) and ntsc_film (24000/1001) in its expression. **How:** `ffmpeg -i in.mp4 -vf fps=fps=ntsc -an -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
1322. **Input -r ignores the file's timestamps** — As an input option, -r ignores stored timestamps and generates CFR timestamps at the given rate (for image inputs prefer -framerate). Use it to re-time a clip whose timestamps are wrong; the duration changes. **How:** `ffmpeg -r 18 -i in.mp4 -an -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Video-Options, checked 2026-10-24]
1323. **-r with stream copy can make an invalid file** — With -c copy, output -r only tells the muxer the rate; nothing is dropped or duplicated, and the file may be invalid if it does not match the packet timestamps (see the setts bitstream filter instead). **How:** Re-encode when you need a real rate change. [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Video-Options, checked 2026-10-24]
1324. **Clamp a wrongly detected huge frame rate: -fpsmax** — -fpsmax caps the auto-set output rate, useful when the input rate is detected wrongly high. **How:** `ffmpeg -i in.mp4 -fpsmax 30 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Video-Options, checked 2026-10-24]
1325. **Rewrite packet timestamps without re-encoding: setts** — The setts bitstream filter sets PTS/DTS/duration from expressions (N, PTS, DTS, PREV_OUTPTS, ...); docs example sets PTS equal to DTS, not recommended when B-frames are involved. **How:** Docs example on the audio stream: `ffmpeg -i in.mp4 -c copy -bsf:a setts=pts=DTS out.mkv` (tested here 2026-10-24) [ffmpeg-bitstream-filters docs, https://ffmpeg.org/ffmpeg-bitstream-filters.html#setts, checked 2026-10-24]
1326. **Regenerate missing PTS while remuxing MKV** — For "Timestamps are unset in a packet" / "Can't write packet with unknown timestamp", +genpts generates missing PTS from DTS during a stream copy. **How:** `ffmpeg -fflags +genpts -i in.mp4 -c copy repaired.mkv` (tested here 2026-10-24) [Ask Ubuntu, https://askubuntu.com/questions/1258787, checked 2026-10-24] [TextOps container-repair.md, https://github.com/TextOps/textops-skills/blob/main/media-fixing-and-repair/references/container-repair.md, checked 2026-10-24] [ffmpeg-formats docs, https://ffmpeg.org/ffmpeg-formats.html#Format-Options, checked 2026-10-24]
1327. **Ignore corrupt DTS: +igndts+genpts** — igndts drops DTS when PTS is set; combined with genpts it gives clean presentation timestamps when DTS is corrupt and seeking gets stuck. **How:** `ffmpeg -fflags +igndts+genpts -ss 1 -i in.mp4 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [salivity ffmpeg, https://salivity.github.io/ffmpeg/article/seek-f-fmpeg-input-with-broken-timestamps, checked 2026-10-24] [ffmpeg-formats docs, https://ffmpeg.org/ffmpeg-formats.html#Format-Options, checked 2026-10-24]
1328. **Seek a broken file on the output side** — -ss before -i relies on the index; after -i ffmpeg decodes from the start and discards up to the point: slower, but accurate when timestamps are broken. **How:** `ffmpeg -i in.mp4 -ss 1 -c:v libx264 -crf 18 -c:a aac out.mp4` (tested here 2026-10-24) [salivity ffmpeg, https://salivity.github.io/ffmpeg/article/seek-f-fmpeg-input-with-broken-timestamps, checked 2026-10-24]
1329. **Repair once, then seek fast** — For many seeks, remux the damaged file once with ignore_err and genpts, then use normal fast input seeking on the repaired copy. **How:** `ffmpeg -err_detect ignore_err -fflags +genpts -i in.mp4 -c copy fixed.mp4 && ffmpeg -ss 1 -i fixed.mp4 -c copy part.mp4` (tested here 2026-10-24) [salivity ffmpeg, https://salivity.github.io/ffmpeg/article/seek-f-fmpeg-input-with-broken-timestamps, checked 2026-10-24]
1330. **Keep the original timestamps: -copyts** — -copyts keeps input timestamps without sanitising (start offset kept); -start_at_zero with it shifts them to start at zero. **How:** `ffmpeg -copyts -start_at_zero -i in.mp4 -c copy out.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1331. **Shift leading negative timestamps: avoid_negative_ts** — avoid_negative_ts make_zero shifts so the first timestamp is 0; make_non_negative only removes leading negatives; all streams move by the same amount so sync is kept. **How:** `ffmpeg -i in.mp4 -c copy -avoid_negative_ts make_zero out.mp4` (tested here 2026-10-24) [ffmpeg-formats docs, https://ffmpeg.org/ffmpeg-formats.html#Format-Options, checked 2026-10-24]
1332. **Stop drops caused by noisy timestamps** — -frame_drop_threshold (in frames, default -1.1) sets how far behind a frame may be before it is dropped; one use is avoiding framedrops with noisy timestamps. **How:** `ffmpeg -i in.mp4 -frame_drop_threshold 4 -fps_mode cfr -r 30 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
1333. **Timestamp discontinuity threshold** — -dts_error_threshold sets the seconds of timestamp jump above which ffmpeg drops the PTS/DTS, for formats that do not allow discontinuities. **How:** `ffmpeg -dts_error_threshold 1 -i in.ts -c copy out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]

## Frame interpolation (low-fps clips)

1334. **minterpolate motion estimation direction** — me_mode=bidir estimates vectors forward and backward for each source frame; bilat (default) estimates them directly for the interpolated frame. **How:** `ffmpeg -i in.mp4 -vf minterpolate=fps=30:mi_mode=mci:me_mode=bidir -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
1335. **minterpolate search algorithm and block size** — me picks the search (esa, tss, tdls, ntss, fss, ds, hexbs, epzs default, umh); mb_size (default 16) and search_param (default 32) set block size and search range. **How:** `ffmpeg -i in.mp4 -vf minterpolate=fps=30:mi_mode=mci:me=umh:mb_size=8:search_param=32 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
1336. **Keep minterpolate scene detection on clips with cuts** — At a scene change, motion vectors point in random directions; scd=fdiff (default) replaces those interpolated frames by duplicates, scd_threshold default 10. **How:** `ffmpeg -i in.mp4 -vf minterpolate=fps=30:mi_mode=mci:scd=fdiff:scd_threshold=10 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
1337. **Blend-interpolate with the framerate filter** — framerate makes new frames as a linear interpolation of two source frames inside interp_start..interp_end (default 15..240), with scene detection (scene default 8.2). It is not for interlaced media: deinterlace first. **How:** `ffmpeg -i in.mp4 -vf framerate=fps=30 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#framerate, checked 2026-10-24]
1338. **AI interpolation on CPU: RIFE ncnn** — rife-ncnn-vulkan is a portable RIFE build (no CUDA/PyTorch); -g -1 selects CPU; input is a folder of frames, output 2x frames by default. Here 6 frames of 320x180 became 12 in 0.5 s with -g -1. **How:** Needs rife-ncnn-vulkan (missing; we downloaded release 20221029 for the test). README workflow: decode frames, interpolate, encode at double rate: `mkdir -p in_frames out_frames && ffmpeg -v error -i in.mp4 in_frames/frame_%08d.png && rife-ncnn-vulkan -i in_frames -o out_frames -m rife-v4.6 -g -1 && ffmpeg -v error -framerate 24 -i out_frames/%08d.png -c:v libx264 -crf 20 -pix_fmt yuv420p out.mp4` (tested here 2026-10-24) [nihui/rife-ncnn-vulkan README, https://github.com/nihui/rife-ncnn-vulkan, checked 2026-10-24]
1339. **RIFE to an exact frame count** — rife-ncnn-vulkan -n sets the target frame count (default N*2) and -s the time step (0-1), so 12 fps can become 2.5x more frames for 30 fps. **How:** Needs rife-ncnn-vulkan (missing). Tested 6 frames to 15: `mkdir -p f o && ffmpeg -v error -i in.mp4 -frames:v 6 f/%08d.png && rife-ncnn-vulkan -i f -o o -n 15 -m rife-v4.6 -g -1 && ls o | wc -l` (tested here 2026-10-24) [nihui/rife-ncnn-vulkan README, https://github.com/nihui/rife-ncnn-vulkan, checked 2026-10-24]
1340. **RIFE threads and test-time augmentation** — -j load:proc:save sets threads for decode, interpolation and encode (default 1:2:2; README suggests 4:4:4 for many small images, 2:2:2 for large); -x enables spatial TTA, -z temporal TTA, -u UHD mode. **How:** Needs rife-ncnn-vulkan (missing). `mkdir -p f o && ffmpeg -v error -i in.mp4 -frames:v 4 f/%08d.png && rife-ncnn-vulkan -i f -o o -m rife-v4.6 -g -1 -j 4:4:4 -x && ls o | wc -l` (tested here 2026-10-24) [nihui/rife-ncnn-vulkan README, https://github.com/nihui/rife-ncnn-vulkan, checked 2026-10-24]
1341. **RIFE model 4.6 vs 4.4** — SVP notes model 4.6 gives higher quality but is about 10-15% slower than 4.4, and 4.4 needs a little less memory. **How:** Pick with -m rife-v4.6 (folder in the ncnn release). [SVP RIFE docs, https://www.svp-team.com/docs/rife-ai/, checked 2026-10-24]
1342. **Undo telecine judder: dejudder cycle** — dejudder removes judder from partially telecined content (e.g. after pullup); cycle 4 = film to NTSC (24 to 30), 5 = PAL to NTSC (25 to 30), 20 = a mixture; output may become VFR. **How:** `ffmpeg -i in.mp4 -vf dejudder=cycle=4 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dejudder, checked 2026-10-24]

## Upscaling

1343. **Real-ESRGAN on a CPU-only box via Mesa lavapipe** — The portable realesrgan-ncnn-vulkan needs no CUDA/PyTorch but does need a Vulkan device; with Mesa's llvmpipe (lavapipe) Vulkan driver it ran here on CPU: one 160x90 frame to 320x180 in 7.9 s. **How:** Needs realesrgan-ncnn-vulkan + apt mesa-vulkan-drivers (missing). README_ubuntu frame workflow: extract, upscale, merge with original audio: `mkdir -p tmp_frames out_frames && ffmpeg -v error -i in.mp4 -vf scale=160:90 -frames:v 2 -qscale:v 1 -qmin 1 -qmax 1 -fps_mode passthrough tmp_frames/frame%08d.jpg && realesrgan-ncnn-vulkan -i tmp_frames -o out_frames -n realesr-animevideov3 -s 2 -f jpg && ffmpeg -v error -i out_frames/frame%08d.jpg -i in.mp4 -map 0:v:0 -map 1:a:0 -c:a copy -c:v libx264 -r 30 -pix_fmt yuv420p -shortest out.mp4` (tested here 2026-10-24) [Real-ESRGAN ncnn release README_ubuntu.md, https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.5.0, checked 2026-10-24] [Real-ESRGAN README, https://github.com/xinntao/Real-ESRGAN, checked 2026-10-24]
1344. **Real-ESRGAN ncnn model choice** — The ncnn release ships realesr-animevideov3 (default, x2/x3/x4, for anime video), realesrgan-x4plus (general) and realesrgan-x4plus-anime; -n picks the model, -s the scale (2, 3, 4). **How:** Needs realesrgan-ncnn-vulkan (missing). General-photo model on one frame: `ffmpeg -v error -i in.mp4 -vf scale=96:54 -frames:v 1 s.png && realesrgan-ncnn-vulkan -i s.png -o s4.png -n realesrgan-x4plus -s 4` (tested here 2026-10-24) [Real-ESRGAN ncnn release README_ubuntu.md, https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.5.0, checked 2026-10-24] [Real-ESRGAN README, https://github.com/xinntao/Real-ESRGAN, checked 2026-10-24]
1345. **Real-ESRGAN tiles and block seams** — -t sets tile size (>=32, 0 = auto); the ncnn build crops the image into tiles and stitches them, which can introduce block inconsistency vs the PyTorch version; -x enables TTA mode. **How:** Needs realesrgan-ncnn-vulkan (missing). `ffmpeg -v error -i in.mp4 -vf scale=160:90 -frames:v 1 s.png && realesrgan-ncnn-vulkan -i s.png -o s2.png -n realesr-animevideov3 -s 2 -t 64` (tested here 2026-10-24) [Real-ESRGAN ncnn release README_ubuntu.md, https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.5.0, checked 2026-10-24]
1346. **Real-ESRGAN Python features the ncnn build lacks** — The Python inference script supports --outscale (arbitrary scale, a further LANCZOS4 resize), --face_enhance (GFPGAN), -t tile, alpha, gray and 16-bit images; realesr-general-x4v3 adds -dn denoise strength to avoid over-smoothing. The ncnn build does not support outscale. **How:** Needs the realesrgan Python package and weights (missing). [Real-ESRGAN README, https://github.com/xinntao/Real-ESRGAN, checked 2026-10-24]
1347. **Lanczos taps: param0** — In libswscale, lanczos is a windowed sinc whose number of taps is set by param0 (default 3). **How:** `ffmpeg -i in.mp4 -vf scale=1280:720:flags=lanczos:param0=5 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-scaler docs, https://ffmpeg.org/ffmpeg-scaler.html#Scaler-Options, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scale-1, checked 2026-10-24]
1348. **Bicubic B and C: param0/param1** — bicubic is a BC-spline (Mitchell-Netravali); B and C are param0 and param1, default 0.0 and 0.6. **How:** `ffmpeg -i in.mp4 -vf scale=1280:720:flags=bicubic:param0=0:param1=0.5 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-scaler docs, https://ffmpeg.org/ffmpeg-scaler.html#Scaler-Options, checked 2026-10-24]
1349. **Gaussian and spline scalers** — gauss has a sharpness param0 (default 3.0); spline is an unwindowed natural bicubic spline; area averages and equals bilinear when upscaling. **How:** `ffmpeg -i in.mp4 -vf scale=1280:720:flags=spline -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-scaler docs, https://ffmpeg.org/ffmpeg-scaler.html#Scaler-Options, checked 2026-10-24]
1350. **Accurate rounding and full chroma interpolation** — Scaler flags accurate_rnd (accurate rounding), full_chroma_int (full chroma interpolation) and full_chroma_inp (full chroma input) can be added to the algorithm flag. **How:** `ffmpeg -i in.mp4 -vf scale=1280:720:flags=lanczos+accurate_rnd+full_chroma_int -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-scaler docs, https://ffmpeg.org/ffmpeg-scaler.html#Scaler-Options, checked 2026-10-24]
1351. **Choose the scaler dither** — sws_dither sets dithering: auto (default), none, bayer, ed (error diffusion), a_dither, x_dither. **How:** `ffmpeg -i in.mp4 -vf scale=1280:720:flags=lanczos:sws_dither=ed -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-scaler docs, https://ffmpeg.org/ffmpeg-scaler.html#Scaler-Options, checked 2026-10-24]
1352. **Keep aspect and even sizes with -2** — If one of w/h is -n, scale computes it from the aspect ratio and makes it divisible by n. **How:** `ffmpeg -i in.mp4 -vf scale=1280:-2:flags=lanczos -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scale-1, checked 2026-10-24]
1353. **Pixel-art magnifiers: xbr, hqx, epx** — xbr (2/3/4x, edge-detection rules), hqx (hq2x-hq4x by Maxim Stepin) and epx (2x/3x) are magnification filters designed for pixel art. **How:** `ffmpeg -i in.mp4 -vf xbr=n=2 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#xbr, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#hqx, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#epx, checked 2026-10-24]
1354. **Nearest-neighbour scaling** — point/neighbor is plain point sampling (nearest neighbour). **How:** `ffmpeg -i in.mp4 -vf scale=iw*4:ih*4:flags=neighbor -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-scaler docs, https://ffmpeg.org/ffmpeg-scaler.html#Scaler-Options, checked 2026-10-24]
1355. **zscale resize kernels and dither** — zscale (z.lib) offers point, bilinear (default), bicubic, spline16, spline36, spline64 and lanczos; param_a is the lanczos tap count or bicubic b; dither none/ordered/random/error_diffusion. **How:** `ffmpeg -i in.mp4 -vf zscale=w=1280:h=720:filter=spline36:dither=error_diffusion,format=yuv420p -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#zscale-1, checked 2026-10-24]
1356. **Interlace-aware scaling: interl=1** — scale interl=1 forces interlaced-aware scaling, -1 decides from the frame flags (default 0); Encode Wiki: deinterlace before scaling, because resizing blends the two fields. **How:** Here `scale=720:-2:interl=1` crashed ffmpeg 6.1 (signal 11) on a TFF H.264 test clip, so deinterlace first instead. [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scale-1, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace, checked 2026-10-24]
1357. **ffmpeg sr / dnn_processing need a DNN backend** — sr (SRCNN/ESPCN) and dnn_processing need ffmpeg built with TensorFlow, OpenVINO, LibTorch or ONNX Runtime plus a model file; our ffmpeg 6.1 has none of them. **How:** Needs a DNN-enabled ffmpeg build (missing); use Real-ESRGAN ncnn instead. [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sr-1, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dnn_005fprocessing-1, checked 2026-10-24]
1358. **Do not scan 8mm higher than about 1024x768** — An 8mm frame holds limited detail; Jim Battle found 1920x1080 just shows the grain clearly and calls more than 1024x768 overkill for 8mm. **How:** Ask for SD/1024-class scans, save the pixels for restoration. [Jim Battle, https://thebattles.net/video/8mm_restoration.html, checked 2026-10-24]

## Denoising

1359. **Pick a denoiser by speed and type** — ffmpeg-user summary: atadenoise very fast, temporal only, no motion compensation; hqdn3d fast spatial+temporal, low-pass that blurs at extreme settings; nlmeans very slow; bm3d very very slow; vaguedenoiser slow, spatial wavelet, pretty good; dctdnoiz very very slow, blurs too much; fftdnoiz slow, limited temporal, may ring; owdenoise very very very slow; removegrain fast, limited use. **How:** Licences in the same list: hqdn3d and owdenoise GPL; atadenoise, nlmeans, bm3d, vaguedenoiser, dctdnoiz and fftdnoiz LGPL. [ffmpeg-user list, https://ffmpeg.org/pipermail/ffmpeg-user/2021-April/052781.html, checked 2026-10-24]
1360. **Test denoisers on representative frames first** — Pick a couple of representative frames, try several denoise filters and options on them, and keep what works for that footage; nlmeans if you are patient, atadenoise or hqdn3d for speed. **How:** `ffmpeg -ss 1 -i in.mp4 -frames:v 1 -vf vaguedenoiser f_vague.png && ffmpeg -ss 1 -i in.mp4 -frames:v 1 -vf hqdn3d f_hq.png` (tested here 2026-10-24) [Super User accepted answer, https://superuser.com/questions/1547426, checked 2026-10-24]
1361. **hqdn3d parameter defaults** — hqdn3d luma_spatial defaults 4.0; chroma_spatial 3*ls/4; luma_tmp 6*ls/4; chroma_tmp luma_tmp*cs/ls; it aims to make still images really still and improve compressibility. **How:** `ffmpeg -i in.mp4 -vf hqdn3d=luma_spatial=4 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#hqdn3d-1, checked 2026-10-24]
1362. **VHS chroma bleed: chroma-only hqdn3d** — claude-mods suggests, for VHS-style chroma bleed, a mild chroma-only denoise with a slight desaturation. **How:** Source-given chain: `ffmpeg -i in.mp4 -vf "hqdn3d=0:6:0:6,eq=saturation=0.92" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [claude-mods restoration.md, https://github.com/0xdarkmatter/claude-mods/blob/main/skills/ffmpeg-ops/references/restoration.md, checked 2026-10-24]
1363. **nlmeans patch and research sizes for chroma** — nlmeans s strength 1-30 (default 1), p patch (odd, default 7), r research window (odd, default 15); pc and rc set them for chroma (0 = automatic). **How:** `ffmpeg -i in.mp4 -vf nlmeans=s=3:p=7:r=9:pc=5:rc=7 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#nlmeans-1, checked 2026-10-24]
1364. **Basic bm3d** — bm3d (Block-Matching 3D) is very sensitive to sigma (default 1); docs basic example: sigma=3:block=4:bstep=2:group=1:estim=basic. group=1 means no block matching. **How:** Our ffmpeg 6.1 rejects block=4 (range 8-64 there), so block=8: `ffmpeg -i in.mp4 -vf bm3d=sigma=3:block=8:bstep=2:group=1:estim=basic -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bm3d, checked 2026-10-24]
1365. **bm3d on luma only** — planes=1 filters only the first (luma) plane. **How:** block=8 because 6.1 needs 8-64: `ffmpeg -i in.mp4 -vf bm3d=sigma=3:block=8:bstep=2:group=1:estim=basic:planes=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bm3d, checked 2026-10-24]
1366. **Two-stage bm3d (basic, then final)** — estim=final uses a second (reference) stream for block matching; docs run a basic pass and feed it as reference to a final pass with group=16. **How:** Docs filtergraph, with block=8 for 6.1: `ffmpeg -i in.mp4 -vf "split[a][b],[a]bm3d=sigma=3:block=8:bstep=2:group=1:estim=basic[a],[b][a]bm3d=sigma=3:block=8:bstep=2:group=16:estim=final:ref=1" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bm3d, checked 2026-10-24]
1367. **bm3d with an nlmeans pre-filter** — Docs variant: nlmeans makes the reference stream for the final bm3d stage. **How:** block=8 for 6.1; took about 6 min on this 2 s 640x360 clip: `ffmpeg -i in.mp4 -vf "split[a][b],[a]nlmeans=s=3:r=7:p=3[a],[b][a]bm3d=sigma=3:block=8:bstep=2:group=16:estim=final:ref=1" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bm3d, checked 2026-10-24]
1368. **Wavelet denoise: vaguedenoiser** — vaguedenoiser (CDF 9/7 wavelet) should smooth and reduce noise without blurring features; threshold default 2, method garrote (default), soft or hard; hard tolerates a higher threshold before looking overfiltered. **How:** `ffmpeg -i in.mp4 -vf vaguedenoiser=threshold=4:method=hard -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vaguedenoiser, checked 2026-10-24]
1369. **vaguedenoiser decomposition, percent and bayes** — nsteps (1-32, default 6) cannot exceed what the frame size allows (about 8 for 640x480); percent (default 85) gives partial denoise; type=bayes makes the threshold depend on each decomposition. **How:** `ffmpeg -i in.mp4 -vf vaguedenoiser=nsteps=5:percent=70:type=bayes -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vaguedenoiser, checked 2026-10-24]
1370. **Overcomplete wavelet denoise: owdenoise** — owdenoise depth 8-16 (default 8; larger denoises lower frequencies more, slower), luma_strength and chroma_strength 0-1000 (default 1). **How:** `ffmpeg -i in.mp4 -vf owdenoise=depth=8:ls=4:cs=4 -t 0.5 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#owdenoise, checked 2026-10-24] [ffmpeg-user list, https://ffmpeg.org/pipermail/ffmpeg-user/2021-April/052781.html, checked 2026-10-24]
1371. **3D FFT denoise with neighbour frames: fftdnoiz** — fftdnoiz sigma (0-30, default 1), amount, block (default 32), overlap (0.2-0.8, default 0.5), method wiener/hard; prev/next add temporal frames (default 0). Very high sigma with low overlap may block. **How:** `ffmpeg -i in.mp4 -vf fftdnoiz=sigma=6:prev=1:next=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fftdnoiz, checked 2026-10-24]
1372. **DCT denoise: dctdnoiz** — dctdnoiz drops DCT coefficients below 3*sigma (docs: dctdnoiz=4.5, same as e='gte(c, 4.5*3)'); n=4 uses 16x16 blocks (docs call dctdnoiz=15:n=4 violent); not designed for real time. **How:** `ffmpeg -i in.mp4 -vf dctdnoiz=4.5 -t 0.5 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dctdnoiz, checked 2026-10-24]
1373. **removegrain median mode** — removegrain is a spatial denoiser for progressive video with modes 0-24 per plane; mode 4 clips to the 4th min/max of the 8 neighbours, equivalent to a median filter; mode 1 clips to their min/max. **How:** `ffmpeg -i in.mp4 -vf removegrain=m0=4:m1=4:m2=4 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#removegrain, checked 2026-10-24]
1374. **removegrain blur and line-sensitive modes** — Modes 11/12 are a [1 2 1] blur, 20 a 3x3 average, 19 the average of the 8 neighbours, 5-9 line-sensitive clipping, 17 clips with opposite-neighbour pairs; 23/24 "reputed useless". **How:** `ffmpeg -i in.mp4 -vf removegrain=m0=17:m1=11:m2=11 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#removegrain, checked 2026-10-24]
1375. **Spatial median with its own radius** — median picks the median pixel in a rectangle: radius (1-127), radiusV (0 = same as radius), percentile 0.5 (0 = minimum, 1 = maximum). **How:** `ffmpeg -i in.mp4 -vf median=radius=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#median, checked 2026-10-24]
1376. **Temporal median: tmedian** — tmedian picks the median pixel over successive frames (radius 1-127, default 1; percentile like median). **How:** `ffmpeg -i in.mp4 -vf tmedian=radius=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmedian, checked 2026-10-24]
1377. **Average frames: tmix** — tmix mixes successive frames with weights; docs average 7 frames with tmix=frames=7:weights="1 1 1 1 1 1 1". **How:** `ffmpeg -i in.mp4 -vf "tmix=frames=7:weights=1 1 1 1 1 1 1" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
1378. **Chroma noise only: chromanr** — chromanr averages chroma from neighbours whose summed Y/U/V difference is under thres (default 30); luma is copied; sizew/sizeh radius (default 5); stepw/steph speed it up. **How:** `ffmpeg -i in.mp4 -vf chromanr=thres=30:sizew=5:sizeh=5:stepw=2:steph=2 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#chromanr, checked 2026-10-24] [ffmpeglab, https://ffmpeglab.com/articles/ffmpeg-video-denoising.html, checked 2026-10-24]
1379. **atadenoise frame count and serial mode** — atadenoise s = frames averaged (odd 5-129, default 9); a=p parallel (default, aborts early on the first big change) or s serial (keeps checking the other side); per-plane 0a/0b... thresholds; 0s=0 disables a plane. **How:** `ffmpeg -i in.mp4 -vf atadenoise=s=15:a=s -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atadenoise, checked 2026-10-24]
1380. **Edge-preserving smoothing: bilateral** — bilateral smooths while preserving edges; sigmaS spatial (0-512, default 0.1), sigmaR range (0-1, default 0.1); filters only the first plane by default. **How:** `ffmpeg -i in.mp4 -vf bilateral=sigmaS=4:sigmaR=0.1:planes=7 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bilateral, checked 2026-10-24]
1381. **Smooth flat areas only: smartblur threshold** — smartblur blurs without touching outlines; luma_threshold 0 filters everything, 1..30 only flat areas, -30..0 only edges; luma_strength -1..0 sharpens instead. **How:** `ffmpeg -i in.mp4 -vf smartblur=lr=1.5:ls=0.8:lt=10 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#smartblur-1, checked 2026-10-24]
1382. **Shape adaptive blur: sab** — sab luma_radius 0.1-4, pre-filter radius 0.1-2, luma_strength 0.1-100 (max pixel difference still considered); chroma values follow luma unless set. **How:** `ffmpeg -i in.mp4 -vf sab=lr=1.5:lpfr=1:ls=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sab, checked 2026-10-24]
1383. **Guided filter smoothing** — guided is an edge-preserving smoother (radius 1-20, default 3; eps default 0.01; mode basic/fast with sub); with guidance=on a second same-size input is the guide, which the docs mention for dehazing and detail transfer. **How:** `ffmpeg -i in.mp4 -vf guided=radius=3:eps=0.01 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#guided, checked 2026-10-24]
1384. **pp temporal noise reducer** — libpostproc's pp filter (still in our ffmpeg 6.1, removed from current docs) has tn/tmpnoise with three thresholds (larger = stronger); docs example pp=default/tmpnoise|1|2|3. **How:** `ffmpeg -i in.mp4 -vf "pp=default/tmpnoise|1|2|3" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ayosec FFmpeg 7.1 docs (pp), https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/pp.html, checked 2026-10-24]
1385. **Keep intended grain: -tune grain** — For intentional film grain, do not denoise; encode with -tune grain instead. **How:** `ffmpeg -i in.mp4 -c:v libx264 -tune grain -crf 18 -c:a copy out.mp4` (tested here 2026-10-24) [claude-mods restoration.md, https://github.com/0xdarkmatter/claude-mods/blob/main/skills/ffmpeg-ops/references/restoration.md, checked 2026-10-24]
1386. **Restoration order of operations** — claude-mods order: deinterlace, denoise, deband, stabilize, grade, sharpen, encode; stabilize after denoise because noise defeats motion estimation. **How:** Apply the steps in that order on one chain. ## Deblocking, deringing, debanding

1387. **Weak small-block deblock** — deblock removes blocking artifacts; filter weak/strong (default strong), block 4-512 (default 8); docs example deblock=filter=weak:block=4. **How:** `ffmpeg -i in.mp4 -vf deblock=filter=weak:block=4 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deblock, checked 2026-10-24]
1388. **Stronger deblock thresholds** — alpha (default 0.098) detects at the exact block edge, beta/gamma/delta (default 0.05) near it; higher = more deblocking, 0 disables; docs example with alpha=0.12:beta=0.07:gamma=0.06:delta=0.05, planes=1 luma only, planes=6 chroma only. **How:** `ffmpeg -i in.mp4 -vf deblock=filter=strong:block=4:alpha=0.12:beta=0.07:gamma=0.06:delta=0.05:planes=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deblock, checked 2026-10-24]
1389. **pp7 deblocking** — pp7 is an spp variant (7-point DCT); qp forces 0-63 (else the stream QP), mode hard/soft/medium (default medium; soft = better deringing, blurrier). **How:** `ffmpeg -i in.mpg -vf pp7=qp=8:mode=medium -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#pp7, checked 2026-10-24]
1390. **spp quality levels** — spp compresses/decompresses at several shifts and averages; quality 0-6 (default 3; each step about halves speed), mode hard (default)/soft; use_bframe_qp may cause flicker. **How:** `ffmpeg -i in.mpg -vf spp=quality=4:qp=8 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#spp-1, checked 2026-10-24]
1391. **fspp strength** — fspp is a faster spp; quality 4-5, strength -15..32 (lower = more detail and artifacts, higher = smoother and blurrier; 0 = PSNR-optimal). **How:** `ffmpeg -i in.mpg -vf fspp=quality=4:strength=4:qp=8 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fspp, checked 2026-10-24]
1392. **uspp with Snow encodes** — uspp actually encodes/decodes each shift with Snow (spp uses an MJPEG-like DCT); quality 0-8; not available in ffmpeg 5.0-6.0 (works in our 6.1). **How:** `ffmpeg -i in.mpg -vf uspp=quality=1:qp=8 -t 0.3 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#uspp, checked 2026-10-24]
1393. **pp deblock and dering subfilters** — pp subfilters hb/vb (horizontal/vertical deblock, difference default 32, flatness 39), ha/va accurate versions, dr dering; presets de (hb|a,vb|a,dr|a), fa fast, ac high quality; docs example pp=de/-al. **How:** `ffmpeg -i in.mpg -vf pp=de/-al -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ayosec FFmpeg 7.1 docs (pp), https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/pp.html, checked 2026-10-24]
1394. **Luma-only pp deblocking** — Subfilter option y/nochrom filters luma only; a/autoq follows quality commands; docs example pp=hb|y/vb|a. **How:** `ffmpeg -i in.mpg -vf "pp=hb|y/vb|a" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ayosec FFmpeg 7.1 docs (pp), https://ayosec.github.io/ffmpeg-filters-docs/7.1/Filters/Video/pp.html, checked 2026-10-24]
1395. **Decoder error concealment: -ec** — ec sets the decoder's concealment: guess_mvs (iterative motion vector search, slow), deblock (strong deblock on damaged macroblocks), favor_inter (predict from the previous frame). **How:** `ffmpeg -ec guess_mvs+deblock+favor_inter -i in.ts -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg-codecs docs, https://ffmpeg.org/ffmpeg-codecs.html#Codec-Options, checked 2026-10-24]
1396. **Deband in 10-bit before encoding** — An 8-bit frame has no in-between values, so convert to 10-bit before deband and keep -pix_fmt yuv420p10le on the output, or ffmpeg may negotiate back to 8-bit. **How:** Encode Wiki command: `ffmpeg -i in.mp4 -vf "format=yuv420p10le,deband" -c:v libsvtav1 -crf 30 -pix_fmt yuv420p10le output.mkv` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/deband, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deband, checked 2026-10-24]
1397. **deband thresholds and blur** — 1thr..4thr per plane 0.00003-0.5 (default 0.02): higher fixes stronger banding but flattens more detail; range default 16; blur=0 requires all four neighbours under threshold, touching less real detail. **How:** `ffmpeg -i in.mp4 -vf deband=1thr=0.015:2thr=0.015:3thr=0.015:blur=0 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/deband, checked 2026-10-24] [claude-mods restoration.md, https://github.com/0xdarkmatter/claude-mods/blob/main/skills/ffmpeg-ops/references/restoration.md, checked 2026-10-24]
1398. **deband coupling and direction** — coupling=1 changes a pixel only if all components are banded; direction sets the angle of compared pixels (negative = exact; -PI/2 picks only the same column). **How:** `ffmpeg -i in.mp4 -vf deband=coupling=1:direction=-3.14159 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deband, checked 2026-10-24]
1399. **Banding that appears only in your encode** — If the source is clean and the encode bands, the encoder flattened the gradient: encode at 10-bit (even from 8-bit), use a lower CRF, and consider grain. **How:** `ffmpeg -i in.mp4 -c:v libx264 -pix_fmt yuv420p10le -crf 16 out.mp4` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/deband, checked 2026-10-24]
1400. **Deband only the shots that band** — Too high a threshold blurs dark texture, grain and skin; start low, apply to the scenes that band and check the others for damage. **How:** Limit it with timeline editing (enable=): `ffmpeg -i in.mp4 -vf "deband=enable='between(t,0,1)'" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/deband, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]

## Deinterlacing and inverse telecine

1401. **Single rate or double rate** — Double rate (one frame per field, 50/59.94 fps) keeps all captured motion and suits sports and fast movement; single rate (send_frame) discards half the temporal information but is fine at moderate motion when you must keep the source rate. **How:** bwdif defaults to double rate; add mode=send_frame for single rate: `ffmpeg -i in.mp4 -vf bwdif=mode=send_frame -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bwdif-1, checked 2026-10-24]
1402. **Force the field order when flags lie** — yadif/bwdif parity tff/bff overrides auto detection; with unknown parity they assume top field first. **How:** `ffmpeg -i in.mp4 -vf bwdif=mode=send_field:parity=tff -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bwdif-1, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#yadif-1, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace, checked 2026-10-24]
1403. **Deinterlace only flagged frames** — deint=interlaced makes yadif/bwdif touch only frames marked interlaced (deint=all is default); Encode Wiki: leave deint alone unless you trust the flags. **How:** `ffmpeg -i in.mp4 -vf yadif=mode=send_frame:deint=interlaced -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#yadif-1, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace, checked 2026-10-24]
1404. **yadif without the spatial check** — yadif modes 2/3 (send_frame_nospatial, send_field_nospatial) are like 0/1 but skip the spatial interlacing check. **How:** `ffmpeg -i in.mp4 -vf yadif=mode=send_field_nospatial -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#yadif-1, checked 2026-10-24]
1405. **BBC Weston 3-field deinterlacer: w3fdif** — w3fdif uses BBC R&D coefficients (filter=complex default, or simple), outputs one frame per field by default, and takes field dominance from the frame; if wrong, put setfield before it. **How:** `ffmpeg -i in.mp4 -vf setfield=tff,w3fdif=filter=complex:mode=field -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#w3fdif, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setfield-1, checked 2026-10-24]
1406. **Edge-slope deinterlacer: estdif** — estdif is spatial-only, interpolating missing lines by edge slope tracing; rslope, redge, ecost/mcost/dcost tune the matching; interp 2p/4p (default)/6p. **How:** `ffmpeg -i in.mp4 -vf estdif=mode=frame:interp=6p -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#estdif, checked 2026-10-24]
1407. **Neural edge-directed deinterlace: nnedi** — nnedi needs the nnedi3_weights.bin file (from dubhater/vapoursynth-nnedi3); field af/a/t/b/tf/bf; nsize, nns, qual, etype, pscrn (prescreener, default new) tune it. **How:** Weights downloaded for the test (13.6 MB): `ffmpeg -i in.mp4 -vf nnedi=weights=nnedi3_weights.bin:field=af -t 0.5 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#nnedi, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/deinterlace, checked 2026-10-24]
1408. **See what kerndeint touches: map=1** — kerndeint (Donald Graft adaptive kernel) has thresh (default 10, 0 = every pixel); map=1 paints pixels above the threshold white; sharp=1 and twoway=1 add sharpening. **How:** `ffmpeg -i in.mp4 -vf kerndeint=map=1 -frames:v 1 kd_map.png` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#kerndeint, checked 2026-10-24]
1409. **Motion-compensated deinterlace: yadif=1,mcdeint** — mcdeint needs one field per frame as input, so it follows yadif=1/3; mode fast/medium/slow/extra_slow; parity default bff; qp smooths the vector field. **How:** `ffmpeg -i in.mp4 -vf yadif=1,mcdeint=mode=fast:parity=tff -t 0.5 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mcdeint, checked 2026-10-24]
1410. **Inspect fields: separatefields** — separatefields splits each frame into its fields: half height, twice the rate and frame count; use setfield first if the dominance is wrong. **How:** `ffmpeg -i in.mp4 -vf separatefields -frames:v 4 field_%02d.png` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#separatefields-1, checked 2026-10-24]
1411. **Keep one field only: field** — field type=top/bottom extracts a single field cheaply by stride arithmetic; output frames are marked progressive. **How:** `ffmpeg -i in.mp4 -vf field=type=top,scale=iw:ih*2 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#field, checked 2026-10-24]
1412. **Mark the field order: setfield** — setfield sets the interlace property (auto, bff, tff, prog) without changing pixels; it affects how later filters such as fieldorder or yadif treat the frame. **How:** `ffmpeg -i in.mp4 -vf setfield=bff,yadif -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setfield-1, checked 2026-10-24]
1413. **Change field order: fieldorder** — fieldorder shifts the picture one line to change field order (default tff); useful to or from PAL DV, which is bottom field first; unflagged input is left alone. **How:** `ffmpeg -i in.mp4 -vf fieldorder=bff -c:v libx264 -flags +ildct+ilme -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldorder, checked 2026-10-24]
1414. **PAL film captured with the wrong field order: phase** — phase delays interlaced video by one field to fix PAL movies captured with the opposite field order to the transfer; modes t, b, a, u and the analysing T, B, A (default), U. **How:** `ffmpeg -i in.mp4 -vf phase=mode=A -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#phase, checked 2026-10-24]
1415. **Simple IVTC: fieldmatch,decimate** — fieldmatch rebuilds progressive frames but does not drop duplicates, so a decimate after it completes inverse telecine; docs example for TFF. **How:** `ffmpeg -i in.mp4 -vf fieldmatch=order=tff:combmatch=none,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24]
1416. **IVTC with a deinterlace fallback** — fieldmatch marks frames it cannot match as interlaced; yadif=deint=interlaced fixes only those before decimate. kfrn saw some artefacts with deint=interlaced and preferred plain yadif on their DVD. **How:** Docs/Encode Wiki chain: `ffmpeg -i in.mp4 -vf fieldmatch,yadif=deint=interlaced,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/ivtc, checked 2026-10-24] [kfrn/ffmpeg-things, https://github.com/kfrn/ffmpeg-things/blob/master/inverse_telecine.md, checked 2026-10-24]
1417. **IVTC for mixed 30i and 24p content** — decimate only works on CFR input; for mixed telecined (30 fps) and progressive 24 fps content the docs give dejudder,fps=30000/1001,fieldmatch,decimate. **How:** `ffmpeg -i in.mp4 -vf dejudder,fps=30000/1001,fieldmatch,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/ivtc, checked 2026-10-24]
1418. **Ignore subtitles or logos while field-matching** — fieldmatch y0/y1 define a band of lines excluded from the match decision (subtitles, a logo); equal values disable it. **How:** `ffmpeg -i in.mp4 -vf fieldmatch=y0=300:y1=359,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24]
1419. **fieldmatch safety vs matching** — mode pc is safest against jerkiness but outputs combed frames where a good match existed in damaged sections; pcn_ub almost always finds a match at the most jerkiness risk; default pc_n. pc is fastest. **How:** `ffmpeg -i in.mp4 -vf fieldmatch=mode=pcn_ub,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24] [Encode Wiki, https://encode.wiki/tools/filtering/ivtc, checked 2026-10-24]
1420. **Field-match on a cleaned copy, output from the clean source** — ppsrc=1 treats the first input as pre-processed (e.g. denoised) for matching and takes fields from the second, clean input, keeping the output lossless. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]split[a][b];[a]hqdn3d[p];[p][b]fieldmatch=ppsrc=1,decimate" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24]
1421. **Rainbowing breaks field matching** — fieldmatch mchroma=0 excludes chroma from match comparisons when chroma is badly damaged (heavy rainbowing); chroma=0 (default) already leaves chroma out of the combed-frame decision. **How:** `ffmpeg -i in.mp4 -vf fieldmatch=mchroma=0,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24]
1422. **Tune combed-frame detection** — cthresh (default 9, good range 8-12) sets how visible combing must be; combpel (default 80) how many combed pixels per blockx x blocky (default 16) window declare a frame combed. **How:** `ffmpeg -i in.mp4 -vf fieldmatch=cthresh=10:combpel=80,yadif=deint=interlaced,decimate -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fieldmatch, checked 2026-10-24]
1423. **Pattern-free IVTC: pullup** — pullup looks ahead instead of locking to a pattern and handles mixed hard-telecine, 24000/1001 and 30000/1001 content; set the output rate (e.g. -r 24000/1001) to avoid duplicates. **How:** Docs NTSC example: `ffmpeg -i in.mp4 -vf pullup -r 24000/1001 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#pullup-1, checked 2026-10-24]
1424. **pullup junk margins and strict breaks** — jl/jr (units of 8 px) and jt/jb (units of 2 lines) ignore junk at the edges (default 8 px each side); sb=1 reduces mismatched frames but may drop too many in fast motion, -1 matches more easily; mp picks the metric plane. **How:** `ffmpeg -i in.mp4 -vf pullup=jl=1:jr=1:jt=4:jb=4:sb=1 -r 24000/1001 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#pullup-1, checked 2026-10-24]
1425. **Exact inverse of a known pulldown: detelecine** — detelecine undoes a telecine whose pattern is known (same pattern string as the telecine filter, default 23); start_frame fixes a cut stream's position in the pattern. **How:** `ffmpeg -i in.mp4 -vf detelecine=first_field=top:pattern=23 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#detelecine, checked 2026-10-24]
1426. **Pulldown patterns for odd film rates** — telecine pattern examples: NTSC 24p 23 (classic) or 2332 (preferred), 20p 33, 18p 334, 16p 3444; PAL 24p 222222222223 (Euro pulldown), 16p 33333334. detelecine takes the same strings. **How:** `ffmpeg -i in.mp4 -vf telecine=pattern=334 -c:v libx264 -flags +ildct+ilme -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#telecine, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#detelecine, checked 2026-10-24]

## Stabilisation variants

1435. **See what vidstab measures: show=1** — vidstabdetect show=1 (or 2) draws the measurement fields and transforms on the output frames. **How:** `ffmpeg -i in.mp4 -vf vidstabdetect=shakiness=5:show=1:result=tr.trf -c:v libx264 -crf 23 show.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24]

1459. **lenscorrection: the formula and its limits** — r_src = r_tgt*(1 + k1*(r_tgt/r_0)^2 + k2*(r_tgt/r_0)^4), r_0 half the diagonal; k1/k2 in [-1,1]; cx/cy the centre (default 0.5); OpenCV calibration can give k1/k2, otherwise trial and error. **How:** `ffmpeg -i in.mp4 -vf lenscorrection=cx=0.5:cy=0.5:k1=-0.2:k2=-0.02 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lenscorrection, checked 2026-10-24]

1470. **Auto-levels with temporal smoothing: normalize** — normalize stretches each channel's range; smoothing=N rolling frames reduces flicker when small dark/bright objects enter, like camera auto-exposure; independence=0 links channels and preserves hue. **How:** Docs example: `ffmpeg -i in.mp4 -vf normalize=blackpt=black:whitept=white:smoothing=50:independence=0 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#normalize, checked 2026-10-24]

1473. **Projector-and-camera transfers bake in flicker** — Filming a projection captures at the camera rate whatever the projector does: speed errors and flicker get locked into the file, plus hot spots, gate cropping (up to 20%) and keystone; frame-by-frame scanning avoids this. **How:** Ask for a frame-by-frame scan, not a real-time transfer. ## VHS and analog tape

1500. **Mask VHS head-switching noise with black** — Masking the bottom noise with black keeps the aspect ratio; cropping and stretching risks aspect damage and aliasing (digitalFAQ staff). fillborders mode=fixed fills edge rows with a constant colour without changing size. **How:** `ffmpeg -i in.mp4 -vf fillborders=bottom=10:mode=fixed:color=black -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [digitalFAQ forum, https://www.digitalfaq.com/forum/video-editing/14627-removing-vhs-noise.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fillborders, checked 2026-10-24]
1501. **How many lines the head-switching band takes** — Typical bands: VHS SP bottom 4-10 lines, VHS EP/LP 6-16 (wider), S-VHS consumer 4-8, Hi8/Video8 6-14, U-matic 2-4, Betacam SP 2 or less, MiniDV/Digital8 none. It sits at a fixed position on virtually every frame; dropouts are intermittent streaks anywhere; TBC errors tear the whole picture. **How:** Measure on a 2-minute test capture at 100% zoom before choosing the mask. [digitalyearbook.org, https://digitalyearbook.org/blog/athletic-archive-video-head-switching-noise-correction/, checked 2026-10-24]
1502. **Crop and re-pad the frame (M6WIQ VHS script)** — The M6WIQ Linux VHS script crops 10 px width and 14 px height then pads back to the original size so the head-switching lines are hidden. **How:** Source-given crop/pad: `ffmpeg -i in.mp4 -vf "crop=(iw-10):(ih-14):3:0, pad=iw+10:ih+14:(ow-iw)/2:(oh-ih)/2" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [M6WIQ VHS capture on Linux, https://www.m6wiq.uk/2022/11/vhs-capture-linux/, checked 2026-10-24]
1503. **Crop the band and keep 4:3 exactly** — For a 720x480 NTSC capture: 16 px of side bars carry no picture (704 active); removing 6 bottom lines needs 25 side pixels in total off, giving 695x474; removing 4 lines needs 22, giving 698x476. Then scale to any 4:3 size. **How:** `ffmpeg -i in.mp4 -vf crop=695:474:12:0,scale=640:480,setsar=1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [digitalFAQ forum, https://www.digitalfaq.com/forum/video-editing/14627-removing-vhs-noise.html, checked 2026-10-24]
1504. **M6WIQ VHS clean-up chain order** — The M6WIQ script runs fieldorder, bwdif (mode=1, deint=all), nlmeans noise reduction, zscale (to 960x720 bicubic), unsharp, the crop/pad mask, then setsar=1:1. **How:** Tested with simple values for the unnamed variables: `ffmpeg -i in.mp4 -vf "fieldorder=tff,bwdif=mode=1:parity=tff:deint=all,nlmeans,zscale=w=960:h=720:filter=bicubic,format=yuv420p,unsharp,crop=(iw-10):(ih-14):3:0,pad=iw+10:ih+14:(ow-iw)/2:(oh-ih)/2,setsar=1:1" -t 0.5 -c:v libx264 -crf 23 out.mp4` (tested here 2026-10-24) [M6WIQ VHS capture on Linux, https://www.m6wiq.uk/2022/11/vhs-capture-linux/, checked 2026-10-24]
1505. **Keep a lossless interlaced master** — M6WIQ keeps two files per tape: a raw interlaced capture (huffyuv, -flags +ilme+ildct, 4:3) and a deinterlaced, cleaned MP4 for normal use. **How:** `ffmpeg -i in.mp4 -c:v huffyuv -flags +ilme+ildct -aspect 4:3 -an master.avi` (tested here 2026-10-24) [M6WIQ VHS capture on Linux, https://www.m6wiq.uk/2022/11/vhs-capture-linux/, checked 2026-10-24]
1506. **A TBC or DVD-recorder passthrough steadies capture** — An S-VHS deck with built-in TBC is ideal; without one, a mid-2000s Panasonic DVD recorder's "frame adjusters" work similarly in passthrough. An EasyCAP gave unusable results; M6WIQ then used a Hauppauge USB-Live2 on Linux. **How:** Hardware choice before any software repair. [M6WIQ VHS capture on Linux, https://www.m6wiq.uk/2022/11/vhs-capture-linux/, checked 2026-10-24]
1507. **Dot crawl and rainbows: dedot** — dedot reduces cross-luminance (dot crawl) and cross-colour (rainbows); m=dotcrawl+rainbows; lt/tl tune luma, tc/ct chroma (lower ct / higher tc = more rainbow reduction). **How:** `ffmpeg -i in.mp4 -vf dedot=m=dotcrawl+rainbows -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dedot, checked 2026-10-24]
1508. **Composite-era 4:3 pixels: set SAR explicitly** — M6WIQ ends with setsar=1:1 after scaling to square-pixel 960x720, so players do not re-stretch the image. **How:** `ffmpeg -i in.mp4 -vf scale=640:480,setsar=1:1 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [M6WIQ VHS capture on Linux, https://www.m6wiq.uk/2022/11/vhs-capture-linux/, checked 2026-10-24]

## Old film and home movies

1509. **Know the true film speed** — Normal 8 was usually shot at 16 or 18 fps, Super 8 at 18 (sometimes 24), 16mm mostly 24; very old 8mm used 9 or 12 fps. Film shot at 18 and shown at 25 runs about 40% too fast; 16 at 25 more than 50%. **How:** A person's walking pace reveals the right speed; set it scene by scene when unknown. [FilmFix, https://www.filmfix.be/en/blog/frame-rate-adjustment-in-8mm-and-super-8-transfer/, checked 2026-10-24] [Studio Hanabi, https://studiohanabi.com/archives/14520, checked 2026-10-24]
1510. **Re-time a frame-per-frame scan to its real rate** — Files playing at the original 16/18/24 fps give a 1:1 representation with no intermediate frames; input -r ignores the stored timestamps and assigns the rate you give. **How:** `ffmpeg -r 18 -i in.mp4 -an -c:v libx264 -crf 18 film18.mp4` (tested here 2026-10-24) [FilmFix, https://www.filmfix.be/en/blog/frame-rate-adjustment-in-8mm-and-super-8-transfer/, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Video-Options, checked 2026-10-24]
1511. **Blended frames come from projector transfers** — Recording an 18 fps projection at 25 fps creates blended frames showing two images at once; adding duplicate frames (18 to 25) is sharper but slightly jerky on pans. **How:** Prefer a frame-by-frame scan; convert the rate last. [FilmFix, https://www.filmfix.be/en/blog/frame-rate-adjustment-in-8mm-and-super-8-transfer/, checked 2026-10-24]
1512. **Ask the scanner for one frame per film frame** — Ask for one video frame per film frame, progressive, no pulldown, in a lightly compressed or lossless codec (ProRes, MJPEG, huffyuv, lagarith), and test a 10-frame sample first; do the rate conversion after editing. **How:** Order spec for a transfer house. [Jim Battle, https://thebattles.net/video/8mm_restoration.html, checked 2026-10-24]
1513. **Emulsion vs base scratches** — A scratch on the emulsion side often shows as a blue streak and is real damage (fix in post); a base-side scratch shows dark when projected and a wet-gate transfer fills it during capture. **How:** Decide wet-gate rescans before digital fixes. [Jim Battle, https://thebattles.net/video/8mm_restoration.html, checked 2026-10-24]
1514. **Undo a known 18 fps pulldown** — If 18p film was telecined to NTSC with pattern 334, detelecine with the same pattern returns the progressive frames. **How:** `ffmpeg -i in.mp4 -vf detelecine=pattern=334 -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#telecine, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#detelecine, checked 2026-10-24]
1515. **AI dust and scratch removal is still immature** — TheUnduster (macOS, GPL-3.0, ONNX detector + LaMa inpainting) ships an untrained fixture detector, so detection misses real dust until a model is trained. **How:** Needs a dust/scratch tool (missing). ## Dead pixels, logos and burned-in marks

1516. **Hide a dead or hot pixel with delogo** — delogo interpolates a small rectangle from its surroundings; a 2x2 box over a stuck pixel fixed it visually, and the whole job scripts and parallelises well. **How:** `ffmpeg -i in.mp4 -vf delogo=x=299:y=199:w=4:h=4 -c:v libx264 -crf 18 -c:a copy out.mp4` (tested here 2026-10-24) [MadPanic TV, https://www.madpanic.tv/blog/files/fixing-dead-pixels-with-ffmpeg.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#delogo, checked 2026-10-24]
1517. **Several dead pixels: chain delogo** — Chain one delogo per pixel; find x,y by exporting a frame and reading coordinates in GIMP; one user saw a slight washed-out look; preview with ffplay before encoding. **How:** `ffmpeg -ss 1 -i in.mp4 -frames:v 1 frame.png && ffmpeg -i in.mp4 -vf "delogo=x=299:y=199:w=4:h=4,delogo=x=10:y=120:w=2:h=2" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [Ask Ubuntu accepted answer, https://askubuntu.com/questions/706933, checked 2026-10-24]
1518. **Find the delogo box: show=1** — delogo show=1 draws a green rectangle on the outermost pixels used, to set x, y, w, h. **How:** `ffmpeg -ss 1 -i in.mp4 -vf delogo=x=540:y=20:w=80:h=40:show=1 -frames:v 1 box.png` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#delogo, checked 2026-10-24]
1519. **Mask-shaped logo removal: removelogo** — removelogo fills pixels marked non-zero in a same-size bitmap; make it from a black frame with the logo via threshold and one or two erosions; marking too many pixels hurts less than missing some. **How:** `ffmpeg -ss 1 -i in.mp4 -vf "drawbox=x=0:y=0:w=iw:h=ih:color=black:t=fill,drawbox=x=536:y=16:w=88:h=48:color=white:t=fill,format=gray" -frames:v 1 mask.png && ffmpeg -i in.mp4 -vf removelogo=f=mask.png -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#removelogo, checked 2026-10-24]
1520. **Blur over a rectangle: cover_rect** — cover_rect covers a found rectangle by interpolating the surroundings (mode=blur, default) or with a supplied yuv420 image; docs pair it with find_rect. **How:** Docs command shape: `find_rect=newref.pgm,cover_rect=cover.jpg:mode=cover`. - **realesrgan-ncnn-vulkan** (AI upscaling) — MIT — https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.5.0 (realesrgan-ncnn-vulkan-20220424-ubuntu.zip, 47 MB with models). Needs a Vulkan device: on this CPU box install Mesa lavapipe with `apt-get install -y --no-install-recommends mesa-vulkan-drivers` (MIT, Ubuntu archive).
- **Real-ESRGAN Python** (outscale, face_enhance, realesr-general-x4v3 with -dn) — BSD-3-Clause — https://github.com/xinntao/Real-ESRGAN.
- **untrunc** (anthwlock fork, truncated MP4 repair) — GPL-2.0 (COPYING) — https://github.com/anthwlock/untrunc; builds in seconds with `apt-get install libavformat-dev libavcodec-dev libavutil-dev` then `make`.
- **nnedi3_weights.bin** for ffmpeg nnedi — https://github.com/dubhater/vapoursynth-nnedi3/blob/master/src/nnedi3_weights.bin (13.6 MB).
- **QTGMC** via VapourSynth + vs-jetpack (QTempGaussMC) — https://encode.wiki/tools/filtering/deinterlace (licence not checked).
- **Gyroflow** (gyro-data stabilisation, rolling-shutter correction) — GPL-3.0 (the binary links closed-source mdk-sdk) — https://github.com/gyroflow/gyroflow.
- **Rolling-Shutter-Video-Stabilizer (rsvs)** — licence unclear, personal use only per README — https://github.com/Efenstor/Rolling-Shutter-Video-Stabilization.
- **DVRescue** (DV double-capture repair) — https://mediaarea.net/DVRescue/Download (licence not checked).
- **lensfun** filter (ffmpeg built with --enable-liblensfun) — https://ffmpeg.org/ffmpeg-filters.html (lensfun library licence not checked).
- **DNN-enabled ffmpeg** (TensorFlow/OpenVINO/LibTorch/ONNX Runtime backends) for sr and dnn_processing — https://ffmpeg.org/ffmpeg-filters.html#dnn_005fprocessing-1.
- **Dust/scratch removal**: TheUnduster (GPL-3.0, macOS, detector not trained yet) — https://github.com/acornelissen/TheUnduster; no working free CPU option was verified.
