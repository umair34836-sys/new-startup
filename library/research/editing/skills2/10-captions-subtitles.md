# Captions and subtitles
Scope: captions and subtitles in all styles - SRT/VTT/ASS/TTML/LRC files, soft tracks in MP4/MKV/HLS, ASS styling and karaoke tags, libass burn-in with ffmpeg, Whisper word timing, social caption styles, Urdu/Nastaliq RTL and Hindi/Devanagari shaping, bilingual subs, and accessibility rules (Netflix, BBC, DCMP, FCC, WCAG, Apple, EBU safe areas). Not general kinetic type (file 09).
Researched 2026-10-24 via agent-reach (Exa) web search (rate-limited, so WebSearch was used only to find URLs), official docs read with curl/pandoc, and local tests with ffmpeg 6.1.1 (libass 0.17.1 + HarfBuzz + FriBidi + libunibreak), openai-whisper 20250625 (small model, /home/user/tools/venv) and pysubs2 1.9.0 (pure-Python, installed with `pip --target` into the scratch folder only). Test clips: `testsrc2`/`color` lavfi sources and Whisper's public-domain test file `jfk.flac`. Fonts for tests: Noto Nastaliq Urdu, Noto Naskh Arabic, Noto Sans Devanagari (OFL, google/fonts) in the scratch folder, plus library/fonts (Kalam, Rozha One, Anton).

## Formats: convert and repair caption files
2721. **SRT to WebVTT in one command** — ffmpeg picks the WebVTT muxer from the `.vtt` extension and writes the `WEBVTT` header, keeping `<i>`/`<b>`. **How:** `ffmpeg -i s.srt s.vtt` (tested here 2026-10-24) [ffmpeg -h muxer=webvtt, local ffmpeg 6.1.1, 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2722. **WebVTT back to SRT** — the reverse conversion works the same way when a platform wants SRT. **How:** `ffmpeg -i s.vtt s.srt` (tested here 2026-10-24) [ffmpeg -h muxer=srt, local ffmpeg 6.1.1, 2026-10-24]
2723. **SRT to ASS keeps basic markup** — on conversion ffmpeg turned `<i>` into `{\i1}`, `<b>` into `{\b1}`, `<font color="#ff0000">` into `{\c&HFF&}` (ASS colours are BGR) and kept an inline `{\an8}`. **How:** `ffmpeg -i s.srt s.ass`, then style the `.ass` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2724. **Fix the header ffmpeg writes into a converted ASS** — ffmpeg's generated ASS had `PlayResX: 384`, `PlayResY: 288`, `Fontsize 16` and no LayoutRes; the libass guide says new files should set PlayRes and LayoutRes to the video's display size. **How:** after `ffmpeg -i in.srt out.ass`, edit `[Script Info]` to `PlayResX: 1920` `PlayResY: 1080` `LayoutResX: 1920` `LayoutResY: 1080` and scale Fontsize to match (tested here 2026-10-24, header observed) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2725. **ASS back to SRT** — ffmpeg converts `\i1`/`\b1`/`\c` back to `<i>`/`<b>`/`<font color>`, but a position tag like `{\an8}` stays in the text as a brace block. **How:** `ffmpeg -i s.ass s.srt` and check the result for leftover `{...}` (tested here 2026-10-24) [ffmpeg -h muxer=srt, local ffmpeg 6.1.1, 2026-10-24]
2726. **LRC lyrics file from an SRT** — ffmpeg's LRC muxer takes a subrip/text stream and writes `[mm:ss.xx]` lines, but it copied `<i>`/`<font>` tags into the LRC, so strip markup first; 6.1.1 has no `precision` option (the current docs list one for newer builds). **How:** `ffmpeg -i lyrics.srt lyrics.lrc` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#lrc, checked 2026-10-24]
2727. **TTML/DFXP from an SRT** — ffmpeg 6.1 has a TTML muxer/encoder; its output sets `ttp:cellResolution="384 288"` and a bottom `Default` region in Arial. **How:** `ffmpeg -i s.srt s.ttml` (tested here 2026-10-24) [ffmpeg -h muxer=ttml, local ffmpeg 6.1.1, 2026-10-24] [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24]
2728. **YouTube SBV to SRT** — YouTube's SubViewer `.sbv` uses `0:00:00.500,0:00:01.500` times with no counter; ffmpeg reads it when the subviewer demuxer is forced. **How:** `ffmpeg -f subviewer -i captions.sbv captions.srt` (tested here 2026-10-24) [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24]
2729. **Don't try to make SCC from SRT in ffmpeg** — the SCC format only carries EIA-608 data; ffmpeg 6.1.1 refused `-i s.srt s.scc` ("Output file does not contain any stream"). **How:** deliver SRT/VTT instead, or use a dedicated 608 tool (needs a 608 encoder (missing)) (tested here 2026-10-24, failure confirmed) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#mcc, checked 2026-10-24]
2730. **YouTube's basic formats are plain** — for SRT and SBV YouTube supports only basic files: no style markup is recognised and the file must be plain UTF-8. **How:** for YouTube uploads export SRT with `pysubs2 --clean` (removes styling) and save UTF-8 (tested here 2026-10-24) [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24] [pysubs2 CLI, https://pysubs2.readthedocs.io/en/latest/cli.html, checked 2026-10-24]
2731. **YouTube advanced formats** — YouTube's WebVTT support handles positioning but only `<b>`, `<i>`, `<u>` styling; TTML is partial (iTT supported), SAMI/RealText take simple markup without positioning, and SCC is the preferred broadcast format. **How:** if a YouTube caption must sit at the top, upload a `.vtt` with a `line:0` cue setting rather than an SRT [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24]
2732. **A UTF-8 BOM doesn't break ffmpeg** — an SRT starting with the BOM bytes `EF BB BF` converted cleanly. **How:** `ffmpeg -i bom.srt bom.vtt` (tested here 2026-10-24) [libass wiki: ASS File Format Guide (BOM advice for ASS), https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2733. **Read a sloppy SRT** — an SRT with no cue numbers and `.` instead of `,` before the milliseconds parsed when the format was forced, and was written back as a clean numbered SRT. **How:** `ffmpeg -f srt -i loose.srt clean.srt` (tested here 2026-10-24) [ffmpeg -h demuxer=srt, local ffmpeg 6.1.1, 2026-10-24]
2734. **Legacy Arabic/Urdu code page to UTF-8** — `sub_charenc` sets the input subtitle character encoding; a Windows-1256 SRT came out byte-identical to the UTF-8 original (apart from a final newline). **How:** `ffmpeg -sub_charenc CP1256 -i old.srt fixed.srt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#Codec-Options, checked 2026-10-24]
2735. **Burn a legacy-encoded file without converting** — the `subtitles` filter's `charenc` option; the CP1256 burn was pixel-identical (same md5) to the UTF-8 burn. **How:** `ffmpeg -i in.mp4 -vf "subtitles=old.srt:charenc=CP1256" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2736. **Shift a whole subtitle file with -itsoffset** — the offset is added to the input timestamps; a cue at 0.500 s became 2.000 s with `-itsoffset 1.5` and no re-typing. **How:** `ffmpeg -itsoffset 1.5 -i s.srt -c copy shifted.srt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2737. **ffmpeg loses every cue after a WebVTT STYLE block** — a `.vtt` with a `STYLE` block produced an empty output in ffmpeg 6.1.1, while the same file loaded fully in pysubs2; a `NOTE` block alone was fine. **How:** convert styled VTT with `python3 -m pysubs2 --to srt in.vtt` instead of ffmpeg (tested here 2026-10-24) [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2738. **ffmpeg drops WebVTT cue settings** — `line:0 position:20% align:start` disappeared on a VTT to VTT copy and on VTT to ASS; `<v Bob>` and `<c.loud>` tags were stripped to plain text. **How:** keep positioned VTT as the master file; to burn it, re-create the position as `{\an7\pos(x,y)}` in ASS (tested here 2026-10-24) [W3C WebVTT, https://www.w3.org/TR/webvtt1/, checked 2026-10-24]
2739. **List the subtitle tracks in a file** — ffprobe can print each subtitle stream's index, codec and language tag. **How:** `ffprobe -v error -select_streams s -show_entries stream=index,codec_name:stream_tags=language -of csv=p=0 in.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Stream-specifiers, checked 2026-10-24]
2740. **Extract one subtitle track** — map the subtitle stream by type index and give an `.srt` name. **How:** `ffmpeg -i in.mkv -map 0:s:1 urdu.srt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Stream-selection, checked 2026-10-24]
2741. **Drop all subtitle tracks** — `-sn` as an output option disables subtitle mapping, so a client copy carries no stray tracks. **How:** `ffmpeg -i in.mkv -map 0 -sn -c copy clean.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Subtitle-options, checked 2026-10-24]

## pysubs2 (Python) for batch caption work
2742. **pysubs2 basics** — pure-Python, MIT library that reads SRT, ASS/SSA, MicroDVD, MPL2, TMP, WebVTT, TTML and SAMI into an ASS-based model; times are int milliseconds. **How:** `pip install --target <scratch>/pylib pysubs2` then `subs = pysubs2.load("s.srt"); subs.save("s.ass")` (tested here 2026-10-24) [pysubs2 docs, https://pysubs2.readthedocs.io/en/latest/, checked 2026-10-24]
2743. **Retime by a constant** — `SSAFile.shift()` takes h/m/s/ms or frames+fps; negative times are treated as zero on export. **How:** `subs.shift(s=1.5)` moved 0.5 s to 2.0 s (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2744. **Fix subs made for another frame rate** — `transform_framerate(in_fps, out_fps)` rescales all times. **How:** `subs.transform_framerate(25, 23.976)` moved 500 ms to 521 ms (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24]
2745. **Times from frames** — `pysubs2.make_time(frames=50, fps=25)` returns 2000 ms; `pysubs2.time.ms_to_frames(1000, 30)` returns 30. **How:** use these in timing scripts instead of hand maths (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24]
2746. **Text without tags** — `SSAEvent.plaintext` hides override tags and turns `\N` into newlines (writing to it throws tags away). **How:** `[e.plaintext for e in subs]` gave `Hello world, this is line one` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2747. **One model, many outputs** — `to_string()`/`save()` write vtt, ass, json, tmp, mpl2, ttml and (with `fps=`) microdvd from the same object. **How:** `subs.to_string("ttml")` (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24]
2748. **Pass unknown encodings through untouched** — `errors="surrogateescape"` lets you retime or convert a non-UTF-8 file without knowing its encoding; a CP1256 file kept its exact Arabic bytes. **How:** `subs = pysubs2.load("old.srt", errors="surrogateescape"); subs.save("old_fixed.srt", errors="surrogateescape")` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2749. **Sort events by time** — `SSAFile.sort()` orders events chronologically (events compare by time). **How:** after appending cues out of order, `subs.sort()` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2750. **Strip drawings and karaoke junk** — `remove_miscellaneous_events()` removed a `{\p1}` drawing event (4 events to 3); the CLI `--clean` does the same and strips styling for non-SSA output. **How:** `python3 -m pysubs2 --to srt --clean in.ass` kept only the text line (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24] [pysubs2 CLI, https://pysubs2.readthedocs.io/en/latest/cli.html, checked 2026-10-24]
2751. **Rename a style safely** — `rename_style(old, new)` also fixes every event that points to it. **How:** `subs.rename_style("top", "English")` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2752. **Batch convert and shift from the shell** — the pysubs2 CLI converts with `--to` and retimes with `--shift`/`--shift-back` ("1m30s", "0.5s"), writing to `-o DIR`. **How:** `python3 -m pysubs2 --to vtt *.srt -o out/` and `python3 -m pysubs2 --shift 0.5s s.srt -o shifted/` (tested here 2026-10-24) [pysubs2 CLI, https://pysubs2.readthedocs.io/en/latest/cli.html, checked 2026-10-24]
2753. **Bilingual subtitles, top and bottom** — pysubs2's own example puts one language in a `BOTTOM_CENTER` style and the other in a `TOP_CENTER` style in one ASS file. **How:** load `ur.srt` and `en.srt`, set `subs.styles = {"bottom": SSAStyle(fontname="Noto Nastaliq Urdu", alignment=Alignment.BOTTOM_CENTER), "top": SSAStyle(alignment=Alignment.TOP_CENTER)}`, append events with `e.style`, `subs.save("bi.ass")` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]

## Soft subtitle tracks in MP4, MKV and HLS
2754. **Soft subs in MP4 must be mov_text** — MP4 takes the 3GPP timed-text codec; add a language tag so players label the track. **How:** `ffmpeg -i in.mp4 -i s.srt -map 0 -map 1 -c copy -c:s mov_text -metadata:s:s:0 language=urd out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2755. **What mov_text keeps** — extracting back from MP4 kept `<i>` and `<b>` but lost the font colour and the `{\an8}` position. **How:** keep coloured/positioned captions as ASS (burn them) or MKV, not MP4 soft subs (tested here 2026-10-24) [ffmpeg -h encoder=mov_text, local ffmpeg 6.1.1, 2026-10-24]
2756. **Two languages in one MKV, choose the default** — set language per track and move the default flag; ffmpeg's own example clears `s:0` and sets `s:1` default. **How:** `ffmpeg -i v.mp4 -i en.srt -i ur.srt -map 0 -map 1 -map 2 -c copy -c:s srt -metadata:s:s:0 language=eng -metadata:s:s:1 language=urd -disposition:s:0 0 -disposition:s:1 default out.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2757. **Flag a forced-narrative track** — forced subtitles carry only the on-screen-text/foreign-dialogue lines; mark the track `forced` and give it a title. **How:** `-disposition:s:0 forced -metadata:s:s:0 title="Forced narrative"` (ffprobe showed forced=1) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24] [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2758. **Attach the fonts inside the MKV** — the libass guide says every font a script uses must exist and be attached to the release; Matroska needs a mimetype tag on the attachment. **How:** `ffmpeg -i in.mkv -map 0 -c copy -attach NotoNastaliqUrdu.ttf -metadata:s:t mimetype=application/x-truetype-font out.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24] [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2759. **Pull fonts out of someone's MKV** — `-dump_attachment:t ""` writes every attachment under its stored filename. **How:** `ffmpeg -dump_attachment:t "" -i in.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2760. **Burn a track that lives inside the video file** — the `subtitles` filter can read from a container; `si` picks the subtitle stream. **How:** `ffmpeg -i in.mkv -vf "subtitles=in.mkv:si=1:fontsdir=fonts" out.mp4` (also worked on an MP4's mov_text track) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2761. **HLS with a WebVTT subtitle rendition** — the HLS muxer can segment a text stream as WebVTT and add `#EXT-X-MEDIA:TYPE=SUBTITLES` to the master playlist; `language:` in the var_stream_map adds `LANGUAGE=`. In 6.1.1 the `sname:` key from the current docs was rejected. **How:** `ffmpeg -i v.mp4 -i s.srt -map 0:v -map 0:a -map 1 -c:v copy -c:a copy -c:s webvtt -f hls -hls_time 1 -var_stream_map "v:0,a:0,s:0,sgroup:subs,language:eng" -master_pl_name master.m3u8 h_%v.m3u8` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#hls-2, checked 2026-10-24]
2762. **Check HLS WebVTT segments for X-TIMESTAMP-MAP** — Apple requires WebVTT segments to carry an X-TIMESTAMP-MAP header; ffmpeg 6.1.1's segments had none and a cue at 0.500 s was written as 0.567 s. **How:** `grep -L X-TIMESTAMP-MAP *.vtt` before delivering to Apple devices (tested here 2026-10-24) [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2763. **Apple: which caption formats** — Apple devices take CEA-608/708 captions, WebVTT subtitles and IMSC1 (text profile) subtitles; subtitles must be WebVTT text files or IMSC1 in fMP4, and the subtitle playlist must cover the whole programme. **How:** for an HLS delivery pick WebVTT unless the client asks for IMSC1 [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2764. **Apple: mark SDH tracks** — a subtitle track meant for deaf/hard-of-hearing viewers must have `CHARACTERISTICS="public.accessibility.transcribes-spoken-dialog,public.accessibility.describes-music-and-sound"`, `AUTOSELECT=YES` and a LANGUAGE attribute. **How:** edit the `#EXT-X-MEDIA` line of `master.m3u8` after ffmpeg writes it [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2765. **Apple: forced plus full subs** — if a language has forced and regular subtitles, the regular track must contain both; forced tracks should be AUTOSELECT=YES; and if a clean (no burnt text) version exists, forced subtitles should be used instead of burnt-in text. **How:** build the full track as forced lines + dialogue lines merged with `subs.sort()` [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2766. **Apple: codec strings** — use `stpp.ttml.im1t` for IMSC1 subtitles; `wvtt` may be used for WebVTT in the CODECS attribute. **How:** add it to `#EXT-X-STREAM-INF` CODECS when the player needs it [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]

## Burn-in with ffmpeg (libass)
2767. **Prefer the `ass` filter for burning ASS** — it is the subtitles filter without the libavcodec/libavformat conversion, limited to ASS files, and it is the one that exposes `shaping` in ffmpeg 6.1.1 (`ffmpeg -h filter=subtitles` lists no shaping option). **How:** `ffmpeg -i in.mp4 -vf "ass=caps.ass:fontsdir=library/fonts" -c:a copy out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2768. **The `subtitles` filter broke Hindi and Urdu here** — with ffmpeg 6.1.1, `subtitles=` rendered Devanagari with broken conjuncts (visible halant in नमस्ते, क्ष split) and Noto Nastaliq Urdu as empty boxes, even for an `.ass` input; the same text through `ass=` was correct. **How:** never burn Urdu/Hindi with `subtitles=`; convert first (next skill) (tested here 2026-10-24, frames inspected) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2769. **SRT in Urdu/Hindi: convert, then burn with `ass`** — converting the SRT to ASS and rendering with the `ass` filter gave correct conjuncts. **How:** `ffmpeg -i h.srt h.ass` → set Fontname (e.g. Noto Sans Devanagari) and PlayRes → `ffmpeg -i in.mp4 -vf "ass=h.ass:fontsdir=fonts" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2770. **Force complex shaping for scripts that need it** — `shaping=complex` uses OpenType substitution and positioning and is required for Arabic, Hebrew, Devanagari and Thai; `simple` only substitutes. On the same Hindi line `simple` and `complex` produced different frames, and only `complex`/`auto` joined the conjuncts. **How:** `-vf "ass=hi.ass:fontsdir=fonts:shaping=complex"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2771. **Use repo fonts without installing them** — `fontsdir` adds a folder of fonts to what the font provider already has. **How:** `-vf "ass=caps.ass:fontsdir=/home/user/new-startup/library/fonts"` rendered Kalam and Rozha One (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2772. **Prove which font file libass picked** — at `-v verbose` the filter logs `fontselect: (Noto Nastaliq Urdu, 400, 0) -> NotoNastaliqUrdu-Regular`; a silent fallback font is the usual cause of tofu. **How:** `ffmpeg -v verbose -i in.mp4 -vf "ass=u.ass:fontsdir=fonts" -frames:v 1 -f null - 2>&1 | grep fontselect` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2773. **original_size only matters when the aspect changes** — the docs say it is needed to scale fonts correctly if the aspect ratio was changed; on a same-aspect 640x360 to 1280x720 burn it made no difference (identical frames). **How:** `subtitles=s.srt:original_size=640x360` only after anamorphic or aspect changes (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2774. **Input seeking shifts burned subtitles** — with `-ss 1` before `-i`, timestamps restart at 0 and the filter shows the wrong cues (a cue at 0.5-1.5 s vanished from the first second). Shift the clock for the filter and back. **How:** `ffmpeg -ss 1 -i in.mp4 -vf "setpts=PTS+1/TB,subtitles=s.srt,setpts=PTS-STARTPTS" out.mp4` showed the cue correctly (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts, checked 2026-10-24]
2775. **Transparent caption layer for compositing** — render captions onto a fully transparent canvas with `alpha=1` and keep alpha in the codec (qtrle wrote argb). **How:** `ffmpeg -f lavfi -i "color=c=black@0.0:s=1920x1080:r=30:d=10,format=rgba" -vf "ass=caps.ass:alpha=1" -c:v qtrle caps.mov` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2776. **Caption-only or lyric video** — burn the ASS onto a colour source and add the audio. **How:** `ffmpeg -f lavfi -i color=c=black:s=1080x1920:r=30:d=11 -i voice.flac -vf "ass=caps.ass" -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac lyric.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2777. **Darken the caption band before burning** — a filled semi-transparent `drawbox` under the text (CLAUDE.md: put captions over a darker lower part of the frame). **How:** `-vf "drawbox=x=0:y=ih*0.7:w=iw:h=ih*0.3:color=black@0.5:t=fill,subtitles=s.srt"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawbox, checked 2026-10-24] [repo: CLAUDE.md "HyperFrames learnings"]
2778. **force_style colours carry alpha** — `force_style` takes ASS `KEY=VALUE` pairs; the docs' example `PrimaryColour=&HCCFF0000` is 80% transparent blue (AABBGGRR). **How:** `subtitles=s.srt:force_style='Fontname=DejaVu Serif,PrimaryColour=&HCCFF0000'` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2779. **Find the cuts to time captions against** — `scdet` logs `lavfi.scd.time` at each scene change; a red/blue cut at 1.3 s (24 fps) was found at 1.33333 s. Feed these times to the shot-change rules below. **How:** `ffmpeg -i in.mp4 -vf "scdet=threshold=10,metadata=print:key=lavfi.scd.time" -f null - 2>&1 | grep scd.time` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scdet-1, checked 2026-10-24]
2780. **Snap caption edges to cuts like Aegisub's keyframe snapping** — Aegisub moves a line start onto a keyframe when it is within a threshold, and an end to the frame before the keyframe; its post-processor applies lead-in/out first, then joins adjacent lines, then snaps. **How:** in Python, for each cut time `c` from scdet: if `0 <= c - start < 0.5` set `start = c`; if `0 <= c - end < 0.5` set `end = c - 2/fps` [Aegisub manual: Timing Post-Processor, https://aegisub.org/docs/latest/timing_post-processor/, checked 2026-10-24] [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]

## drawtext captions (no subtitle file)
2781. **drawtext is fine for Arabic Naskh, not for Urdu Nastaliq or Hindi** — `text_shaping` (needs FriBidi) reverses RTL text and joins Arabic letters: Noto Naskh Arabic came out joined and right-to-left, but Noto Nastaliq Urdu showed boxes and Devanagari conjuncts broke. **How:** use drawtext only for Latin/Naskh text; burn Urdu and Hindi with the `ass` filter (tested here 2026-10-24, frames inspected) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2782. **Put caption text in a file** — drawtext's text needs up to four levels of escaping; `textfile` avoids that and must be UTF-8. **How:** `printf 'مرحبا 123' > line.txt` then `drawtext=fontfile=NotoNaskhArabic.ttf:textfile=line.txt:fontsize=36:fontcolor=white:x=(w-tw)/2:y=h-120` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2783. **Live-updating caption from a file** — `reload=N` re-reads the textfile every N frames; update the file atomically or it may be read half-written. **How:** `drawtext=fontfile=DejaVuSans.ttf:textfile=live.txt:reload=1:fontsize=30:fontcolor=white:x=20:y=20` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2784. **Time a drawtext line with `enable`** — timeline editing evaluates `enable` per frame (with `t` in seconds); outside the window the frame passes unchanged. **How:** `drawtext=...:text='Timed line':enable='between(t,1,2)'` showed the text at 1.5 s and not at 0.5 s (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]
2785. **Change the words mid-clip with sendcmd** — drawtext's `reinit` command re-sets options (text, fontsize...) at a given time. **How:** a command file `1.0 drawtext reinit text=Second;` with `-vf "sendcmd=f=cmds.txt,drawtext=fontfile=DejaVuSans.ttf:text=First:fontsize=30:fontcolor=white:x=20:y=300"` switched the text at 1 s (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2786. **Asymmetric box padding** — `boxborderw` takes 1-4 values; `8|24` pads 8 px top/bottom and 24 px left/right for a wide caption pill. **How:** `drawtext=...:box=1:boxcolor=black@0.7:boxborderw=8|24` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2787. **Fixed caption box with centred lines** — `boxw`/`boxh` fix the box size and `text_align` places the text inside it; in 6.1.1 the flags are joined with `+` (`M+C`), the docs' `MC` form was rejected. **How:** `drawtext=...:textfile=two.txt:box=1:boxw=500:boxh=100:text_align=M+C:line_spacing=8:x=(w-500)/2:y=h-130` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2788. **fix_bounds pulls text back on screen, within limits** — with `fix_bounds=1` text placed off the bottom-right moved up and left into the frame, but a line wider than the frame still overflowed. **How:** add `:fix_bounds=1`, and still wrap long lines yourself (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]

## ASS script structure (libass best practice)
2789. **Minimum header for a portable ASS** — `ScriptType: v4.00+` is required; the guide also wants `ScaledBorderAndShadow`, `YCbCr Matrix`, `PlayResX/Y` and `LayoutResX/Y`, sections in order with `[Events]` last, UTF-8 (BOM recommended). **How:** start every file from the guide's example header (`ScaledBorderAndShadow: yes`, `YCbCr Matrix: None`, PlayRes = LayoutRes = video size); every test file here used it (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2790. **ScaledBorderAndShadow: yes, always** — the guide says `no` has no benefit and only exists for backward compatibility; with `yes` border and shadow sizes are in script pixels. **How:** keep `ScaledBorderAndShadow: yes` in `[Script Info]` [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24] [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2791. **Set YCbCr Matrix to match the video** — for BT.601/BT.709 video set exactly `TV.709` (or `TV.601`, `PC.*` for full range), otherwise `None`; a missing header is read as TV.601, which mangles colours on modern HD video in VSFilter-style renderers. **How:** for normal phone/YouTube HD footage use `YCbCr Matrix: TV.709` (or `None`) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24] [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2792. **Script resolution is a coordinate system** — font sizes, margins, `\pos`, clips and drawings are in PlayRes units, independent of the video size; it only needs the same aspect as the video (1280x720 is fine for 1920x1080, 1440x1080 is not). **How:** author vertical reels at `PlayResX: 1080 PlayResY: 1920` so numbers equal pixels [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2793. **LayoutRes keeps blur and 3D rotation consistent** — `\blur`, the 3D-rotation focal length and text widths scale with Layout Resolution; set it so the file renders the same at any size, with the same aspect as PlayRes. **How:** `LayoutResX`/`LayoutResY` = display size of the source video [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24] [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2794. **Pick the wrap mode** — 0 balances line lengths (top wider), 1 fills the first line then breaks, 2 never wraps (only `\N`/`\n` break). Rendered: `\q0` and `\q1` broke the same 60-character line at different words, `\q2` ran off both edges. **How:** global `WrapStyle: 0` for dialogue, `{\q2}` plus manual `\N` for styled social captions (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2795. **Don't use wrap mode 3** — VSFilter's mode 3 (bottom line wider) is unsupported in libass and treated as 0; the guide says use `\q2` with explicit `\N` for a specific break shape. **How:** for a bottom-heavy two-liner write the break yourself: `{\q2}Short top\Nlonger bottom line` [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2796. **Style line rules** — booleans are `-1`/`0`, colours are `&HAABBGGRR` (alpha 00 opaque, FF invisible), `Encoding` must be `1` (see the libass RTL exception below), Fontname ≤ 31 characters, Fontsize ≤ 511 (scale with tags instead). **How:** `Style: Default,DejaVu Sans,32,&H00FFFFFF,&H000000FF,&H00000000,&H80000000,-1,0,0,0,100,100,0,0,1,2,1,2,20,20,24,1` (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2797. **No letter Spacing on Urdu/Hindi styles** — the guide says Spacing is not advisable with scripts that depend on complex shaping. **How:** keep `Spacing` 0 and no `\fsp` on Nastaliq/Devanagari styles [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2798. **Event times are h:mm:ss.cc** — exactly two digits for minutes, seconds and centiseconds; start is inclusive and end exclusive. **How:** write times with a helper such as `f"{h}:{m:02d}:{s:02d}.{cs:02d}"` (used by the generators below) (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2799. **Layers decide what sits on top** — lower `Layer` values are drawn behind higher ones; a Layer 1 yellow "TOP" drew over a larger Layer 0 "BOTTOM". **How:** box/drawing events on Layer 0, text on Layer 1 (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2800. **Overlapping lines stack themselves** — two unpositioned events in the same style that overlap in time were stacked (the later one above), not drawn over each other; events on different Layers never count as colliding. **How:** to keep two speakers apart use `\an1`/`\an3` or `\pos`, otherwise let libass stack them (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2801. **Comment lines and inline comments** — `Comment:` events are never rendered (frame identical to the bare video); unknown text inside `{}` is silently ignored, so `{note}` works as an inline comment. **How:** keep alternate takes as `Comment:` lines in the master ASS (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24] [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2802. **Name field = speaker label for you, not the viewer** — the `Name` field is free metadata for who speaks and does not affect rendering. **How:** fill Name with the speaker so a script can colour or position by speaker later [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2803. **Built-in ticker and credit roll** — the Effect field `Banner;delay` scrolls text sideways (lower delay = faster) and `Scroll up;y1;y2;delay` rolls it up between two y limits. **How:** `Dialogue: 0,0:00:00.00,0:00:03.00,Default,,0,0,0,Scroll up;40;320;10,Credits roll up` (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2804. **Don't use the VSFilter fadeaway effect argument or \fe** — the optional `fadeaway` effect parameter is not supported by libass and must not be used; `\fe` must not be used at all. **How:** do fades with `\fad`, and fonts by name, never by encoding [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]

## ASS override tags for caption styling
2805. **Three kinds of line break** — `\N` always breaks, `\n` breaks only in wrap mode 2 (otherwise a space), `\h` is a non-breaking space that also isn't trimmed at line ends. **How:** `Mr.\hSmith` kept "Mr. Smith" together when the line wrapped (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2806. **Line-level vs text-level tags** — `\pos`, `\move`, `\clip`, `\iclip`, `\org`, `\fade`, `\fad` set properties of the whole line and should appear once (and `\pos`/`\move`, `\clip`/`\iclip`, `\fad`/`\fade` exclude each other); all other tags change the text after them. **How:** put one positioning tag at the start: `{\an5\pos(540,1180)}` [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2807. **Separate X and Y outline** — `\xbord`/`\ybord` set border width per axis (a later `\bord` overrides both); useful to correct borders on anamorphic renders. **How:** `{\xbord4\ybord2}` [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2808. **Shadow up-left with negative offsets** — `\shad` can't be negative, but `\xshad`/`\yshad` can, putting the shadow above/left of the text. **How:** `{\xshad-4\yshad-4\4c&H0000FF&\4a&H00&}` drew a red shadow up-left (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2809. **Glow outline with \blur** — `\blur` softens the border (or the fill if there is no border) with a Gaussian kernel; use it instead of `\be`, which does not scale with resolution. **How:** `{\bord6\blur6\3c&H00D7FF&}` gave a soft gold glow (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24] [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2810. **Animate size with \fscx/\fscy, not \fs** — `\fs` is integer and goes through font hinting, so animating it jumps; `\fscx`/`\fscy` scale after hinting and should be used inside `\t`. **How:** `{\t(0,200,\fscx120\fscy120)}` instead of `{\t(\fs60)}` [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2811. **Font weight numbers** — `\b<weight>` takes 100-900 (400 normal, 700 bold), but most fonts only have one or two weights. **How:** `{\b900}` only helps with a font that ships a Black weight [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2812. **Letter spacing** — `\fsp` adds spacing in script pixels, can be negative or fractional. **How:** `{\fsp6}SPACED OUT` (tested here 2026-10-24) (not on Urdu/Hindi, see 2797) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2813. **Shear for a speed look** — `\fax`/`\fay` shear the text; values outside -2..2 rarely look right. **How:** `{\fax-0.3}` gave a forward-leaning line (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2814. **Colours are BGR** — `\1c` fill, `\2c` karaoke pre-highlight, `\3c` border, `\4c` shadow, written `&HBBGGRR&` (opposite of HTML). **How:** HTML #FFD700 gold is `\1c&H00D7FF&` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2815. **Outline-only (hollow) text** — `\1a&HFF&` makes the fill invisible and leaves border and shadow. **How:** `{\1a&HFF&\bord2}OUTLINE ONLY` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2816. **Numpad alignment and its anchor** — `\an1..9` follows the numeric keypad (1 bottom-left, 5 centre, 8 top-centre) and is also the anchor point for `\pos` and rotation. **How:** to centre a caption on a point use `{\an5\pos(540,1180)}` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2817. **Slide in with \move and times** — `\move(x1,y1,x2,y2,t1,t2)` holds at the start until t1 ms, moves at constant speed to t2, then holds; one move per line and no easing. **How:** `{\move(100,300,540,300,500,1500)}` was still at 0.2 s and 0.4 s and moved by 1.0 s (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2818. **Fade inside the line's time** — `\fad(in,out)` in ms uses the line's own start/end, so fade-in + fade-out must not exceed the duration. **How:** `{\fad(150,150)}` on a 1.2 s caption (tested with `\fad(1000,500)` here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2819. **Five-part fade** — `\fade(a1,a2,a3,t1,t2,t3,t4)` with decimal alpha 0-255 and ms times, e.g. fade in, hold, fade to half. **How:** `{\fade(255,0,255,0,500,2000,2500)}` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2820. **Eased transforms** — `\t(t1,t2,accel,tags)`: accel 1 is linear, below 1 starts fast and ends slow, above 1 starts slow. **How:** `{\t(0,250,0.5,\fscx100\fscy100)}` for an ease-out settle [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2821. **Pop-in word** — the manual's example grows text from 0 to 100% scale with `\t`; add a small overshoot with a second `\t`. **How:** `{\an5\pos(320,180)\fscx0\fscy0\t(0,200,\fscx110\fscy110)\t(200,300,\fscx100\fscy100)}POP` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2822. **Wipe-on reveal with an animated clip** — only rectangular `\clip` can be animated with `\t`; a clip growing from width 0 to full reveals the line left to right. **How:** `{\clip(0,0,0,360)\t(0,1000,\clip(0,0,640,360))}` (at 0.3 s only "Wi" showed) (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2823. **Hide part of a line with \iclip** — `\iclip` hides what is inside its rectangle (e.g. where text would cover a logo); vector clips work too but can't be animated. **How:** `{\iclip(0,0,320,360)}` hid the left half (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2824. **Rounded caption pill from a drawing** — `\p1` turns text into drawing commands (`m`, `l`, `b` Bézier) filled with the primary colour; put the pill on Layer 0 and the text on Layer 1 at the same `\pos`. Coordinates starting at 0 placed correctly; a drawing with negative coordinates landed off-centre. **How:** `Dialogue: 0,...,{\an5\pos(320,300)\bord0\shad0\1c&H000000&\1a&H40&\p1}m 20 0 l 320 0 b 340 0 340 50 320 50 l 20 50 b 0 50 0 0 20 0{\p0}` + `Dialogue: 1,...,{\an5\pos(320,300)}Pill box caption` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2825. **Jump bounce via a far rotation origin** — the manual notes that an `\org` placed far away turns small `\frz` rotations into near-straight up/down moves. **How:** `{\an2\pos(320,300)\org(320,10000)\t(0,150,\frz-0.6)\t(150,300,\frz0)}Jump` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2826. **Reset mid-line with \r** — `\r` returns to the line's style and `\rStyle` switches to another style for the rest of the line. **How:** `{\c&H0000FF&\bord5}Red {\r}normal {\rKara}kara` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]

## Karaoke and word-by-word highlight in ASS
2827. **\kf sweeps, \k jumps, \ko outlines** — `\k` switches a syllable from secondary to primary colour at its start, `\K`/`\kf` sweep left to right over the syllable's duration, `\ko` also hides the outline until the syllable starts; durations are centiseconds. **How:** `{\k50}Har {\kf80}lafz {\ko60}chamakta {\k60}hai` with PrimaryColour yellow and SecondaryColour white showed "lafz" half-filled at 0.9 s (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2828. **The not-yet-sung colour is SecondaryColour** — `\2c`/`\2a` are only used as karaoke pre-highlight; set the style's Secondary to the "waiting" colour and Primary to the "sung" colour. **How:** `Style: K,...,&H0000FFFF,&H00FFFFFF,...` = sung yellow, waiting white (tested here 2026-10-24) [Aegisub manual: Editing styles, https://aegisub.org/docs/latest/styles/, checked 2026-10-24]
2829. **\kt for gaps between sung words** — `\kt` sets the next syllable's start relative to the line start, so pauses don't need dummy syllables; supported in libass since 0.17.0 (this box has 0.17.1). **How:** `{\kt0\k20}One {\kt150\k30}Two` lit "Two" only after 1.5 s (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2830. **Karaoke ASS straight from Whisper words** — make one event per 4 words and give each word `\kf` = (next word start − this word start) × 100 so the fill follows the speech. **How:** Python over `result["segments"][i]["words"]`: `"{\\kf%d}%s" % (round((nxt-w["start"])*100), w["word"].strip())`; burned with `ass=` the fill sat on "fellow" at 1.3 s in the JFK test clip (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24] [openai/whisper transcribe.py, https://github.com/openai/whisper/blob/main/whisper/transcribe.py, checked 2026-10-24]

## libass-only extensions (fine for burn-in, not for shared softsubs)

## Urdu, Arabic and other RTL captions
2836. **Nastaliq needs complex shaping** — Noto Nastaliq Urdu rendered as empty boxes with `shaping=simple` and as correct joined Nastaliq with `complex`/`auto` in the `ass` filter. **How:** `-vf "ass=ur.ass:fontsdir=fonts:shaping=complex"` (tested here 2026-10-24, frames inspected) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2837. **Get a free Nastaliq font** — Noto Nastaliq Urdu is OFL-licensed in google/fonts (`ofl/notonastaliqurdu`, variable weight, Regular to Bold); Noto Naskh Arabic and Noto Sans Devanagari are in the same repo. **How:** `curl -LO "https://raw.githubusercontent.com/google/fonts/main/ofl/notonastaliqurdu/NotoNastaliqUrdu%5Bwght%5D.ttf"` (+ OFL.txt) and point `fontsdir` at it (downloaded and used here 2026-10-24) (tested here 2026-10-24) [google/fonts METADATA.pb, https://github.com/google/fonts/tree/main/ofl/notonastaliqurdu, checked 2026-10-24]
2838. **Nastaliq reads small: size it up** — at the same Fontsize 40 the words "پاکستان کیپشن / دوسری لائن" measured 60 px wide in Noto Nastaliq Urdu against 106 px in Noto Naskh Arabic, with a similar block height (70 vs 59 px). **How:** give Nastaliq styles a larger Fontsize than the Naskh/Latin styles and size it by checking a rendered frame (tested here 2026-10-24, measured with numpy) [google/fonts METADATA.pb, https://github.com/google/fonts/tree/main/ofl/notonastaliqurdu, checked 2026-10-24]
2839. **Mixed Urdu + English comes out scrambled by default** — with the standard `Encoding 1` libass laid "میں نے FireCraft پر 25 ہارٹس جیتے!" out left-to-right, putting the words in the wrong order. **How:** always check a frame when Urdu lines contain English names or numbers (tested here 2026-10-24, frame inspected) [libass wiki: Libass' ASS Extensions, https://github.com/libass/libass/wiki/Libass'-ASS-Extensions, checked 2026-10-24]
2840. **Encoding=-1 auto-detects RTL in libass** — libass-only: `Encoding -1` (style or `\fe`) detects the base direction and bidi-reorders the line; the mixed line rendered in correct RTL order. Use it only for lightly styled dialogue, never if VSFilter might play the file. **How:** `Style: UrduRTL,Noto Nastaliq Urdu,...,-1` (last field) (tested here 2026-10-24) [libass wiki: Libass' ASS Extensions, https://github.com/libass/libass/wiki/Libass'-ASS-Extensions, checked 2026-10-24]
2841. **Portable fix: Unicode isolates** — wrapping the whole line in RLI…PDI (U+2067…U+2069) and each Latin/number run in LRI…PDI (U+2066…U+2069) gave the correct order with ordinary `Encoding 1`. **How:** `re.sub(r"([A-Za-z0-9][A-Za-z0-9 .,:'-]*[A-Za-z0-9]|[A-Za-z0-9])", "⁦\\1⁩", text)` then `"⁧"+text+"⁩"` (tested here 2026-10-24) [Unicode UAX #9 rev 52, https://www.unicode.org/reports/tr9/, checked 2026-10-24]
2842. **An RLM alone did not fix it** — prefixing the line with U+200F RIGHT-TO-LEFT MARK left the mixed line in the wrong order in libass. **How:** use isolates (2841) or Encoding -1 (2840), not a single RLM (tested here 2026-10-24) [Unicode UAX #9 rev 52, https://www.unicode.org/reports/tr9/, checked 2026-10-24]
2843. **Know the bidi control characters** — LRI U+2066, RLI U+2067, FSI U+2068 (direction from first strong character), PDI U+2069 ends an isolate; LRM U+200E, RLM U+200F and ALM U+061C are invisible strong characters with local effect. **How:** keep a table of these in caption scripts; FSI is handy when a name's script is unknown [Unicode UAX #9 rev 52, https://www.unicode.org/reports/tr9/, checked 2026-10-24]
2844. **In HTML captions use markup, not control characters** — UAX #9 says markup should be used where available: `dir="rtl"` / CSS `direction:rtl; unicode-bidi:isolate` is the equivalent of RLI…PDI. **How:** in HyperFrames caption groups write `<div dir="rtl" lang="ur">…</div>` and wrap English names in `<bdi>` or `dir="ltr"` spans [Unicode UAX #9 rev 52, https://www.unicode.org/reports/tr9/, checked 2026-10-24]
2845. **WebVTT direction escapes** — cue text may use `&lrm;` and `&rlm;` (also `&amp;`, `&lt;`, `&gt;`, `&nbsp;`); `&` and `<` must be escaped in cues. **How:** in a `.vtt` write `&rlm;` before a line that starts with an English word inside Urdu text [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]

2847. **Check a font really covers Urdu** — fontconfig lists the languages a font file supports; Noto Nastaliq Urdu reported `ur`, `ps-pk`, `pa-pk`, `fa`. **How:** `fc-scan --format '%{lang}\n' NotoNastaliqUrdu.ttf | tr '|' '\n' | grep -x ur` (tested here 2026-10-24) [fc-scan, local fontconfig, 2026-10-24]

## WebVTT features worth knowing
2894. **VTT file skeleton** — optional BOM, `WEBVTT` (+ optional text after a space), a blank line, then optional STYLE/REGION/NOTE blocks, then cues; MIME `text/vtt`, UTF-8. A blank line inside a cue ends it. **How:** never leave an empty line between a cue's timing and its text when writing VTT by script [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2895. **VTT timestamps** — `mm:ss.ttt` or `hh:mm:ss.ttt` (hours may exceed two digits); start times must not go backwards; cues may overlap except in chapter tracks. **How:** use `.` before milliseconds (SRT uses `,`) when converting by hand [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2896. **Position a VTT cue** — cue settings `line` (number or %; `line:0` top, `line:-1` bottom), `position` (%), `size` (% width), `align` (start/center/end), `vertical` (rl/lr); lowercase, each once. **How:** `00:05.000 --> 00:10.000 line:0 position:20% size:60% align:start` puts a caption top-left to clear a lower third [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2897. **Roll-up regions** — a REGION block (`id`, `width`, `lines`, `regionanchor`, `viewportanchor`, `scroll:up`) makes cues scroll up inside a box; the spec's example gives two speakers their own 3-line region on each side. **How:** `REGION` / `id:fred` / `width:40%` / `lines:3` / `regionanchor:0%,100%` / `viewportanchor:10%,90%` / `scroll:up`, then `region:fred` on cues [W3C WebVTT, https://www.w3.org/TR/webvtt1/, checked 2026-10-24]
2898. **Speaker and language tags** — `<v Bob>` marks a voice, `<lang en-GB>` a language, `<c.class>` a class, plus `<i> <b> <u> <ruby>/<rt>`; STYLE blocks can match them with `::cue(v[voice="Bob"])` or `::cue(:lang(ur))`. **How:** in a web player give each speaker a colour with `::cue(v[voice="Ali"]) { color: yellow; }` [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2899. **What ::cue can style** — only colour, opacity, visibility, text-decoration, text-shadow, background, outline, font, line-height, white-space, ruby-position and text-combine-upright properties; backgrounds apply per cue. **How:** a readable web caption: `::cue { color: white; background-color: rgb(0 0 0 / 60%); }` [MDN ::cue, https://developer.mozilla.org/en-US/docs/Web/CSS/::cue, checked 2026-10-24]
2900. **STYLE blocks go before the first cue** — STYLE and REGION blocks must come before any cue; NOTE blocks can appear anywhere after the header. **How:** remember ffmpeg 6.1.1 drops every cue of a styled VTT (2737), so keep a STYLE-free copy for ffmpeg work [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]

## Accessibility law and standards (what "good captions" means)
2901. **FCC accuracy** — captions must match the spoken words (and lyrics) in order, without substituting proper names or paraphrasing unless time forces it, with correct spelling, punctuation, tense and numbers; intentional slang/grammar errors are mirrored; speaker IDs, music, sound effects and audience reaction are included. **How:** caption Whisper output verbatim, then fix names by hand rather than rewording [47 CFR 79.1(j)(2), https://www.ecfr.gov/current/title-47/part-79/section-79.1, checked 2026-10-24]
2902. **FCC synchronicity** — captions begin when the speech or sound begins, end about when it ends, and stay up long enough to be read. **How:** in-times from Whisper word starts, out-times checked by the QC pass (2884) [47 CFR 79.1(j)(2), https://www.ecfr.gov/current/title-47/part-79/section-79.1, checked 2026-10-24]
2903. **FCC completeness** — captioning runs from the beginning to the end of the programme. **How:** caption the outro/CTA too, not just the talking part [47 CFR 79.1(j)(2), https://www.ecfr.gov/current/title-47/part-79/section-79.1, checked 2026-10-24]
2904. **FCC placement** — captions must not block faces, featured text, graphics or credits, must be legibly sized, must not overlap each other, and must not run off the screen edge. **How:** move a caption to the top (`{\an8}`) while a lower third or on-screen text is up [47 CFR 79.1(j)(2), https://www.ecfr.gov/current/title-47/part-79/section-79.1, checked 2026-10-24]
2905. **WCAG 1.2.2: captions for prerecorded video (Level A)** — captions include dialogue, who is speaking and meaningful non-speech sounds; open (always visible) captions are a sufficient technique (G93). **How:** burned-in captions count for web accessibility if they also carry speaker IDs and sound cues [W3C WCAG 2.2 Understanding 1.2.2, https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html, checked 2026-10-24]
2906. **WCAG failure F8** — captions that omit some dialogue or important sound effects fail 1.2.2. **How:** compare caption word count with the Whisper transcript before delivery [W3C WCAG 2.2 Understanding 1.2.2, https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html, checked 2026-10-24]
2907. **Describe music, not just "music"** — WCAG's orchestra example identifies non-vocal music by title, movement and composer and adds a mood line between ♪. **How:** `[Orchestral Suite No. 3 in D major, Air]` / `♪ Calm melody with a slow tempo ♪` style labels [W3C WCAG 2.2 Understanding 1.2.2, https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html, checked 2026-10-24]

## DCMP Captioning Key
2908. **Mixed case, caps for shouting** — mixed case is preferred for readability; capitals are used for screaming or shouting. **How:** don't upper-case long accessible captions; keep ALL-CAPS for short social styles only [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2909. **DCMP duration limits** — captions at least 40 frames (1 second 10 frames) and at most 6 seconds (background-music notes excepted). **How:** QC with `min_s=1.33, max_s=6.0` for educational clients (2884) [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2910. **DCMP placement** — bottom two lines, left-aligned multi-line captions where possible, moved to the top if they'd cover names, faces, mouths or essential graphics; no more than two lines preferred; keep inside margins so characters and descenders aren't cut. **How:** ASS `Alignment 1`/`\an1` with MarginL for left-aligned blocks, `\an7` when moved up [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2911. **Place captions under the speaker** — dialogue goes under its speaker unless graphics interfere; an off-screen speaker's caption goes far left or right toward their position; a moving speaker keeps one placement. **How:** two simultaneous speakers as `{\an1}` and `{\an3}` events (rendered side by side here) (tested here 2026-10-24) [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2912. **DCMP presentation rate by level** — lower-level educational media at most 130 wpm, middle-level 140, upper-level 160, counting every word including speaker IDs and sound labels. **How:** words-per-minute = words / duration × 60 per caption in the QC script [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2913. **Borrow 15 frames** — DCMP reaches the target rate partly by starting or ending a caption up to 15 frames before or after its audio, which it says is hardly noticeable. **How:** before editing words, extend in/out times by up to 0.5 s at 30 fps where there is room [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2914. **DCMP line division** — break where speech pauses; don't separate a modifier from its word, don't split a prepositional phrase, don't end a line on a conjunction, and don't start a new sentence on the same line unless both are 1-2-word related sentences. **How:** put manual `\N` breaks in ASS (`\q2`) rather than trusting auto-wrap [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2915. **DCMP sound effects** — in brackets, lower case, naming the source unless it's clearly on screen ([coins jangling]); an onomatopoeia goes on the line under the described sound ([rain falling] / pitter-patter). **How:** keep a per-project list of sound labels in that form [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2916. **DCMP background music** — describe essential music in brackets (italic if off-screen) with performer/title when possible and objective mood words; non-essential music gets a ♪ in the upper right, never at the expense of dialogue; music under 5 seconds isn't captioned. **How:** a `{\an9}♪` event for background music in ASS [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2917. **DCMP lyrics** — lyrics verbatim, introduced by artist and title in brackets if the rate permits; ♪ at the start and end of each caption, ♪♪ at the end of the song's last line, with spaces inside the notes. **How:** `♪ And I can't wait to get\Non the road again ♪♪` [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]
2918. **DCMP speaker names** — when placement can't show who speaks, put the known name in parentheses on its own line; don't name someone before they are introduced; otherwise identify by what a hearing viewer knows, in inclusive language. **How:** `(Ahmed)\NWelcome back!` [DCMP Captioning Key, https://dcmp.org/captioningkey/print, checked 2026-10-24]

## BBC subtitle guidelines
2919. **BBC line length by platform** — broadcast Teletext allows 37 fixed-width characters; online, the line is limited by width: 68% of a 16:9 frame, 90% of 4:3, 1:1 and 9:16; 37 characters in a 75%-wide 16:9 region correspond to about 25 in a 90%-wide 9:16 region. **How:** for vertical reels plan about 25 characters per line [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2920. **Lines per subtitle by aspect** — up to two lines for 16:9, 4:3 and 1:1; up to three lines for 9:16 vertical video. **How:** allow a third line only in portrait styles [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2921. **Minimum time per word** — at the recommended 160-180 wpm, aim for about 0.3 s per word (1.2 s for a 4-word subtitle), as a guide rather than a crude rule. **How:** QC warns when `duration < 0.3 × words` [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2922. **Sync limits** — when the speaker is in shot, don't anticipate speech by more than 1.5 s or hang on more than 1.5 s after it stops; never appear more than 2 s after the words; don't pre-empt a dramatic sound such as a bang. **How:** check `start - first_word_start` and `end - last_word_end` per cue against ±1.5 s [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2923. **Lips moving = text on screen** — a subtitle or label should be on screen whenever someone's lips are moving, even if that breaks timing conventions for slow speakers. **How:** don't leave caption gaps during long slow words; extend the cue [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2924. **Avoid straddling cuts** — a subtitle should not start mid-shot one and end mid-shot two; split or delay it, or merge two short shots' speech so it ends on the second cut. **How:** use scdet cut times (2779) to split cues at cuts [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2925. **Speaker colours** — in priority white, yellow (#FFFF00), cyan (#00FFFF), green (#00FF00), all on black; a speaker keeps one colour; the narrator is yellow by convention; mixed-colour speech in one subtitle runs on without new lines. **How:** ASS `\1c&H00FFFF&` (yellow) / `&HFFFF00&` (cyan) / `&H00FF00&` (green) per speaker [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2926. **Colour as a floater** — with many minor characters green may be reused for several who never appear together; white can be any number of speakers. **How:** assign yellow/cyan to the two main speakers and green to minor ones [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2927. **Off-screen speech** — single quotes mark an out-of-vision speaker (e.g. phone) when colour can't; labels in white caps only if it's unclear who speaks or more than four speakers share colours; simultaneous speech gets a white label like TOGETHER:. **How:** `'I'm outside.'` for a voice on the phone [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2928. **Caption size for landscape and vertical** — author font size to fit a line height of 7-8% of the active video height for 16:9, 4:3 and 1:1, and 3.9-4.5% for 9:16. **How:** 1080p landscape line height 76-86 px; 1080x1920 vertical 75-86 px (4.5% × 1920 = 86) [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2929. **Author in a wide font** — use a wide font (Reith Sans, Verdana, Tiresias) when authoring so a narrower presentation font never reflows lines; players may shrink (multipliers 0.6-0.8 on most screens, x1 on small phones) but never enlarge. **How:** when sizing soft-sub lines, test with a wide font such as DejaVu Sans [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2930. **BBC safe positioning** — 16:9 landscape: keep subtitles inside the central 90% vertically and 75% horizontally; 9:16: central 75% vertically and 90% horizontally; 4:3 and 1:1: central 90% both ways. **How:** for 1080x1920 keep captions between y 240 and y 1680 and x 54-1026 [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2931. **Vertical video: a little higher** — in 9:16 it is common to place subtitles a bit higher but still in the lower third, since faces sit in the top half. **How:** vertical ASS style with `Alignment 2` and `MarginV 600` on PlayRes 1080x1920 (rendered here) (tested here 2026-10-24) [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2932. **Move vertically for graphics, horizontally for people** — vertical displacement avoids on-screen captions/graphics; horizontal displacement indicates speakers or avoids a mouth when moving up would cover a face. **How:** lower third up → `\an8`; face above the lower third → shift sideways with `\an1`/`\an3` [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2933. **Prepared vs live alignment** — prepared subtitles are centre-aligned in a centred region; live (cued or cumulative) subtitles are normally left-aligned. **How:** keep edited reels centred [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2934. **Sarcasm, incredulity and stress** — sarcasm: `Charming(!)`; sarcastic question `(?)`; incredulous question `?!`; stressed words in caps used sparingly; shouting in caps. **How:** apply in English captions instead of extra styling [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2935. **Whispered speech** — a `WHISPERS:` label is most effective; when time is short put the words in brackets; for long whispers label the first subtitle only. **How:** `WHISPERS:\NDon't let him near you.` [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2936. **BBC sound-effect labels** — white caps, own line, placed left unless the sound clearly comes from the right; describe sounds not actions (GUNFIRE, not THEY SHOOT EACH OTHER); subject + active verb (FLOORBOARDS CREAK); don't label what can be subtitled. **How:** `{\an1}DOOR SLAMS` [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2937. **BBC music labels** — source music in caps (POP MUSIC ON RADIO); identifiable incidental music as `MUSIC: "Title"` (title in mixed case); unknown mood music only labelled when needed for the plot (EERIE MUSIC). **How:** use these as text events in `\an8` while dialogue runs [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2938. **BBC song lyrics** — every song subtitle starts with # (♫ allowed online) and the last has # at both ends; well-known lyrics are never edited; song lines are centred and follow the song's pace; `..` at the start if the song is joined mid-way, `...` at the end if it continues. **How:** `♫ ..Now I need a place to hide away` [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2939. **No emoji notes** — emoji such as 🎵 (U+1F3B5) must not be used; use ♫ (U+266B). **How:** `text.replace("\U0001F3B5", "♫")` in caption scripts [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2940. **Cumulative subtitles** — two or three parts appearing at different times with one out-time; for punchlines, quiz answers, backing singers or delayed responses; max three lines, not at a shot change, not over mouths. **How:** in ASS, a second event starting later at `\an2` with `MarginV` raised by one line height, same end time [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2941. **Bleeped words** — write BLEEP in caps, in a contrasting colour, without an exclamation mark. **How:** `{\1c&H00FFFF&}BLEEP{\r}` [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]
2942. **Children's subtitles: keep timings even** — avoid jumping between inconsistent timings (e.g. a 6 s then an 8 s two-liner of similar difficulty) and give more time when visuals matter. **How:** for kids' content compare neighbouring cue durations in QC [BBC Subtitle Guidelines, https://www.bbc.co.uk/accessibility/forproducts/guides/subtitles/, checked 2026-10-24]

## Netflix timing and SDH rules (beyond CPL/CPS)
2943. **Netflix duration window** — minimum 5/6 second per event (20 frames at 24 fps), maximum 7 seconds. **How:** QC with `min_s=5/6, max_s=7.0` (2884) [Netflix TTSG General Requirements, https://partnerhelp.netflixstudios.com/hc/en-us/articles/215758617, checked 2026-10-24]
2944. **"Half a second" scales with frame rate, the 2-frame gap doesn't** — the timing rules are written for 24 fps (12 frames); at 30 fps half a second is 15 frames, at 60 fps 30 frames, but the minimum gap stays 2 frames at every rate. **How:** in scripts use `half = 0.5` s and `gap = 2/fps` [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2945. **Don't chain past half a second of hang** — Netflix: if an out-time was already extended half a second beyond the end of the audio, don't extend it further to close a gap; re-segment, merge, or leave a gap of half a second or more (at 24 fps no 3-11 frame gaps may remain). **How:** in the gap closer (2885) skip cues where `a.end - last_word_end >= 0.5` and flag them for merging [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2946. **Pull the in-time back onto the cut** — if dialogue starts on a shot change or within half a second after it, the in-time goes on the first frame of the new shot (Netflix allows bringing in-times forward to sync with cuts). **How:** with scdet cut times (2779): `if 0 <= start - cut < 0.5: start = cut` [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2947. **Dialogue that crosses a cut** — a subtitle may cross a shot change only if the dialogue does; then its in-time must be at least half a second before the cut (or moved to the first frame after it), and its out-time either 2 frames before the cut or at least half a second after. **How:** move an in-time that lands less than half a second before a cut either onto the cut or to 0.5 s before it [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2948. **Reserve 20 frames for tiny lines** — no subtitle shorter than 20 frames, and that minimum is for one- or two-word lines; extend longer subtitles where possible. **How:** QC warning when a cue has > 2 words and lasts < 1 s [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2949. **Borrow time across neighbours** — when reading speeds are uneven, merge with the previous or next subtitle to even out the rhythm, then re-time to shot and audio without spoiling punchlines. **How:** merge two short cues whose combined CPS is under the limit [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2950. **Time on-screen-text translations to the text** — forced narratives for on-screen text mimic its timing; for text that fades, set in/out halfway through the fade. **How:** for a promo's title card, start the Urdu translation cue at the middle of the card's fade-in [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]
2951. **Forced narratives in English: ALL CAPS, never mixed with dialogue** — FNs for on-screen text are in caps (sentence case for long passages), never in the same subtitle as dialogue, and redundant FNs are deleted; an FN interrupting dialogue gets ellipses either side. **How:** `I don't think we should…` / `NO TRESPASSING` / `…go any further.` [Netflix English (USA) TTSG, https://backlothelp.netflix.com/hc/en-us/articles/217350977, checked 2026-10-24]
2952. **Positioning and on-screen text** — subtitles are centre-justified at the top or bottom; avoid overlapping on-screen text, and if text is at both top and bottom choose the easier-to-read place. **How:** `{\an8}` for the events that overlap a lower-third card [Netflix TTSG General Requirements, https://partnerhelp.netflixstudios.com/hc/en-us/articles/215758617, checked 2026-10-24]
2953. **SDH labels in US English** — brackets, all lower case except proper nouns, describe sounds not visuals, [man]/[woman] or [male voice] before a name is known, numbers for repeated IDs, and never italicise IDs or effects even in italic narration. **How:** `-[Kimmy] Are you coming?` / `-[Titus] In a minute.` [Netflix English (USA) TTSG, https://backlothelp.netflix.com/hc/en-us/articles/217350977, checked 2026-10-24]
2954. **Interruptions vs trail-offs** — two hyphens for an abrupt interruption by an action, sound or other speaker (`-What are you--`), an ellipsis for a trail-off or change of thought by the same speaker; no ellipsis when a sentence just continues into the next subtitle. **How:** QC that `--` only appears at line ends [Netflix English (USA) TTSG, https://backlothelp.netflix.com/hc/en-us/articles/217350977, checked 2026-10-24]
2955. **English lyric formatting** — italicise sung lyrics, ♪ at the start and end of each lyric subtitle with spaces, a capital at the start of every line, and only ? or ! at line ends; song titles in quotes, e.g. ["Forever Your Girl" playing]. **How:** `{\i1}♪ Line one\NLine two ♪{\i0}` [Netflix English (USA) TTSG, https://backlothelp.netflix.com/hc/en-us/articles/217350977, checked 2026-10-24]
2956. **English punctuation preferences** — no double spaces, no en or em dashes, avoid colons and semicolons, prefer "okay" over "OK", interrobang as `?!`. **How:** QC regexes for `  `, `[–—]`, `\bOK\b` on English files [Netflix English (USA) TTSG, https://backlothelp.netflix.com/hc/en-us/articles/217350977, checked 2026-10-24]
2957. **Censored audio** — dialogue is never censored unless the audio itself is dipped or bleeped; then use one asterisk per letter and only audible letters (f***, ****). **How:** match the bleep in the captions of client cuts that have it [Netflix English (USA) TTSG, https://backlothelp.netflix.com/hc/en-us/articles/217350977, checked 2026-10-24]
2958. **Promos and social cuts may read faster** — Netflix's marketing-asset guide allows reading speed above the normal limits to keep meaning and audio alignment (social viewers tolerate dense, fast subtitles), forbids condensing punchlines/taglines/iconic lines, and says not to condense if the full line fits in the safe area. **How:** for the owner's promos keep near-verbatim captions and only split them [Netflix TTSG Supplementals & Marketing, https://backlothelp.netflix.com/hc/en-us/articles/115000239632, checked 2026-10-24]
2959. **Marketing subs live at the bottom, inside the safe area** — for marketing assets subtitles are not placed at the top (they get repositioned to the bottom), translations must stay fully inside the prescribed safe area, and song lyrics are left out unless instructed. **How:** keep promo captions in one bottom band and skip lyric captions on music beds [Netflix TTSG Supplementals & Marketing, https://backlothelp.netflix.com/hc/en-us/articles/115000239632, checked 2026-10-24]
2960. **EBU R 95 safe areas** — all graphics inside the Graphics Safe Area (5% in from top, bottom and each side) and essential action inside the Action Safe Area (3.5%). **How:** on 1920x1080 keep captions at least 96 px from the sides and 54 px from top/bottom (5% of each dimension) [EBU R 95 v1.1, https://tech.ebu.ch/docs/r/r095.pdf, checked 2026-10-24]
