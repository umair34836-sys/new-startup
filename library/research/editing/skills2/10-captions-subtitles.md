# Captions and subtitles
Scope: captions and subtitles in all styles - SRT/VTT/ASS/TTML/LRC files, soft tracks in MP4/MKV/HLS, ASS styling and karaoke tags, libass burn-in with ffmpeg, Whisper word timing, social caption styles, Urdu/Nastaliq RTL and Hindi/Devanagari shaping, bilingual subs, and accessibility rules (Netflix, BBC, DCMP, FCC, WCAG, Apple, EBU safe areas). Not general kinetic type (file 09).
Researched 2026-10-24 via agent-reach (Exa) web search (rate-limited, so WebSearch was used only to find URLs), official docs read with curl/pandoc, and local tests with ffmpeg 6.1.1 (libass 0.17.1 + HarfBuzz + FriBidi + libunibreak), openai-whisper 20250625 (small model, /home/user/tools/venv) and pysubs2 1.9.0 (pure-Python, installed with `pip --target` into the scratch folder only). Test clips: `testsrc2`/`color` lavfi sources and Whisper's public-domain test file `jfk.flac`. Fonts for tests: Noto Nastaliq Urdu, Noto Naskh Arabic, Noto Sans Devanagari (OFL, google/fonts) in the scratch folder, plus library/fonts (Kalam, Rozha One, Anton).

## Formats: convert and repair caption files
2721. **SRT to WebVTT in one command** — ffmpeg picks the WebVTT muxer from the `.vtt` extension and writes the `WEBVTT` header, keeping `<i>`/`<b>`. **How:** `ffmpeg -i s.srt s.vtt` (tested here 2026-10-24) [ffmpeg -h muxer=webvtt, local ffmpeg 6.1.1, 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2722. **WebVTT back to SRT** — the reverse conversion works the same way when a platform wants SRT. **How:** `ffmpeg -i s.vtt s.srt` (tested here 2026-10-24) [ffmpeg -h muxer=srt, local ffmpeg 6.1.1, 2026-10-24]
2723. **SRT to ASS keeps basic markup** — on conversion ffmpeg turned `<i>` into `{\i1}`, `<b>` into `{\b1}`, `<font color="#ff0000">` into `{\c&HFF&}` (ASS colours are BGR) and kept an inline `{\an8}`. **How:** `ffmpeg -i s.srt s.ass`, then style the `.ass` (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2724. **Fix the header ffmpeg writes into a converted ASS** — ffmpeg's generated ASS had `PlayResX: 384`, `PlayResY: 288`, `Fontsize 16` and no LayoutRes; the libass guide says new files should set PlayRes and LayoutRes to the video's display size. **How:** after `ffmpeg -i in.srt out.ass`, edit `[Script Info]` to `PlayResX: 1920` `PlayResY: 1080` `LayoutResX: 1920` `LayoutResY: 1080` and scale Fontsize to match (tested here 2026-10-24, header observed) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2725. **ASS back to SRT** — ffmpeg converts `\i1`/`\b1`/`\c` back to `<i>`/`<b>`/`<font color>`, but a position tag like `{\an8}` stays in the text as a brace block. **How:** `ffmpeg -i s.ass s.srt` and check the result for leftover `{...}` (tested here 2026-10-24) [ffmpeg -h muxer=srt, local ffmpeg 6.1.1, 2026-10-24]
2726. **LRC lyrics file from an SRT** — ffmpeg's LRC muxer takes a subrip/text stream and writes `[mm:ss.xx]` lines, but it copied `<i>`/`<font>` tags into the LRC, so strip markup first; 6.1.1 has no `precision` option (the current docs list one for newer builds). **How:** `ffmpeg -i lyrics.srt lyrics.lrc` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#lrc, checked 2026-10-24]
2727. **TTML/DFXP from an SRT** — ffmpeg 6.1 has a TTML muxer/encoder; its output sets `ttp:cellResolution="384 288"` and a bottom `Default` region in Arial. **How:** `ffmpeg -i s.srt s.ttml` (tested here 2026-10-24) [ffmpeg -h muxer=ttml, local ffmpeg 6.1.1, 2026-10-24] [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24]
2728. **YouTube SBV to SRT** — YouTube's SubViewer `.sbv` uses `0:00:00.500,0:00:01.500` times with no counter; ffmpeg reads it when the subviewer demuxer is forced. **How:** `ffmpeg -f subviewer -i captions.sbv captions.srt` (tested here 2026-10-24) [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24]
2729. **Don't try to make SCC from SRT in ffmpeg** — the SCC format only carries EIA-608 data; ffmpeg 6.1.1 refused `-i s.srt s.scc` ("Output file does not contain any stream"). **How:** deliver SRT/VTT instead, or use a dedicated 608 tool (needs a 608 encoder (missing)) (tested here 2026-10-24, failure confirmed) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#mcc, checked 2026-10-24]
2730. **YouTube's basic formats are plain** — for SRT and SBV YouTube supports only basic files: no style markup is recognised and the file must be plain UTF-8. **How:** for YouTube uploads export SRT with `pysubs2 --clean` (removes styling) and save UTF-8 (tested here 2026-10-24) [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24] [pysubs2 CLI, https://pysubs2.readthedocs.io/en/latest/cli.html, checked 2026-10-24]
2731. **YouTube advanced formats** — YouTube's WebVTT support handles positioning but only `<b>`, `<i>`, `<u>` styling; TTML is partial (iTT supported), SAMI/RealText take simple markup without positioning, and SCC is the preferred broadcast format. **How:** if a YouTube caption must sit at the top, upload a `.vtt` with a `line:0` cue setting rather than an SRT [YouTube Help, https://support.google.com/youtube/answer/2734698, checked 2026-10-24]
2732. **A UTF-8 BOM doesn't break ffmpeg** — an SRT starting with the BOM bytes `EF BB BF` converted cleanly. **How:** `ffmpeg -i bom.srt bom.vtt` (tested here 2026-10-24) [libass wiki: ASS File Format Guide (BOM advice for ASS), https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2733. **Read a sloppy SRT** — an SRT with no cue numbers and `.` instead of `,` before the milliseconds parsed when the format was forced, and was written back as a clean numbered SRT. **How:** `ffmpeg -f srt -i loose.srt clean.srt` (tested here 2026-10-24) [ffmpeg -h demuxer=srt, local ffmpeg 6.1.1, 2026-10-24]
2734. **Legacy Arabic/Urdu code page to UTF-8** — `sub_charenc` sets the input subtitle character encoding; a Windows-1256 SRT came out byte-identical to the UTF-8 original (apart from a final newline). **How:** `ffmpeg -sub_charenc CP1256 -i old.srt fixed.srt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-codecs.html#Codec-Options, checked 2026-10-24]
2735. **Burn a legacy-encoded file without converting** — the `subtitles` filter's `charenc` option; the CP1256 burn was pixel-identical (same md5) to the UTF-8 burn. **How:** `ffmpeg -i in.mp4 -vf "subtitles=old.srt:charenc=CP1256" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2736. **Shift a whole subtitle file with -itsoffset** — the offset is added to the input timestamps; a cue at 0.500 s became 2.000 s with `-itsoffset 1.5` and no re-typing. **How:** `ffmpeg -itsoffset 1.5 -i s.srt -c copy shifted.srt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2737. **ffmpeg loses every cue after a WebVTT STYLE block** — a `.vtt` with a `STYLE` block produced an empty output in ffmpeg 6.1.1, while the same file loaded fully in pysubs2; a `NOTE` block alone was fine. **How:** convert styled VTT with `python3 -m pysubs2 --to srt in.vtt` instead of ffmpeg (tested here 2026-10-24) [MDN, https://developer.mozilla.org/en-US/docs/Web/API/WebVTT_API/Web_Video_Text_Tracks_Format, checked 2026-10-24]
2738. **ffmpeg drops WebVTT cue settings** — `line:0 position:20% align:start` disappeared on a VTT to VTT copy and on VTT to ASS; `<v Bob>` and `<c.loud>` tags were stripped to plain text. **How:** keep positioned VTT as the master file; to burn it, re-create the position as `{\an7\pos(x,y)}` in ASS (tested here 2026-10-24) [W3C WebVTT, https://www.w3.org/TR/webvtt1/, checked 2026-10-24]
2739. **List the subtitle tracks in a file** — ffprobe can print each subtitle stream's index, codec and language tag. **How:** `ffprobe -v error -select_streams s -show_entries stream=index,codec_name:stream_tags=language -of csv=p=0 in.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Stream-specifiers, checked 2026-10-24]
2740. **Extract one subtitle track** — map the subtitle stream by type index and give an `.srt` name. **How:** `ffmpeg -i in.mkv -map 0:s:1 urdu.srt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Stream-selection, checked 2026-10-24]
2741. **Drop all subtitle tracks** — `-sn` as an output option disables subtitle mapping, so a client copy carries no stray tracks. **How:** `ffmpeg -i in.mkv -map 0 -sn -c copy clean.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Subtitle-options, checked 2026-10-24]

## pysubs2 (Python) for batch caption work
2742. **pysubs2 basics** — pure-Python, MIT library that reads SRT, ASS/SSA, MicroDVD, MPL2, TMP, WebVTT, TTML and SAMI into an ASS-based model; times are int milliseconds. **How:** `pip install --target <scratch>/pylib pysubs2` then `subs = pysubs2.load("s.srt"); subs.save("s.ass")` (tested here 2026-10-24) [pysubs2 docs, https://pysubs2.readthedocs.io/en/latest/, checked 2026-10-24]
2743. **Retime by a constant** — `SSAFile.shift()` takes h/m/s/ms or frames+fps; negative times are treated as zero on export. **How:** `subs.shift(s=1.5)` moved 0.5 s to 2.0 s (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2744. **Fix subs made for another frame rate** — `transform_framerate(in_fps, out_fps)` rescales all times. **How:** `subs.transform_framerate(25, 23.976)` moved 500 ms to 521 ms (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24]
2745. **Times from frames** — `pysubs2.make_time(frames=50, fps=25)` returns 2000 ms; `pysubs2.time.ms_to_frames(1000, 30)` returns 30. **How:** use these in timing scripts instead of hand maths (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24]
2746. **Text without tags** — `SSAEvent.plaintext` hides override tags and turns `\N` into newlines (writing to it throws tags away). **How:** `[e.plaintext for e in subs]` gave `Hello world, this is line one` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2747. **One model, many outputs** — `to_string()`/`save()` write vtt, ass, json, tmp, mpl2, ttml and (with `fps=`) microdvd from the same object. **How:** `subs.to_string("ttml")` (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24]
2748. **Pass unknown encodings through untouched** — `errors="surrogateescape"` lets you retime or convert a non-UTF-8 file without knowing its encoding; a CP1256 file kept its exact Arabic bytes. **How:** `subs = pysubs2.load("old.srt", errors="surrogateescape"); subs.save("old_fixed.srt", errors="surrogateescape")` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2749. **Sort events by time** — `SSAFile.sort()` orders events chronologically (events compare by time). **How:** after appending cues out of order, `subs.sort()` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2750. **Strip drawings and karaoke junk** — `remove_miscellaneous_events()` removed a `{\p1}` drawing event (4 events to 3); the CLI `--clean` does the same and strips styling for non-SSA output. **How:** `python3 -m pysubs2 --to srt --clean in.ass` kept only the text line (tested here 2026-10-24) [pysubs2 API, https://pysubs2.readthedocs.io/en/latest/api-reference.html, checked 2026-10-24] [pysubs2 CLI, https://pysubs2.readthedocs.io/en/latest/cli.html, checked 2026-10-24]
2751. **Rename a style safely** — `rename_style(old, new)` also fixes every event that points to it. **How:** `subs.rename_style("top", "English")` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]
2752. **Batch convert and shift from the shell** — the pysubs2 CLI converts with `--to` and retimes with `--shift`/`--shift-back` ("1m30s", "0.5s"), writing to `-o DIR`. **How:** `python3 -m pysubs2 --to vtt *.srt -o out/` and `python3 -m pysubs2 --shift 0.5s s.srt -o shifted/` (tested here 2026-10-24) [pysubs2 CLI, https://pysubs2.readthedocs.io/en/latest/cli.html, checked 2026-10-24]
2753. **Bilingual subtitles, top and bottom** — pysubs2's own example puts one language in a `BOTTOM_CENTER` style and the other in a `TOP_CENTER` style in one ASS file. **How:** load `ur.srt` and `en.srt`, set `subs.styles = {"bottom": SSAStyle(fontname="Noto Nastaliq Urdu", alignment=Alignment.BOTTOM_CENTER), "top": SSAStyle(alignment=Alignment.TOP_CENTER)}`, append events with `e.style`, `subs.save("bi.ass")` (tested here 2026-10-24) [pysubs2 tutorial, https://pysubs2.readthedocs.io/en/latest/tutorial.html, checked 2026-10-24]

## Soft subtitle tracks in MP4, MKV and HLS
2754. **Soft subs in MP4 must be mov_text** — MP4 takes the 3GPP timed-text codec; add a language tag so players label the track. **How:** `ffmpeg -i in.mp4 -i s.srt -map 0 -map 1 -c copy -c:s mov_text -metadata:s:s:0 language=urd out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2755. **What mov_text keeps** — extracting back from MP4 kept `<i>` and `<b>` but lost the font colour and the `{\an8}` position. **How:** keep coloured/positioned captions as ASS (burn them) or MKV, not MP4 soft subs (tested here 2026-10-24) [ffmpeg -h encoder=mov_text, local ffmpeg 6.1.1, 2026-10-24]
2756. **Two languages in one MKV, choose the default** — set language per track and move the default flag; ffmpeg's own example clears `s:0` and sets `s:1` default. **How:** `ffmpeg -i v.mp4 -i en.srt -i ur.srt -map 0 -map 1 -map 2 -c copy -c:s srt -metadata:s:s:0 language=eng -metadata:s:s:1 language=urd -disposition:s:0 0 -disposition:s:1 default out.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2757. **Flag a forced-narrative track** — forced subtitles carry only the on-screen-text/foreign-dialogue lines; mark the track `forced` and give it a title. **How:** `-disposition:s:0 forced -metadata:s:s:0 title="Forced narrative"` (ffprobe showed forced=1) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24] [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2758. **Attach the fonts inside the MKV** — the libass guide says every font a script uses must exist and be attached to the release; Matroska needs a mimetype tag on the attachment. **How:** `ffmpeg -i in.mkv -map 0 -c copy -attach NotoNastaliqUrdu.ttf -metadata:s:t mimetype=application/x-truetype-font out.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24] [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2759. **Pull fonts out of someone's MKV** — `-dump_attachment:t ""` writes every attachment under its stored filename. **How:** `ffmpeg -dump_attachment:t "" -i in.mkv` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
2760. **Burn a track that lives inside the video file** — the `subtitles` filter can read from a container; `si` picks the subtitle stream. **How:** `ffmpeg -i in.mkv -vf "subtitles=in.mkv:si=1:fontsdir=fonts" out.mp4` (also worked on an MP4's mov_text track) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2761. **HLS with a WebVTT subtitle rendition** — the HLS muxer can segment a text stream as WebVTT and add `#EXT-X-MEDIA:TYPE=SUBTITLES` to the master playlist; `language:` in the var_stream_map adds `LANGUAGE=`. In 6.1.1 the `sname:` key from the current docs was rejected. **How:** `ffmpeg -i v.mp4 -i s.srt -map 0:v -map 0:a -map 1 -c:v copy -c:a copy -c:s webvtt -f hls -hls_time 1 -var_stream_map "v:0,a:0,s:0,sgroup:subs,language:eng" -master_pl_name master.m3u8 h_%v.m3u8` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#hls-2, checked 2026-10-24]
2762. **Check HLS WebVTT segments for X-TIMESTAMP-MAP** — Apple requires WebVTT segments to carry an X-TIMESTAMP-MAP header; ffmpeg 6.1.1's segments had none and a cue at 0.500 s was written as 0.567 s. **How:** `grep -L X-TIMESTAMP-MAP *.vtt` before delivering to Apple devices (tested here 2026-10-24) [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2763. **Apple: which caption formats** — Apple devices take CEA-608/708 captions, WebVTT subtitles and IMSC1 (text profile) subtitles; subtitles must be WebVTT text files or IMSC1 in fMP4, and the subtitle playlist must cover the whole programme. **How:** for an HLS delivery pick WebVTT unless the client asks for IMSC1 [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2764. **Apple: mark SDH tracks** — a subtitle track meant for deaf/hard-of-hearing viewers must have `CHARACTERISTICS="public.accessibility.transcribes-spoken-dialog,public.accessibility.describes-music-and-sound"`, `AUTOSELECT=YES` and a LANGUAGE attribute. **How:** edit the `#EXT-X-MEDIA` line of `master.m3u8` after ffmpeg writes it [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2765. **Apple: forced plus full subs** — if a language has forced and regular subtitles, the regular track must contain both; forced tracks should be AUTOSELECT=YES; and if a clean (no burnt text) version exists, forced subtitles should be used instead of burnt-in text. **How:** build the full track as forced lines + dialogue lines merged with `subs.sort()` [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]
2766. **Apple: codec strings** — use `stpp.ttml.im1t` for IMSC1 subtitles; `wvtt` may be used for WebVTT in the CODECS attribute. **How:** add it to `#EXT-X-STREAM-INF` CODECS when the player needs it [Apple HLS Authoring Spec, https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices, checked 2026-10-24]

## Burn-in with ffmpeg (libass)
2767. **Prefer the `ass` filter for burning ASS** — it is the subtitles filter without the libavcodec/libavformat conversion, limited to ASS files, and it is the one that exposes `shaping` in ffmpeg 6.1.1 (`ffmpeg -h filter=subtitles` lists no shaping option). **How:** `ffmpeg -i in.mp4 -vf "ass=caps.ass:fontsdir=library/fonts" -c:a copy out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2768. **The `subtitles` filter broke Hindi and Urdu here** — with ffmpeg 6.1.1, `subtitles=` rendered Devanagari with broken conjuncts (visible halant in नमस्ते, क्ष split) and Noto Nastaliq Urdu as empty boxes, even for an `.ass` input; the same text through `ass=` was correct. **How:** never burn Urdu/Hindi with `subtitles=`; convert first (next skill) (tested here 2026-10-24, frames inspected) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2769. **SRT in Urdu/Hindi: convert, then burn with `ass`** — converting the SRT to ASS and rendering with the `ass` filter gave correct conjuncts. **How:** `ffmpeg -i h.srt h.ass` → set Fontname (e.g. Noto Sans Devanagari) and PlayRes → `ffmpeg -i in.mp4 -vf "ass=h.ass:fontsdir=fonts" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2770. **Force complex shaping for scripts that need it** — `shaping=complex` uses OpenType substitution and positioning and is required for Arabic, Hebrew, Devanagari and Thai; `simple` only substitutes. On the same Hindi line `simple` and `complex` produced different frames, and only `complex`/`auto` joined the conjuncts. **How:** `-vf "ass=hi.ass:fontsdir=fonts:shaping=complex"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2771. **Use repo fonts without installing them** — `fontsdir` adds a folder of fonts to what the font provider already has. **How:** `-vf "ass=caps.ass:fontsdir=/home/user/new-startup/library/fonts"` rendered Kalam and Rozha One (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2772. **Prove which font file libass picked** — at `-v verbose` the filter logs `fontselect: (Noto Nastaliq Urdu, 400, 0) -> NotoNastaliqUrdu-Regular`; a silent fallback font is the usual cause of tofu. **How:** `ffmpeg -v verbose -i in.mp4 -vf "ass=u.ass:fontsdir=fonts" -frames:v 1 -f null - 2>&1 | grep fontselect` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2773. **original_size only matters when the aspect changes** — the docs say it is needed to scale fonts correctly if the aspect ratio was changed; on a same-aspect 640x360 to 1280x720 burn it made no difference (identical frames). **How:** `subtitles=s.srt:original_size=640x360` only after anamorphic or aspect changes (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2774. **Input seeking shifts burned subtitles** — with `-ss 1` before `-i`, timestamps restart at 0 and the filter shows the wrong cues (a cue at 0.5-1.5 s vanished from the first second). Shift the clock for the filter and back. **How:** `ffmpeg -ss 1 -i in.mp4 -vf "setpts=PTS+1/TB,subtitles=s.srt,setpts=PTS-STARTPTS" out.mp4` showed the cue correctly (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts, checked 2026-10-24]
2775. **Transparent caption layer for compositing** — render captions onto a fully transparent canvas with `alpha=1` and keep alpha in the codec (qtrle wrote argb). **How:** `ffmpeg -f lavfi -i "color=c=black@0.0:s=1920x1080:r=30:d=10,format=rgba" -vf "ass=caps.ass:alpha=1" -c:v qtrle caps.mov` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2776. **Caption-only or lyric video** — burn the ASS onto a colour source and add the audio. **How:** `ffmpeg -f lavfi -i color=c=black:s=1080x1920:r=30:d=11 -i voice.flac -vf "ass=caps.ass" -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac lyric.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#ass, checked 2026-10-24]
2777. **Darken the caption band before burning** — a filled semi-transparent `drawbox` under the text (CLAUDE.md: put captions over a darker lower part of the frame). **How:** `-vf "drawbox=x=0:y=ih*0.7:w=iw:h=ih*0.3:color=black@0.5:t=fill,subtitles=s.srt"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawbox, checked 2026-10-24] [repo: CLAUDE.md "HyperFrames learnings"]
2778. **force_style colours carry alpha** — `force_style` takes ASS `KEY=VALUE` pairs; the docs' example `PrimaryColour=&HCCFF0000` is 80% transparent blue (AABBGGRR). **How:** `subtitles=s.srt:force_style='Fontname=DejaVu Serif,PrimaryColour=&HCCFF0000'` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#subtitles-1, checked 2026-10-24]
2779. **Find the cuts to time captions against** — `scdet` logs `lavfi.scd.time` at each scene change; a red/blue cut at 1.3 s (24 fps) was found at 1.33333 s. Feed these times to the shot-change rules below. **How:** `ffmpeg -i in.mp4 -vf "scdet=threshold=10,metadata=print:key=lavfi.scd.time" -f null - 2>&1 | grep scd.time` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#scdet-1, checked 2026-10-24]
2780. **Snap caption edges to cuts like Aegisub's keyframe snapping** — Aegisub moves a line start onto a keyframe when it is within a threshold, and an end to the frame before the keyframe; its post-processor applies lead-in/out first, then joins adjacent lines, then snaps. **How:** in Python, for each cut time `c` from scdet: if `0 <= c - start < 0.5` set `start = c`; if `0 <= c - end < 0.5` set `end = c - 2/fps` [Aegisub manual: Timing Post-Processor, https://aegisub.org/docs/latest/timing_post-processor/, checked 2026-10-24] [Netflix Subtitle Timing Guidelines, https://backlothelp.netflix.com/hc/en-us/articles/360051554394, checked 2026-10-24]

## drawtext captions (no subtitle file)
2781. **drawtext is fine for Arabic Naskh, not for Urdu Nastaliq or Hindi** — `text_shaping` (needs FriBidi) reverses RTL text and joins Arabic letters: Noto Naskh Arabic came out joined and right-to-left, but Noto Nastaliq Urdu showed boxes and Devanagari conjuncts broke. **How:** use drawtext only for Latin/Naskh text; burn Urdu and Hindi with the `ass` filter (tested here 2026-10-24, frames inspected) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2782. **Put caption text in a file** — drawtext's text needs up to four levels of escaping; `textfile` avoids that and must be UTF-8. **How:** `printf 'مرحبا 123' > line.txt` then `drawtext=fontfile=NotoNaskhArabic.ttf:textfile=line.txt:fontsize=36:fontcolor=white:x=(w-tw)/2:y=h-120` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2783. **Live-updating caption from a file** — `reload=N` re-reads the textfile every N frames; update the file atomically or it may be read half-written. **How:** `drawtext=fontfile=DejaVuSans.ttf:textfile=live.txt:reload=1:fontsize=30:fontcolor=white:x=20:y=20` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2784. **Time a drawtext line with `enable`** — timeline editing evaluates `enable` per frame (with `t` in seconds); outside the window the frame passes unchanged. **How:** `drawtext=...:text='Timed line':enable='between(t,1,2)'` showed the text at 1.5 s and not at 0.5 s (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]
2785. **Change the words mid-clip with sendcmd** — drawtext's `reinit` command re-sets options (text, fontsize...) at a given time. **How:** a command file `1.0 drawtext reinit text=Second;` with `-vf "sendcmd=f=cmds.txt,drawtext=fontfile=DejaVuSans.ttf:text=First:fontsize=30:fontcolor=white:x=20:y=300"` switched the text at 1 s (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2786. **Asymmetric box padding** — `boxborderw` takes 1-4 values; `8|24` pads 8 px top/bottom and 24 px left/right for a wide caption pill. **How:** `drawtext=...:box=1:boxcolor=black@0.7:boxborderw=8|24` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2787. **Fixed caption box with centred lines** — `boxw`/`boxh` fix the box size and `text_align` places the text inside it; in 6.1.1 the flags are joined with `+` (`M+C`), the docs' `MC` form was rejected. **How:** `drawtext=...:textfile=two.txt:box=1:boxw=500:boxh=100:text_align=M+C:line_spacing=8:x=(w-500)/2:y=h-130` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]
2788. **fix_bounds pulls text back on screen, within limits** — with `fix_bounds=1` text placed off the bottom-right moved up and left into the frame, but a line wider than the frame still overflowed. **How:** add `:fix_bounds=1`, and still wrap long lines yourself (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#drawtext-1, checked 2026-10-24]

## ASS script structure (libass best practice)
2789. **Minimum header for a portable ASS** — `ScriptType: v4.00+` is required; the guide also wants `ScaledBorderAndShadow`, `YCbCr Matrix`, `PlayResX/Y` and `LayoutResX/Y`, sections in order with `[Events]` last, UTF-8 (BOM recommended). **How:** start every file from the guide's example header (`ScaledBorderAndShadow: yes`, `YCbCr Matrix: None`, PlayRes = LayoutRes = video size); every test file here used it (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2790. **ScaledBorderAndShadow: yes, always** — the guide says `no` has no benefit and only exists for backward compatibility; with `yes` border and shadow sizes are in script pixels. **How:** keep `ScaledBorderAndShadow: yes` in `[Script Info]` [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24] [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2791. **Set YCbCr Matrix to match the video** — for BT.601/BT.709 video set exactly `TV.709` (or `TV.601`, `PC.*` for full range), otherwise `None`; a missing header is read as TV.601, which mangles colours on modern HD video in VSFilter-style renderers. **How:** for normal phone/YouTube HD footage use `YCbCr Matrix: TV.709` (or `None`) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24] [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2792. **Script resolution is a coordinate system** — font sizes, margins, `\pos`, clips and drawings are in PlayRes units, independent of the video size; it only needs the same aspect as the video (1280x720 is fine for 1920x1080, 1440x1080 is not). **How:** author vertical reels at `PlayResX: 1080 PlayResY: 1920` so numbers equal pixels [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24]
2793. **LayoutRes keeps blur and 3D rotation consistent** — `\blur`, the 3D-rotation focal length and text widths scale with Layout Resolution; set it so the file renders the same at any size, with the same aspect as PlayRes. **How:** `LayoutResX`/`LayoutResY` = display size of the source video [Aegisub manual: Resolution and Matrix, https://aegisub.org/docs/latest/resolution_and_matrix/, checked 2026-10-24] [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2794. **Pick the wrap mode** — 0 balances line lengths (top wider), 1 fills the first line then breaks, 2 never wraps (only `\N`/`\n` break). Rendered: `\q0` and `\q1` broke the same 60-character line at different words, `\q2` ran off both edges. **How:** global `WrapStyle: 0` for dialogue, `{\q2}` plus manual `\N` for styled social captions (tested here 2026-10-24) [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2795. **Don't use wrap mode 3** — VSFilter's mode 3 (bottom line wider) is unsupported in libass and treated as 0; the guide says use `\q2` with explicit `\N` for a specific break shape. **How:** for a bottom-heavy two-liner write the break yourself: `{\q2}Short top\Nlonger bottom line` [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2796. **Style line rules** — booleans are `-1`/`0`, colours are `&HAABBGGRR` (alpha 00 opaque, FF invisible), `Encoding` must be `1` (see the libass RTL exception below), Fontname ≤ 31 characters, Fontsize ≤ 511 (scale with tags instead). **How:** `Style: Default,DejaVu Sans,32,&H00FFFFFF,&H000000FF,&H00000000,&H80000000,-1,0,0,0,100,100,0,0,1,2,1,2,20,20,24,1` (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2797. **No letter Spacing on Urdu/Hindi styles** — the guide says Spacing is not advisable with scripts that depend on complex shaping. **How:** keep `Spacing` 0 and no `\fsp` on Nastaliq/Devanagari styles [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2798. **Event times are h:mm:ss.cc** — exactly two digits for minutes, seconds and centiseconds; start is inclusive and end exclusive. **How:** write times with a helper such as `f"{h}:{m:02d}:{s:02d}.{cs:02d}"` (used by the generators below) (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2799. **Layers decide what sits on top** — lower `Layer` values are drawn behind higher ones; a Layer 1 yellow "TOP" drew over a larger Layer 0 "BOTTOM". **How:** box/drawing events on Layer 0, text on Layer 1 (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2800. **Overlapping lines stack themselves** — two unpositioned events in the same style that overlap in time were stacked (the later one above), not drawn over each other; events on different Layers never count as colliding. **How:** to keep two speakers apart use `\an1`/`\an3` or `\pos`, otherwise let libass stack them (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2801. **Comment lines and inline comments** — `Comment:` events are never rendered (frame identical to the bare video); unknown text inside `{}` is silently ignored, so `{note}` works as an inline comment. **How:** keep alternate takes as `Comment:` lines in the master ASS (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24] [Aegisub manual: ASS Override Tags, https://aegisub.org/docs/latest/ass_tags/, checked 2026-10-24]
2802. **Name field = speaker label for you, not the viewer** — the `Name` field is free metadata for who speaks and does not affect rendering. **How:** fill Name with the speaker so a script can colour or position by speaker later [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2803. **Built-in ticker and credit roll** — the Effect field `Banner;delay` scrolls text sideways (lower delay = faster) and `Scroll up;y1;y2;delay` rolls it up between two y limits. **How:** `Dialogue: 0,0:00:00.00,0:00:03.00,Default,,0,0,0,Scroll up;40;320;10,Credits roll up` (tested here 2026-10-24) [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
2804. **Don't use the VSFilter fadeaway effect argument or \fe** — the optional `fadeaway` effect parameter is not supported by libass and must not be used; `\fe` must not be used at all. **How:** do fades with `\fad`, and fonts by name, never by encoding [libass wiki: ASS File Format Guide, https://github.com/libass/libass/wiki/ASS-File-Format-Guide, checked 2026-10-24]
