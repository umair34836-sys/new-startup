# After Effects and mobile-app effects translated to HyperFrames, GSAP and ffmpeg

Scope: effects people know from After Effects, CapCut, Alight Motion, VN and InShot (velocity/speed curves, shake, glow, RGB split, glitch, datamosh, VHS bits, zoom/spin/directional blur, motion blur, echo/trails, mirror/kaleidoscope/tiles, pixel sort, mosaic, freeze-cutout, 3D camera, flicker/strobe, beat-synced effects) and how to rebuild each one here. Plain colour work is in files 02/03.
Researched 2026-10-24 via agent-reach (Exa) web search, official docs and local tests.

Notes for this file: Exa search was rate-limited for the whole session, so URLs were found with WebSearch and every page was then opened and read here (headless Chromium via Playwright, or curl); only text that was on the page is cited. "Tested here" lines were run on this container's ffmpeg 6.1.1 with synthetic 640x360/30 fps clips (testsrc2, mandelbrot, a moving white square), GSAP 3.14.2 under Node 22 and numpy/Pillow scripts; the full list and pass/fail log is in the session scratchpad (`sk2_12/t/tests.py`, `results.json`: 128 ffmpeg commands, 127 pass; the one failure is the inline sendcmd [expr] form, kept on purpose and noted in its line), plus Node GSAP checks (`t/py/gsap_test*.js`), numpy scripts (`t/py/`) and one headless-Chromium CSS/SVG page (`t/py/css_test.html`). "Tested" means the command ran and wrote a non-empty file of the right length; where a number is given it was measured on the output. Nobody looked at or judged the look of most outputs: a mapping from an AE/Alight/CapCut control to a filter option is ours, built from the two documents cited, and is a starting point, not a pixel match. ffmpeg doc links are the current (8.x) pages; where local 6.1 differs the line says so.

## Velocity edits and speed curves (CapCut, VN, InShot, AE, Alight)

3201. **CapCut speed limits in ffmpeg terms** — CapCut's Normal speed slider runs 0.1x to 100x; its Curve (velocity) graph runs from 0.1x (bottom) to 10x (top). **How:** speed s = `setpts=PTS/s`; 0.1x: `ffmpeg -i in.mp4 -vf "trim=0:0.3,setpts=10*(PTS-STARTPTS)" -an out.mp4`; trim first so a 10x slow-down doesn't make a huge file (tested here 2026-10-24) [Shotkit, https://shotkit.com/velocity-capcut/, checked 2026-10-24] [CapCut, https://www.capcut.com/resource/how-to-do-velocity-on-capcut, checked 2026-10-24]
3202. **"Keep Pitch" = atempo, chained past 2x** — CapCut's Keep Pitch keeps the voice pitch when speeding up; ffmpeg's atempo does the same, accepts 0.5-100, but above 2 it skips samples, so chain instances. **How:** 4x with pitch kept: `ffmpeg -i in.mp4 -filter_complex "[0:v]setpts=PTS/4[v];[0:a]atempo=2,atempo=2[a]" -map "[v]" -map "[a]" out.mp4` (tested here 2026-10-24) [Shotkit, https://shotkit.com/velocity-capcut/, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atempo, checked 2026-10-24]
3203. **Name the CapCut curve preset the client means** — CapCut's Speed > Curve templates are Montage, Hero, Bullet, Jump Cut, Flash In and Flash Out (plus Custom), and each can be opened with Edit to adjust. **How:** when a client says "Hero curve" or "Bullet", ask for a reference clip or rebuild it as a fast-slow-fast segment list (next skill) and show them; don't guess the preset's shape from its name. [Shotkit, https://shotkit.com/velocity-capcut/, checked 2026-10-24] [CapCut, https://www.capcut.com/tools/speed-ramp, checked 2026-10-24]
3204. **Custom velocity curve as a segment list** — in CapCut's Custom curve, dragging a point sideways sets how long the effect lasts and up/down sets the pace (top speeds up, bottom slows down). **How:** write the curve as (start, end, speed) rows and concat: `ffmpeg -i in.mp4 -filter_complex "[0:v]trim=0:0.6,setpts=(PTS-STARTPTS)/3[a];[0:v]trim=0.6:1.0,setpts=(PTS-STARTPTS)*2[b];[0:v]trim=1.0:2,setpts=(PTS-STARTPTS)/3[c];[a][b][c]concat=n=3:v=1:a=0,fps=30" out.mp4` (3x, 0.5x, 3x) (tested here 2026-10-24) [CapCut, https://www.capcut.com/resource/how-to-do-velocity-on-capcut, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#concat, checked 2026-10-24]
3205. **"Smooth slow mo" only where the clip is slow** — CapCut's custom curve has a "Smooth slow mo" checkbox for the point you want to emphasise. **How:** interpolate only the slow segment: in the segment list above make the middle row `setpts=(PTS-STARTPTS)*3,minterpolate=fps=30:mi_mode=mci`; the fast rows need no interpolation (tested here 2026-10-24) [CapCut, https://www.capcut.com/resource/how-to-do-velocity-on-capcut, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3206. **CapCut "Style > Velocity" presets are effect + music** — the mobile Style > Velocity presets (flash, retro zoom, fade blur, blur shake, rainbow...) wait to detect music before applying. **How:** our equivalent is beat times first (`npx hyperframes beats`, file `beats/<audio>.json`), then one effect per beat (flash, zoom punch, blur pulse, hue cycle: see the beat section); we can't reproduce CapCut's exact presets, only the idea. [CapCut, https://www.capcut.com/resource/how-to-do-velocity-on-capcut, checked 2026-10-24] [repo: .claude/skills/hyperframes-cli/references/beats.md]
3207. **Velocity points sit on the music** — CapCut's own tip for syncing a velocity edit: add the track first, then place the curve's points where the speed should change, on the music. **How:** take the segment boundaries of the segment-list skill from the beat file (beat index × 60/BPM, rounded per index, never accumulated) [CapCut, https://www.capcut.com/resource/how-to-do-velocity-on-capcut, checked 2026-10-24] [repo: .claude/skills/hyperframes/references/motion.md]
3208. **VN and InShot have the same tool** — VN offers speed "presets or advanced curve-based speed ramps"; InShot offers speed control, "speed ramping" and "smooth slow-mo". **How:** a VN/InShot speed-ramp brief is the same job as a CapCut curve: build it with the segment list and minterpolate for the slow part. [VN on the App Store, https://apps.apple.com/us/app/vn-video-editor/id1343581380, checked 2026-10-24] [InShot on the App Store, https://apps.apple.com/in/app/inshot-ai-video-editor/id997362197, checked 2026-10-24]
3209. **Forward, back, forward (time-remap rewind)** — AE time remapping can play a walk forward, a few frames backward ("the person retreats"), then forward again. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]trim=0:1,setpts=PTS-STARTPTS[a];[0:v]trim=0.6:1,setpts=PTS-STARTPTS,reverse[b];[0:v]trim=0.6:2,setpts=PTS-STARTPTS[c];[a][b][c]concat=n=3:v=1:a=0" out.mp4` (reverse only the short middle piece: reverse buffers it in memory) (tested here 2026-10-24) [Adobe AE Help "Time-stretching and time-remapping", https://helpx.adobe.com/after-effects/using/time-stretching-time-remapping.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#reverse, checked 2026-10-24]
3210. **Read a speed graph: height is speed** — in AE's speed graph level lines are constant speed and higher means faster; in the motion path, wider dot spacing means faster and Hold keys show no dots. **How:** to see a GSAP ease as a speed graph, sample its slope: `const e=gsap.parseEase('power3.out'); speed_i=(e((i+1)/10)-e(i/10))*10` gave 3.44 2.47 1.70 ... 0.00 (fast start, dead stop) (tested here 2026-10-24) [Adobe AE Help "Speed", https://helpx.adobe.com/after-effects/using/speed.html, checked 2026-10-24] [GSAP docs, https://gsap.com/docs/v3/GSAP/gsap.parseEase(), checked 2026-10-24]
3211. **Alight curve axes: slope = speed** — in Alight Motion's curve editor the X axis is project time, Y is the remapped animation time, the slope is the speed (steeper = faster), and there is one curve per pair of keyframes (keyframes − 1). **How:** read a client's Alight screenshot the same way as a GSAP ease graph; in GSAP give each segment its own ease (separate tweens or per-keyframe eases). [Alight Motion Help "Animation Easing Curves", https://support.alightmotion.com/hc/en-us/articles/10536934703889-Animation-Easing-Curves, checked 2026-10-24]
3212. **"Paste Curve to All Keyframes" = timeline defaults** — Alight can paste one easing curve onto every keyframe pair of a property. **How:** GSAP `gsap.timeline({defaults:{ease:'power2.inOut',duration:1}})` pushes the ease into every child tween (child values still override); checked: x at 25% progress = 6.25 = power2.inOut(0.25)×100 (tested here 2026-10-24) [Alight Motion Help "Animation Easing Curves", https://support.alightmotion.com/hc/en-us/articles/10536934703889-Animation-Easing-Curves, checked 2026-10-24] [GSAP docs, https://gsap.com/docs/v3/GSAP/gsap.timeline(), checked 2026-10-24]
3213. **Alight "Cyclic" easing = wrapYoyo** — Alight's Cyclic easing repeats the progression between the two key values, back and forth or one way. **How:** for a value (or a frame index) that ping-pongs inside a span use `gsap.utils.wrapYoyo(0,3,i)` → 0,1,2,3,2,1,0,1,2 for i=0..8; plain cycling is `gsap.utils.wrap` (tested here 2026-10-24) [Alight Motion Help "Animation Easing Curves", https://support.alightmotion.com/hc/en-us/articles/10536934703889-Animation-Easing-Curves, checked 2026-10-24] [GSAP docs, https://gsap.com/docs/v3/GSAP/UtilityMethods/wrapYoyo(), checked 2026-10-24]
3214. **AE linear() = mapRange + clamp** — AE `linear(t, tMin, tMax, value1, value2)` maps t into a value range (e.g. `linear(time, 0, 6, 20, 80)`) and holds at the ends. **How:** `gsap.utils.clamp(20,80,gsap.utils.mapRange(0,6,20,80,t))` → 50 at t=3, 80 at t=9; mapRange alone does not clamp (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24] [GSAP docs, https://gsap.com/docs/v3/GSAP/UtilityMethods/mapRange(), checked 2026-10-24]
3215. **AE ease() = parseEase + interpolate** — AE `ease(t, tMin, tMax, value1, value2)` is the eased version of linear(). **How:** `const e=gsap.parseEase('sine.inOut'); v=gsap.utils.interpolate(v1,v2,e(clamp(0,1,(t-tMin)/(tMax-tMin))))` → 0, 50, 100 at t=0,1,2 for 0..2 s (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24] [GSAP docs, https://gsap.com/docs/v3/GSAP/gsap.parseEase(), checked 2026-10-24]
3216. **AE posterizeTime(fps) for one property** — `posterizeTime(1); random()` updates a property only once per second while the comp runs at full rate. **How:** in a GSAP/HyperFrames driver quantise the time you feed the formula: `tq=Math.floor(t*8)/8` (8 updates a second: 0.01→0, 0.13→0.125, 0.26→0.25) (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24]
3217. **Velocity-matched hard cut** — registry `cut-the-curve`: the outgoing subject accelerates with power4.in, the cut happens at peak velocity, and the incoming subject continues the same direction with power4.out. **How:** `npx hyperframes add cut-the-curve`, or by hand: last tween of shot A `ease:'power4.in'`, first tween of shot B `ease:'power4.out'`, same direction, cut between them. [HyperFrames registry `cut-the-curve` (`npx hyperframes catalog --json`), checked 2026-10-24]
3218. **Beat-driven ramp + freeze + cut block** — registry block `beat-freeze-cut` is "a beat-driven speed ramp, freeze-frame hit, and hard-cut sequence for music-led promos and montages". **How:** `npx hyperframes add beat-freeze-cut` and point its beats at the music's beat file instead of rebuilding the sequence. [HyperFrames registry `beat-freeze-cut` (`npx hyperframes catalog --json`), checked 2026-10-24]
3219. **Whip rail that overshoots and snaps** — registry `velocity-throw-snap`: a five-shot rail whips past on a fast decaying curve, overshoots and snaps the hero shot to centre. **How:** `npx hyperframes add velocity-throw-snap` for a "which one is it" product/feature pick. [HyperFrames registry `velocity-throw-snap` (`npx hyperframes catalog --json`), checked 2026-10-24]
3220. **"Never fully lands" arrival** — registry `extended-keyframe`: an element covers most of its move in the first fifth of the duration, creeps the rest to the last frame, exits along its arrival vector and carries shutter blur. **How:** `npx hyperframes add extended-keyframe` (it also exports the ease alone for any tween). [HyperFrames registry `extended-keyframe` (`npx hyperframes catalog --json`), checked 2026-10-24]
3221. **Full-frame whip with matched speed** — registry `whip-pan-cut`: scene A whips off with capped directional blur while B enters the same way at matched velocity on a speed-ramp profile; both ride one strip so seam velocity is exact. **How:** `npx hyperframes add whip-pan-cut`, fill its before/after slots. [HyperFrames registry `whip-pan-cut` (`npx hyperframes catalog --json`), checked 2026-10-24]

## Shake presets (AE wiggle, CapCut Shake, Alight Oscillate/Jitter)

3222. **AE wiggle(freq, amp) as a crop shake** — `wiggle(freq, amp)` shakes a property about freq times a second by about amp units; CapCut's Camera Shake has the same two controls (intensity, speed). **How:** overscan, then move the crop window with sines at roughly freq Hz: `ffmpeg -i in.mp4 -vf "scale=704:396,crop=640:360:'32+20*sin(2*PI*5*t)':'18+12*sin(2*PI*4.3*t+1)'" out.mp4` (two different frequencies so x and y never line up) (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24] [Miracamp, https://www.miracamp.com/learn/capcut/video-stabilization-camera-shake, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#crop, checked 2026-10-24]
3223. **Overscan = twice the shake amplitude** — crop's x must stay between 0 and in_w−out_w, so a ±A px shake needs A px of extra picture on each side. **How:** scale up by 2A first (640→704 for ±32, 360→396 for ±18) and centre the crop at x=A, y=A; registry `camera-shake` solves this per frame including rotation (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#crop, checked 2026-10-24] [HyperFrames registry source `compositions/components/camera-shake.html` (`npx hyperframes add camera-shake`), checked 2026-10-24]
3224. **The ffmpeg doc shake zooms 2x** — the crop docs' "trembling" and "erratic camera" examples crop to in_w/2 × in_h/2 and swing across the remaining half. **How:** the doc line `crop=in_w/2:in_h/2:(in_w-out_w)/2+((in_w-out_w)/2)*sin(t*10):(in_h-out_h)/2+((in_h-out_h)/2)*sin(t*13),scale=640:360` works but doubles the zoom and swings ±25% of the frame: for a subtle shake use the small-overscan form above (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#crop, checked 2026-10-24]
3225. **wiggle octaves = summed harmonics** — `wiggle(5, 20, 3, .5)` adds two finer layers at 10 and 20 Hz with 10 and 5 px; amp_mult near 1 keeps detail, near 0 removes it. **How:** `crop=640:360:'40+(20*sin(2*PI*5*t)+10*sin(2*PI*10*t+1)+5*sin(2*PI*20*t+2))/1.2':'22+(12*sin(2*PI*5*t+3)+6*sin(2*PI*10*t+4)+3*sin(2*PI*20*t+5))/1.2'` after `scale=720:405` (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24]
3226. **Shake on one axis only** — the AE example `w = wiggle(freq,amp); [value[0], w[1]]` wiggles only y. **How:** keep x fixed: `scale=704:396,crop=640:360:32:'18+16*sin(2*PI*3*t)'` (bass-drop bounce, footsteps) (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24]
3227. **Uniform scale wiggle** — the AE example `v = wiggle(5, 10); [v[0], v[0]]` wiggles scale by the same amount on both axes. **How:** zoompan on video with d=1: `zoompan=z='1.06+0.03*sin(2*PI*5*it)':d=1:x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=640x360:fps=30` (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#zoompan, checked 2026-10-24]
3228. **Stepped jitter (posterizeTime + wiggle / Alight Random Jitter)** — AE posterizeTime lowers a property's update rate; Alight's Random Jitter "jumps the layer randomly back and forth", unlike Random Displacement, which moves "smoothly but randomly". **How:** hold each offset for 1/8 s with a hashed floor: `crop=640:360:'32+20*sin(floor(t*8)*12.9898)':'18+12*sin(floor(t*8)*78.233)'` after `scale=704:396` (deterministic, re-renders identically) (tested here 2026-10-24) [Adobe AE Help "Expression language reference", https://helpx.adobe.com/after-effects/using/expression-language-reference.html, checked 2026-10-24] [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/random-jitter, checked 2026-10-24] [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/random-displacement, checked 2026-10-24]
3229. **Shake only for a window** — CapCut's Basic > Shake is added as an effect clip whose duration you drag. **How:** gate the amplitude with between(): `crop=640:360:'32+24*between(t,0.5,1.2)*sin(2*PI*9*t)':'18+14*between(t,0.5,1.2)*sin(2*PI*7*t)'` after `scale=704:396` (tested here 2026-10-24) [FlexClip, https://www.flexclip.com/learn/how-to-do-the-shake-effect-on-capcut.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#crop, checked 2026-10-24]
3230. **Shake that ramps up (or dies out)** — Alight's Oscillate tip: keyframe Magnitude from or to zero to make a shake transition. **How:** multiply the amplitude by an envelope: in `min(1,t/0.5)` (up over 0.5 s) or out `exp(-8*(t-T0))`; tested `crop=640:360:'32+25*min(1,t/0.5)*sin(2*PI*8*t)':18` (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/oscillate, checked 2026-10-24]
3231. **Hit shake that decays on every beat** — a FlexClip CapCut tutorial shakes on the beat points of the music. **How:** restart a decaying shake at each beat (0.5 s = 120 BPM): `crop=640:360:'32+30*exp(-8*mod(t,0.5))*sin(2*PI*14*t)':'18+18*exp(-8*mod(t,0.5))*sin(2*PI*11*t)'` after `scale=704:396` (tested here 2026-10-24) [FlexClip, https://www.flexclip.com/learn/how-to-do-the-shake-effect-on-capcut.html, checked 2026-10-24]
3232. **Beat bounce: down on one beat, up on the next** — FlexClip's manual CapCut shake: zoom in, keyframe the clip down on the first beat and up on the second, repeat in pairs. **How:** `crop=640:360:32:'18+14*(1-2*mod(floor(t/0.5),2))'` after `scale=704:396` (hard jumps each 0.5 s beat); in GSAP the same is `tl.set(wrapper,{y:±14},beatTime)` per beat (tested here 2026-10-24) [FlexClip, https://www.flexclip.com/learn/how-to-do-the-shake-effect-on-capcut.html, checked 2026-10-24]
3233. **Alight Oscillate in numbers** — Oscillate moves the layer back and forth: Angle 0º = horizontal (right first), 90º = vertical (down first); Frequency in Hz (1 = back home after exactly 1 s); Magnitude = max distance in px (default 25 at 45º, 2 Hz). **How:** `crop=640:360:'32+25*cos(PI/4)*sin(2*PI*2*t)':'18+25*sin(PI/4)*sin(2*PI*2*t)'` after `scale=704:396` (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/oscillate, checked 2026-10-24]
3234. **Triangle-wave oscillation = zig-zag** — Oscillate's Triangle wave moves at constant speed with an abrupt reversal; Alight suggests it perpendicular to a move for zig-zag motion. **How:** triangle of period 0.5 s: `crop=640:360:'32+25*(2*abs(2*(2*t-floor(2*t+0.5)))-1)':18` after `scale=704:396`; in GSAP a finite `repeat:N, yoyo:true, ease:'none'` (HyperFrames forbids `repeat: -1`) (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/oscillate, checked 2026-10-24] [repo: .claude/skills/hyperframes/SKILL.md]
3235. **Swing (rotation shake) from the rotate docs** — Alight Swing "rotates the layer back and forth"; ffmpeg's rotate docs give the oscillation form A*sin(2*PI/T*t). **How:** overscan so corners never show: `ffmpeg -i in.mp4 -vf "scale=736:414,rotate=0.04*sin(2*PI*1.5*t),crop=640:360" out.mp4` (±0.04 rad ≈ 2.3°) (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/swing, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rotate, checked 2026-10-24]
3236. **Spin with no black corners** — rotate's doc example `rotate=2*PI*t:ow='min(iw,ih)/sqrt(2)':oh=ow:c=none` shrinks the output so no background shows (Alight Spin = constant spin). **How:** with libx264/yuv420p the doc's size is odd (254.5 px) and the encoder refuses it; round to even: `rotate=2*PI*t/4:ow='trunc(min(iw,ih)/sqrt(2)/2)*2':oh=ow:c=none` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rotate, checked 2026-10-24] [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/spin, checked 2026-10-24]
3237. **Stabilise first, then add the shake you want** — Miracamp's CapCut advice: stabilise to remove unwanted shake, then add a controlled shake for style; CapCut's stabiliser zooms in slightly. **How:** `vidstabdetect=result=tr.trf` pass, then `vidstabtransform=input=tr.trf:smoothing=10,scale=704:396,crop=640:360:'32+15*sin(2*PI*6*t)':'18+9*sin(2*PI*5*t)'` (tested here 2026-10-24) [Miracamp, https://www.miracamp.com/learn/capcut/video-stabilization-camera-shake, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform, checked 2026-10-24]
3238. **Yoyo shake legs must be whole frames** — the repo's core-GSAP shake is a short tween with repeat + yoyo (GSAP's "rough" ease isn't in core). **How:** `tl.to(wrap,{x:8,duration:0.04,repeat:7,yoyo:true,ease:'none'})` ends exactly at rest (x=0 after the odd repeat count), but at 30 fps a 0.04 s leg aliases (sampled x per frame: 0, 6.7, 2.7, 4.0, 5.3...): use leg durations that are whole frames (1/30 s) (tested here 2026-10-24) [repo: CLAUDE.md (Client phone-video edits)] [GSAP docs, https://gsap.com/docs/v3/GSAP/Tween, checked 2026-10-24]
3239. **camera-shake: nine measured profiles** — registry component `camera-shake` gives handheld (normal, wide-angle, telephoto; mild/strong/extreme) and rig (6D shake "engine buzz", 6D wobble) profiles with an intensity multiplier 0-3 and a frequency multiplier 0.1-4. **How:** `npx hyperframes add camera-shake`, wrap the shot in `.camera-shake-frame > .camera-shake-rig`, then `cameraShake(tl, "#shot", { profile: "handheld-tele-mild", duration: 8 })` [HyperFrames registry source `compositions/components/camera-shake.html` (`npx hyperframes add camera-shake`), checked 2026-10-24]
3240. **Long lens = smaller angular shake** — camera-shake's profile table: wide-angle carries 12° on X where telephoto carries 4°, "because a long lens magnifies angular jitter"; keep the 3x ratio. **How:** pick the profile from the shot's look (wide vlog vs zoomed-in), not by taste; a hand-written shake on a tight shot needs less amplitude. [HyperFrames registry source `compositions/components/camera-shake.html` (`npx hyperframes add camera-shake`), checked 2026-10-24]
3241. **Seek-safe shake: drive it from a property setter** — camera-shake computes every value as a closed form of t and runs it from a setter on a tweened driver object, because GSAP suppresses onUpdate on seek() and the shake would freeze on frame 0. **How:** `tl.to(driver,{t:dur,duration:dur,ease:'none'})` with `driver` defining `set t(v){ applyShake(v) }`; no accumulators, no unseeded random [HyperFrames registry source `compositions/components/camera-shake.html` (`npx hyperframes add camera-shake`), checked 2026-10-24]

## Glow (AE Glow, Alight Glow family)

3244. **AE Glow = threshold, radius, intensity** — Glow brightens pixels above Glow Threshold, spreads them by Glow Radius (px) and scales by Glow Intensity. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]format=gbrp,split[o][g];[g]lutrgb=r='if(gt(val,180),val,0)':g='if(gt(val,180),val,0)':b='if(gt(val,180),val,0)',gblur=sigma=15[gl];[o][gl]blend=all_mode=screen" out.mp4` (threshold in the lutrgb, radius = sigma, intensity = add `colorlevels`/a second screen pass) (tested here 2026-10-24) [Adobe AE Help "Stylize effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/stylize-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#gblur, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
3245. **Horizontal-only glow (anamorphic streak)** — AE Glow Dimensions can be horizontal, vertical or both. **How:** gblur has separate sigma (horizontal) and sigmaV: `...lutrgb=...(gt(val,200)...),gblur=sigma=40:sigmaV=0.5[gl];[o][gl]blend=all_mode=screen` (tested here 2026-10-24) [Adobe AE Help "Stylize effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/stylize-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#gblur, checked 2026-10-24]
3246. **Glow in float so it doesn't clip** — AE notes glows look brighter and more real in 32-bpc because the high range keeps glow values from clipping. **How:** run the glow branch in float: `[0:v]format=gbrpf32le,split[o][g];[g]gblur=sigma=15[gl];[o][gl]blend=all_mode=addition:all_opacity=0.6,format=yuv420p` (blend accepted gbrpf32le here) (tested here 2026-10-24) [Adobe AE Help "Stylize effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/stylize-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
3247. **Glow behind a cutout or text (backlight)** — AE Glow's Composite Original "Behind" puts the glow behind the image; glows based on alpha make brightness only at the edges. **How:** in HyperFrames put CSS `filter: drop-shadow(0 0 18px #ffd27a)` on the cutout/text: drop-shadow is a blurred copy of the element's alpha mask drawn below it (stack two for a stronger halo) [Adobe AE Help "Stylize effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/stylize-effects.html, checked 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/CSS/filter-function/drop-shadow, checked 2026-10-24]
3248. **Alight Light Glow numbers** — Light Glow glows pixels above a luminance threshold (default 0.7), Diffusion = softness (default 0.25), Intensity 1 = light areas don't get brighter, they only spill into darker neighbours. **How:** threshold 0.7 ≈ lutrgb `gt(val,178)`; keep the screen blend at 1 pass for "intensity 1", add passes only when they ask for blown highlights. [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/light-glow, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lutrgb, checked 2026-10-24]
3249. **Dark Glow (Alight)** — Dark Glow makes dark blooms from pixels under a luminance threshold (default 0.3). **How:** invert, glow the (now bright) darks, invert back: `[0:v]format=gbrp,negate,split[o][g];[g]lutrgb=...gt(val,180)...,gblur=sigma=15[gl];[o][gl]blend=all_mode=screen,negate` (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/dark-glow, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#negate, checked 2026-10-24]
3250. **Edge Glow (Alight)** — Edge Glow "detects edges in a photo or video and creates a glow around them" (Threshold up = fewer edges). **How:** `[0:v]format=gbrp,split[o][e];[e]edgedetect=low=0.1:high=0.3:mode=colormix,gblur=sigma=6[g];[o][g]blend=all_mode=screen`; raise edgedetect low/high for fewer edges (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/edge-glow, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#edgedetect, checked 2026-10-24]

## RGB split and channel tricks

3255. **Alight RGB Split = rgbashift with opposite offsets** — RGB Split keeps one channel fixed and shifts the other two in opposite directions. **How:** keep green, push red left and blue right: `ffmpeg -i in.mp4 -vf "rgbashift=rh=-8:bh=8" out.mp4` (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/rgb-split, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rgbashift, checked 2026-10-24]
3256. **rgbashift edge mode on ffmpeg 6.1 is "wrap", not "warp"** — the current docs list edge = smear, default or warp; this container's 6.1 accepts only smear (default) and wrap (`ffmpeg -h filter=rgbashift`). **How:** `rgbashift=rh=-30:bv=20:edge=wrap` makes pixels pushed off one side reappear on the other (a harder glitch than smear) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rgbashift, checked 2026-10-24]
3257. **Animate the split with sendcmd** — rgbashift supports all its options as commands, so a split can jump on and off at set times. **How:** `-vf "sendcmd=c='0.5 rgbashift rh -20, rgbashift bh 20; 0.7 rgbashift rh 0, rgbashift bh 0',rgbashift"`; inside one interval separate commands with commas and don't repeat the time (writing the time again fails to parse) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sendcmd_002c-asendcmd, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rgbashift, checked 2026-10-24]
3258. **AE Shift Channels = channel swap** — Shift Channels replaces R, G, B (and alpha) with values taken from other channels. **How:** swap red and blue: `ffmpeg -i in.mp4 -vf "colorchannelmixer=rr=0:rb=1:bb=0:br=1" out.mp4` (tested here 2026-10-24) [Adobe AE Help "Channel effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/channel-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#colorchannelmixer, checked 2026-10-24]
3259. **Invert one channel (AE Invert / Alight Invert)** — AE Invert can invert RGB, a single Red/Green/Blue channel, HLS or YIQ channels; Alight's Invert flips R, G or B independently. **How:** negate takes components, but r/g/b only work on RGB input: `ffmpeg -i in.mp4 -vf "format=rgb24,negate=components=r" out.mp4` (tested here 2026-10-24) [Adobe AE Help "Channel effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/channel-effects.html, checked 2026-10-24] [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/invert, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#negate, checked 2026-10-24]
3260. **Glitch only in short windows** — CapCut's glitch effects are dragged onto the clip for a chosen duration. **How:** most ffmpeg filters take `enable`: `-vf "rgbashift=rh=-16:bh=16:enable='between(t,0.5,0.7)+between(t,1.5,1.7)',shufflepixels=m=block:w=40:h=20:enable='between(t,0.55,0.65)'"`; `ffmpeg -h filter=NAME` prints "support for timeline" when enable works (tested here 2026-10-24) [CapCut, https://capcut.com/resource/glitch-filter, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]

## Glitch, datamosh and pixel damage

3265. **Block shuffle (Alight Tile Shift look)** — shufflepixels reorders pixels in horizontal, vertical or block mode with a block size and seed; Alight's Tile Shift shifts the contents of grid tiles randomly. **How:** `ffmpeg -i in.mp4 -vf "shufflepixels=m=block:w=32:h=32:s=3" out.mp4` (keep it to a few frames with enable) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#shufflepixels, checked 2026-10-24] [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/tile-shift, checked 2026-10-24]
3266. **shufflepixels "inverse" didn't undo the shuffle here** — the docs say the seed lets you reverse a shuffle with the same parameters and direction=inverse. **How:** on 6.1 a forward+inverse pair with the same seed in one graph did not restore the picture (lossless check, max difference 231): don't plan a "glitch in, glitch back out" on that; animate enable instead. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#shufflepixels, checked 2026-10-24] NOTE 2026-10-24: #5414 (file 21) tested inverse bit-exact when the block size divides the frame size (8x8 on 640x360; 16x16 did not) — use that.
3267. **Swap two rectangles on some frames** — swaprect swaps two w×h rectangles; its expressions are evaluated once per frame. **How:** `ffmpeg -i in.mp4 -vf "swaprect=w=200:h=40:x1=0:y1=60:x2=300:y2=220:enable='lt(mod(n,10),2)'" out.mp4` (2 frames out of every 10) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#swaprect, checked 2026-10-24]
3268. **Nervous frame order** — `random` flushes cached frames out in random order (cache 2-512, default 30), inspired by frei0r "nervous"; no frame is dropped. **How:** `-vf "random=frames=6:seed=7"`: a small cache keeps the jumble local; set seed for repeatable renders (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#random, checked 2026-10-24]
3269. **Two-frame swap stutter** — shuffleframes remaps frame indexes; the doc example `shuffleframes=0 2 1` swaps the 2nd and 3rd frame of every three. **How:** `ffmpeg -i in.mp4 -vf "shuffleframes=0 2 1" out.mp4` for a subtle broken-playback twitch (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#shuffleframes, checked 2026-10-24]
3270. **AE Noise: colour vs mono** — AE Noise with "Use Color Noise" adds different random values to R, G and B; otherwise the same value goes to all channels. **How:** colour: `noise=alls=25:allf=t+u` (t = changes every frame, u = uniform); mono: noise only on the luma plane `noise=c0s=30:c0f=t` (tested here 2026-10-24) [Adobe AE Help "Noise and Grain effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/noise-grain-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#noise, checked 2026-10-24]
3271. **Alight Block Noise** — Block Noise multiplies random rectangular noise blocks (Size default 20, Strength 0-1 default 0.25) into the layer. **How:** make low-res noise and scale it up with nearest neighbour, then multiply at 0.25: `ffmpeg -i in.mp4 -f lavfi -i "nullsrc=s=32x18:r=30,geq=lum='random(1)*255':cb=128:cr=128,scale=640:360:flags=neighbor" -filter_complex "[0:v]format=yuv444p[a];[1:v]format=yuv444p[b];[a][b]blend=all_mode=multiply:all_opacity=0.25:shortest=1" out.mp4` (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/block-noise, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#geq, checked 2026-10-24]
3272. **Line tear with a displacement map** — displace moves pixels by a second (x) and third (y) input; the repo's VHS Playback treatment keeps its line tear (digitalGlitchLineTear) at 0.04-0.1. **How:** an x-map that is 128 everywhere except a moving band: `-f lavfi -i "nullsrc=s=640x360:r=30,geq=lum='128+if(between(Y,100+50*sin(T*7),130+50*sin(T*7)),60,0)':cb=128:cr=128"` plus a flat 128 y-map, then `[0:v][x][y]displace=edge=wrap` (escape the commas inside -i as `\,`) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#displace, checked 2026-10-24] [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
3273. **Datamosh step 1: prepare a moshable file** — datamoshing needs few I-frames and no B-frames (moshy's `prep` converts to "no B-Frames ... as few I-Frames as possible"). **How:** `ffmpeg -i a.mp4 -i b.mp4 -filter_complex "[0:v][1:v]concat=n=2:v=1:a=0" -c:v libx264 -bf 0 -g 1000 -sc_threshold 0 -force_key_frames 0,2 mosh_src.mp4` (2 = the cut; this gave exactly 2 keyframes) (tested here 2026-10-24) [GlitchTools moshy README, https://raw.githubusercontent.com/GlitchTools/moshy/master/README.md, checked 2026-10-24]
3274. **Datamosh step 2: drop the keyframe at the cut** — the noise bitstream filter can drop packets by expression; datamosh-cli's remove-keyframes does the same idea (keeps the first keyframe) so one scene's pixels leak into the next. **How:** `ffmpeg -i mosh_src.mp4 -c copy -bsf:v "noise=drop='key*gt(pts*tb\,1)'" mosh_raw.mkv` (119 of 120 packets kept, 1 keyframe left); measured: a frame 0.5 s after the cut differed 14 levels from the last frame of A but 56 from the clean frame of B (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-bitstream-filters.html#noise, checked 2026-10-24] [datamosh-cli on npm, https://www.npmjs.com/package/datamosh-cli, checked 2026-10-24]
3275. **Datamosh step 3: bake it** — moshy's "Bake" re-encodes the corruption as real video so it survives upload and further edits. **How:** `ffmpeg -i mosh_raw.mkv -c:v libx264 -pix_fmt yuv420p mosh_baked.mp4`; check the baked file's length (4.03 s here, both shots kept) (tested here 2026-10-24) [GlitchTools moshy README, https://raw.githubusercontent.com/GlitchTools/moshy/master/README.md, checked 2026-10-24]
3276. **Datamosh only between the two shots you choose** — a mosh happens where a keyframe is removed, so control the cut points, not the whole file. **How:** force keyframes only at the cuts you want to mosh (`-force_key_frames 2,5.5`) and use `drop='key*between(pts*tb\,1.9\,2.1)'` to drop just one; other cuts stay clean [ffmpeg docs, https://ffmpeg.org/ffmpeg-bitstream-filters.html#noise, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]
3277. **Registry `glitch` shader block** — registry block `glitch` is a shader transition with digital glitch artifacts. **How:** `npx hyperframes add glitch` when a CapCut-style "glitch transition" is wanted between two HyperFrames scenes; for footage-only edits use the ffmpeg windows above. [HyperFrames registry `glitch` (`npx hyperframes catalog --json`), checked 2026-10-24]
3278. **Effect only inside a box (feedback)** — feedback sends a crop of the frame to a second output, lets you filter it, and lays it back on top; the docs pixelize a region this way. **How:** `-vf "[in][fin]feedback=x=200:y=100:w=200:h=120[out][fout];[fout]pixelize=w=16:h=16[fin]"` (any filter in place of pixelize) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#feedback, checked 2026-10-24]
3279. **Copy Background = adjustment layer = backdrop-filter** — Alight's Copy Background turns a layer into an adjustment layer: effects apply only to the background under its shape. **How:** in HyperFrames give a transparent element `backdrop-filter: blur(8px) hue-rotate(90deg)`: it filters what is painted behind it, up to the nearest backdrop root (an element with clip-path or mask is one) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/copy-background, checked 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/CSS/backdrop-filter, checked 2026-10-24]
3280. **Flash safety check after strobes and glitches** — photosensitivity reduces flashes for viewers with epilepsy (frames default 30, threshold default 1, lower = stricter). **How:** `ffmpeg -i strobe.mp4 -vf "photosensitivity=f=20:t=1" safe.mp4`; on a 0.5 s white strobe it cut the largest frame-to-frame mean jump from 128 to 28 levels: run it on any client piece with strobes (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#photosensitivity, checked 2026-10-24]
3281. **Time-difference ghost (AE Time Difference)** — Time Difference compares a layer with a time-offset copy (e.g. 3/30 s); with Absolute Difference, unchanged areas go black and changes glow. **How:** `-filter_complex "[0:v]split[a][b];[b]setpts=PTS+3/30/TB[d];[a][d]blend=all_mode=difference:shortest=1"`; frame-to-frame version: `tblend=all_mode=difference` (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
3282. **Exaggerate small motion** — amplify boosts differences between a pixel and the same pixel in nearby frames (radius 1-63, factor, threshold). **How:** `-vf "amplify=radius=2:factor=10:threshold=50"` makes moving edges flare while still areas stay; a glitchy "energy" pass for dance/sport clips (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#amplify, checked 2026-10-24]
3283. **Pixel sorting, the original algorithm** — Kim Asendorf's ASDF Pixel Sort walks every column and then every row, finds runs of pixels past a threshold, and sorts each run by colour value; modes are 0 white, 1 black, 2 bright, 3 dark. **How:** `python3 pixelsort.py in.png out.png 127` (our numpy port of mode 2, scratchpad `sk2_12/t/py/pixelsort.py`): on a testsrc2 frame it changed 87% of pixels (tested here 2026-10-24) [Kim Asendorf, ASDFPixelSort.pde, https://raw.githubusercontent.com/kimasendorf/ASDFPixelSort/master/ASDFPixelSort.pde, checked 2026-10-24]
3284. **Pixel sort thresholds** — the original defaults: brightValue 127 and darkValue 223 (Processing brightness 0-255), whiteValue −12345678 and blackValue −3456789 (packed RGB ints, 0 = white, −16581375 = black). **How:** raise the bright threshold to sort only highlights (sky, lights), lower it to smear more of the frame; brightness() is the HSB max of R, G, B (color(0,126,255) → 255) [Kim Asendorf, ASDFPixelSort.pde, https://raw.githubusercontent.com/kimasendorf/ASDFPixelSort/master/ASDFPixelSort.pde, checked 2026-10-24] [Processing reference brightness(), https://processing.org/reference/brightness_.html, checked 2026-10-24]
3285. **Pixel sort on video** — the sort is per image, so video means frames out, sort, frames in. **How:** `ffmpeg -i in.mp4 -t 0.2 d/f%04d.png`, run the script on each PNG, `ffmpeg -framerate 30 -i d/f%04d.png -pix_fmt yuv420p out.mp4` (script `sk2_12/t/py/pixelsort_video.sh`): about 0.35 s per 640x360 frame here, so sort only the beat or the hero shot (tested here 2026-10-24) [Kim Asendorf, ASDFPixelSort.pde, https://raw.githubusercontent.com/kimasendorf/ASDFPixelSort/master/ASDFPixelSort.pde, checked 2026-10-24]

## Motion blur (AE shutter, Pixel Motion Blur, Alight Motion Blur)

3299. **Shutter angle → exposure** — AE: 90° on 24 fps footage = 1/96 s (25% of 1/24 s); 1° ≈ no blur, 720° = heavy; exposure = angle / (360 × fps). **How:** in ffmpeg supersample then average the frames inside the shutter: 4x sub-frames and 180° = 2 of 4: `ffmpeg -i in.mp4 -vf "minterpolate=fps=120:mi_mode=blend,tmix=frames=2:weights='1 1',fps=30" out.mp4` (moving square: 60 px wide → 68 px smear) (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
3300. **Pixel Motion Blur = motion vectors** — AE's Pixel Motion Blur analyses footage and synthesises blur from motion vectors (Shutter Samples = quality). **How:** use motion-compensated sub-frames before averaging: `-vf "minterpolate=fps=120:mi_mode=mci,tmix=frames=4,fps=30"` (360° here); slow, so trim first (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3301. **Blur real footage without changing its speed** — AE's Timewarp note: set Speed 100, enable motion blur in the effect and use manual shutter controls to add blur without retiming. **How:** the minterpolate + tmix + fps chain above keeps duration and frame rate; it only adds blur. [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3302. **Layer motion blur doesn't blur what's inside the footage** — AE's layer Motion Blur only blurs layer animation; for live action at a very different frame rate use frame blending instead. **How:** HyperFrames' blur (`data-hf-motion-blur` / `data-motion-blur`) smears DOM elements along their tweens; motion inside a `<video>` needs the ffmpeg pre-pass above, done before the clip goes in. [Adobe AE Help "Assorted animation tools" (motion blur), https://helpx.adobe.com/after-effects/using/assorted-animation-tools.html, checked 2026-10-24] [HyperFrames registry source `compositions/components/motion-blur.html` (`npx hyperframes add motion-blur`), checked 2026-10-24]
3303. **Centre the blur on the frame with shutter phase** — AE's shutter phase offsets when the shutter opens; it helps when a blurred object seems to lag behind. 3304. **HyperFrames motion-blur snippet** — registry `motion-blur`: put `data-hf-motion-blur` on any element the timeline animates; it seeks the timeline to sub-frame times across the shutter window and stacks copies at 1/N opacity with `mix-blend-mode: plus-lighter` in an isolated group (without isolation a light background blows out to white). **How:** `npx hyperframes add motion-blur`, then set shutterAngle/shutterPhase/samplesPerFrame per element [HyperFrames registry source `compositions/components/motion-blur.html` (`npx hyperframes add motion-blur`), checked 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/CSS/mix-blend-mode, checked 2026-10-24]
3305. **Render-time motion blur switches itself off** — `data-motion-blur="on"` on the composition root blurs fast 2D movers, but it turns off with a WebGL canvas, a 3D flip using backface-visibility, a root transform or opacity, or an HDR render; it costs about 1.7x render time. **How:** after adding it run `hyperframes check`; the `motion_blur_off` warning names the cause [repo: .claude/skills/hyperframes/references/motion.md]
3306. **Blur depends on the frame rate** — Alight's Motion Blur measures how far the layer moved since the previous frame, so the amount changes with the project frame rate. **How:** when a 30 fps edit is re-rendered at 60, re-check blur: in ffmpeg the shutter is a fraction of the frame (sub-frames × angle/360), so recompute the tmix frame count for the new fps. 3307. **Abrupt starts give wrong blur** — Alight: an animation that starts or stops abruptly makes too much or too little blur; ease in/out, or put the keyframes at or beyond the layer's ends. **How:** in GSAP give blurred moves an eased start/end, or start the tween before the scene's data-start so it is already moving when the scene appears. 3308. **Hand-made blur peak on a fast move** — HyperFrames motion defaults: a fast move takes 0.3-0.6 s and carries blur on its own ease, peaking at the fastest frame, 6-12 px on text, 15-20 px full-frame, horizontal-only on a horizontal move. **How:** for horizontal-only blur use an SVG `<feGaussianBlur stdDeviation="12 0">` filter (two numbers = x and y deviation; 0 on one axis blurs only the other) and tween stdDeviation up and back with the move [repo: .claude/skills/hyperframes/references/motion.md] [MDN, https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feGaussianBlur, checked 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/stdDeviation, checked 2026-10-24]

## Echo and trails (AE Echo, Alight Echo Keyframes)

3311. **AE Echo decay = geometric tmix weights** — Echo combines the current frame with Number of Echoes earlier frames; each echo's opacity is Decay × the previous one (Decay 0.5 → 1/2, 1/4...). **How:** 3 echoes, decay 0.5: `ffmpeg -i in.mp4 -vf "tmix=frames=4:weights='1 0.5 0.25 0.125'" out.mp4` (moving 60 px square → 80 px visible trail) (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
3312. **Echo "Add" blows out to white** — AE warns the Add operator overloads into white streaks if Starting Intensity is high. **How:** tmix with scale=1 is a plain sum: `tmix=frames=4:weights='1 1 1 1':scale=1` lifted the dark background to grey and turned 90 columns pure white; leave scale unset (auto = divide by the weight sum) unless you want that burn (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
3313. **Echo "Minimum" = dark trails** — AE's Minimum operator keeps the darkest pixel of all echoes. **How:** lagfun keeps bright pixels and lets them decay ("makes short flashes of light appear longer"), so invert around it for dark trails: `-vf "negate,lagfun=decay=0.9,negate"` (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lagfun, checked 2026-10-24]
3314. **Echo a moving layer: apply it after the move** — AE Echo doesn't echo motion made by moving the layer; precompose and echo the precomp. **How:** in ffmpeg put tmix after the overlay that moves the element: `[0][1]overlay=x='mod(t*300\,560)':y=140:shortest=1,tmix=frames=5:weights='1 0.6 0.36 0.22 0.13'` (tested here 2026-10-24) [Adobe AE Help "Time effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/time-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#overlay, checked 2026-10-24]
3315. **Alight Echo Keyframes → echo-trail** — Echo Keyframes copies the layer as it was at other times: Seconds = how far the most distant echo is (negative = future), Count = echoes in between (Seconds 1, Count 2 → echoes at 0.5 s and 1 s), Alpha fades them. **How:** registry `echo-trail` draws N ghosts at t − i×delta (echoes 2-6, delta 0.03-0.3 s): set delta = Seconds/Count [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/echo-keyframes, checked 2026-10-24] [HyperFrames registry source `compositions/components/echo-trail.html` (`npx hyperframes add echo-trail`), checked 2026-10-24]

## Distort (bulge, ripple, turbulence, twirl, tilt)

3342. **Bulge / pinch with lenscorrection** — AE Bulge pushes an area toward or away from the viewer; ffmpeg lenscorrection remaps radius by r_src = r_tgt × (1 + k1(r/r0)² + k2(r/r0)⁴), k1/k2 in −1..1. **How:** one sign swells the centre, the other pinches it: `-vf "lenscorrection=k1=-0.5:k2=0.1:i=bilinear"` and `lenscorrection=k1=0.5:i=bilinear` (i=bilinear avoids the default nearest's jaggies; check which sign gives bulge on a frame) (tested here 2026-10-24) [Adobe AE Help "Distort effects", https://helpx.adobe.com/after-effects/desktop/apply-effects-and-animation-presets/list-of-effects/distort-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lenscorrection, checked 2026-10-24]

3370. **Flicker without randomness** — Alight Flicker randomly adjusts opacity; the repo's film-memory treatment forbids randomness, infinite keyframes, timers and onUpdate: flicker is a gentle exposure pulse (−0.03..0.03 in sine.inOut segments of 0.45-0.8 s), not a flash. **How:** ffmpeg deterministic flicker: `-vf "eq=brightness='0.06*sin(2*PI*7*t)*sin(2*PI*3.1*t)':eval=frame"` (eval=frame is required for t to change) (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/flicker, checked 2026-10-24] [repo: .claude/skills/media-use/references/media-treatment-recipes.md] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#eq, checked 2026-10-24]
3371. **Pulse Opacity (sine or triangle)** — Alight's Pulse Opacity pulses opacity on a sine or triangle wave. **How:** 1 Hz sine pulse toward white at most 30%: `-filter_complex "[0][1]blend=all_expr='A*(1-0.3*(0.5-0.5*cos(2*PI*T)))+B*0.3*(0.5-0.5*cos(2*PI*T))':shortest=1"` (input 1 = a white color source); in GSAP a finite `repeat:N, yoyo:true` (never `repeat: -1` in HyperFrames) with `sine.inOut` (sine) or `none` (triangle) (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/pulse-opacity, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
3372. **Pulse Size** — Alight's Pulse Size grows and shrinks the layer on a sine or triangle wave. **How:** `-vf "zoompan=z='1.05-0.05*cos(2*PI*1*it)':d=1:x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=640x360:fps=30"` (1.00↔1.10 once a second) (tested here 2026-10-24) [Alight Motion Effect Guide, https://guide.alightmotion.com/effects/pulse-size, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#zoompan, checked 2026-10-24]
3373. **Flash on a list of hits** — for flashes on chosen beats instead of a fixed period. **How:** sum between() windows: `-vf "eq=brightness=0.4:enable='between(t,0.47,0.53)+between(t,1.27,1.33)'"` (generate the list from the beat file) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#eq, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]

## Beat-synced effects

3375. **Beat file for the music** — `npx hyperframes beats` needs a local music `<audio>` marked `data-timeline-role="music"` (or an id containing music, bgm or soundtrack), decodes it with ffmpeg and writes `beats/<audio-path>.json`; with no steady beat it fails and writes nothing. **How:** mark the track, run it, read the JSON before placing any beat effect [repo: .claude/skills/hyperframes-cli/references/beats.md]
3376. **Don't trust beats on calm music** — on calm music the tracker invents a metronome, often at double tempo; `beats` reports bpmConfidence. **How:** on calm stretches place effects on phrase and energy changes from `npx hyperframes audio --only sections,onsets,moments --json`, and give footage one slow push (1.0 → 1.08) instead of beat effects [repo: .claude/skills/hyperframes/references/film.md]
3377. **Land the effect on the hit** — HyperFrames film rules: a move that must land on a hit starts 40-190 ms early, a reaction starts 0-45 ms after, and the hit itself is a 0 ms `tl.set` ("easing a hit kills it"). **How:** flash/RGB split/zoom punch: `tl.set(el,{...},beatTime)` exactly on the beat, decay after it; a slide into the hit starts ~0.1 s before [repo: .claude/skills/hyperframes/references/film.md]
3378. **Beat sync is for music, not voice** — CapCut's beat-sync workflow is for music timing and "not designed to sync voice snippets to beats"; HyperFrames: in narrated pieces the voice is the clock. **How:** apply beat effects only on music-only stretches; under narration time effects to words [CapCut, https://www.capcut.com/create/beat-detection-workflow-goal-compilation-edits, checked 2026-10-24] [repo: .claude/skills/hyperframes/references/sound.md]
3379. **Spend the strong beats on the key moments** — CapCut's beat-detection guide: big actions on strong beats, camera changes on secondary beats, titles or slow motion on breaks; beat drop = stronger transition, steady groove = steady cut pace, breakdown = longer hold. **How:** tag each beat in the JSON as strong/secondary/break first, then assign effect strength by tag instead of hitting every beat the same [CapCut, https://www.capcut.com/create/beat-detection-workflow-goal-compilation-edits, checked 2026-10-24]
3380. **Per-beat effects from a command file** — sendcmd reads timed commands from a file. **How:** write lines like `0.50 rgbashift rh -24, rgbashift bh 24;` and `0.60 rgbashift rh 0, rgbashift bh 0;` from the beat JSON, then `-vf "sendcmd=f=beats.cmd,rgbashift"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sendcmd_002c-asendcmd, checked 2026-10-24]
3381. **Decaying zoom punch on every beat** — **How:** zoompan restarts an exponential decay each beat (0.5 s here): `-vf "zoompan=z='1+0.12*exp(-10*mod(it,0.5))':d=1:x='iw/2-(iw/zoom/2)':y='ih/2-(ih/zoom/2)':s=640x360:fps=30"`; zoompan's doc example `z='if(between(in_time,0,1),2,1)'` is the hard version (2x for one second) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#zoompan, checked 2026-10-24]
3382. **Blur pulse on the beat via sendcmd expressions** — sendcmd's [expr] flag evaluates the argument with T (time), TS, TE, TI. **How:** put it in a file to avoid shell escaping: `0.0-2.0 [expr] gblur sigma 12*exp(-8*mod(T\,0.5));` then `-vf "sendcmd=f=blur.cmd,gblur"` (inline in `c=` the comma split the command and failed); measured detail rose from 0.87 at the beat to 1.19 a quarter-second later (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sendcmd_002c-asendcmd, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#gblur, checked 2026-10-24]
3383. **Hue cycle ("rainbow")** — CapCut's velocity presets include "rainbow"; hue's doc example rotates hue with time. **How:** `-vf "hue=H=2*PI*t"` (one full turn a second); doc variant `hue="H=2*PI*t: s=sin(2*PI*t)+1"` also swings saturation (tested here 2026-10-24) [CapCut, https://www.capcut.com/resource/how-to-do-velocity-on-capcut, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#hue, checked 2026-10-24]
3384. **Music-hit sting** — registry `beat-accent`: impact flash, micro scale-pulse and small shake on one hit; the impact lands 0.25 s into its unscaled IN, and intensity 0.5-2 scales pulse, flash and shake together. **How:** `npx hyperframes add beat-accent`, start it 0.25 s before the beat [HyperFrames registry source `compositions/components/beat-accent.html` (`npx hyperframes add beat-accent`), checked 2026-10-24]
3385. **Background that pulses on the beat** — registry `beat-pulse-background`: an accent backdrop pulses glow intensity and saturation on a supplied deterministic beat grid. **How:** `npx hyperframes add beat-pulse-background` and feed it the beats JSON times [HyperFrames registry `beat-pulse-background` (`npx hyperframes catalog --json`), checked 2026-10-24]

## More translations (CSS/SVG in HyperFrames, extra ffmpeg filters, registry blocks)

3391. **RGB split on any HyperFrames element (SVG filter)** — feColorMatrix can isolate one channel and feOffset shifts a filter result by dx/dy. **How:** filter with three matrices (R only, G only, B only), `feOffset dx="-8"` on red and `dx="8"` on blue, recombined with two `feBlend mode="screen"`, applied as `filter:url(#rgbsplit)`; a white box rendered red | yellow | white | cyan | blue fringes in headless Chromium (`color-interpolation-filters="sRGB"`) (tested here 2026-10-24) [MDN, https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feColorMatrix, checked 2026-10-24] [MDN, https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/feOffset, checked 2026-10-24]

## Missing tools

- **Radial/zoom blur filter for ffmpeg (`rblur`)**: proposed on ffmpeg-devel in 2020, not in this ffmpeg 6.1 build. Use HyperFrames `cinematic-zoom` (registry) or the stacking approximations above.
- **frei0r plugins** (the frei0r project: "more than 100" free video effect plugins incl. blurring and distortion; GNU GPL; https://github.com/dyne/frei0r): our ffmpeg has the `frei0r` filter but no plugins (`/usr/lib/frei0r-1` missing); Ubuntu package `frei0r-plugins` 1.8.0 is available via apt (not installed, not tested). If installed, add it to `library/tools/setup-all.sh`.
- **datamosh-cli** (npm, MIT, https://github.com/timseverien/datamosh-cli): remove-keyframes / shuffle-frames on top of ffmpeg-static; not installed (the bsf noise route above covers keyframe removal).
- **moshy** (Ruby gem, MIT, https://github.com/wayspurrchen/moshy): P-frame duplication (pdupe), isplit, inspect; needs Ruby; not installed.
- **pixelsort** (PyPI, MIT, https://github.com/satyarth/pixelsort): a maintained Python pixel sorter; not installed (our numpy port runs ~0.35 s per 640x360 frame).
- **Halftone of real footage**: no ffmpeg filter in 6.1; registry `halftone-field` only makes a generated background.
