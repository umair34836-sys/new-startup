## vid.stab: options and traps (ffmpeg 6.1 here)

3441. **Read this build's vid.stab defaults, not the web page** — the online docs give smoothing 10, mincontrast 0.3, relative 0 and optalgo gauss, but the 6.1 build here reports smoothing 15, mincontrast 0.25, relative 1 and a default optalgo called `opt` (global optimization). Tune from the real defaults. **How:** `ffmpeg -hide_banner -h filter=vidstabtransform` and `ffmpeg -hide_banner -h filter=vidstabdetect` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3442. **Keep accuracy at or above shakiness** — the 6.1 help text describes accuracy as ">=shakiness" (1 low, 15 high/slow); shakiness 1 means little shake, 10 strong shake or a quick camera. For a violently shaken clip set both high. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=shakiness=10:accuracy=15:result=s10.trf -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24]
3443. **Faster first pass for a quick preview** — accuracy is the slow knob (15 = high, slow) and stepsize sets the search step before the 1-pixel refinement around the minimum; lowering accuracy and raising stepsize trades precision for speed. Use it to judge a clip, then re-run at full accuracy for the deliverable. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=shakiness=5:accuracy=9:stepsize=12:result=fast.trf -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24]
3444. **Lower mincontrast for flat, low-texture shots** — measurement fields whose contrast is below mincontrast are discarded, so sky, walls or night footage may leave too few fields; lower it (6.1 default 0.25) so more fields count. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=mincontrast=0.15:result=mc.trf -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24] [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3445. **See what the detector measured** — `show=1` or `show=2` draws the measurement fields and transforms into the output, so you can see whether it locked on the background or on a moving subject. Write it to a real file (not null). **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=show=1:result=show.trf -t 1 show1.mp4` (also `show=2`) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24] [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3446. **Virtual tripod: lock a near-static shot to one frame** — set `tripod=N` (1-based reference frame) in pass 1 and `tripod=1` in pass 2; motion is then measured against that frame and the view is held still. Frames before the reference are not stabilized (still zoomed/cropped) and the view snaps to the reference pose there, so pick an early reference. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=tripod=1:result=tri.trf -f null -` then `ffmpeg -i shaky.mp4 -vf vidstabtransform=tripod=1:input=tri.trf -an tri.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3447. **smoothing=0 simulates a static camera** — smoothing is the half-window (value*2+1 frames) of the low-pass on camera motion; 0 is the special case "static camera" without needing tripod mode. **How:** `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=s10.trf:smoothing=0 sm0.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3448. **Bigger smoothing = floatier camera, slower pans** — a larger value gives a smoother video but limits how fast the camera may accelerate in pans and tilts; smoothing=30 uses 61 frames. Use high values on walking shots, low values when the operator pans on purpose. **How:** `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=s10.trf:smoothing=30,unsharp=5:5:0.8:3:3:0.4 sm30.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3449. **Pick the camera-path algorithm** — 6.1 offers `opt` (global optimization, default here), `gauss` (Gaussian low-pass) and `avg` (simple averaging). If the default path looks wrong on a shot, render the other two and compare side by side. **How:** `vidstabtransform=input=s10.trf:optalgo=gauss:smoothing=10` / `optalgo=avg` / `optalgo=opt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3450. **Cap the correction with maxshift and maxangle** — maxshift limits translation in pixels and maxangle limits rotation in radians (degrees*PI/180); -1 means no limit. Capping stops one bad measurement from throwing the frame far off. **How:** `vidstabtransform=input=s10.trf:maxshift=20:maxangle=0.05` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3451. **Smooth position only, leave rotation alone** — Final Cut's SmoothCam has separate Translation, Rotation and Scale smoothing; vid.stab has one smoothing value, but maxangle=0 allows no rotation correction, so only position is stabilized. **How:** `vidstabtransform=input=s10.trf:maxangle=0` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/verbacf92b/mac, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3452. **Border fill: previous-frame vs black** — `crop=keep` (default) fills the moving borders with image from the previous frame, `crop=black` fills them black; with `optzoom=0` you see the borders and can judge how far the frame really moves. **How:** `vidstabtransform=input=s10.trf:crop=black:optzoom=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3453. **Zoom modes: static, adaptive, manual** — `optzoom=1` (default) picks one static zoom so only very strong moves show borders; `optzoom=2` zooms adaptively so no borders show, limited per frame by `zoomspeed` (0-5 %, default 0.25); `zoom=` adds a fixed percentage on top (negative zooms out). **How:** `vidstabtransform=input=s10.trf:optzoom=2:zoomspeed=0.5`; `vidstabtransform=input=s10.trf:zoom=-5:optzoom=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3454. **Bicubic interpolation for the final render** — interpol is no / linear (horizontal only) / bilinear (default) / bicubic (cubic in both directions, slow). Preview bilinear, render bicubic. **How:** `vidstabtransform=input=s10.trf:interpol=bicubic` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3455. **Absolute vs relative transforms** — `relative=1` (the 6.1 default) treats transforms as relative to the previous frame, `relative=0` as absolute. Tripod mode is equivalent to relative=0:smoothing=0. **How:** `vidstabtransform=input=s10.trf:relative=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3456. **invert=1 flips the stored transforms** — the option only inverts the transforms read from the file. Running a clean clip through another clip's inverted, relative transforms ran here, but whether it reproduces that clip's shake was not checked by eye, so look at frames before using it as a "borrowed shake". **How:** `ffmpeg -i clean.mp4 -vf vidstabtransform=input=s10.trf:invert=1:relative=1:smoothing=0:optzoom=0 -an inv.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3457. **Dump the per-frame global motion with debug=1** — pass 2 with debug=1 writes `global_motions.trf` in the working folder: one data line per frame `time x y alpha zoom extra` (x/y in pixels, alpha in radians), each followed by a comment line. Use it to find the shakiest seconds. **How:** `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=s10.trf:debug=1 -f null - && head -4 global_motions.trf` (tested here 2026-10-24: frame 2 read `0 35.107748 17.861798 -0.035629 -0.128952 0`) [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3458. **Feed vid.stab your own camera path** — vidstabtransform also accepts the global_motions format as input (the time column is ignored, frames are taken in file order), which is the supported way to apply a path you computed or edited yourself, e.g. in numpy. **How:** edit global_motions.trf, then `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=global_motions.trf -an own.mp4` (tested here 2026-10-24 with the unedited dump) [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3459. **This build writes text .trf files, and fileformat is missing** — the current vid.stab doc says ffmpeg always gets the binary encoding, but libvidstab 1.1.0 here wrote a text file starting `VID.STAB 1` with `Frame N (List ...)` lines, and `fileformat=ascii` failed with "Option not found". Text means you can read the fields with grep. **How:** `head -c 300 s10.trf` (tested here 2026-10-24); the reader auto-detects either encoding [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3460. **A .trf belongs to one resolution** — every value in the file is in pixels of the analysed frame and the frame size is not stored, so detecting on a downscaled copy and transforming the full-size clip does not work unless you rescale the values yourself. Detect at the size you transform. **How:** run both passes on the same `-vf` chain and size [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3461. **Drop duplicated frames before stabilizing** — duplicates (e.g. 25 fps stored as 30 fps) are measured as exactly zero motion and show up as a regular jerk; drop them with mpdecimate in both passes (or work at the true rate). **How:** `ffmpeg -i dup.mp4 -vf mpdecimate,vidstabdetect=result=dd.trf -f null -` then `ffmpeg -i dup.mp4 -vf mpdecimate,vidstabtransform=input=dd.trf -fps_mode vfr dd.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3462. **Deinterlace before both passes** — vid.stab treats each frame as one progressive picture, so combing is measured as content and the motion is an average of two fields; put the same deinterlacer before detect and transform. **How:** `ffmpeg -i il.mp4 -vf yadif,vidstabdetect=result=il.trf -f null -` then `ffmpeg -i il.mp4 -vf yadif,vidstabtransform=input=il.trf,unsharp=5:5:0.8:3:3:0.4 out.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3463. **Convert 10-bit 4:2:2 to 8-bit 4:2:0 first** — the README warns that 10-bit 4:2:2 input gives chroma shift and colour bleeding; add `format=yuv420p` at the start of both passes. **How:** `ffmpeg -i t422.mp4 -vf format=yuv420p,vidstabdetect=result=t422.trf -f null -` then `ffmpeg -i t422.mp4 -vf format=yuv420p,vidstabtransform=input=t422.trf out.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3464. **Hyperlapse: drop frames first, then stabilize, in both passes** — any filter that changes the number, order or rate of frames (fps, minterpolate, select, framestep, trim, -r) must run before vidstabdetect too, or the transforms stop lining up ("not enough transforms found"). For a hyperlapse from walking video, framestep before both passes. **How:** `ffmpeg -i walk.mp4 -vf "framestep=3,vidstabdetect=shakiness=8:result=hl.trf" -f null -` then `ffmpeg -i walk.mp4 -vf "framestep=3,vidstabtransform=input=hl.trf:smoothing=10,unsharp=5:5:0.8:3:3:0.4,setpts=N/(30*TB)" -r 30 -an hyper.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3465. **Judge stabilization side by side** — put the original and the result next to each other (LearnOpenCV's stabilizer writes a "Before and After" hconcat) and watch both; on a vertical deliverable stack them. **How:** `ffmpeg -i shaky.mp4 -i stab.mp4 -filter_complex "[0:v][1:v]hstack" -t 2 sbs.mp4` (or `vstack`) (tested here 2026-10-24) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3466. **Newer vid.stab has an L1-optimal "dolly/crane" path** — the current README describes an L1-optimal camera path (Grundmann et al., CVPR 2011) made of static, linear and parabolic segments, steered by zoom/optzoom (crop budget) and smoothing. The 6.1 build here lists only opt/gauss/avg, so don't assume it has the L1 path; it would need a newer libvidstab build. **How:** check `ffmpeg -h filter=vidstabtransform` for the available optalgo values (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3467. **Black bars after stabilizing: three fixes** — Final Cut's guide gives three ways to lose the black edges a big move causes: lower the smoothing values, cut out the shakiest stretch, or crop the edges. In ffmpeg: lower `smoothing`, trim with -ss/-t in both passes, or leave `optzoom=1`/`2` on. **How:** `vidstabtransform=input=s10.trf:optalgo=gauss:smoothing=10` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/verbacf92b/mac, checked 2026-10-24]

## deshake and OpenCV stabilizers

3468. **Tell deshake where the static background is** — `x:y:w:h` limits the motion search to a rectangle (same meaning as drawbox), so a person walking through the frame is not mistaken for camera motion; -1 means the full frame. Draw the box first to check it. **How:** `ffmpeg -i shaky.mp4 -vf drawbox=x=0:y=0:w=200:h=150:color=red -frames:v 1 box.png`, then `-vf deshake=x=0:y=0:w=200:h=150` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3469. **Raise deshake's search range for big jolts** — rx/ry set the maximum movement searched in x and y, 0-64 px, default 16; a shake bigger than that is not found. **How:** `-vf deshake=rx=64:ry=64` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3470. **Choose how deshake fills the edges** — edge = blank (zeros), original (original image), clamp (extruded edge pixels) or mirror (default). Mirror hides gaps on texture but can show mirrored objects; clamp smears the last row. **How:** `-vf deshake=edge=clamp` / `edge=blank` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3471. **deshake blocksize, contrast and search speed** — blocksize (4-128, default 8) is the motion-search block; only blocks whose darkest-to-lightest difference exceeds `contrast` (1-255, default 125) are used; `search=less` is a less exhaustive, faster search than the default exhaustive one. Lower contrast on flat footage. **How:** `-vf deshake=blocksize=16:contrast=60`; `-vf deshake=search=less` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3472. **Log deshake's motion search** — `filename=` writes a per-frame log with columns Ori/Avg/Fin for x, y, angle and zoom, so you can see the raw and the corrected motion. **How:** `ffmpeg -i shaky.mp4 -vf deshake=filename=deshake.log -f null - && head -3 deshake.log` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3473. **deshake_opencl needs an OpenCL device (none here)** — the feature-point OpenCL stabilizer offers tripod, smooth_strength (0-1, 0 = adaptive), smooth_window_multiplier (window = fps x value, default 2.0) and adaptive_crop. This container has no OpenCL device (`-init_hw_device opencl` failed with "No such device"), so use vid.stab. **How:** needs an OpenCL GPU (missing) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake_005fopencl, checked 2026-10-24]
3474. **OpenCV point-feature stabilizer as a second opinion** — LearnOpenCV's script tracks Shi-Tomasi corners (maxCorners 200, qualityLevel 0.01, minDistance 30) with Lucas-Kanade flow, fits `estimateAffinePartial2D` per frame pair, integrates the trajectory, smooths it and warps each frame; it writes a before/after video. **How:** copy the script into its own folder, then `/home/user/tools/venv/bin/python -I vs.py --input shaky.mp4 --output-dir out --output-name out.mp4 --smoothing-radius 15 --no-display --validate` (tested here 2026-10-24: "VALIDATION PASSED: 89 frames, 1280x360, mean tracked points 28.26") [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3475. **Moving-average radius = how much intent survives** — the script's default radius 50 is a 101-frame window (50 each side) chosen to remove high-frequency shake while keeping slower intentional camera motion; it smooths x, y and angle separately and pads the ends with edge values. Smaller radius keeps more of the operator's moves. **How:** `--smoothing-radius 15` for short handheld clips (tested here 2026-10-24) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3476. **Hide warp wedges with a 4% centre scale** — the script's `fix_border` scales each stabilized frame by 1.04 around its centre to hide most of the empty wedges the warp leaves. In ffmpeg the same idea is a small scale-up then crop back to size. **How:** in Python `cv2.warpAffine(frame, cv2.getRotationMatrix2D((w/2,h/2),0,1.04),(w,h))` (part of the tested run above) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3477. **Fall back to the last good transform** — when a frame pair has fewer than 3 tracked points or a non-finite result, the script reuses the previous transform instead of failing; copy that guard into any custom tracker or reframe script. **How:** see `estimate_transforms()` in the script (tested here 2026-10-24) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3478. **Gyro stabilization for action-cam footage** — Gyroflow stabilizes from the gyroscope (and optionally accelerometer) data that GoPro (HERO 5+), Sony, Insta360, DJI and others record, with rolling-shutter correction, adaptive zoom, horizon levelling and lens profiles; it also works with already-HyperSmoothed GoPro clips (HERO 8+). For a client's action-cam file, ask for the original file with metadata intact. **How:** needs Gyroflow (missing; GPLv3) [Gyroflow README, https://raw.githubusercontent.com/gyroflow/gyroflow/master/README.md, checked 2026-10-24]
3479. **Phone footage can be gyro-stabilized too** — for cameras without a built-in gyro, Gyroflow reads logs from phone apps such as Sensor Logger (iOS/Android) or a separate logger; its "additional 3D rotation" option is noted as useful for framing vertical videos. **How:** needs Gyroflow (missing) plus a gyro log recorded during the shoot [Gyroflow README, https://raw.githubusercontent.com/gyroflow/gyroflow/master/README.md, checked 2026-10-24]
3480. **Pans and zooms: smoothing; static shots: tripod** — Final Cut's InertiaCam is for footage with camera moves such as pans and zooms (one Smoothing slider) and may offer Tripod Mode after analysis; SmoothCam smooths translation, rotation and scale separately. In ffmpeg: a moderate `smoothing` for moving shots, `tripod` for locked-off shots. **How:** see 3446 and 3448 (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/verbacf92b/mac, checked 2026-10-24]

## Slow motion quality: interpolation and blending

3481. **The retime quality ladder** — Final Cut's Video Quality menu is the clearest map of the options: Fast (Floor) duplicates frames or rounds down, Fast (Nearest Frame) reduces artifacts but may stutter, Good (Frame Blending) blends neighbouring frames, Better (Optical Flow) draws new frames from pixel motion, Best (Machine Learning) uses bidirectional ML optical flow with better occlusion handling. Apple's tip: try frame blending first, go to optical flow or ML only if you see artifacts. ffmpeg's matching steps: `minterpolate=mi_mode=dup`, `mi_mode=blend`, `mi_mode=mci`; ML needs RIFE (missing). **How:** `-vf minterpolate=fps=60:mi_mode=dup`, `...:mi_mode=blend`, `...:mi_mode=mci` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/ver40b00150/mac, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3482. **minterpolate defaults to mci in 6.1** — the 6.1 help shows mi_mode default mci, mc_mode obmc, me_mode bilat, me epzs, mb_size 16, search_param 32, scd fdiff, scd_threshold 10. A bare `minterpolate=fps=60` therefore already runs the slow motion-compensated mode. **How:** `ffmpeg -hide_banner -h filter=minterpolate` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3483. **Bidirectional motion estimation** — me_mode `bidir` estimates vectors for each source frame forwards and backwards, while the default `bilat` estimates them directly for the interpolated frame; try bidir when bilat warps a shot. **How:** `-vf minterpolate=fps=60:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3484. **Pick the motion search algorithm** — `me` accepts esa (exhaustive), tss, tdls, ntss, fss, ds, hexbs, epzs (default) and umh (uneven multi-hexagon). esa is the brute-force search; test it on a short troublesome stretch only. **How:** `-vf minterpolate=fps=60:mi_mode=mci:me=esa` / `me=umh` (tested here 2026-10-24 on 1 s clips) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3485. **Smaller blocks and search window** — `mb_size` (4-16, default 16) is the macroblock size and `search_param` (default 32) the search range; smaller blocks follow small moving parts, a smaller search range suits slow motion between frames. `vsbmc=1` uses smaller blocks at object boundaries so they blur less. **How:** `-vf minterpolate=fps=60:mi_mode=mci:mb_size=8:search_param=16` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3486. **Scene-cut protection in minterpolate** — at a scene change motion vectors point in random directions, so `scd=fdiff` replaces interpolated frames there with duplicates when the frame difference passes `scd_threshold` (default 10); lower the threshold if a cut inside the clip still morphs. **How:** `-vf minterpolate=fps=60:mi_mode=mci:scd=fdiff:scd_threshold=5` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3487. **Exact NTSC rates in minterpolate** — `fps` accepts a rational like 60000/1001, so a 29.97 source can be doubled without drift. **How:** `-vf minterpolate=fps=60000/1001:mi_mode=mci` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#minterpolate, checked 2026-10-24]
3488. **Only analyse the part you use** — Final Cut analyses only the media between the clip's start and end points for optical flow; in ffmpeg put `-ss`/`-t` on the input before minterpolate so the slow filter only sees the used seconds. **How:** `ffmpeg -ss S -t T -i in.mp4 -vf minterpolate=... out.mp4` (the CLAUDE.md slow-mo recipe already uses this form) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/ver40b00150/mac, checked 2026-10-24] [repo: CLAUDE.md "Editing a phone video"]
3489. **framerate filter: cheap blended rate change** — `framerate` builds new frames as a linear interpolation of two frames inside the interp_start..interp_end window (0-255, defaults 15 and 240) and has its own scene detection (`scene`, default 8.2). It is not for interlaced media (deinterlace first). **How:** `-vf framerate=fps=60`; `-vf framerate=fps=50:interp_start=64:interp_end=192:scene=20` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#framerate, checked 2026-10-24]
3490. **Turn off framerate's scene detection** — the `scene_change_detect` flag is on by default; set `flags=0` on a single continuous shot where false cuts would leave duplicate frames. **How:** `-vf framerate=fps=60:flags=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#framerate, checked 2026-10-24]
3491. **See the motion vectors before interpolating** — `mestimate` exports block motion vectors as side data; `codecview` can draw them, showing where the motion is too big or chaotic for clean interpolation. **How:** `ffmpeg -i in.mp4 -vf mestimate=method=epzs:mb_size=16:search_param=7,codecview=mv=pf -frames:v 5 mv.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mestimate, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#codecview, checked 2026-10-24]
3492. **ML frame interpolation (RIFE)** — Practical-RIFE interpolates with `inference_video.py --multi=2` (or 4) on a video, `--img=input/` on numbered PNGs, `--scale=0.5` (or `--UHD`) for 4K, `--fps` to force the output rate; the README recommends model 4.25 for most scenes, needs Python <= 3.11, MIT licence. It is the open stand-in for Final Cut's Best (Machine Learning). **How:** needs Practical-RIFE + a model download (missing) [Practical-RIFE README (hzwer), https://raw.githubusercontent.com/hzwer/Practical-RIFE/main/README.md, checked 2026-10-24]
3493. **Average frames for a motion-blur or long-exposure look** — `tmix` mixes successive frames; the docs' example averages 7 frames with equal weights. Moving parts smear, static parts stay sharp. **How:** `-vf tmix=frames=7:weights="1 1 1 1 1 1 1"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
3494. **Weighted trails with tmix** — each frame gets its own weight (space separated; missing ones reuse the last) and the sum is normalised unless `scale` is set. Rising weights favour one end of the window; check by eye which end, since the docs only define the weights. **How:** `-vf tmix=frames=5:weights="1 2 3 4 5"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
3495. **Show only what moves** — the docs' temporal-difference example `weights="-1 2 -1":scale=1` keeps only temporal differences: a quick way to see which areas move (to place a reframe or check that a "static" shot is static). **How:** `-vf tmix=frames=3:weights="-1 2 -1":scale=1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
3496. **Blend-then-drop time-lapse** — instead of dropping frames (choppy), average every 10 frames and keep one of each 10, then retime to 30 fps; motion between kept frames becomes blur. **How:** `ffmpeg -i in.mp4 -vf "tmix=frames=10,framestep=10,setpts=N/(30*TB)" -r 30 -an lapse.mp4` (tested here 2026-10-24; how it looks not judged) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#framestep, checked 2026-10-24]
3497. **Two-frame blend with tblend** — tblend blends each frame with the previous one using any blend mode; `all_mode=average` is a 2-frame mix, `difference` shows change between frames. **How:** `-vf tblend=all_mode=average`; `-vf tblend=all_mode=difference` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tblend, checked 2026-10-24]
3498. **Light trails with lagfun** — lagfun slowly updates darker pixels so short flashes of light last longer (decay 0-1, default 0.95): car lights, sparklers, phone screens at night. **How:** `-vf lagfun=decay=0.95` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lagfun, checked 2026-10-24]
3499. **Check for high-frame-rate sources first** — Final Cut marks clips recorded at 95 fps or more as high frame rate, and iPhone Slo-mo records up to 240 fps; such clips give real slow motion without interpolation. Read the true rate before choosing a method. **How:** `ffprobe -v error -select_streams v:0 -show_entries stream=r_frame_rate,avg_frame_rate -of csv=p=0 in.mp4` [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/play-back-slow-motion-clips-ver5daf09b7a/mac, checked 2026-10-24]
3500. **Conform a high-fps clip so every frame plays** — Final Cut's Automatic Speed plays every frame of, say, 120 fps footage at the project's 30 fps, so nothing is skipped or duplicated. In ffmpeg renumber the timestamps at the project rate: a 2 s 60 fps clip became 4 s with all 120 frames. **How:** `ffmpeg -i hfr.mp4 -vf "setpts=N/(30*TB)" -r 30 out.mp4` (tested here 2026-10-24: 120 frames, 4.0 s) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/ver40b00150/mac, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts, checked 2026-10-24]
3501. **Or scale the input timestamps with -itsscale** — `-itsscale` rescales input timestamps by a factor before decoding filters; 2 on a 60 fps clip, output at 30 fps, also gave 4 s with 120 frames. Audio would need its own tempo change. **How:** `ffmpeg -itsscale 2 -i hfr.mp4 -an -r 30 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]

## Speed changes, ramps and time remap in ffmpeg

3502. **setpts knows time, frame number and timebase** — the expression can use T (current time in s), N (frame count), PTS, STARTPTS, TB (timebase), FRAME_RATE (constant-rate video only), PREV_INPTS/PREV_OUTPTS and the eval functions (if, lt, between, clip, st/ld). That is enough to write a whole speed curve in one filter. **How:** see 3503 [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts, checked 2026-10-24] [ffmpeg-utils docs, https://ffmpeg.org/ffmpeg-utils.html#Expression-Evaluation, checked 2026-10-24]
3503. **One-expression speed ramp** — keep the first second at normal speed, then play the rest at half speed: output time = T before 1 s, 1+(T-1)*2 after. A 3 s clip came out 5 s long. Add `fps=30` after it so the output is constant-rate (frames are duplicated where it slows; interpolate first if that stutters). **How:** `ffmpeg -i in.mp4 -vf "setpts='if(lt(T,1),PTS,(1+(T-1)*2)/TB)',fps=30" -an ramp.mp4` (tested here 2026-10-24: 5.0 s) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#setpts_002c-asetpts, checked 2026-10-24]
3504. **Speed segments like Final Cut's Blade Speed** — Final Cut builds variable speed from "speed segments", each with its own constant speed (its Speed Ramp preset splits a range into four). In ffmpeg: split, trim each segment, give each its own setpts factor and concat. 1 s at 1x + 1 s at 0.5x + 1 s at 2x gave 3.5 s. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]split=3[a][b][c];[a]trim=0:1,setpts=PTS-STARTPTS[v1];[b]trim=1:2,setpts=2*(PTS-STARTPTS)[v2];[c]trim=2:3,setpts=0.5*(PTS-STARTPTS)[v3];[v1][v2][v3]concat=n=3:v=1:a=0,fps=30[v]" -map "[v]" seg.mp4` (tested here 2026-10-24: 3.5 s) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/create-variable-speed-effects-ver95783cbbc/mac, checked 2026-10-24]
3505. **Speed segments with their sound** — give each audio segment the inverse tempo with atempo and concat video and audio together (v=1:a=1), so sound stays in sync per segment. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]trim=0:1,setpts=PTS-STARTPTS[v1];[0:a]atrim=0:1,asetpts=PTS-STARTPTS[a1];[0:v]trim=1:2,setpts=2*(PTS-STARTPTS)[v2];[0:a]atrim=1:2,asetpts=PTS-STARTPTS,atempo=0.5[a2];[v1][a1][v2][a2]concat=n=2:v=1:a=1[v][a]" -map "[v]" -map "[a]" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atempo, checked 2026-10-24]
3506. **Ramp duration = ramp feel** — in Final Cut a speed transition between segments makes the change gradual; the shorter the transition, the faster the speed ramps; there is no smooth transition between a forward and a reverse segment. In ffmpeg build the ramp from several short in-between segments (e.g. 1x → 0.75x → 0.5x) instead of one jump. **How:** extend the 3504 graph with more trim/setpts pairs (tested here 2026-10-24 with three segments) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/add-speed-transitions-ver41a2cd3ae/mac, checked 2026-10-24]
3507. **atempo above 2x skips samples** — atempo accepts 0.5-100, but above 2 it skips samples instead of blending them; for a clean 3x chain two instances of sqrt(3). **How:** `ffmpeg -i in.mp4 -af "atempo=sqrt(3),atempo=sqrt(3)" -vf setpts=PTS/3 out.mp4` (tested here 2026-10-24: 1.07 s from 3 s) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atempo, checked 2026-10-24]
3508. **Change audio tempo at a set time** — asendcmd can send `tempo` to atempo at a timestamp, e.g. 1.5x from 1 s on; a 3 s file became 2.35 s. **How:** `ffmpeg -i in.mp4 -vn -af "asendcmd=c='1.0 atempo tempo 1.5',atempo" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sendcmd_002c-asendcmd, checked 2026-10-24]
3509. **rubberband for slowed sound** — the rubberband filter (librubberband, present in this build) time-stretches with controls for transients (crisp/mixed/smooth), window (standard/short/long), phase and pitch quality; tempo also works as a command. Compare it with atempo on a slow-mo voice. **How:** `ffmpeg -i in.mp4 -vn -af rubberband=tempo=0.5:transients=smooth:window=long out.wav` (tested here 2026-10-24: 3 s → 6.04 s) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rubberband, checked 2026-10-24]
3510. **Let the pitch move with the speed (tape effect)** — Final Cut preserves pitch by default and lets you turn Preserve Pitch off to accentuate a retime. In ffmpeg, asetrate changes speed and pitch together (like a tape), then aresample restores the sample rate; 2x halved a 3 s file to 1.5 s. **How:** `ffmpeg -i in.mp4 -vn -af asetrate=44100*2,aresample=44100 chip.wav` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/ver40b00150/mac, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#asetrate, checked 2026-10-24]
3511. **trim does not reset timestamps** — trim keeps the original timestamps (the docs say so), so a clip trimmed from 1 s still starts at 1.0 s and players or concat may show a gap. Add setpts=PTS-STARTPTS (and asetpts for audio) after it. **How:** `-vf trim=start=1,setpts=PTS-STARTPTS -af atrim=start=1,asetpts=PTS-STARTPTS` (tested here 2026-10-24: without the setpts the mkv start_time was 1.000000) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#trim, checked 2026-10-24]
3512. **Trim by frame number** — `start_frame`/`end_frame` count frames that pass through the filter instead of reading timestamps: exact for "frames 15 to 44". **How:** `-vf trim=start_frame=15:end_frame=45,setpts=PTS-STARTPTS` (tested here 2026-10-24: 30 frames) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#trim, checked 2026-10-24]
3513. **Several trim limits are OR, not AND** — with more than one start/end option, trim keeps every frame that matches at least one of them; to require all at once, chain two trim filters. **How:** `trim=start=2,trim=end_frame=200` instead of one trim with both [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#trim, checked 2026-10-24]
3514. **fps rounding mode** — the fps filter drops or duplicates frames to reach a constant rate; `round` picks zero, inf, down, up or near (default). Keep the same mode across clips so conversions line up. **How:** `-vf fps=fps=24:round=down` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
3515. **Pad a late video start with fps start_time** — `start_time=0` makes fps assume the first frame belongs at 0 s, padding the beginning with copies of the first frame (e.g. video starting after the audio) or trimming negative-time frames. **How:** `-vf fps=fps=30:start_time=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
3516. **Keep the last frame when converting rate** — `eof_action=pass` passes the last frame through if the input duration has not been reached; a 3 s 30 fps clip at 24 fps gave 72 frames, 3.0 s. **How:** `-vf fps=fps=24:eof_action=pass` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
3517. **Named rates in fps** — fps accepts source_fps, ntsc (30000/1001), pal (25), film (24) and ntsc_film (24000/1001) as constants. **How:** `-vf fps=fps=ntsc_film` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#fps-1, checked 2026-10-24]
3518. **-fps_mode decides what the muxer does with timing** — passthrough passes each frame with its demuxer timestamp, cfr duplicates/drops to a constant rate, vfr passes frames through (dropping same-timestamp ones). After dropping duplicates, vfr kept the original timing (75 frames, 2.97 s). **How:** `ffmpeg -i dup.mp4 -vf mpdecimate -fps_mode vfr -an out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Advanced-options, checked 2026-10-24]
3519. **Keep one frame in N with framestep** — `framestep=step=N` selects one frame every N; renumber at the target rate for a time-lapse (3 s at step 4 → 0.77 s). select with `not(mod(n,5))` does the same with more conditions available. **How:** `-vf "framestep=step=4,setpts=N/(30*TB)" -r 30`; `-vf "select='not(mod(n,5))',setpts=N/(30*TB)"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#framestep, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#select_002c-aselect, checked 2026-10-24]
3520. **Jump cuts instead of fast motion** — Final Cut's "Jump Cut at Markers" compresses time by skipping 3-30 frames at each marker rather than playing fast. In ffmpeg drop a frame range from video and the same time from audio with select/aselect. **How:** `-vf "select='not(between(n,30,59))',setpts=N/FRAME_RATE/TB" -af "aselect='not(between(t,1,2))',asetpts=N/SR/TB"` (tested here 2026-10-24: 3 s → 2.02 s) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/speed-up-a-clip-with-jump-cuts-ver9b215183d/mac, checked 2026-10-24]
3521. **Stutter or drop frames in a pattern** — shuffleframes maps input frames to output slots per group; `0 2 1` swaps frames 2 and 3 of every three, `-1` drops a slot (so `0 -1` keeps every other frame). Use for deliberate stutter or step-printing looks. **How:** `-vf "shuffleframes=0 2 1"`; `-vf "shuffleframes=0 -1"` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#shuffleframes, checked 2026-10-24]
3522. **Repeat a short chunk for a stutter loop** — loop repeats `size` frames starting at `start` `loop` times; the docs' example loops the first 10 frames 5 times. Renumber timestamps after it. **How:** `-vf loop=loop=5:size=10:start=0,setpts=N/FRAME_RATE/TB` (tested here 2026-10-24: 3 s → 4.67 s) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#loop, checked 2026-10-24]
3523. **Hold the first frame before the action starts** — tpad with `start_mode=clone` adds copies of the first frame before the clip (start_duration in seconds), a pre-roll hold for a title to land on. **How:** `-vf tpad=start_duration=1:start_mode=clone` (tested here 2026-10-24: 3 s → 4 s) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tpad, checked 2026-10-24]
3524. **Replace a frame range with one frame from another input** — freezeframes freezes frames first..last using frame `replace` from the second input (e.g. a clean frame over a glitch or blink). **How:** `ffmpeg -i in.mp4 -i in.mp4 -filter_complex "[0:v][1:v]freezeframes=first=30:last=60:replace=30" -an out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#freezeframes, checked 2026-10-24]
3525. **Instant replay** — Final Cut's Instant Replay appends a duplicate of the selected range and plays it at the chosen speed. In ffmpeg split the range, slow the copy, concat. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]trim=1:2,setpts=PTS-STARTPTS,split[a][b];[b]setpts=2*PTS[s];[a][s]concat=n=2:v=1:a=0,fps=30" -an replay.mp4` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/create-instant-replays-ver40affee3/mac, checked 2026-10-24]
3526. **Rewind effect** — Final Cut's Rewind duplicates the range, plays the copy backwards at 1x, 2x or 4x, then plays the range forward again. In ffmpeg: three copies, the middle one reversed and sped up. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]trim=1:2,setpts=PTS-STARTPTS,split=3[a][b][c];[b]reverse,setpts=0.5*PTS[r];[a][r][c]concat=n=3:v=1:a=0" -an rewind.mp4` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/reverse-or-rewind-clips-ver15f879b3/mac, checked 2026-10-24]
3527. **Stream-copy segments split only at keyframes** — to reverse a long clip in pieces, `-f segment -c copy` cuts only on keyframes, so a short phone clip may come out as one piece; re-encode with forced keyframes (or use trim) when you need exact pieces. **How:** `ffmpeg -i in.mp4 -f segment -segment_time 1 -reset_timestamps 1 -c copy sg%02d.mp4` (tested here 2026-10-24: one segment only, keyframe interval longer than the clip) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#reverse, checked 2026-10-24] [ffmpeg-formats docs, https://ffmpeg.org/ffmpeg-formats.html#segment_002c-stream_005fsegment_002c-ssegment, checked 2026-10-24]
3528. **Drop near-duplicate frames (screen recordings, static stretches)** — mpdecimate drops frames whose 8x8 blocks differ less than hi (768 = 64*12) and where no more than frac (0.33) of blocks exceed lo (320); `max`/`keep` limit consecutive drops. Renumbering afterwards compresses static stretches (a 25-in-30 clip went from 3 s to 2.5 s); keep `-fps_mode vfr` instead to keep real timing. **How:** `-vf mpdecimate=hi=768:lo=320:frac=0.33,setpts=N/FRAME_RATE/TB` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#mpdecimate, checked 2026-10-24]
3529. **Remove one duplicate in every N frames** — decimate drops one frame per `cycle`; a 25 fps clip stored as 30 fps with duplicates came back to 25 fps with cycle=6. (mpdecimate `mode=1` from the online docs does not exist in 6.1.) **How:** `-vf decimate=cycle=6` (tested here 2026-10-24: r_frame_rate 25/1) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#decimate-1, checked 2026-10-24]
3530. **24p to 30 with a pulldown pattern** — telecine applies a pulldown pattern; 23 is classic 24p→30i, 2332 is listed as preferred, 222222222223 is "Euro pulldown" for 24p→25i. 1 s of 24p became 30 frames. Undo such material with dejudder (cycle 4 for 24→30, 5 for 25→30, 20 mixed). **How:** `-vf telecine=pattern=23`; `-vf dejudder=cycle=4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#telecine, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dejudder, checked 2026-10-24]
3531. **Find frozen stretches after retiming** — freezedetect logs where the picture does not change for at least `d` seconds within noise `n`; useful to confirm a hold is as long as planned, or that a ramp did not freeze by mistake. **How:** `ffmpeg -i out.mp4 -vf freezedetect=n=-60dB:d=1 -map 0:v -f null -` (tested here 2026-10-24: reported freeze_duration 2.03333 on a 2 s hold) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#freezedetect, checked 2026-10-24]
3532. **Pick the frame rate before anything else** — Final Cut's guide says the most important early decision is the project frame rate: format and size are easy to change later, but changing the rate can shift every edit point. Decide 30 (or 25/24) before cutting on beats. **How:** probe the main source, then set `fps` once for every clip [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/conform-frame-sizes-and-rates-ver3363b44e/mac, checked 2026-10-24]
3533. **Find the action peak for a ramp from optical flow** — OpenCV's DIS optical flow gives a per-frame motion size; the frame with the most motion is a candidate for the slowest point of a ramp. **How:** `/home/user/tools/venv/bin/python -I motion_peak.py in.mp4` using `cv2.DISOpticalFlow.create(cv2.DISOPTICAL_FLOW_PRESET_FAST)` and the mean flow length per frame (tested here 2026-10-24: printed the peak frame and time) [OpenCV 5.0.0 cv2 API, checked 2026-10-24 (tested here)]

## Reverse, holds and timing in HyperFrames and GSAP

3534. **HyperFrames can't play media backwards** — `data-playback-rate` and the `rate` automation lane take 0.1-10, so reverse, rewind and boomerang must be rendered in ffmpeg first and placed as their own clip. **How:** render with `reverse` (see 3526), then `<video src="rewind.mp4" data-duration=...>` [repo: .claude/skills/hyperframes/references/format.md] [repo: .claude/skills/hyperframes/references/motion.md]
3535. **Constant speed in HyperFrames keeps pitch** — `data-playback-rate` on the media gives a constant speed change (0.1-10) with pitch-preserved sound; use it for a plain 1.5x setup shot instead of re-encoding. **How:** `<video ... data-playback-rate="1.5">` [repo: .claude/skills/hyperframes/references/motion.md]
3536. **Slow the whole GSAP animation with timeScale** — timeScale 0.5 plays a timeline at half speed (a 2 s timeline takes 4 s), -1 plays it backwards; duration() still reports 2, so place later beats by real time. **How:** `tl.timeScale(0.5)` (tested here 2026-10-24 in node with gsap 3.14.2: duration() 2) [GSAP docs, https://gsap.com/docs/v3/GSAP/Timeline/timeScale(), checked 2026-10-24]
3537. **Replay a stretch of animation with tweenFromTo** — `tl.tweenFromTo(1, 3, {duration: 1})` creates a tween that scrubs the timeline's playhead from 1 s to 3 s (here at 2x), which is a time remap for motion graphics; it pauses the timeline first. **How:** `master.add(tl.tweenFromTo(1, 3, {duration: 1}))` (tested here 2026-10-24: half-way the timeline time was 2) [GSAP docs, https://gsap.com/docs/v3/GSAP/Timeline/tweenFromTo(), checked 2026-10-24]
3538. **SlowMo ease for fly-through text** — SlowMo decelerates, moves linearly for a chosen share (linearRatio), then accelerates: zoom text in, keep it moving slowly long enough to read, zoom out, without the velocity jumps of three chained tweens. It lives in EasePack (not GSAP core; the repo vendors only core). **How:** copy `EasePack.min.js` from the gsap 3.14.2 npm package to assets/vendor, `gsap.registerPlugin(EasePack)`, `ease: "slow(0.5, 0.8)"` (tested here 2026-10-24 in node) [GSAP docs, https://gsap.com/docs/v3/Eases/SlowMo, checked 2026-10-24]
3539. **Custom speed curves with CustomEase** — CustomEase turns an SVG path drawn in the Ease Visualizer into an ease, e.g. a camera move that rushes, hangs, then settles. **How:** `CustomEase.create("hop", "M0,0 C...")` then `ease: "hop"` (needs CustomEase.min.js beside gsap in assets/vendor) [GSAP docs, https://gsap.com/docs/v3/Eases/CustomEase, checked 2026-10-24]
