## vid.stab: options and traps (ffmpeg 6.1 here)

3441. **Read this build's vid.stab defaults, not the web page** — the online docs give smoothing 10, mincontrast 0.3, relative 0 and optalgo gauss, but the 6.1 build here reports smoothing 15, mincontrast 0.25, relative 1 and a default optalgo called `opt` (global optimization). Tune from the real defaults. **How:** `ffmpeg -hide_banner -h filter=vidstabtransform` and `ffmpeg -hide_banner -h filter=vidstabdetect` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3442. **Keep accuracy at or above shakiness** — the 6.1 help text describes accuracy as ">=shakiness" (1 low, 15 high/slow); shakiness 1 means little shake, 10 strong shake or a quick camera. For a violently shaken clip set both high. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=shakiness=10:accuracy=15:result=s10.trf -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24]
3443. **Faster first pass for a quick preview** — accuracy is the slow knob (15 = high, slow) and stepsize sets the search step before the 1-pixel refinement around the minimum; lowering accuracy and raising stepsize trades precision for speed. Use it to judge a clip, then re-run at full accuracy for the deliverable. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=shakiness=5:accuracy=9:stepsize=12:result=fast.trf -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24]
3444. **Lower mincontrast for flat, low-texture shots** — measurement fields whose contrast is below mincontrast are discarded, so sky, walls or night footage may leave too few fields; lower it (6.1 default 0.25) so more fields count. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=mincontrast=0.15:result=mc.trf -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24] [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3445. **See what the detector measured** — `show=1` or `show=2` draws the measurement fields and transforms into the output, so you can see whether it locked on the background or on a moving subject. Write it to a real file (not null). **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=show=1:result=show.trf -t 1 show1.mp4` (also `show=2`) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabdetect-1, checked 2026-10-24] [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3446. **Virtual tripod: lock a near-static shot to one frame** — set `tripod=N` (1-based reference frame) in pass 1 and `tripod=1` in pass 2; motion is then measured against that frame and the view is held still. Frames before the reference are not stabilized (still zoomed/cropped) and the view snaps to the reference pose there, so pick an early reference. **How:** `ffmpeg -i shaky.mp4 -vf vidstabdetect=tripod=1:result=tri.trf -f null -` then `ffmpeg -i shaky.mp4 -vf vidstabtransform=tripod=1:input=tri.trf -an tri.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3447. **smoothing=0 simulates a static camera** — smoothing is the half-window (value*2+1 frames) of the low-pass on camera motion; 0 is the special case "static camera" without needing tripod mode. **How:** `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=s10.trf:smoothing=0 sm0.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3448. **Bigger smoothing = floatier camera, slower pans** — a larger value gives a smoother video but limits how fast the camera may accelerate in pans and tilts; smoothing=30 uses 61 frames. Use high values on walking shots, low values when the operator pans on purpose. **How:** `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=s10.trf:smoothing=30,unsharp=5:5:0.8:3:3:0.4 sm30.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3449. **Pick the camera-path algorithm** — 6.1 offers `opt` (global optimization, default here), `gauss` (Gaussian low-pass) and `avg` (simple averaging). If the default path looks wrong on a shot, render the other two and compare side by side. **How:** `vidstabtransform=input=s10.trf:optalgo=gauss:smoothing=10` / `optalgo=avg` / `optalgo=opt` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3450. **Cap the correction with maxshift and maxangle** — maxshift limits translation in pixels and maxangle limits rotation in radians (degrees*PI/180); -1 means no limit. Capping stops one bad measurement from throwing the frame far off. **How:** `vidstabtransform=input=s10.trf:maxshift=20:maxangle=0.05` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3451. **Smooth position only, leave rotation alone** — Final Cut's SmoothCam has separate Translation, Rotation and Scale smoothing; vid.stab has one smoothing value, but maxangle=0 allows no rotation correction, so only position is stabilized. **How:** `vidstabtransform=input=s10.trf:maxangle=0` (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/verbacf92b/mac, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3452. **Border fill: previous-frame vs black** — `crop=keep` (default) fills the moving borders with image from the previous frame, `crop=black` fills them black; with `optzoom=0` you see the borders and can judge how far the frame really moves. **How:** `vidstabtransform=input=s10.trf:crop=black:optzoom=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3453. **Zoom modes: static, adaptive, manual** — `optzoom=1` (default) picks one static zoom so only very strong moves show borders; `optzoom=2` zooms adaptively so no borders show, limited per frame by `zoomspeed` (0-5 %, default 0.25); `zoom=` adds a fixed percentage on top (negative zooms out). **How:** `vidstabtransform=input=s10.trf:optzoom=2:zoomspeed=0.5`; `vidstabtransform=input=s10.trf:zoom=-5:optzoom=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3454. **Bicubic interpolation for the final render** — interpol is no / linear (horizontal only) / bilinear (default) / bicubic (cubic in both directions, slow). Preview bilinear, render bicubic. **How:** `vidstabtransform=input=s10.trf:interpol=bicubic` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3455. **Absolute vs relative transforms** — `relative=1` (the 6.1 default) treats transforms as relative to the previous frame, `relative=0` as absolute. Tripod mode is equivalent to relative=0:smoothing=0. **How:** `vidstabtransform=input=s10.trf:relative=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3456. **invert=1 flips the stored transforms** — the option only inverts the transforms read from the file. Running a clean clip through another clip's inverted, relative transforms ran here, but whether it reproduces that clip's shake was not checked by eye, so look at frames before using it as a "borrowed shake". **How:** `ffmpeg -i clean.mp4 -vf vidstabtransform=input=s10.trf:invert=1:relative=1:smoothing=0:optzoom=0 -an inv.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#vidstabtransform-1, checked 2026-10-24]
3457. **Dump the per-frame global motion with debug=1** — pass 2 with debug=1 writes `global_motions.trf` in the working folder: one data line per frame `time x y alpha zoom extra` (x/y in pixels, alpha in radians), each followed by a comment line. Use it to find the shakiest seconds. **How:** `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=s10.trf:debug=1 -f null - && head -4 global_motions.trf` (tested here 2026-10-24: frame 2 read `0 35.107748 17.861798 -0.035629 -0.128952 0`) [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3458. **Feed vid.stab your own camera path** — vidstabtransform also accepts the global_motions format as input (the time column is ignored, frames are taken in file order), which is the supported way to apply a path you computed or edited yourself, e.g. in numpy. **How:** edit global_motions.trf, then `ffmpeg -i shaky.mp4 -vf vidstabtransform=input=global_motions.trf -an own.mp4` (tested here 2026-10-24 with the unedited dump) [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3459. **This build writes text .trf files, and fileformat is missing** — the current vid.stab doc says ffmpeg always gets the binary encoding, but libvidstab 1.1.0 here wrote a text file starting `VID.STAB 1` with `Frame N (List ...)` lines, and `fileformat=ascii` failed with "Option not found". Text means you can read the fields with grep. **How:** `head -c 300 s10.trf` (tested here 2026-10-24); the reader auto-detects either encoding [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3460. **A .trf belongs to one resolution** — every value in the file is in pixels of the analysed frame and the frame size is not stored, so detecting on a downscaled copy and transforming the full-size clip does not work unless you rescale the values yourself. Detect at the size you transform. **How:** run both passes on the same `-vf` chain and size [vid.stab docs/trf-format.md, https://raw.githubusercontent.com/georgmartius/vid.stab/master/docs/trf-format.md, checked 2026-10-24]
3461. **Drop duplicated frames before stabilizing** — duplicates (e.g. 25 fps stored as 30 fps) are measured as exactly zero motion and show up as a regular jerk; drop them with mpdecimate in both passes (or work at the true rate). **How:** `ffmpeg -i dup.mp4 -vf mpdecimate,vidstabdetect=result=dd.trf -f null -` then `ffmpeg -i dup.mp4 -vf mpdecimate,vidstabtransform=input=dd.trf -fps_mode vfr dd.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3462. **Deinterlace before both passes** — vid.stab treats each frame as one progressive picture, so combing is measured as content and the motion is an average of two fields; put the same deinterlacer before detect and transform. **How:** `ffmpeg -i il.mp4 -vf yadif,vidstabdetect=result=il.trf -f null -` then `ffmpeg -i il.mp4 -vf yadif,vidstabtransform=input=il.trf,unsharp=5:5:0.8:3:3:0.4 out.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3463. **Convert 10-bit 4:2:2 to 8-bit 4:2:0 first** — the README warns that 10-bit 4:2:2 input gives chroma shift and colour bleeding; add `format=yuv420p` at the start of both passes. **How:** `ffmpeg -i t422.mp4 -vf format=yuv420p,vidstabdetect=result=t422.trf -f null -` then `ffmpeg -i t422.mp4 -vf format=yuv420p,vidstabtransform=input=t422.trf out.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3464. **Hyperlapse: drop frames first, then stabilize, in both passes** — any filter that changes the number, order or rate of frames (fps, minterpolate, select, framestep, trim, -r) must run before vidstabdetect too, or the transforms stop lining up ("not enough transforms found"). For a hyperlapse from walking video, framestep before both passes. **How:** `ffmpeg -i walk.mp4 -vf "framestep=3,vidstabdetect=shakiness=8:result=hl.trf" -f null -` then `ffmpeg -i walk.mp4 -vf "framestep=3,vidstabtransform=input=hl.trf:smoothing=10,unsharp=5:5:0.8:3:3:0.4,setpts=N/(30*TB)" -r 30 -an hyper.mp4` (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3465. **Judge stabilization side by side** — put the original and the result next to each other (LearnOpenCV's stabilizer writes a "Before and After" hconcat) and watch both; on a vertical deliverable stack them. **How:** `ffmpeg -i shaky.mp4 -i stab.mp4 -filter_complex "[0:v][1:v]hstack" -t 2 sbs.mp4` (or `vstack`) (tested here 2026-10-24) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3466. **Newer vid.stab has an L1-optimal "dolly/crane" path** — the current README describes an L1-optimal camera path (Grundmann et al., CVPR 2011) made of static, linear and parabolic segments, steered by zoom/optzoom (crop budget) and smoothing. The 6.1 build here lists only opt/gauss/avg, so don't assume it has the L1 path; it would need a newer libvidstab build. **How:** check `ffmpeg -h filter=vidstabtransform` for the available optalgo values (tested here 2026-10-24) [vid.stab README, https://raw.githubusercontent.com/georgmartius/vid.stab/master/README.md, checked 2026-10-24]
3467. **Black bars after stabilizing: three fixes** — Final Cut's guide gives three ways to lose the black edges a big move causes: lower the smoothing values, cut out the shakiest stretch, or crop the edges. In ffmpeg: lower `smoothing`, trim with -ss/-t in both passes, or leave `optzoom=1`/`2` on. **How:** `vidstabtransform=input=s10.trf:smoothing=8` (tested here 2026-10-24 as part of the smoothing tests) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/verbacf92b/mac, checked 2026-10-24]

## deshake and OpenCV stabilizers

3468. **Tell deshake where the static background is** — `x:y:w:h` limits the motion search to a rectangle (same meaning as drawbox), so a person walking through the frame is not mistaken for camera motion; -1 means the full frame. Draw the box first to check it. **How:** `ffmpeg -i shaky.mp4 -vf drawbox=x=0:y=0:w=200:h=150:color=red -frames:v 1 box.png`, then `-vf deshake=x=0:y=0:w=200:h=150` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3469. **Raise deshake's search range for big jolts** — rx/ry set the maximum movement searched in x and y, 0-64 px, default 16; a shake bigger than that is not found. **How:** `-vf deshake=rx=64:ry=64` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3470. **Choose how deshake fills the edges** — edge = blank (zeros), original (original image), clamp (extruded edge pixels) or mirror (default). Mirror hides gaps on texture but can show mirrored objects; clamp smears the last row. **How:** `-vf deshake=edge=clamp` / `edge=blank` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3471. **deshake blocksize, contrast and search speed** — blocksize (4-128, default 8) is the motion-search block; only blocks whose darkest-to-lightest difference exceeds `contrast` (1-255, default 125) are used; `search=less` is a less exhaustive, faster search than the default exhaustive one. Lower contrast on flat footage. **How:** `-vf deshake=blocksize=16:contrast=60`; `-vf deshake=search=less` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3472. **Log deshake's motion search** — `filename=` writes a per-frame log with columns Ori/Avg/Fin for x, y, angle and zoom, so you can see the raw and the corrected motion. **How:** `ffmpeg -i shaky.mp4 -vf deshake=filename=deshake.log -f null - && head -3 deshake.log` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake, checked 2026-10-24]
3473. **deshake_opencl needs an OpenCL device (none here)** — the feature-point OpenCL stabilizer offers tripod, smooth_strength (0-1, 0 = adaptive), smooth_window_multiplier (window = fps x value, default 2.0) and adaptive_crop. This container has no OpenCL device (`-init_hw_device opencl` failed with "No such device"), so use vid.stab. **How:** needs an OpenCL GPU (missing) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deshake_005fopencl, checked 2026-10-24]
3474. **OpenCV point-feature stabilizer as a second opinion** — LearnOpenCV's script tracks Shi-Tomasi corners (maxCorners 200, qualityLevel 0.01, minDistance 30) with Lucas-Kanade flow, fits `estimateAffinePartial2D` per frame pair, integrates the trajectory, smooths it and warps each frame; it writes a before/after video. **How:** copy the script into its own folder, then `/home/user/tools/venv/bin/python -I vs.py --input shaky.mp4 --output-dir out --output-name out.mp4 --smoothing-radius 15 --no-display --validate` (tested here 2026-10-24: "VALIDATION PASSED: 89 frames, 1280x360, mean tracked points 28.26") [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3475. **Moving-average radius = how much intent survives** — the script's default radius 50 is a 101-frame window (50 each side) chosen to remove high-frequency shake while keeping slower intentional camera motion; it smooths x, y and angle separately and pads the ends with edge values. Smaller radius keeps more of the operator's moves. **How:** `--smoothing-radius 15` for short handheld clips (tested here 2026-10-24) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3476. **Hide warp wedges with a 4% centre scale** — the script's `fix_border` scales each stabilized frame by 1.04 around its centre to hide most of the empty wedges the warp leaves. In ffmpeg the same idea is a small scale-up then crop back to size. **How:** in Python `cv2.warpAffine(frame, cv2.getRotationMatrix2D((w/2,h/2),0,1.04),(w,h))` (part of the tested run above) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3477. **Fall back to the last good transform** — when a frame pair has fewer than 3 tracked points or a non-finite result, the script reuses the previous transform instead of failing; copy that guard into any custom tracker or reframe script. **How:** see `estimate_transforms()` in the script (tested here 2026-10-24) [LearnOpenCV video_stabilization.py (Satya Mallick), https://raw.githubusercontent.com/spmallick/learnopencv/master/VideoStabilization/video_stabilization.py, checked 2026-10-24]
3478. **Gyro stabilization for action-cam footage** — Gyroflow stabilizes from the gyroscope (and optionally accelerometer) data that GoPro (HERO 5+), Sony, Insta360, DJI and others record, with rolling-shutter correction, adaptive zoom, horizon levelling and lens profiles; it also works with already-HyperSmoothed GoPro clips (HERO 8+). For a client's action-cam file, ask for the original file with metadata intact. **How:** needs Gyroflow (missing; GPLv3) [Gyroflow README, https://raw.githubusercontent.com/gyroflow/gyroflow/master/README.md, checked 2026-10-24]
3479. **Phone footage can be gyro-stabilized too** — for cameras without a built-in gyro, Gyroflow reads logs from phone apps such as Sensor Logger (iOS/Android) or a separate logger; its "additional 3D rotation" option is noted as useful for framing vertical videos. **How:** needs Gyroflow (missing) plus a gyro log recorded during the shoot [Gyroflow README, https://raw.githubusercontent.com/gyroflow/gyroflow/master/README.md, checked 2026-10-24]
3480. **Pans and zooms: smoothing; static shots: tripod** — Final Cut's InertiaCam is for footage with camera moves such as pans and zooms (one Smoothing slider) and may offer Tripod Mode after analysis; SmoothCam smooths translation, rotation and scale separately. In ffmpeg: a moderate `smoothing` for moving shots, `tripod` for locked-off shots. **How:** see 3446 and 3448 (tested here 2026-10-24) [Apple FCP User Guide, https://support.apple.com/guide/final-cut-pro/verbacf92b/mac, checked 2026-10-24]
