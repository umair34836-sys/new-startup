## Project folders and file naming

4641. **Pick the naming convention before the shoot** — Frame.io: decide it before a single shot is recorded; a camera name like `WB2A2468.MOV` says nothing, while `20181004-wfg-filenaming-camA-01-001-4k30.mov` gives date (YYYYMMDD), project ID, scene, camera, shot, take and format. **How:** agree one pattern per job (e.g. `YYYYMMDD-<proj>-<cam>-<shot>-<take>-<res><fps>`) and write it in the job's notes before ingest; apply it to every render too. [Frame.io Workflow Guide, "File Naming", https://workflow.frame.io/guide/file-naming, checked 2026-10-24]
4642. **Unique names stop offload overwrites** — a convention that forbids duplicate file names makes it much harder to overwrite footage during camera offloads, and every team (DIT, editorial, VFX) must use the same date format. **How:** before merging cards, `find card -type f -printf '%f\n' | sort | uniq -d` must print nothing; it printed `A001_Clip001.mov` when two cards held that name. (tested here 2026-10-24) [Frame.io Workflow Guide, "File Naming", https://workflow.frame.io/guide/file-naming, checked 2026-10-24]
4643. **Numbered top-level folders** — bins grouped into sequences, audio, footage, graphics and misc, numbered (`00_Sequences`, `10_Audio`, `20_Footage`, `30_Graphics`, `40_Misc`) only so alphabetical sorting keeps that order. **How:** `mkdir -p proj/{00_Sequences,10_Audio/{Music,SFX,VO},20_Footage,30_Graphics,40_Misc}`; `ls proj` lists 00_Sequences first. (tested here 2026-10-24) [Frame.io Workflow Guide, "Bin Organization", https://workflow.frame.io/guide/bin-organization, checked 2026-10-24]
4644. **One folder per camera card (A001, B002 ...)** — give every camera a letter and count its cards in shooting order (A001-A005, B001-B002, C001-C004) so `/A003/Clip001.mov` and `/F002/Clip001.mov` stay distinguishable even when clip names collide. **How:** `mkdir -p OCN/<date>/{A001,B001}` and copy each card into its own folder untouched. [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24]
4645. **ISO-8601 date folders above the cards** — Freethink's layout: `Original Digital Negatives/20180723/{A001,B001,...}` plus `20180723_Sound`, so the file system lists days chronologically and a director can say "the shot from Tuesday". **How:** `mkdir -p OCN/20180723/{A001,A002,B001} OCN/20180723_Sound OCN/20180724/{A003,B003}`; `ls OCN` sorted 20180723 first. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24]
4646. **Prefix repeating prosumer clip names with the card** — DSLRs, GoPros and drones restart numbering every card, so one day can hold ten `C0001` files; Resolve relinks largely by file name, so rename every clip to be unique. **How:** `for d in card/*/; do r=$(basename "$d"); for f in "$d"*.mov; do b=$(basename "$f"); echo "$f,$d${r}_$b" >> rename_log.csv; mv "$f" "$d${r}_$b"; done; done` gave `A001/A001_Clip001.mov`, `F002/F002_Clip001.mov`. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24]
4647. **Log the original camera name before any rename** — renaming clips and losing the original camera file names "can be a disaster" for conform; copy the OCF names into another column first. **How:** keep the `old,new` `rename_log.csv` written by the rename loop next to the media and hand it over with the project. (tested here 2026-10-24) [Frame.io Workflow Guide, "The most common conform issues", https://workflow.frame.io/guide/common-conform-issues, checked 2026-10-24]
4648. **Rename clips from their recording date** — exiftool can rename by writing FileName from CreateDate with a date format; `%%-c` adds a copy number if the name exists and `%%e` keeps the extension. **How:** `exiftool '-FileName<CreateDate' -d '%Y%m%d_%H%M%S%%-c.%%e' dir` renamed a clip stamped 2018-10-04 09:30 to `20181004_093000.mp4`. (tested here 2026-10-24) [ExifTool documentation, https://exiftool.org/exiftool_pod.html, checked 2026-10-24]
4649. **Sort a dump into date folders without moving originals** — `-o .` with `-Directory<CreateDate -d %Y/%m/%d` copies instead of moving. **How:** `exiftool -o . '-Directory<CreateDate' -d '%Y/%m/%d' dir` put `x.mp4` into `2018/10/04/x.mp4` and left the original. (tested here 2026-10-24) [ExifTool documentation, https://exiftool.org/exiftool_pod.html, checked 2026-10-24]
4650. **Keep the whole card structure, sidecars included** — some technical metadata lives in camera-specific XML sidecar files next to the media, which is why the entire card structure must be kept before importing. **How:** copy the card root folder (`cp -r card/. dest/` or rsync), never just the `.MP4` files. [Frame.io Workflow Guide, "Metadata", https://workflow.frame.io/guide/metadata, checked 2026-10-24]

## Backups, checksums and storage safety

4651. **Back up the card before anything else** — the first thing after a card leaves the camera is a backup in multiple places; keep the original camera files ("camera negative") even after later conversions. **How:** copy the card to two different drives before transcoding or renaming anything, and never delete the OCN after making proxies. [Frame.io Workflow Guide, ch.02 "Prep", https://workflow.frame.io/guide/, checked 2026-10-24]
4652. **Source checksum, copy, destination checksum, compare** — checksum software reads the file (source checksum), copies it, reads the copy (destination checksum) and compares; one changed bit gives a different sum. **How:** `cd card && find . -type f -exec sha256sum {} + > ../card.sha256`, copy, then `cd ../bk && sha256sum -c ../card.sha256` printed OK for every file. (tested here 2026-10-24) [Frame.io Workflow Guide, "Checksums and Robust Backup", https://workflow.frame.io/guide/checksums-backups, checked 2026-10-24]
4653. **A single changed byte fails verification** — the reason checksums are used: they detect a problem as it happens. **How:** after appending one byte to a copied clip, `sha256sum -c --quiet ../card.sha256` printed `FAILED` for that file and nothing for the others. (tested here 2026-10-24) [Frame.io Workflow Guide, "Checksums and Robust Backup", https://workflow.frame.io/guide/checksums-backups, checked 2026-10-24]
4654. **Choosing the checksum algorithm** — MD5 is popular in video for speed and cross-platform support but old; xxHash, SHA-2 or SHA-3 are newer choices. DPC: MD5 is sufficient against accidental damage; stronger algorithms matter when you must resist deliberate tampering or need legal weight. **How:** `sha256sum` (coreutils, installed) for manifests; `md5sum` when the other side only speaks MD5. [Frame.io Workflow Guide, "Checksums and Robust Backup", https://workflow.frame.io/guide/checksums-backups, checked 2026-10-24] [Digital Preservation Coalition Handbook, "Fixity and checksums", https://www.dpconline.org/handbook/technical-solutions-and-tools/fixity-and-checksums, checked 2026-10-24]
4655. **Checksum shelf drives at creation and re-check later** — a drive stored a long time can lose bits; make checksums at the start so you can check later. DPC suggests checking tape about yearly and hard drives about every six months ("data scrubbing"). **How:** store `card.sha256` on the drive and in the job notes; on each check run `sha256sum -c --quiet` and replace failed files from another copy. [Frame.io Workflow Guide, "Checksums and Robust Backup", https://workflow.frame.io/guide/checksums-backups, checked 2026-10-24] [Digital Preservation Coalition Handbook, "Fixity and checksums", https://www.dpconline.org/handbook/technical-solutions-and-tools/fixity-and-checksums, checked 2026-10-24]
4656. **New checksum after a deliberate change** — migrating or transcoding changes the checksum, so a new reference must be made for the new file. **How:** regenerate the manifest after every transcode or rewrap and keep the old one with the original. [Digital Preservation Coalition Handbook, "Fixity and checksums", https://www.dpconline.org/handbook/technical-solutions-and-tools/fixity-and-checksums, checked 2026-10-24]
4657. **Picture-only hash survives a rewrap** — the ffmpeg `hash` muxer hashes decoded frames and ignores timestamps, so equality checks need no binary comparison. **How:** `ffmpeg -i in.mp4 -map 0:v -f hash -` and the same on an MP4 remuxed to MKV gave the identical SHA256, proving the rewrap did not touch the pictures. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#hash-1, checked 2026-10-24]
4658. **Per-stream hashes** — `streamhash` prints one line per stream (`index,type,algo=hash`). **How:** `ffmpeg -i t.mp4 -f streamhash -` printed `0,v,SHA256=...` and `1,a,SHA256=...`; compare the audio line alone after a video-only re-grade. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#streamhash-1, checked 2026-10-24]
4659. **Off-site copy** — rule 3: keep backups in a different physical location; Backblaze's 3-2-1 says one of three copies off-site, ideally miles away. **How:** cloud storage or a drive kept at another address counts; two drives on one desk do not. [Frame.io Workflow Guide, "Checksums and Robust Backup", https://workflow.frame.io/guide/checksums-backups, checked 2026-10-24] [Backblaze, "The 3-2-1 Backup Strategy", https://www.backblaze.com/blog/the-3-2-1-backup-strategy/, checked 2026-10-24]
4660. **Write down where every backup is** — rule 5: without a record of where backups are and what they are called, they practically do not exist; rule 6: at least one complete backup must be reachable fast. **How:** keep a `BACKUPS.md` per job (drive name, path, date, checksum file) in the job notes. [Frame.io Workflow Guide, "Checksums and Robust Backup", https://workflow.frame.io/guide/checksums-backups, checked 2026-10-24]
4661. **The 3-2-1 rule** — three copies (original plus two), on two different media/devices, one off-site; today two different devices is enough rather than two media types. **How:** working drive + external drive + cloud = 3-2-1. [Backblaze, "The 3-2-1 Backup Strategy", https://www.backblaze.com/blog/the-3-2-1-backup-strategy/, checked 2026-10-24]
4662. **3-2-1-1-0 for ransomware** — add one offline/air-gapped or immutable copy, and zero errors: monitor backups and run regular restore tests. **How:** keep one drive unplugged, and once a month restore one random clip and `sha256sum -c` it. [Backblaze, "3-2-1 vs. 3-2-1-1-0 vs. 4-3-2", https://www.backblaze.com/blog/whats-the-diff-3-2-1-vs-3-2-1-1-0-vs-4-3-2/, checked 2026-10-24]
4663. **Sync by content, not date** — rsync's default quick check compares size and modification time; `-c` compares a checksum for each same-size file (much more disk I/O). **How:** `rsync -a --checksum card/ backup/`, then a second `rsync -a --checksum --itemize-changes card/ backup/` printed 0 lines (nothing differs). (tested here 2026-10-24) [rsync(1) manual, https://download.samba.org/pub/rsync/rsync.1.html, checked 2026-10-24]
4664. **Dry-run before syncing** — `-n` does a trial run; with `-i` its itemised output matches the real run; always dry-run before `--delete`. **How:** `rsync -an --itemize-changes card/ backup/` listed `>f+++++++++ A001/note.txt` and copied nothing. (tested here 2026-10-24) [rsync(1) manual, https://download.samba.org/pub/rsync/rsync.1.html, checked 2026-10-24]
4665. **Daily snapshots that cost no space for unchanged clips** — `--link-dest=DIR` hard-links files unchanged since DIR. **How:** `rsync -a card/ snap/day1/` then `rsync -a --link-dest=../day1 card/ snap/day2/`; `stat -c %h` on an unchanged clip showed 2 links. (tested here 2026-10-24) [rsync(1) manual, https://download.samba.org/pub/rsync/rsync.1.html, checked 2026-10-24]
4666. **Keep overwritten versions on sync** — `--backup-dir=DIR` (implies `--backup`) stores replaced files in DIR; a relative path is relative to the destination, so start it with `../`. **How:** `rsync -a --backup --backup-dir=../old_$(date +%Y%m%d) card/ rs1/` kept the old `note.txt` in `old_20261024/A001/`. (tested here 2026-10-24) [rsync(1) manual, https://download.samba.org/pub/rsync/rsync.1.html, checked 2026-10-24]
4667. **Git is not a backup and has hard size limits** — GitHub warns above 50 MiB, blocks files over 100 MiB (Git LFS needed), recommends repos under 1 GB (<5 GB strongly) and says Git is not designed as a backup tool. **How:** media and weights stay out of this repo (owner rule); only small reusable assets go to `library/`. [GitHub Docs, "About large files on GitHub", https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github, checked 2026-10-24] [repo: CLAUDE.md]

## Proxies, optimised media and mezzanine files

4668. **ProRes 422 Proxy with ffmpeg** — Frame.io names ProRes 422 Proxy as one of two good offline formats. **How:** `ffmpeg -i in.mp4 -vf scale=iw/2:ih/2 -c:v prores_ks -profile:v proxy -c:a pcm_s16le px.mov` → ffprobe `prores,Proxy,320,180`. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24]
4669. **DNxHR LB with ffmpeg** — the other recommended offline format, easy to create cross-platform. **How:** `ffmpeg -i in.mp4 -vf scale=1280:720 -c:v dnxhd -profile:v dnxhr_lb -pix_fmt yuv422p -c:a pcm_s16le lb.mov` → ffprobe `dnxhd,DNXHR LB`. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24] [Frame.io Workflow Guide, "How to Choose a Proxy Codec", https://workflow.frame.io/guide/proxy-codecs, checked 2026-10-24]
4670. **"Half" resolution is a quarter of the pixels** — Resolve's Half/Quarter fractions refer to one dimension, so Half = (1/2)² = 1/4 of the pixels. **How:** `scale=iw/2:ih/2` turned 640x360 into 320x180 (1/4 of the pixels). (tested here 2026-10-24) [Frame.io Workflow Guide, "DaVinci Resolve Proxy Workflow", https://workflow.frame.io/guide/resolve-proxies, checked 2026-10-24]
4671. **Only shrink clips bigger than the timeline** — Resolve's "Choose automatically" downsizes only media larger than the timeline (8K→quarter, 4K→half in a 1080 project) and leaves 1080 and smaller at source size. **How:** `scale=w=min(iw\,1920):h=-2` caps width; tested with a 320 cap: a 640-wide clip became 320, a 320-wide clip stayed 320. (tested here 2026-10-24) [Blackmagic, DaVinci Resolve 19.1 Reference Manual ch.8 "Improving Performance, Proxies, and the Render Cache", https://documents.blackmagicdesign.com/UserManuals/DaVinci_Resolve_19_Reference_Manual.pdf, checked 2026-10-24]
4672. **Proxies must carry the source timecode** — timecode is "the glue" of offline/online; proxies whose timecode matches the camera originals let apps switch back and forth. **How:** `ffmpeg -i in.mp4 -c:v prores_ks -profile:v proxy -timecode 01:00:00:00 tc.mov` wrote a `tmcd` track reading 01:00:00:00, and transcoding that MOV kept 01:00:00:00. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24] [ffprobe docs, https://ffmpeg.org/ffprobe.html#Timecode, checked 2026-10-24]
4673. **MP4 and timecode** — Frame.io says MP4 cannot contain timecode; ffmpeg's mov/mp4 muxer docs say `write_tmcd` (default auto) writes a timecode track for mov and mp4, and here `-timecode 01:00:00:00` into `.mp4` did add a `tmcd` data stream. **How:** still deliver proxies as MOV, since other apps may not read a tmcd track in MP4. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#MOV_002fMPEG_002d4_002fISOMBFF-muxers, checked 2026-10-24]
4674. **Rewrap production audio losslessly into proxies** — don't transcode the interleaved WAV to AAC; rewrapping keeps every ISO track and saves hunting the field-recorder files later. **How:** `ffmpeg -i pic.mp4 -i prod.wav -map 0:v -map 1:a -c:v prores_ks -profile:v proxy -c:a copy synced.mov` kept `pcm_s24le, 2 ch`. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24]
4675. **Bake the LUT into proxies only** — pre-baking the camera LUT into proxies spares the editor LUT management and CPU, but only if you go back to the camera originals later. **How:** `ffmpeg -i log.mov -vf "lut3d=file=show.cube,scale=iw/2:-2" -c:v prores_ks -profile:v proxy px.mov` (ran with an identity cube). (tested here 2026-10-24) [Frame.io Workflow Guide, "Editing Codecs", https://workflow.frame.io/guide/editing-codecs, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lut3d-1, checked 2026-10-24]
4676. **Mezzanine: never bake the LUT** — a mezzanine file replaces the originals, so baking a LUT would throw away the log latitude; apply the LUT as an effect instead. **How:** transcode log footage to the mezzanine codec untouched and add `lut3d` only at render. [Frame.io Workflow Guide, "Mezzanine Workflow", https://workflow.frame.io/guide/mezzanine-workflow, checked 2026-10-24]
4677. **Mezzanine codec at least as good as capture** — match chroma and bit depth (4:2:0 8-bit source needs at least 4:2:0 8-bit) and raise the bitrate a lot when leaving long-GOP; for 100 Mbps H.264 use ProRes 422 or 422 HQ. **How:** `ffmpeg -i in.mp4 -c:v prores_ks -profile:v hq -an mez.mov` → profile `HQ`. (tested here 2026-10-24) [Frame.io Workflow Guide, "Mezzanine Workflow", https://workflow.frame.io/guide/mezzanine-workflow, checked 2026-10-24]
4678. **Proxy tree mirrors the original tree** — OCN and proxy folder structures should be identical. **How:** copy only the directory tree with rsync's include/exclude pair: `rsync -a --include='*/' --exclude='*' card/ PROXY/` created `PROXY/A001`, `PROXY/F002` with no files. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24] [rsync(1) manual, https://download.samba.org/pub/rsync/rsync.1.html, checked 2026-10-24]
4679. **Batch proxies into the mirrored tree** — **How:** `for f in $(find card -name '*.mov'); do o=PROXY/${f#card/}; ffmpeg -nostdin -n -i "$f" -vf scale=iw/2:-2 -c:v prores_ks -profile:v proxy -c:a pcm_s16le "$o"; done` wrote `PROXY/A001/A001_Clip001.mov` and `PROXY/F002/F002_Clip001.mov`. (tested here 2026-10-24) [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Generic-options, checked 2026-10-24]
4680. **Proxy format for sending vs for speed** — Resolve: for faster playback while keeping quality use ProRes 422 HQ or DNxHR HQ; to send media over the internet use ProRes Proxy or even H.264/H.265 to keep files small. **How:** choose by purpose: `-profile:v hq` locally, `libx264` for a remote editor's preview set. [Blackmagic, DaVinci Resolve 19.1 Reference Manual ch.8 "Improving Performance, Proxies, and the Render Cache", https://documents.blackmagicdesign.com/UserManuals/DaVinci_Resolve_19_Reference_Manual.pdf, checked 2026-10-24]
4681. **Optimised media that keeps alpha and overshoots** — Resolve preserves alpha only in Uncompressed 10-bit/16-bit float, ProRes 4444/4444 XQ and DNxHR 444; to avoid clipping super-whites use 16-bit float or ProRes 4444/XQ (also for HDR). **How:** for alpha graphics proxies `ffmpeg -f lavfi -i "color=red@0.5:s=320x180:d=1,format=rgba" -c:v prores_ks -profile:v 4444 -pix_fmt yuva444p10le a.mov` → ffprobe `4444,yuva444p12le`. (tested here 2026-10-24) [Blackmagic, DaVinci Resolve 19.1 Reference Manual ch.8 "Improving Performance, Proxies, and the Render Cache", https://documents.blackmagicdesign.com/UserManuals/DaVinci_Resolve_19_Reference_Manual.pdf, checked 2026-10-24]
4682. **Two dailies sets in one pass** — DITs often make an editorial codec set plus an H.264 set for producers. **How:** one ffmpeg command with two outputs: `ffmpeg -i in.mp4 -map 0:v -c:v prores_ks -profile:v proxy -s 320x180 ed.mov -map 0 -c:v libx264 -preset ultrafast -c:a aac rev.mp4` made both. (tested here 2026-10-24) [Frame.io Workflow Guide, ch.02 "Prep", https://workflow.frame.io/guide/, checked 2026-10-24]
4683. **Use licensed ProRes for paid deliverables** — Frame.io: unlicensed ProRes encoders in some software transcoders have no quality control and may fail QC; use licensed implementations for professional deliverables. **How:** ffmpeg's `prores_ks` is fine for our proxies/mezzanine; if a client's QC demands licensed ProRes, say so rather than promising it. [Frame.io Workflow Guide, "Software Transcoding", https://workflow.frame.io/guide/software-transcoding, checked 2026-10-24]
4684. **Transcoding never improves quality** — an intermediate codec cannot make images better, only worse if chosen badly; don't transcode when the camera codec is already edit-friendly (e.g. Canon XF 50 Mb 4:2:2). **How:** check with ffprobe first; if the source is already intra-frame and editable, edit it directly. [Frame.io Workflow Guide, "Mezzanine Workflow", https://workflow.frame.io/guide/mezzanine-workflow, checked 2026-10-24] [Frame.io Workflow Guide, "The most common conform issues", https://workflow.frame.io/guide/common-conform-issues, checked 2026-10-24]

## Picture lock, conform and hand-off packages

4685. **Lock picture before conform** — after a conform, a "simple" shot swap costs the colourist, VFX artist, sound editor and sound designer extra work each; Van Hurkman calls locking "a scheduling milestone". **How:** tag the locked HyperFrames project (`git tag -a v010-lock -m "picture lock"`) and route later change requests through a written change list. [Frame.io Workflow Guide, "Pitfalls of an offline workflow", https://workflow.frame.io/guide/offline-workflow-pitfalls, checked 2026-10-24] [Pro Git, "2.6 Git Basics - Tagging", https://git-scm.com/book/en/v2/Git-Basics-Tagging, checked 2026-10-24]
4686. **Name versions by edit stage** — assembly (often over twice the final length, close to script), rough cut, optional first/fine cut, director's/producer's cut, picture lock. **How:** use the stage in render names (`proj_v003_rough.mp4`, `proj_v007_fine.mp4`) so a client knows what kind of feedback fits. [Frame.io Workflow Guide, "Stages of the editing process", https://workflow.frame.io/guide/editing-stages, checked 2026-10-24]
4687. **Include the project file in every turnover** — online facilities need the `.prproj`/`.avb` (the most complete history) to fall back on when an EDL/XML/AAF is missing something. **How:** our equivalent: hand over the HyperFrames project folder (or `.otio`) plus any EDL/XML, never the list alone. [Frame.io Workflow Guide, "The most common conform issues", https://workflow.frame.io/guide/common-conform-issues, checked 2026-10-24]
4688. **One "final" sequence only** — several sequences called "final", "final approved revised" confuse the conform; put exactly one sequence in a final bin. **How:** one `FINAL/` folder holding one render and one timeline file; older ones move to `50_Renders/archive`. 4857. **One encode, several files** — the tee muxer encodes once and writes to several outputs (streams must be mapped; per-output options in brackets). **How:** `ffmpeg -i in.mp4 -map 0 -c:v libx264 -c:a aac -f tee "[f=mp4:movflags=+faststart]a.mp4|[f=matroska]b.mkv"` wrote both. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#tee-1, checked 2026-10-24]
4858. **Quick tail preview** — `-sseof` seeks relative to the end. **How:** `ffmpeg -sseof -1 -i in.mp4 tail1.mp4` → 1.02 s of the ending for a quick check of end cards. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
4859. **-fs is a rough stop, not a size target** — `-fs` stops writing after the limit and the file is "slightly more"; here `-fs 50000` on a libx264 MP4 stopped at 1.44 s but the file was 267 KB, and an MKV ignored it entirely. **How:** control size with bitrate, not `-fs`. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
4860. **Long filtergraphs from a file** — `-filter_script:v file.txt` (6.1) avoids shell quoting. **How:** `echo "scale=160:-2,hflip" > f.txt && ffmpeg -i in.mp4 -filter_script:v f.txt -frames:v 1 fs.png` → 160 px wide. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
4861. **Live-updating thumbnail** — image2 `-update 1` overwrites one file instead of a numbered sequence. **How:** `ffmpeg -i in.mp4 -vf fps=1 -update 1 latest.jpg` for a status image of a long job. (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-formats.html#image2_002c-image2pipe, checked 2026-10-24]

## HyperFrames CLI workflow

4862. **Scaffold non-interactively** — outside a TTY `init` scaffolds the centred blank; `--non-interactive` forces it; `HYPERFRAMES_SKIP_SKILLS=1` skips the skills check; `--video/--audio` auto-transcribe unless `--skip-transcribe`. **How:** `HYPERFRAMES_SKIP_SKILLS=1 npx hyperframes init proj --non-interactive` made index.html, hyperframes.json, package.json. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/init-and-scaffold.md]
4863. **Fix the scaffold's GSAP CDN line first** — the 0.8.191 blank scaffold loads GSAP from cdn.jsdelivr.net; repo learning: load `assets/vendor/gsap-3.14.2.min.js` or renders fail. **How:** copy `video/assets/vendor/gsap-3.14.2.min.js` into the project and point the script tag at it (the test project then rendered). (tested here 2026-10-24) [repo: CLAUDE.md]
4864. **Project facts in one call** — `info --json` (name, resolution, duration, element counts, size, version), `compositions --json` (every data-composition-id). **How:** both returned JSON with `duration` and the `main` composition. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/upgrade-info-misc.md]
4865. **lint while writing, check as the gate** — `check --json` returns `{ok, browserSkipped, lint, runtime, layout, motion, contrast, craft, ...}`; lint errors skip the browser so empty sections then mean "not checked". **How:** `npx hyperframes check --json > check.json; jq '{ok, browserSkipped}' check.json` → `ok: true, browserSkipped: false`. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/lint-validate-inspect.md]
4866. **Craft warnings to read** — `line_unread`, `dead_stretch` (>3 s with no change), `text_below_floor`, `first_frame_empty` (frame 0 is the social thumbnail), `film_silent` (>15 s without audio). **How:** fix them unless the film breaks the rule on purpose; `data-hold` exempts deliberate stillness. [repo: .claude/skills/hyperframes-cli/references/lint-validate-inspect.md]
4867. **Motion assertions in a sidecar** — a `*.motion.json` next to the composition (`appearsBy`, `before`, `staysInFrame`, `keepsMoving`) is checked by `check`; a selector matching nothing fails loudly. **How:** `{"assertions":[{"kind":"appearsBy","selector":"#title","bySec":0.5}]}` for a title that must be up by 0.5 s. [repo: .claude/skills/hyperframes-cli/references/lint-validate-inspect.md]
4868. **Snapshots at chosen times** — `snapshot --at t1,t2` adds an end frame unless `--no-end`; `--output` sets the folder and a contact sheet is written. **How:** `npx hyperframes snapshot --at 0.5,2.5 --output snaps` → frames at 0.5, 2.5, 2.91 s plus `contact-sheet.jpg`. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/lint-validate-inspect.md]
4869. **Review sheets: beats, seams, phone size** — `snapshot --review` writes `review-beats.jpg`, `review-seam-NN.jpg` (±0.2 s around every cut) and `review-phone.jpg` (360 px wide). **How:** `snapshot --review --json` returned the sheet paths; with fewer than two scenes it spreads 5 beats evenly. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/lint-validate-inspect.md]
4870. **Render quality ladder** — `draft` while iterating, `looks` (default, CRF 16) for the first real encode, `delivery` (= high) for final; default output is timestamped `renders/<project>_<date>_<time>.mp4`, `--output` gives a stable name. **How:** `npx hyperframes render --quality draft --output out.mp4` → 3.0 s file in 6.4 s. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/preview-render.md]
4871. **Verify the render's duration** — confirm the file is non-empty and its ffprobe duration equals the root `data-duration`. **How:** `ffprobe -v error -show_entries format=duration -of csv=p=0 out.mp4` → 3.000000 for `data-duration="3"`. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/SKILL.md]
4872. **Read the render summary line** — it shows capture path, GPU mode and stage timings; `screenshot capture` + `software gpu` on Linux is the slow path. **How:** the draft MP4 reported `beginframe capture · software gpu`, the PNG-sequence render `screenshot capture` with the BeginFrame hint. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/preview-render.md]
4873. **Frames for compositing tools** — `--format png-sequence` writes RGBA frames to a folder; `--format mov/webm` render with transparency. **How:** `render --quality draft --format png-sequence --output seq` → 90 PNGs (`frame_000001.png` …) for 3 s at 30 fps. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/preview-render.md]
4874. **GIF for READMEs/PRs** — `--format gif` (two-pass palette, fps capped at 30, prefer `--fps 15`, no audio). **How:** `render --quality draft --format gif --fps 15 --output out.gif` → ffprobe codec gif. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/preview-render.md]
4875. **Batch renders from a rows file** — `render --batch rows.json --output "renders/{name}.mp4"` (`--batch-concurrency` default 1, `--batch-fail-fast`, `--strict-variables`) writes and updates `manifest.json`. **How:** one row per client name/headline; check the manifest has no failed rows. [repo: .claude/skills/hyperframes-cli/references/compare-and-batch.md]
4876. **Gate on doctor's checks, not its exit code** — `doctor --json` always exits 0; gate on the payload. **How:** here `doctor --json` exited 0 with `ok: false` because optional whisper-cpp, Kokoro, MusicGen and Docker were missing; `jq -r '.checks[] | select(.ok==false) | .name'` shows which, so gate on the ones you need. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/conventions.md] [repo: .claude/skills/hyperframes-cli/references/doctor-browser.md]
4877. **Project history around each turn** — `history begin --who <you> --label "<plan>"`, `history --since mine --who <you>` to see the person's edits, `history undo` to revert, `history end`. **How:** the test listed snapshot/check files as "Changed outside the app" and `history end` reported "Nothing changed in this turn". (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/SKILL.md]
4878. **Disk housekeeping without losing history** — `clean --dry-run` lists what it would remove; `--snapshots` also discards snapshot evidence; never delete `.hyperframes` (history lives there). **How:** `clean --dry-run` → "Nothing to clean" plus the reclaimable snapshot sizes. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/conventions.md]
4879. **One run id per verification loop** — use one `HYPERFRAMES_RUN_ID` for all commands in the same loop; telemetry off with `HYPERFRAMES_NO_TELEMETRY=1`. **How:** `export HYPERFRAMES_RUN_ID=job42 HYPERFRAMES_NO_TELEMETRY=1` before lint/check/snapshot/render. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/conventions.md] [repo: .claude/skills/hyperframes-cli/references/upgrade-info-misc.md]
4880. **Terminal docs** — `docs` lists topics (data-attributes, examples, rendering, gsap, troubleshooting, compositions); `docs rendering` prints one. **How:** `npx hyperframes docs` listed them, no browser needed. (tested here 2026-10-24) [repo: .claude/skills/hyperframes-cli/references/upgrade-info-misc.md]
