# Audio dialogue editing and repair (skills2, part 05)
Scope: dialogue editing and repair - room tone and fill, breaths, clicks, plosives, de-noise, de-hum, de-clip, de-ess, de-reverb, voice EQ, multi-mic and phase, sync, ADR, Whisper transcript editing and the repo voice tools. Not mixing/mastering, SFX or music.
Researched 2026-10-24 via agent-reach (Exa) web search, official docs and local tests.

Test material for every "tested here" line: an 18.3 s LibriSpeech speech clip (librosa example `libri1`, kept in the scratchpad only) at 48 kHz mono with 2 s of silence in front; "noisy" = that clip + pink noise + 50 Hz hum (pause RMS -42.9 dB, speech RMS -18.6 dB). "Pause dB" = mean RMS of 50 ms windows where the clean speech is silent, measured with numpy. ffmpeg here is 6.1.1 (Ubuntu); the online filter docs describe a newer build.

## Know the local ffmpeg build
1521. **Read `ffmpeg -h filter=NAME` before copying options from the online docs** — the online page documents a newer ffmpeg than our 6.1.1, and option values differ: online `adynamicequalizer` lists modes like `cutbelow`/`cutabove`, but 6.1.1 only accepts `mode=listen|cut|boost` plus a separate `direction=downward|upward`; `mode=cutabove` fails with "Unable to parse option value". **How:** `ffmpeg -hide_banner -h filter=adynamicequalizer` and use the values it prints (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adynamicequalizer, checked 2026-10-24]
1522. **Find which options can change while the file plays** — options marked `T` in `ffmpeg -h filter=NAME` accept runtime commands; the command name is the option name. **How:** `ffmpeg -hide_banner -h filter=afftdn | grep -E "sample_noise|gain_smooth"` shows the `T` flag column (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Changing-options-at-runtime-with-a-command, checked 2026-10-24]
1523. **Change a filter setting at a set time with asendcmd** — `asendcmd` sends `TIME TARGET COMMAND ARG` to a later audio filter, e.g. raise de-noise strength only where a noisy shot starts. **How:** `ffmpeg -i noisy.wav -af "asendcmd=c='5.0 afftdn nr 20',afftdn=nr=8" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sendcmd_002c-asendcmd, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1524. **Keep a list of timed commands in a file** — `asendcmd=f=FILE` reads intervals like `4.0 volume@b volume 0.3;`; name the target instance with `@name`. **How:** `echo "4.0 volume@b volume 0.3;4.4 volume@b volume 1.0;" > cmds.txt` then `ffmpeg -i sp.wav -af "asendcmd=f=cmds.txt,volume@b=1" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sendcmd_002c-asendcmd, checked 2026-10-24]

## Broadband de-noise: afftdn
1525. **Teach afftdn the noise from a noise-only stretch** — `sample_noise` start/stop commands capture a noise profile from the input; the docs' example learns from the first 0.4 s. On our noisy clip (pauses at -42.9 dB) this took pauses to -55.0 dB with speech level unchanged (-18.6 -> -18.8 dB). **How:** `ffmpeg -i noisy.wav -af "asendcmd=0.0 afftdn sn start,asendcmd=0.4 afftdn sn stop,afftdn=nr=20:nf=-40" out.wav` - put the start/stop times on a pause with no speech (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1526. **afftdn's default noise model is white noise** — `noise_type` defaults to white; on our pink-noise + hum clip plain `afftdn` only moved pauses from -42.9 to -43.8 dB, while on a white-noise clip it gave -44.8 -> -49.3 dB. Learn a profile (above) when the noise is not white. **How:** compare `ffmpeg -i noisy.wav -af afftdn a.wav` and the sample-noise command, then measure the pauses (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1527. **Set afftdn's noise floor near the real noise level** — `nf` (default -50 dB, range -80 to -20) is the measured noise floor the filter works from. With a profile learned from 0-1.5 s at nr=20 our pauses came out at -53.2 dB (nf=-30), -50.5 (nf=-40), -44.5 (nf=-50), -43.1 (nf=-60): a floor set far below the actual noise did almost nothing. **How:** measure a pause first: `ffmpeg -i in.wav -af "atrim=0:1.5,astats=measure_perchannel=RMS_level+Noise_floor:measure_overall=none" -f null -`, then try nf a little above that value (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#astats-1, checked 2026-10-24]
1528. **Listen to what afftdn removes** — `output_mode=noise` (`om=n`) passes only the removed noise; if words are audible in it, the setting is eating speech. **How:** `ffmpeg -i noisy.wav -af "afftdn=nr=12:om=n" removed.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1529. **Let afftdn follow a changing floor** — `track_noise=1` (`tn=1`) adjusts the noise floor automatically during processing; the docs pair it with a very low starting floor. On our steady test noise it changed little (-42.9 -> -42.9 dB at nr=10), so keep it for noise that really changes. **How:** `ffmpeg -i in.wav -af "afftdn=nr=10:nf=-80:tn=1" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1530. **Smooth afftdn gains against "music noise"** — `gain_smooth` (`gs`, 0-50, default 0) smooths the gain of neighbouring frequency bins and is meant to reduce random music-noise artefacts. On a white-noise clip nr=24 gave pauses -49.7 dB without and -52.1 dB with gs=15. **How:** `ffmpeg -i in.wav -af "afftdn=nr=24:gs=15" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1531. **Give afftdn a hand-made 15-band noise profile** — `noise_type=custom` reads `band_noise`: 15 values separated by space or `|`. **How:** `ffmpeg -i in.wav -af "afftdn=nt=c:bn='-40 -40 -42 -44 -46 -48 -50 -50 -52 -54 -56 -58 -60 -60 -60'" out.wav` (ran here; values are an example, not a measured profile) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1532. **Residual floor and adaptivity in afftdn** — `residual_floor` (`rf`, default -38 dB) sets where the reduced noise sits; `adaptivity` (`ad`, 0-1, default 0.5) sets how fast per-bin gains adapt: 0 is instant, higher is slower. **How:** `ffmpeg -i in.wav -af "afftdn=nr=20:rf=-30" a.wav` and `afftdn=nr=12:ad=0.9` (both tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1533. **Link the noise floor across mics in a multichannel file** — `noise_link` (`nl`) chooses whether each channel uses its own floor (`none`) or the min/max/average of all channels (default `min`). **How:** `ffmpeg -i twomic.wav -af "afftdn=nr=10:nl=average" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afftdn, checked 2026-10-24]
1534. **afftdn output is late by about 25 ms here** — cross-correlating input and output showed the sample-noise afftdn result 1200 samples (25.0 ms at 48 kHz) behind the input. That matters when the cleaned track is mixed back with the dry track or another mic. **How:** trim the head after the filter: `...,afftdn=nr=20:nf=-40,atrim=start_sample=1200,asetpts=PTS-STARTPTS` (re-measured lag 0) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atrim, checked 2026-10-24]

## Other de-noisers in ffmpeg and Python
1535. **anlmdn patch and research sizes, and its noise-only output** — `anlmdn` compares patches (`p`, 1-100 ms, default 2 ms) inside a research area (`r`, 2-300 ms, default 6 ms); `o=n` outputs only the removed noise; `m` is a smooth factor (default 11). **How:** `ffmpeg -i noisy.wav -af "anlmdn=s=0.001:o=n" removed.wav`, `anlmdn=s=0.001:p=0.004:r=0.015:m=15` (both ran here) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#anlmdn, checked 2026-10-24]
1536. **Wavelet de-noise with afwtdn** — `afwtdn` reduces broadband noise with wavelets; `sigma` sets strength and is most usefully given in dB (e.g. -45dB); `percent` (default 85) is partial de-noising. Plain sigma=-45dB moved our pauses -42.9 -> -44.2 dB. **How:** `ffmpeg -i noisy.wav -af "afwtdn=sigma=-45dB" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afwtdn, checked 2026-10-24]
1537. **afwtdn profile and adaptive modes** — `profile` uses the first input frame as the noise profile (very poor if that frame has non-noise); `adaptive` re-detects noise frames and uses them as profile. On our clip (2 s of noise first): profile=1 -> pauses -59.3 dB, adaptive=1:percent=70 -> -51.2 dB, speech level unchanged. **How:** `ffmpeg -i noisy.wav -af "afwtdn=sigma=-45dB:profile=1" out.wav` - only when the file starts on pure noise (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afwtdn, checked 2026-10-24]
1538. **arnndn needs a real model file** — `arnndn` (recurrent-network speech de-noise) has a required `model` option; the `.rnnn` files are in richardpl/arnndn-models (std.rnnn is the one bundled with Xiph RNNoise; the others are by Gregor Richards). With std.rnnn our pauses went -42.9 -> -65.6 dB, speech -18.6 -> -18.8 dB. **How:** `curl -sSLO https://raw.githubusercontent.com/richardpl/arnndn-models/master/std.rnnn` then `ffmpeg -i noisy.wav -af "arnndn=m=std.rnnn" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#arnndn, checked 2026-10-24] [richardpl/arnndn-models README, https://github.com/richardpl/arnndn-models, checked 2026-10-24]
1539. **Pick the rnnoise model by signal and noise type** — GregorR's table maps expected signal (general / voice / speech; "voice" includes laughter and other non-speech sounds) against expected noise (general / recording): e.g. speech + recording noise = somnolent-hogwash, voice + recording = beguiling-drafter, general + recording = conjoined-burgers, general + general = marathon-prescription. In richardpl's repo the files are named by those initials (sh, bd, cb, mp, lq). On our test sh.rnnn gave pauses -55.7 dB vs -65.6 dB for std.rnnn: compare models on your own clip. **How:** `for m in std sh; do ffmpeg -i in.wav -af arnndn=m=$m.rnnn out_$m.wav; done` (tested here 2026-10-24) [GregorR/rnnoise-models README, https://github.com/GregorR/rnnoise-models, checked 2026-10-24]
1540. **Blend arnndn with the original** — `mix` (-1 to 1, default 1) sets how much filtered signal goes out; mix=0.7 gave pauses -52.4 dB instead of -65.6 dB. Negative values keep the removed noise, and `mix=-1` lets you hear exactly what was taken out. **How:** `arnndn=m=std.rnnn:mix=0.7` and `arnndn=m=std.rnnn:mix=-1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#arnndn, checked 2026-10-24]
1541. **arnndn output is late by 10 ms here** — cross-correlation put the arnndn result 479-480 samples (10 ms at 48 kHz) behind the input. **How:** `arnndn=m=std.rnnn,atrim=start_sample=480,asetpts=PTS-STARTPTS` re-aligned it to 0 samples (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atrim, checked 2026-10-24]
1542. **Measure what a de-noiser does to the speech, not just the noise** — `asdr`, `asisdr` and `apsnr` compare two time-aligned streams (processed vs clean reference) and print dB per channel. Aligned results here: noisy input SDR 22.9 dB, profile-afftdn 25.1 dB, arnndn 11.2 dB - arnndn removed more noise but changed the speech more. Un-aligned output gives nonsense (arnndn read -3.3 dB before the 480-sample trim). **How:** `ffmpeg -i processed.wav -i clean.wav -filter_complex "[0][1]asdr" -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#asdr, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#asisdr, checked 2026-10-24]
1543. **Adaptive self-reference de-noise with anlms** — the docs' noise-reduction example filters the input with a copy of itself delayed by a fixed amount. It ran here, but on our clip it also pulled the speech down by about 24 dB (-18.6 -> -42.6 dB), so check the level before trusting it. **How:** `ffmpeg -i in.wav -af "asplit[a][b],[a]adelay=32S:all=1[a],[b][a]anlms=order=128:leakage=0.0005:mu=.5:out_mode=o" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#anlmf_002c-anlms, checked 2026-10-24]
1544. **Adaptive filters that take a second (reference) stream** — `anlms`/`anlmf` and `arls` adapt the 1st input toward the "desired" 2nd input; `out_mode` picks input, desired, output, noise or error. Useful when a separate noise-reference recording exists. **How:** `ffmpeg -i main.wav -i ref.wav -filter_complex "[0][1]arls=order=16:out_mode=o" out.wav` (ran here; no quality claim) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#arls, checked 2026-10-24]
1545. **noisereduce: stationary spectral gating with a noise clip** — the Python package `noisereduce` (MIT per its package metadata) gates noise per frequency band; with `stationary=True` and a noise-only clip as `y_noise` it took our pauses to -74.8 dB with speech -1.3 dB. **How:** `uv pip install --target pylib --no-deps noisereduce` (pure Python; numpy/scipy are in /home/user/tools/venv), then `nr.reduce_noise(y=y, sr=sr, stationary=True, y_noise=y[:int(1.5*sr)])` (tested here 2026-10-24) [timsainb/noisereduce README, https://github.com/timsainb/noisereduce, checked 2026-10-24]
1546. **noisereduce non-stationary mode can cost speech level** — the default (`stationary=False`) keeps updating the noise threshold over time (`time_constant_s`, default 2.0); on our steady-noise clip it reached -76.7 dB pauses but dropped speech by about 11 dB. Use it for changing noise and check levels. **How:** `nr.reduce_noise(y=y, sr=sr)` vs the stationary call, then measure (tested here 2026-10-24) [timsainb/noisereduce README, https://github.com/timsainb/noisereduce, checked 2026-10-24]
1547. **noisereduce prop_decrease for partial reduction** — `prop_decrease` is the proportion to reduce the noise by (1.0 = 100%); 0.7 gave pauses -54.5 dB instead of -74.8 dB. **How:** `nr.reduce_noise(y=y, sr=sr, stationary=True, y_noise=noise, prop_decrease=0.7)` (tested here 2026-10-24) [noisereduce source docstring, https://github.com/timsainb/noisereduce/blob/master/noisereduce/noisereduce.py, checked 2026-10-24]

## Gates and expanders between lines
1548. **agate: reduce noise between lines instead of muting it** — below `threshold` the gate divides the level by `ratio`, down to the floor set by `range` (default 0.06125; 0 turns it into an expander); `attack` and `release` level the change. With range=0.25 our pauses dropped about 12 dB (-42.9 -> -55.0 dB) and speech was untouched. **How:** `ffmpeg -i in.wav -af "agate=threshold=0.05:range=0.25:attack=10:release=250" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#agate, checked 2026-10-24]
1549. **agate detection and knee** — `detection` is `rms` (default) or `peak`; `knee` (1-8, default 2.83) curves the threshold so reduction starts more softly. **How:** `agate=threshold=0.05:range=0.1:detection=peak:knee=4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#agate, checked 2026-10-24]
1550. **A gate threshold must sit above the noise** — the docs' compand noise gate opens at about -50 dB; our noise is at -43 dB, so it changed nothing (pauses stayed -42.9 dB). Measure the pause level first and set the gate between noise and speech. **How:** `compand=.1|.1:.2|.2:-900/-900|-50.1/-900|-50/-50:.01:0:-90:.1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#compand, checked 2026-10-24]
1551. **Key a gate from a filtered copy** — `sidechaingate` processes the 1st stream from the level of the 2nd; filtering the key (the docs' example cuts the lows) stops rumble from opening it. Keying from a 300 Hz high-passed copy gave pauses -56.9 dB. **How:** `ffmpeg -i in.wav -af "asplit[m][k];[k]highpass=f=300[k2];[m][k2]sidechaingate=threshold=0.04:range=0.2:release=300" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#sidechaingate, checked 2026-10-24]
1552. **compand as a downward expander** — the docs give an expander transfer curve for compand that pushes low levels further down. **How:** `compand=attacks=0:points=-80/-169|-54/-80|-49.5/-64.6|-41.1/-41.1|-25.8/-15|-10.8/-4.5|0/0|20/8.3` (ran here) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#compand, checked 2026-10-24]

## Clicks, crackle and mouth noise
1553. **adeclick: detection threshold and the "save" method** — lower `threshold` (1-100, default 2) means more samples are treated as impulsive noise; `method=save` (`m=s`) leaves non-interpolated samples unchanged, while the default overlap-add slightly changes even good samples. **How:** `ffmpeg -i clicks.wav -af "adeclick=t=4:m=s" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adeclick, checked 2026-10-24]
1554. **adeclick window, overlap and burst** — `window` (10-100 ms, default 55), `overlap` (50-95%, default 75; higher removes more but is much slower) and `burst` (0-10%, default 2; fuses detected samples that are close together). **How:** `ffmpeg -i clicks.wav -af "adeclick=w=20:o=90:b=4" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adeclick, checked 2026-10-24]
1555. **See clicks and clipping in a waveform picture** — `showwavespic` draws the whole file as one image; `filter=peak` draws peak values instead of averages, so single-sample spikes show. **How:** `ffmpeg -i clicks.wav -lavfi "showwavespic=s=1600x300:filter=peak" wave.png` and look at the PNG (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#showwavespic, checked 2026-10-24]
1556. **Mouth De-click: run it twice** — iZotope's Mouth De-click targets clicks and lip smacks; higher Sensitivity can damage plosives, Frequency Skew at zero or above targets mid-frequency mouth clicks, Click Widening extends the repair for lip smacks with a decay, and a second pass often catches quieter clicks masked by louder ones. **How:** needs iZotope RX (missing, paid); in ffmpeg the nearest tool is `adeclick` (above) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/mouth-de-click.html, checked 2026-10-24]
1557. **De-click algorithm choice and "clicks only" listening** — RX De-click offers Single band (narrow digital clicks), Multi-band periodic, Multi-band random, and Low latency (mouth clicks other modes miss); "Output clicks only" outputs the difference so you hear what is removed. **How:** needs iZotope RX (missing); ffmpeg has no clicks-only output for adeclick, so subtract by ear [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-click.html, checked 2026-10-24]
1558. **Short click: interpolate under 4000 samples** — RX Interpolate repairs individual clicks below 4000 samples by synthesizing a replacement from the selection; RX's Instant Process uses Interpolate for selections under 4000 samples and De-click settings above. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/interpolate.html, checked 2026-10-24] [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-click.html, checked 2026-10-24]
1559. **Longer damage: Spectral Repair instead of De-click** — with a time selection, RX Spectral Repair gives better results than De-click on corrupted segments longer than 10 ms; Attenuate (vertical) is unlimited in length, Attenuate horizontal/2D and Replace up to 10 s, Pattern and Partials+Noise up to 4 s. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/spectral-repair.html, checked 2026-10-24]
1560. **Attenuate over speech, Replace over room tone** — for a creak under a line, iZotope's editor attenuated the noise where it overlapped dialogue and replaced it with surrounding audio where only room tone was present. **How:** needs iZotope RX Spectral Repair (missing) [iZotope blog, https://www.izotope.com/community/blog/how-to-remove-background-noise-from-dialogue-recordings, 2024-05-15]
1561. **De-crackle after De-click** — crackle is many quiet, close-together clicks; RX De-crackle works better after De-click has removed the worst clicks; RX also lists it for dry-mouthed spoken word. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-crackle.html, checked 2026-10-24] [iZotope RX product page, https://www.izotope.com/products/rx-advanced, checked 2026-10-24]
1562. **Audacity click tools and their size limits** — Click Removal needs a selection longer than 4096 samples (about 93 ms at 44.1 kHz), may miss broad clicks of 10 ms or more, and does not remove soft crackle (use Noise Reduction for that); Repair fixes a selection of at most 128 samples from the audio either side. **How:** needs Audacity (missing, free GPL); in ffmpeg use `adeclick` on whole stretches [Audacity Manual, https://manual.audacityteam.org/man/click_removal.html, checked 2026-10-24] [Audacity Manual, https://manual.audacityteam.org/man/repair.html, 2026-09-02]
1563. **Audition: Automatic Click Remover vs DeClicker** — Automatic Click Remover runs in real time in the Effects Rack/Multitrack and applies several scan-and-repair passes automatically; DeClicker (Diagnostics) lets you review detected clicks and choose which to fix but must be run several times for the same reduction. **How:** needs Adobe Audition (missing, paid) [Adobe Audition Help, https://helpx.adobe.com/audition/desktop/effects-reference/noise-reduction-restoration-effects.html, 2026-01-21] [Adobe Audition Help, https://helpx.adobe.com/si/audition/using/diagnostics-effects-waveform-editor-only.html, checked 2026-10-24]
1564. **Paste clean "air" over small noises** — dialogue editor Brad Semenoff sets RX's paste preferences to "To Selection" so he can copy full-bandwidth clean air from one place and paste it over clicks or birds elsewhere. **How:** needs iZotope RX (missing); the ffmpeg equivalent is a room-tone patch with `amix` (see the fill section) [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]

## Plosives
1565. **Run de-plosive before any high-pass** — RX De-plosive looks for plosives between 20 and 80 Hz, so a file already high-passed may defeat detection; plosives usually sit 20-300 Hz and can reach 500 Hz (set Frequency Limit just above them). **How:** needs iZotope RX (missing); in our chains keep `highpass` after any plosive fix [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-plosive.html, checked 2026-10-24]
1566. **Sensitivity before strength on plosives** — in RX De-plosive, Sensitivity affects results more than Strength; to keep speech quality, raise Sensitivity and lower Strength. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-plosive.html, checked 2026-10-24]
1567. **Which letters pop** — plosives come from stopping and suddenly releasing air; the low-frequency boom happens most with p, b, d, t and k. **How:** listen for low thumps on those consonants; find them as bright low-frequency blobs with `showspectrumpic=start=0:stop=500` [iZotope blog, https://www.izotope.com/community/blog/removing-plosives-from-a-voice-recording, 2022-10-05] [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-plosive.html, checked 2026-10-24]
1568. **A dynamic low-shelf in ffmpeg 6.1 syntax** — `adynamicequalizer` can detect with a lowpass and act with a lowshelf, cutting only while the detector is over threshold (6.1: `mode=cut`). **How:** `ffmpeg -i in.wav -af "adynamicequalizer=dftype=lowpass:dfrequency=150:tftype=lowshelf:tfrequency=150:mode=cut:threshold=20:attack=1:release=60:range=8" out.wav` (ran here; values not tuned on real pops) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adynamicequalizer, checked 2026-10-24]

## Hum, buzz, rumble and DC
1569. **Find the hum frequency on a spectrogram** — `showspectrumpic` with `start`/`stop` limits the picture to a frequency range, so 50/60 Hz and harmonics are easy to read. **How:** `ffmpeg -i in.wav -lavfi "showspectrumpic=s=800x400:start=0:stop=500:legend=1" hum.png` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#showspectrumpic, checked 2026-10-24]
1570. **Notch each harmonic with its own width** — Audacity's manual: notch the fundamental (60 Hz North America, 50 Hz UK and most other countries), find further spikes with a spectrum plot, use a higher Q on higher harmonics, and a Q between 2 and 10 generally works for mains hum. **How:** `anequalizer=c0 f=50 w=4 g=-30 t=0|c0 f=100 w=4 g=-20 t=0` (ran here; per-band f, width in Hz, gain) (tested here 2026-10-24) [Audacity Manual, https://manual.audacityteam.org/man/notch_filter.html, 2026-09-02] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#anequalizer, checked 2026-10-24]
1571. **Narrow notches ring** — a higher Q makes a notch narrower but adds longer "tails" (ringing) to its impulse response; minimum-phase filters put the ringing after the transient where it is more easily masked, linear-phase filters add pre-ringing and latency. **How:** use the widest notch that removes the hum; ffmpeg `bandreject`/`equalizer` are two-pole IIR filters [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-hum.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#bandreject, checked 2026-10-24]
1572. **Static vs dynamic de-hum** — RX De-hum Static suits simple hum with few harmonics that doesn't overlap speech; Dynamic suits hum with more than a dozen harmonics, inharmonic tones, buzz reaching high frequencies or hum overlapping speech; "Output hum only" helps tune Q and slope. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-hum.html, checked 2026-10-24]
1573. **Notch first, compress last around noise reduction** — Audacity advises notch filtering and click removal before Noise Reduction, and compression after it; RX likewise uses De-hum Dynamic before Voice/Spectral De-noise. **How:** order a chain as `bandreject...,adeclick,afftdn...` [Audacity Manual, https://manual.audacityteam.org/man/noise_reduction.html, 2026-09-02] [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-hum.html, checked 2026-10-24]
1574. **FIR notch with firequalizer adds 10 ms** — `firequalizer` takes a gain curve from `gain_entry`; its `delay` option defaults to 0.01 s, and our output was 480 samples (10 ms) late even with `zero_phase=on` written to WAV. **How:** `firequalizer=gain_entry='entry(40,0);entry(48,-30);entry(52,-30);entry(60,0)'` then `atrim=start_sample=480,asetpts=PTS-STARTPTS` if it must stay aligned (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#firequalizer, checked 2026-10-24]
1575. **Steep rumble cut with asubcut** — `asubcut` cuts below `cutoff` (2-200 Hz) with a selectable `order` (3-20, default 10), a steeper roll-off than `highpass`. **How:** `ffmpeg -i in.wav -af "asubcut=cutoff=80:order=20" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#asubcut, checked 2026-10-24]
1576. **Gentler high-pass with one pole** — `highpass` rolls off 6 dB per pole per octave; default is 2 poles, `p=1` gives a gentler 6 dB/octave slope. **How:** `ffmpeg -i in.wav -af "highpass=f=100:p=1" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#highpass, checked 2026-10-24]
1577. **Check and remove DC offset before noise reduction** — Adobe says Noise Reduction works best on audio with no DC offset; `astats` reports `DC_offset`; a 20 Hz high-pass or `dynaudnorm=correctdc=1` removes it. A test with `dcshift=0.05` read 0.050022 and the high-passed version ran clean. **How:** `ffmpeg -i in.wav -af "astats=measure_perchannel=DC_offset:measure_overall=none" -f null -` then `highpass=f=20` (tested here 2026-10-24) [Adobe Audition Help, https://helpx.adobe.com/audition/using/noise-reduction-restoration-effects.html, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#astats-1, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dynaudnorm, checked 2026-10-24]
1578. **Single-tone buzz or many-harmonic buzz** — RX suggests Spectral Repair Attenuate (vertical, 1024-4096 bands) for an occasional single-tone buzz and Spectral De-noise's tonal controls for buzz with harmonics up the spectrum. **How:** needs iZotope RX (missing); in ffmpeg notch a single tone with `bandreject=f=F:width_type=q:w=10` [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-hum.html, checked 2026-10-24]

## Clipping
1579. **Detect clipping with astats** — `Peak_count` counts how often the signal hits its min/max level and `Flat_factor` measures flat runs at the peaks; our deliberately clipped test read Peak level 0.0003 dB, Flat factor 32.6, Peak count 32858. **How:** `ffmpeg -i in.wav -af "astats=measure_perchannel=Peak_count+Flat_factor+Peak_level:measure_overall=none" -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#astats-1, checked 2026-10-24]
1580. **adeclip threshold, histogram and method** — `threshold` (default 10) and `hsize` (histogram size, default 1000): higher values make clip detection less aggressive; `method=save` keeps non-interpolated samples unchanged. **How:** `ffmpeg -i clip.wav -af "volume=-6dB,adeclip=t=5:n=1500:m=s" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adeclip, checked 2026-10-24]
1581. **Save de-clipped audio as 32-bit float** — de-clipping raises peaks above the old clip level; RX notes restored intervals above 0 dBFS survive if saved as 32-bit float. Our adeclip output written as `pcm_f32le` read a peak of +5.2 dBFS (a 16-bit file would clip it again). **How:** `ffmpeg -i clip.wav -af adeclip -c:a pcm_f32le out.wav`, then lower gain later (tested here 2026-10-24) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-clip.html, checked 2026-10-24]
1582. **Set de-clip threshold just under the clip level, per side if needed** — RX's histogram shows clipping as a line across the meter; set Threshold just below where peaks pile up, and unlink positive/negative thresholds for one-sided clipping (their example shears at -13 dB only on the positive side). **How:** needs iZotope RX (missing); in ffmpeg read `Min_level`/`Max_level` from `astats` to see if clipping is one-sided [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-clip.html, checked 2026-10-24]

## Sibilance
1583. **Hear only the esses the de-esser takes** — `deesser` output mode `s=e` passes only the detected ess, `s=o` the de-essed signal, `s=i` the input. **How:** `ffmpeg -i in.wav -af "deesser=i=0.4:s=e" ess_only.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#deesser, checked 2026-10-24]
1584. **Listen to adynamicequalizer's detector band** — `mode=listen` outputs only the isolated detection signal, which helps place `dfrequency` on the harsh band before switching to `mode=cut`. **How:** `ffmpeg -i in.wav -af "adynamicequalizer=dfrequency=6500:mode=listen" det.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adynamicequalizer, checked 2026-10-24]
1585. **Band de-essing with adynamicequalizer (6.1 syntax)** — detector and target can sit on the same band; in 6.1 use `mode=cut:direction=downward`; `auto=on` picks the threshold from the detector. **How:** `adynamicequalizer=dfrequency=6500:dqfactor=2:tfrequency=6500:tqfactor=2:mode=cut:direction=downward:threshold=10:range=6` and `...:mode=cut:auto=on` (both ran here; not tuned on a real voice) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adynamicequalizer, checked 2026-10-24]
1586. **Classic vs spectral de-ess** — RX Classic mode attenuates sibilants with a broadband gain envelope; Spectral mode attenuates only the high frequencies where sibilance is active (a multiband compressor with dozens of bands); the Cutoff frequency is the lower boundary of detection; Fast speed fixes high-frequency pumping, Slow keeps transients. **How:** needs iZotope RX (missing); ffmpeg `deesser` and `adynamicequalizer` are the local options [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/de-ess.html, checked 2026-10-24]

## Reverb and room echo
1587. **ML dialogue de-reverb needs no learning pass** — RX Dialogue De-reverb separates reverb from dialogue without learning a profile; Reduction sets the dB cut of the reverb part, higher Sensitivity removes more but adds artifacts, Ambience Preservation keeps background noise from being cut with the reverb. **How:** needs iZotope RX (missing); locally `clean_voice.py --dereverb` [iZotope RX 10 Help, https://docs.izotope.com/rx10/en/dialogue-de-reverb/index.html, checked 2026-10-24]
1588. **One module that splits voice, reverb and noise** — RX 11 Dialogue Isolate separates dialogue, noise and reverberation into three components with separate Voice/Reverb/Noise gain faders; lower Sensitivity keeps clarity but leaves more noise. Best/Offline quality is Advanced only. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/dialogue-isolate.html, checked 2026-10-24]

## Voice EQ and matching
1589. **Parallel EQ amount with `mix`** — `equalizer` (and the other biquad filters) take `mix` 0-1 for how much filtered signal is used, a quick way to soften a move. **How:** `ffmpeg -i in.wav -af "equalizer=f=3000:t=q:w=1:g=6:m=0.5" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#equalizer, checked 2026-10-24]
1590. **Tilt a dull or bright voice with tiltshelf** — `tiltshelf` boosts or cuts lows and does the opposite to highs around `f` (default 3000 Hz), like a hi-fi tone control. **How:** `ffmpeg -i in.wav -af "tiltshelf=g=-3:f=1500" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tiltshelf, checked 2026-10-24]
1591. **Draw an EQ curve point by point** — `firequalizer` interpolates between `entry(f,g)` points (the docs' custom example: 0 dB at 100 Hz, -4 at 400, -6 at 1000, 0 at 2000). **How:** `firequalizer=gain_entry='entry(100,0); entry(400, -4); entry(1000, -6); entry(2000, 0)'` (ran here; output 10 ms late, see the FIR note) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#firequalizer, checked 2026-10-24]
1592. **EQ one mic of a two-mic file** — `anequalizer` bands start with `cN` for the channel, so boom (c0) and lav (c1) in one stereo file can get different EQ. **How:** `ffmpeg -i twomic.wav -af "anequalizer=c1 f=4000 w=2000 g=4 t=1" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#anequalizer, checked 2026-10-24]
1593. **Add missing highs with an exciter, sparingly** — `aexciter` creates harmonics above `freq` (default 7500 Hz) instead of just boosting; Thunderbird Sound uses an exciter, sparingly, to give clean ADR the grit of a production lav. **How:** `ffmpeg -i in.wav -af "aexciter=amount=2:freq=6000" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#aexciter, checked 2026-10-24] [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1594. **Same EQ plug-in on boom and lav** — a film mixer keeps the same EQ type on boom and lavalier tracks because different EQ algorithms can shift phase differently between the tracks. **How:** in ffmpeg use the same filter (e.g. `equalizer`) on both channels [Film Mixing, https://film-mixing.com/2013/12/16/dialogue-mixing-part-1/, 2013-12-16]
1595. **EQ-match at 10-40%, not 100%** — RX EQ Match copies one selection's spectrum to another (lav to boom, location to ADR); a 100% match can sound unnatural, and 10-40% is often enough. **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/eq-match.html, checked 2026-10-24]
1596. **Proximity effect only on directional mics** — bass rises as a directional (cardioid-family) mic gets close to the mouth; omni capsules do not show it, and the more directional the mic the stronger it is. **How:** if a close VO is boomy, check the mic pattern before EQ [Wikipedia, https://en.wikipedia.org/wiki/Proximity_effect_(audio), 2025-10-28] [SoundGuys, https://www.soundguys.com/proximity-effect-explained-51333/, 2021-07-09]
1597. **Four EQ zones for matching ADR** — Thunderbird Sound's map: 100-250 Hz tubby/boomy, 250-800 Hz boxy, 800 Hz-4 kHz clarity (too much = "telephone"), 4 kHz+ sparkle (studio ADR often has too much here); use gentle cuts where ADR differs from production. **How:** `equalizer=f=F:t=q:w=1:g=-2` per zone, A/B against the production line [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1598. **Steeper filters to match production** — to match production, Thunderbird Sound sometimes high-passes ADR as high as 200 Hz and low-passes it as low as 5 kHz. **How:** `highpass=f=200,lowpass=f=5000` as a starting experiment, by ear [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]

## Room tone and fill
1599. **Where to look for fill, in order** — Idyll Sounds' priority: fill per shot crossfaded into the dialogue; near the moment; same clip; same location; room tone recorded per setup; other takes of the shot; other shots in the location; synthesized fill; library room tone (absolute last resort, mono). **How:** pull pauses from the same clip first with `atrim` [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24]
1600. **Stitch small silences into one fill** — collect tiny pauses (between lines, right after "action") and join them with tiny equal-power crossfades. **How:** `ffmpeg -i in.wav -i in.wav -i in.wav -filter_complex "[0]atrim=0.1:1.0,asetpts=PTS-STARTPTS[p];[1]atrim=17.0:18.2,asetpts=PTS-STARTPTS[q];[2]atrim=0.3:1.2,asetpts=PTS-STARTPTS[r];[p][q]acrossfade=d=0.02:c1=qsin:c2=qsin[pq];[pq][r]acrossfade=d=0.02:c1=qsin:c2=qsin" fill.wav` (2.96 s out) (tested here 2026-10-24) [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24]
1601. **Make fill loopable: add a reversed copy** — duplicate the stitched fill and reverse the duplicate; for plain broadband noise that is usually enough. **How:** `ffmpeg -i fill.wav -i fill.wav -filter_complex "[1]areverse[r];[0][r]acrossfade=d=0.05:c1=qsin:c2=qsin" loopfill.wav` (tested here 2026-10-24) [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#areverse, checked 2026-10-24]
1602. **Make fill loopable: swap the halves** — cut the fill in the middle into A and B, put B before A and crossfade the B-A joint, so the loop point is the original continuous middle. **How:** `ffmpeg -i fill.wav -i fill.wav -filter_complex "[0]atrim=0:0.8,asetpts=PTS-STARTPTS[A];[1]atrim=start=0.8,asetpts=PTS-STARTPTS[B];[B][A]acrossfade=d=0.03:c1=qsin:c2=qsin" loopfill.wav` (tested here 2026-10-24) [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24]
1603. **acrossfade gotcha: feed the file twice, not through asplit** — in ffmpeg 6.1.1 `[0]asplit[x][y]` followed by `[B][A]acrossfade` (later part first) produced a 0.023 s file instead of 1.57 s; the same graph with the file given as two `-i` inputs worked. Cutting in normal order (`[a][b]`) from one asplit worked. **How:** use `-i fill.wav -i fill.wav` whenever the second-in-time piece must play first (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#acrossfade, checked 2026-10-24]
1604. **AIRFILL: room tone as a convolution impulse** — a tiny sample of production room tone used as the impulse of a convolution reverb, fed with pink noise, gives perfectly steady (but sterile) fill; Idyll credits Douglas Murray. **How:** `ffmpeg -f lavfi -i "anoisesrc=c=pink:a=0.1:r=48000:d=6" -i tone.wav -filter_complex "[0][1]afir=dry=0:wet=1" airfill.wav`, then match its level to the real tone (tested here 2026-10-24) [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afir-1, checked 2026-10-24]
1605. **Name fill after the shot it came from** — Idyll names fill like "5B-T3.Boom Fill A", adds a tag (AF, IZ, AM) when synthesized, and makes Fill B etc. for different moments; a fill can serve another take of the same setup if the background doesn't change. **How:** name scratch fills `scene-take-mic-fillA.wav` in the scratchpad [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24]
1606. **Don't slather fill over a scene** — Brad Semenoff: fill eases transitions but too much makes the scene noisier; he prefers hand-built fill from bits between lines (natural movement) and uses RX Ambience Match only as a last resort or for M&E centre fill. **How:** fill only the holes and the clip heads/tails [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1607. **Ambience Match: static vs complex, and it only adds** — RX Ambience Match learns a noise floor and generates matching ambience; Static suits steady room tone/AC/fans, Complex generates moving ambience (new random result each render); it cannot reduce ambience already present (use Spectral De-noise for that). **How:** needs iZotope RX Advanced (missing); locally use stitched fill or AIRFILL [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/ambience-match.html, checked 2026-10-24]
1608. **Generated ambience is usually too loud** — with Ambience Match's "Output Ambience Only" Idyll usually has to trim it down by about 2-4 dB, and adds handles for crossfades. **How:** after making AIRFILL, lower it with `volume=-3dB` and compare with the real pauses [Idyll Sounds, https://idyllsounds.com/blog/dialog-editing-how-to-fill-a-scene-with-noise, checked 2026-10-24]
1609. **Learn ambience without fades in the selection** — iZotope warns against learning Ambience Match from audio containing fades (Pro Tools fade dither, worst at 16-bit, throws off the noise-floor detection). **How:** take tone samples from unfaded source audio, before any `afade` [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/ambience-match.html, checked 2026-10-24]
1610. **Record room tone with the dialogue chain untouched** — same mic, polar pattern, distance, angle, input, gain, sample rate and room state; don't switch off a fan that ran during the take; about a minute gives far more choice. **How:** ask for a minute of quiet before moving any mic [Sound Forge Pro guide, https://soundforgepro.com/room-tone-sound-forge/, 2026-09-19]
1611. **Patch a gap without changing the runtime** — overwrite the gap instead of inserting audio, so later words stay in sync; soften both boundaries with short fades. **How:** mute the gap and lay tone under it in place: `ffmpeg -i in.wav -i tone.wav -filter_complex "[0]volume=0:enable='between(t,5,5.6)'[m];[1]atrim=0:0.7,afade=t=in:d=0.05,afade=t=out:st=0.65:d=0.05,adelay=4950:all=1[f];[m][f]amix=inputs=2:normalize=0:duration=first" out.wav` (duration unchanged) (tested here 2026-10-24) [Sound Forge Pro guide, https://soundforgepro.com/room-tone-sound-forge/, 2026-09-19] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#amix, checked 2026-10-24]
1612. **amix sums at full level only with normalize=0** — `amix` scales inputs by default (`normalize` enabled); for laying fill under dialogue, the docs' example uses `normalize=0` with `weights`. **How:** `amix=inputs=2:duration=first:dropout_transition=0:weights="1 0.25":normalize=0` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#amix, checked 2026-10-24]
1613. **Start the fill level at the surrounding background** — begin with the room-tone level close to the background on both sides of the patch and lengthen fades only until the join disappears; no fade rescues tone that is brighter, louder or rhythmically different. **How:** read the pause level on both sides with `astats=measure_perchannel=RMS_level`, set the patch `volume` to match (tested here 2026-10-24) [Sound Forge Pro guide, https://soundforgepro.com/room-tone-sound-forge/, 2026-09-19] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#astats-1, checked 2026-10-24]
1614. **Re-check fills after compression and loudness** — compression, limiting and loudness changes lift the background between phrases and can expose a loop or mismatch that seemed harmless. **How:** listen to and measure patched pauses again on the final render [Sound Forge Pro guide, https://soundforgepro.com/room-tone-sound-forge/, 2026-09-19]
1615. **Bridge two takes with different floors** — for a modest difference, a little of the noisier take's room tone laid under the cleaner take at low level lets the two floors meet; a large mismatch needs a different editing decision. **How:** `amix=inputs=2:normalize=0:weights="1 0.3"` with the noisier take's tone [Sound Forge Pro guide, https://soundforgepro.com/room-tone-sound-forge/, 2026-09-19]
1616. **Fade a noisy background in and out with tone** — when a recording's background noise would pop in with the first word, use clean room tone to fade the noise in before the line and out after it. **How:** `afade=t=in:d=0.5` on a tone clip placed before the line with `adelay`, mixed with `amix ... normalize=0` [Frame.io Workflow Guide, https://workflow.frame.io/guide/roomtone, checked 2026-10-24]
1617. **Pull clip handles to find tone** — handles are the extra recording before and after each clip; the picture editor should include them in the OMF/AAF so the dialogue editor can extend a clip edge into clean room tone. **How:** when a client sends an export, ask for handles; locally keep the full camera clip and `atrim` wider than the edit [Frame.io Workflow Guide, https://workflow.frame.io/guide/roomtone, checked 2026-10-24]
1618. **Extend a loopable fill to any length** — `aloop` repeats samples (`loop=-1` infinite, `size` max samples); trim the result to the gap. **How:** `ffmpeg -i loopfill.wav -af "aloop=loop=-1:size=2e6,atrim=0:6" fill6s.wav` (6.0 s out) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#aloop, checked 2026-10-24]
1619. **Pull the background out to use as tone** — iZotope's editor runs Dialogue Isolate the other way round (keep noise, remove dialogue) when she needs extra room tone. Locally, `audio-separator --single_stem Instrumental` keeps only the non-voice stem (45 s for our 18 s clip with MDX-Net Voc FT). **How:** `/home/user/tools/venv/bin/audio-separator in.wav -m UVR-MDX-NET-Voc_FT.onnx --model_file_dir /home/user/tools/sep-models --single_stem Instrumental --output_format WAV --output_dir out/` (tested here 2026-10-24) [iZotope blog, https://www.izotope.com/community/blog/how-to-remove-background-noise-from-dialogue-recordings, 2024-05-15] [repo: library/tools/clean_voice.py]
1620. **Build fill as a mono centre track** — a film mixer describes fill tracks as mono ambience of the same location sent to the centre channel; they cover ADR noise jumps, smooth takes and are needed for the M&E. **How:** render fill as mono (`-ac 1`) [Film Mixing, https://film-mixing.com/2013/12/16/dialogue-mixing-part-1/, 2013-12-16]
1621. **Room tone also matches recordings from different rooms** — iZotope's example: lines recorded in two rooms sounded different; de-noising the odd line and laying the original room tone under it hid the change. **How:** `afftdn` on the odd line, then `amix ... normalize=0` with the scene's tone [iZotope blog, https://www.izotope.com/community/blog/basics-of-room-tone-audio-editing, 2021-10-13]
1622. **Duplicating a short noise sample doesn't improve a profile** — Audacity: Noise Reduction calculates noise statistics, so repeating the same short block adds nothing; it needs at least 2048 samples and longer is better. **How:** learn afftdn profiles from the longest clean pause you have [Audacity Manual, https://manual.audacityteam.org/man/noise_reduction.html, 2026-09-02]

## Breaths
1623. **Duck one breath by its time range** — many ffmpeg filters take a generic `enable` expression; `volume=0.3:enable='between(t,4.0,4.4)'` lowered just that 0.4 s by 10.4 dB (-18.5 -> -28.9 dB) and left the rest untouched. **How:** `ffmpeg -i in.wav -af "volume=0.3:enable='between(t,4.0,4.4)'" out.wav`; chain several for several breaths (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#Timeline-editing, checked 2026-10-24]
1624. **Breath ducking as one volume expression** — with `eval=frame` the volume expression is evaluated per frame and can use `t`. **How:** `ffmpeg -i in.wav -af "volume='if(between(t,4,4.4),0.3,1)':eval=frame" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#volume, checked 2026-10-24]
1625. **Target mode beats fixed gain for breaths** — RX Breath Control detects breaths by harmonic structure, not level; Gain mode cuts every breath by the same dB (quiet breaths can vanish, loud ones stay), Target mode only pulls breaths above a target level, which sounds more natural; "Output breaths only" checks detection. **How:** needs iZotope RX (missing); locally duck only the loud breaths by hand with `volume ... enable` [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/breath-control.html, checked 2026-10-24]
1626. **Replace an unwanted breath with room tone, not silence** — for voice-over where the speaker is off camera, a breath can be cut and the hole filled with clean room tone instead of hard cuts out and in. **How:** the runtime-safe patch command in the fill section, with the breath's times (tested here 2026-10-24) [Frame.io Workflow Guide, https://workflow.frame.io/guide/roomtone, checked 2026-10-24]

## Speech levelling and pauses
1628. **speechnorm: four strengths from the docs** — `speechnorm` expands/compresses each half-cycle toward a peak target; the docs list weak (`e=3:r=0.00001:l=1`), moderate (`e=6.25:r=0.00001:l=1`), strong (`e=12.5:r=0.0001:l=1`) and very strong (`e=25:r=0.0001:l=1`) presets. **How:** `ffmpeg -i in.wav -af "speechnorm=e=6.25:r=0.00001:l=1" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#speechnorm, checked 2026-10-24]
1629. **speechnorm with an RMS target** — option `rms` (`m`, default 0 = off) sets the highest allowed RMS level instead of only the peak target. **How:** `speechnorm=e=6.25:r=0.00001:l=1:m=0.1` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#speechnorm, checked 2026-10-24]
1630. **dynaudnorm without pumping up the noise** — `threshold` (`t`) skips frames below a level so digital noise is not amplified; `framelen` (default 500 ms) and `gausssize` (default 31, odd) set how fast gain follows; smaller gausssize behaves more like a compressor. **How:** `ffmpeg -i in.wav -af "dynaudnorm=f=250:g=15:t=0.05:m=6" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dynaudnorm, checked 2026-10-24]
1631. **dynaudnorm compress factor** — `compress` (`s`, 0-30, default off) adds soft-knee thresholding; smaller values compress harder and values below 3.0 can distort audibly. **How:** `dynaudnorm=f=500:g=31:s=5` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dynaudnorm, checked 2026-10-24]
1632. **List every pause with times** — `silencedetect` logs silence_start/end when the level stays below `noise` for at least `duration`; `mono=1` checks each channel separately (handy for two mics). On our clip at -40 dB / 0.1 s it found the pauses at 5.23-5.38, 6.53-6.79, 11.77-12.21 s. **How:** `ffmpeg -i in.wav -af "silencedetect=n=-40dB:d=0.1" -f null - 2>&1 | grep silence_` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#silencedetect, checked 2026-10-24]
1633. **silenceremove: cap every pause at a set length** — `silenceremove` with negative `stop_periods` works through the whole file, `stop_duration` is the pause length that triggers it and `stop_silence` keeps up to that much of each pause. **How:** `ffmpeg -i in.wav -af "silenceremove=stop_periods=-1:stop_duration=0.6:stop_threshold=-38dB:stop_silence=0.3" out.wav` (18.34 -> 17.67 s here) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#silenceremove, checked 2026-10-24]
1634. **Trim the dead head of a take but keep a lead-in** — `start_periods=1` trims leading silence; `start_silence` keeps up to that many seconds of it. **How:** `ffmpeg -i in.wav -af "silenceremove=start_periods=1:start_threshold=-50dB:start_silence=0.2" out.wav` (18.34 -> 16.23 s) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#silenceremove, checked 2026-10-24]
1635. **silenceremove timestamps: write vs copy** — `timestamp=write` (default) rewrites timestamps; `timestamp=copy` leaves kept frames at their original times. **How:** `silenceremove=stop_periods=-1:stop_duration=0.5:stop_threshold=-50dB:timestamp=copy` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#silenceremove, checked 2026-10-24]
1636. **Retime by compressing or decompressing pauses** — Inside the Edit's two core moves: if a character talks too slowly, shorten pauses between words and phrases; if too fast, add space so the meaning can breathe. **How:** get pause times from `silencedetect`, then cut with `atrim`+`acrossfade` or pad with fill [Inside the Edit, https://www.insidetheedit.com/blog/how-to-retime-dialogue, checked 2026-10-24]
1637. **Keep a pause between sentences** — Larry Jordan: there is a slight pause between the end of one sentence and the start of the next; when picture cuts make one clip's audio crash into the next, recreate that pause. **How:** `apad=pad_dur=0.3` on the first line, or fill [Larry Jordan, https://larryjordan.com/articles/fcp-x-better-dialog-editing/, 2013-06-16] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#apad, checked 2026-10-24]

## Word-level edits and fillers
1638. **Cut mid-word on hard consonants** — Podcast Engineering School: when an edit must fall inside a word (e.g. a restated word with odd inflection), cut on hard consonants like t, k, p. **How:** zoom with `showwavespic` on the word, cut at the consonant burst with `atrim` + 5-20 ms `acrossfade` [Podcast Engineering School, https://podcastengineeringschool.com/mid-word-edit-points/, checked 2026-10-24]
1639. **Cut on a later word or a syllable** — it can be easier to cut on the 2nd or 3rd word of a sentence, or on a syllable, than on the first word; repeats spoken while laughing are nearly impossible to edit. **How:** try several cut points against the retake before settling [Podcast Engineering School, https://podcastengineeringschool.com/making-edit-cuts-on-words-and-syllables/, checked 2026-10-24]
1640. **Cut after the breath, not before** — a sound editor lists cutting after the breath instead of before it, and cutting on plosives or hard consonants, as useful filler-edit moves. **How:** place the out-point after the inhale so the next line keeps its breath [Sound StackExchange, https://sound.stackexchange.com/questions/15533/dealing-with-fillers, checked 2026-10-24]
1641. **Break filler clusters and patterns, not every filler** — remove clusters ("um, uh, you know"), shorten extended fillers to normal length (under one second), and remove enough of a speaker's signature filler that the pattern is no longer noticed. **How:** list fillers from the transcript, cut clusters first [PodRewind, https://podrewind.com/blog/removing-ums-ahs-podcasts, 2025-11-14]
1642. **Transcript-driven word cut in ffmpeg** — cut out a phrase using Whisper word times (adjusted to the real pause from silencedetect) and join with a short equal-power crossfade. **How:** `ffmpeg -i sp.wav -filter_complex "[0]asplit[x][y];[x]atrim=0:6.53[a];[y]atrim=start=8.32,asetpts=PTS-STARTPTS[b];[a][b]acrossfade=d=0.02:c1=qsin:c2=qsin" out.wav` removed "one of the two small steamers" (18.34 -> 16.53 s) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#acrossfade, checked 2026-10-24]
1643. **Salvage a take with one bad word** — Apple's dialogue tips: if someone mumbles a single word, salvage the rest of the take instead of dropping the whole take. **How:** cut the replacement word with `atrim` and drop it in with short crossfades; check lip sync [Final Cut Pro 6 manual, https://final-cut-pro-6.helpnox.com/en-us/final-cut-pro-user-manual/volume-iii-audio-mixing-and-effects/part-i-audio-mixing/tips-for-better-audio/tips-for-cutting-dialogue/, checked 2026-10-24]
1644. **Use alts sparingly and label them** — Brad Semenoff replaces as little as possible with alternate takes, colour-labels the alt clip and keeps the original muted underneath. **How:** keep the replaced original as a separate muted file next to the edit [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1645. **Text-based editing in Premiere** — Premiere transcribes clips and cutting, copying or pasting text trims and moves the clips on the timeline; Find/Replace works in the transcript. **How:** needs Adobe Premiere (missing); locally edit from Whisper JSON as above [Adobe Premiere Help, https://helpx.adobe.com/premiere/desktop/edit-projects/edit-video-using-text-based-editing/overview-of-text-based-editing.html, 2026-01-07] [Adobe Premiere Help, https://helpx.adobe.com/premiere/desktop/add-text-images/insert-captions/find-and-replace-text-in-transcription.html, 2025-08-22]

## Choosing mics, phase and bleed
1663. **Choose the mic by tone, noise and echo** — Frame.io's questions: which recording has the fuller, more realistic tone (not tinny, not muffled), which is less noisy (lavs may add clothing rustle), and which is less echoey; send all mics to the sound studio because another may be easier to improve. **How:** split dual-mono camera audio with `channelsplit` and A/B each mic [Frame.io Workflow Guide, https://workflow.frame.io/guide/choose-dialog-recording, checked 2026-10-24]
1664. **One mic per scene, swap only for a problem line** — use the same mic for a whole scene, but swap in another recording for one line if the better mic has a hiccup there (e.g. a lav rustle). **How:** keep the alternate mic aligned underneath so the swap is a simple cut [Frame.io Workflow Guide, https://workflow.frame.io/guide/choose-dialog-recording, checked 2026-10-24] [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1665. **Grade each mic: good, usable, poor** — April Tucker listens scene by scene: good (close, present, not too noisy), usable if necessary (minor placement/noise/correctable tech issue), poor (hard to understand, distant, very noisy, dropouts). **How:** write the grade per mic in the edit notes before cutting [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1666. **Boom or lavs: when lavs win** — for two characters in a quiet scene a well-placed boom may be preferred; if they yell over each other, lavs give the mixer control to favour one line; a lav with constant cloth rubbing pushes you to the boom. **How:** decide per scene, not per line [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1667. **Keep usable alts muted or on X tracks** — Tucker leaves a good second mic muted on an active track or moves it to an "X" (alt) track so the mixer can find it; only completely unusable mics are deleted. **How:** keep alternate mic WAVs next to the edit, named `X-...` [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1668. **Same mic choice for the same location** — when a location returns across scenes shot at the same time, reuse the same mic choice so the mixer can reuse settings. **How:** note "location -> mic" in the project notes [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1669. **Why two mics sound hollow together** — sound travels about 34 cm per millisecond, so a distance difference becomes a time offset and summing gives comb-filter notches (hollow, thin); it is most obvious in a mono sum and vanishes when either track is soloed. **How:** always test the mono sum: `pan=mono|c0=0.5*c0+0.5*c1,volumedetect` (tested here 2026-10-24) [Audio Tool Kit, https://audio-tool-kit.com/blog/phase-cancellation, checked 2026-10-24] [Sound On Sound, https://www.soundonsound.com/sound-advice/q-how-do-stop-comb-filtering-when-recording-stereo, checked 2026-10-24]
1670. **The 3:1 mic rule** — place the second mic at least three times further from the first than the first is from the source, so the level difference keeps cancellation inaudible; a film mixer avoids mixing two ADR mics that don't follow the 1:3 rule. **How:** when two mics must be blended, check the rule first [Audio Tool Kit, https://audio-tool-kit.com/blog/phase-cancellation, checked 2026-10-24] [Film Mixing, https://film-mixing.com/2013/12/16/dialogue-mixing-part-1/, 2013-12-16]
1671. **Flip polarity only for reversed signals** — inverting polarity flips the whole waveform; it fixes reversed wiring and some close pairs but cannot fix a time offset, which needs a delay. Our test pair with one channel inverted summed to -91 dB (near total cancellation); after flipping it summed to -19.9 dB. **How:** `stereotools=phaser=1` (flip right) or `pan=stereo|c0=c0|c1=-1*c1`, then re-check the mono sum (tested here 2026-10-24) [Audio Tool Kit, https://audio-tool-kit.com/blog/phase-cancellation, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#stereotools, checked 2026-10-24]
1672. **Measure the delay between two mics and line them up** — delay between mic signals can be estimated with signal processing (e.g. cross-correlation, GCC-PHAT) and corrected with a compensating delay; estimation errors cause flanging. Our scipy cross-correlation found exactly the 72-sample (1.5 ms) offset we built in; `adelay` takes sample counts with `S`. **How:** `scipy.signal.correlate(b, a, mode='full', method='fft')`, argmax minus (n-1) = lag, then `adelay=72S|0` (tested here 2026-10-24) [Clifford & Reiss, JAES, https://joshreiss.github.io/documents/2013/clifford%20reiss%20-%20JAES.pdf, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#adelay, checked 2026-10-24]
1673. **Delay a mic by distance** — `compensationdelay` delays by `mm`/`cm`/`m` at a given `temp` (default 20 °C); the docs note about 30 cm between mics puts one in antiphase. cm=51 gave a 71-sample (1.48 ms) shift here. **How:** `ffmpeg -i boom.wav -af "compensationdelay=cm=51" out.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#compensationdelay, checked 2026-10-24]
1674. **Log out-of-phase stretches automatically** — `aphasemeter` with `phasing=1` logs mono and out-of-phase sequences (angle threshold default 170°) lasting at least `duration`; on our inverted pair it logged `out_phase_start: 2.28`. **How:** `ffmpeg -i pair.wav -af "aphasemeter=video=0:phasing=1:duration=1" -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#aphasemeter, checked 2026-10-24]
1675. **Boom left, lav right, then look at phase** — a mixer routes the lav and boom to a stereo bus (one left, one right) and checks them on a phase scope; a sudden dip in body or low mids usually means the two are slipped or out of phase, and nudging fixes tone without EQ. **How:** `join=inputs=2:channel_layout=stereo:map=0.0-FL|1.0-FR` then `aphasemeter` or `channelsplit,axcorrelate=size=1024:algo=fast` (tested here 2026-10-24) [Film Mixing, https://film-mixing.com/2013/12/16/dialogue-mixing-part-1/, 2013-12-16] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#axcorrelate, checked 2026-10-24]
1676. **Read correlation between channels** — `axcorrelate` outputs normalized windowed cross-correlation: 1 = highly correlated, 0 = unrelated, -1 = out of phase (cancel). Our aligned pair averaged -1.0 dB (near 1); the inverted pair hit the -1 end. **How:** `ffmpeg -i pair.wav -af "channelsplit,axcorrelate=size=1024:algo=fast" corr.wav` then `astats` on corr.wav (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#axcorrelate, checked 2026-10-24]
1677. **Split dual-mono camera audio into separate mics** — `channelsplit` makes one stream per channel; `pan=mono|c0=c1` keeps only the right channel. **How:** `ffmpeg -i in.wav -filter_complex "channelsplit=channel_layout=stereo[L][R]" -map "[L]" boom.wav -map "[R]" lav.wav` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#channelsplit, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#pan-1, checked 2026-10-24]
1678. **High-pass the lav to reduce overlap** — besides time alignment and choosing one mic per line, Audio Tool Kit suggests a high-pass on the lav so boom and lav overlap less in the low mids. **How:** `highpass=f=150` on the lav before any blend (value is a starting point, by ear) [Audio Tool Kit, https://audio-tool-kit.com/blog/phase-cancellation, checked 2026-10-24]
1679. **Mid/side to pull a centred voice out of stereo** — `stereotools` `mode=lr>ms` converts L/R to mid/side; `slev` lowers the side signal (e.g. wide ambience) while the centred voice stays. **How:** `stereotools=mode=lr>ms` or `stereotools=slev=0.3` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#stereotools, checked 2026-10-24]
1680. **dialoguenhance builds a speech centre channel** — it takes stereo and outputs 3.0 with an enhanced dialogue centre (FC), leaving FL/FR as input; `enhance` 0-3, `voice` detection 2-32. Our FC output was 1679 samples (35 ms) late vs the input. **How:** `dialoguenhance=enhance=2,pan=mono|c0=FC` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#dialoguenhance, checked 2026-10-24]
1681. **Why a gate fails on mic bleed** — a gate opens from its own track's level, but bleed can be as loud as word starts and ends, so it opens late, cuts consonants or chatters, and during overlap both mics stay open. **How:** for two-host clips, cut bleed by hand or use a gain-sharing automixer [Clarum Audio, https://clarumaudio.com/mic-bleed-vs-noise-gate.html, 2026-09-06]
1682. **Gain-sharing automixers compare all mics** — a Dugan-style automixer looks at all mic tracks together: the active mic stays open, quieter mics attenuate, overlaps can keep several open; with no one talking, the gains are set uniformly. **How:** needs an automixer plug-in (missing); not the same as spectral de-bleed [Clarum Audio, https://clarumaudio.com/mic-bleed-vs-noise-gate.html, 2026-09-06] [Yamaha MTX technology, https://usa.yamaha.com/products/proaudio/processors/mtx/technology.html, checked 2026-10-24]
1683. **Edit bleed out by removing regions** — with two people on separate close mics, removing each mic's region while the other person talks makes the speaker clearer; listen before deleting because quiet reactions or words may be in there. **How:** get each mic's speech regions from `silencedetect=m=1`, mute the rest with `volume=0:enable=...` [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1684. **Bleed also causes phase problems** — each mic hears a quieter, delayed copy of the other speakers, and that delayed bleed combines with the direct signal on another track into thin, hollow voices; EQ/compression on one host also reacts to the bleed. **How:** prevent with close mics; in the edit, mute bleed regions [Pristine Podcasts, https://app.pristinepodcasts.com/blog/editing-multiple-mics-bleed-podcast, 2026-02-26]
1685. **Reduce bleed while recording** — use dynamic mics close to the mouth, point each mic away from the other speakers; placement cuts bleed before any plug-in. **How:** brief clients before multi-person shoots [podswitch, https://www.usepodswitch.com/guides/how-to-remove-mic-bleed-from-a-podcast, 2026-10-06] [Clarum Audio, https://clarumaudio.com/mic-bleed-vs-noise-gate.html, 2026-09-06]

## Sync
1686. **How much sync error is acceptable (EBU R37)** — at any output for emission, sound should be no more than 40 ms before and no more than 60 ms after the picture; each production stage should stay within 5 ms early to 15 ms late. **How:** keep every processing step's added delay inside 15 ms or trim it out (see the latency lines) [EBU R37-2007, https://tech.ebu.ch/docs/r/r037.pdf, checked 2026-10-24]
1687. **When viewers notice (ITU-R BT.1359)** — subjective tests put detectability at about +45 ms (sound early) to -125 ms (sound late) and acceptability at about +90 ms to -185 ms; the limit for late sound is wider than for early sound. **How:** when unsure, err toward audio slightly late rather than early [ITU-R BT.1359-1, https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.1359-1-199811-I!!PDF-E.pdf, checked 2026-10-24]
1688. **Film sync within half a frame** — BT.1359 notes that for 24 fps film, ±half a frame (about ±22 ms) is an acceptable variation. **How:** at 24/25/30 fps, a one-frame slip (42/40/33 ms) is already near the limit; fix it [ITU-R BT.1359-1, https://www.itu.int/dms_pubrec/itu-r/rec/bt/R-REC-BT.1359-1-199811-I!!PDF-E.pdf, checked 2026-10-24]
1689. **Most viewers notice at 2-3 frames** — TV Technology: most viewers don't detect lip-sync error until about two or three frames, professionals may see one frame, and once noticed viewers become more sensitive to it. **How:** check talking-head sync at full speed after every audio replacement [TV Technology, https://www.tvtechnology.com/opinions/managing-lip-sync-267386, 2012-05-11]
1690. **Make a blip-and-flash sync test** — EBU R37 describes measuring sync with a "flash" (one full frame of peak white) and a "blip" (1 kHz tone for the same duration). Build one, run it through the pipeline, and compare `silencedetect` vs `blackdetect` times; after `adelay=120` the blip read 2.12 s vs the flash at 2.00 s. **How:** `ffmpeg -f lavfi -i "color=black:s=320x180:r=25:d=4" -f lavfi -i "aevalsrc=if(between(t\,2\,2.04)\,0.5*sin(2*PI*1000*t)\,0):s=48000:d=4" -vf "geq=lum='if(between(T,2,2.039),235,16)':cb=128:cr=128" -c:v libx264 -c:a pcm_s16le test.mov`, then `ffmpeg -i out.mov -af silencedetect=n=-40dB:d=0.5 -vf blackdetect=d=0.5:pix_th=0.5 -f null -` (tested here 2026-10-24) [EBU R37-2007, https://tech.ebu.ch/docs/r/r037.pdf, checked 2026-10-24]
1691. **Audio filters shift sync: measure each one** — measured output delay at 48 kHz: afftdn 1200 samples (25 ms), dialoguenhance 1679 (35 ms), arnndn 480 (10 ms), firequalizer 480 (10 ms); afwtdn, agate, speechnorm, adynamicequalizer about 0. afftdn + dialoguenhance together would already pass EBU's 15 ms per-stage limit. **How:** cross-correlate input vs output (`scipy.signal.correlate`) and trim with `atrim=start_sample=N,asetpts=PTS-STARTPTS` (tested here 2026-10-24) [EBU R37-2007, https://tech.ebu.ch/docs/r/r037.pdf, checked 2026-10-24]
1692. **Sync two recordings by cross-correlation** — the same idea PluralEyes uses (comparing audio content): correlate camera scratch audio with the recorder file; our test found a built-in 120 ms offset exactly (5760 samples). **How:** `lag = argmax(abs(correlate(b, a, mode='full', method='fft'))) - (len(a)-1)` on the first ~10 s, then `adelay` or `atrim` (tested here 2026-10-24) [Maxon PluralEyes Help, https://help.maxon.net/rg/en-us/Content/html/Pluraleyes-troubleshoot-the-sync.html, checked 2026-10-24]
1693. **Move audio earlier by trimming its head** — `adelay` can only delay; to make audio earlier cut the start with `atrim` (`start` in seconds or `start_sample`) and reset timestamps with `asetpts`. **How:** `ffmpeg -i late.wav -af "atrim=start_sample=5760,asetpts=PTS-STARTPTS" out.wav` brought our 120 ms late copy to 0 lag (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atrim, checked 2026-10-24]
1694. **Shift only the audio input with -ss** — put `-ss` before the audio file's `-i` and map video from the other input to skip the audio's first part. **How:** `ffmpeg -i v.mp4 -ss 0.12 -i late.wav -map 0:v -map 1:a -c:v copy -c:a aac -shortest out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg.html#Main-options, checked 2026-10-24]
1695. **Clap sync: match the spike to the frame** — the editor lines up the waveform spike of the slate clap (or a hand clap/finger snap) with the frame where the sticks meet. **How:** find the clap time with `astats`/`silencedetect`, the frame by stepping through `ffmpeg -ss T -frames:v 1` stills [StudioBinder, https://www.studiobinder.com/blog/how-to-use-a-film-slate/, 2023-08-13] [TechSmith Academy, https://www.techsmith.com/learn/tutorials/academy/basics-syncing-audio-and-video/, 2024-12-30]
1696. **Resolve Auto Sync: timecode, waveform, in/out or markers** — Resolve syncs dual-system audio by matching timecode to Broadcast WAVs, by waveform (needs camera audio), or by In/Out points or Markers placed on a known sync point; "Use channel number" Auto/Mix/specific channel avoids noisy channels; organise by day/scene to speed waveform sync. **How:** needs DaVinci Resolve (missing) [DaVinci Resolve manual ch. 20, https://docs.imaster.org/davinci-resolve-21-manual/part-3-ingest-and-organize-media/ch.-20-syncing-audio-and-video, checked 2026-10-24]
1697. **Keep the camera audio when syncing** — Resolve's "Retain embedded audio" adds the synced channels on an extra track instead of replacing the camera audio, so both can be edited. **How:** locally keep the camera track as a second audio stream: `-map 0:a -map 1:a` [DaVinci Resolve manual ch. 20, https://docs.imaster.org/davinci-resolve-21-manual/part-3-ingest-and-organize-media/ch.-20-syncing-audio-and-video, checked 2026-10-24]
1698. **Premiere: synchronize before merging** — Premiere's Merge Clips aligns from clip start unless you first use Clip > Synchronize (by clip start/end, timecode, numbered marker or audio); its Merge Clips dialog can also sync by audio. **How:** needs Adobe Premiere (missing) [Adobe Premiere Help, https://helpx.adobe.com/premiere/desktop/add-audio-effects/basic-audio-editing/merge-clips-in-the-timeline-panel.html, 2025-08-22] [Adobe Learn, https://www.adobe.com/learn/premiere-pro/web/professional-audio-mix, 2026-01-05]
1699. **Why automatic waveform sync fails** — PluralEyes needs about 5-10 s of good audio per clip (3 s or less is a problem), cannot sync silent video, ignores clappers and timecode, and fails on discontinuous clips with dropped sound - trim those so each clip is one continuous recording. **How:** give the sync tool clean, continuous, long-enough clips [Maxon PluralEyes Help, https://help.maxon.net/rg/en-us/Content/html/Pluraleyes-troubleshoot-the-sync.html, checked 2026-10-24]
1700. **Sync good in the middle, off at the ends = drift** — that pattern means the recorder's speed was not exact; PluralEyes detects it and writes drift-corrected new audio files. **How:** measure the offset at the start and the end; if they differ, correct the speed (next line) [Maxon PluralEyes Help, https://help.maxon.net/rg/en-us/Content/html/Pluraleyes-troubleshoot-the-sync.html, checked 2026-10-24]
1701. **Fix linear drift with rubberband or a re-stamped rate, not atempo** — to slow a file by 0.1% we measured the lag at 3, 8 and 14 s: `rubberband=tempo=0.999` and `asetrate=47952,aresample=48000` both grew by about 1.0 ms per second as they should (3.7 -> 14.9 ms and 3.9 -> 15.1 ms), but `atempo=0.999` grew only about 0.57 ms per second and came out shorter (18.337 s). rubberband keeps pitch; the asetrate route changes pitch by the same 0.1%. **How:** tempo factor = current length / wanted length (below 1 makes it longer), then `ffmpeg -i rec.wav -af "rubberband=tempo=0.999" out.wav`; re-measure the end offset (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rubberband, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#atempo, checked 2026-10-24]
1702. **0.1% pull-up/pull-down sample rates** — 48.048 kHz is 0.1% above 48 kHz, the same 0.1% as 24 vs 23.98 fps; 48 kHz sound pulled down plays as 47.952 kHz to stay in sync with slowed video. Re-stamping the rate gives the 0.1% speed change: `asetrate=48048,aresample=48000` turned 18.34 s into 18.32 s. **How:** `ffmpeg -i in.wav -af "asetrate=48048,aresample=48000" out.wav` (tested here 2026-10-24) [Trew Audio, https://www.trewaudio.com/articles/48048-khz/, 2007-03-19] [Sound Devices, https://www.sounddevices.com/file-format-overview/, 2007-12-12]
1703. **"F" stamped rates on Sound Devices recorders** — if told to shoot 48.048 or 47.952 kHz, select the 'fake' stamped rates 48.048F or 47.952F unless pre-production says otherwise; some editors want 48.048 files stamped as 48 kHz. **How:** ask the post team which stamp they expect before a shoot [Sound Devices, https://www.sounddevices.com/sample-rate-and-frame-rate-settings-for-production-sound/, 2008-01-16] [Sound Devices, https://www.sounddevices.com/file-format-overview/, 2007-12-12]
1704. **Drift causes and prevention** — mixing 44.1 kHz with 48 kHz, variable frame rate footage and devices with independent clocks cause drift; set everything to 48 kHz and constant frame rate, and use timecode generators on multi-device shoots. **How:** check `ffprobe -show_entries stream=sample_rate,r_frame_rate,avg_frame_rate` on every source [Video Editing Rentals, https://www.video-editing-rentals.com/how-to-fix-drifting-audio-sync-in-long-interviews-without-cutting/, 2024-03-12]
1705. **Resample to timestamps with aresample async** — `aresample=async=1000` stretches/squeezes samples (up to 1000 samples per second) to match the timestamps. **How:** `ffmpeg -i in.mp4 -af "aresample=async=1000" -c:v copy out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#aresample-1, checked 2026-10-24]
1706. **Jam-sync timecode** — Tentacle devices can sync almost any camera or recorder with either a dedicated timecode input or at least one audio channel; Deity's TC-SL1 drifts less than 1 frame per 48 hours. **How:** on client shoots ask whether timecode was jammed; if so, sync by timecode, not waveform [Tentacle Sync Help, https://support.tentaclesync.com/hc/en-us/articles/360007324538-How-do-I-connect-my-Tentacle-device-to-a-camera-or-audio-recorder, checked 2026-10-24] [Deity Help, https://help.deitymic.com/en/tc-sl1/how-to-sync-timecode, checked 2026-10-24]
1707. **Word anchors for drifting long recordings** — WhisperSync transcribes both tracks with per-word timestamps and matches word anchors along the whole recording to follow clock drift that start-locked waveform matching misses. **How:** needs WhisperSync (missing); locally compare Whisper word times of both tracks at start and end to measure drift [Bormotoon/WhisperSync, https://github.com/Bormotoon/WhisperSync, checked 2026-10-24]

## ADR and wild lines
1708. **Wild lines: re-record on set, camera off** — actors repeat lines with the same mics and positions right after the take, without camera; editors line them up later; also used for off-screen voices. **How:** when a line is ruined on a client shoot, ask for a wild line before the setup is struck [SetHero, https://sethero.com/blog/article/wild-lines-film-set-terminology/, 2025-07-02] [Wikipedia, https://en.wikipedia.org/wiki/Wild_track, 2023-04-01]
1709. **Same mics as production, both boom and lav** — use the exact make and model used on set (ask the location recordist) and record lav and boom simultaneously to choose later. **How:** note the production mics on every job [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30] [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1710. **ADR mic placement** — Thunderbird Sound: boom about 12-18 inches above the talent angled to the mouth (too far off in a poor room brings out resonances); lav on the shirt about 8 inches below the chin; the lav is often the better match to production. **How:** for owner VO pickups, copy the original mic distance [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1711. **Record ADR at a higher rate if it will be stretched** — heavy time-stretching makes 48 kHz audio grainy; record higher, process, then convert to the 48 kHz/24-bit delivery spec. **How:** `aresample=48000` after stretching; deliver `-c:a pcm_s24le -ar 48000` [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30]
1712. **Fit ADR length with rubberband** — `rubberband` changes tempo and pitch independently, with `formant=preserved` and `pitchq=quality` options. **How:** `ffmpeg -i adr.wav -af "rubberband=tempo=1.08:formant=preserved:pitchq=quality" out.wav` (18.34 -> 16.98 s) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rubberband, checked 2026-10-24]
1713. **Match the performance level to the scene** — a softly spoken ADR line in a noisy city scene never sounds convincing, however good the sync; deliver at the level the person would really use there. **How:** play the scene's background to the speaker before the take [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30]
1714. **Record every take, warm-ups included** — natural performances often happen when the actor feels no pressure; keep recording past the "last" take. **How:** for owner VO sessions keep one continuous recording and cut later [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30]
1715. **Remove noisy clothes and jewellery before ADR** — rustling fabrics, open zips and rattling jewellery ruin takes; a jewellery bowl on arrival helps. **How:** check before recording owner VO [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30]
1716. **Set ADR levels at both ends of the range** — performances go from whisper to shout; check level at the top and bottom, e.g. by making the talent laugh to find the peak. **How:** leave headroom for the loudest cue [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30]
1717. **Sync ADR by matching waveforms** — line the ADR waveform up with the production waveform, slide words or syllables that don't fall in sync, then listen and watch for lip sync. **How:** cut ADR into words with `atrim` at the peaks that match production [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1718. **Use only the ADR you need** — if noise covered only a syllable and a half, use just that frame or so of ADR instead of replacing the whole line, which can stick out. **How:** patch the syllable with a 5-20 ms crossfade [Production Expert, https://www.production-expert.com/production-expert-1/how-to-get-adr-to-sit-well-in-a-mix, 2024-10-24]
1719. **Place ADR in the room with an impulse-response reverb, in mono** — Thunderbird Sound uses realistic IR-style reverbs (Altiverb, Revibe), in mono to match a mono boom; ffmpeg's `afir` convolves with any IR file (the docs' example applies reverb from a mono IR). **How:** `ffmpeg -i adr.wav -i room_ir.wav -filter_complex "[0]asplit[d][w];[w][1]afir[wet];[d][wet]amix=inputs=2:weights='1 0.25':normalize=0" out.wav` (ran here with a synthetic IR) (tested here 2026-10-24) [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#afir-1, checked 2026-10-24]
1720. **Capture location impulse responses on the shoot** — sound editors suggest recording IRs of locations during filming for ADR matching later, and recording exterior ADR outdoors rather than faking an exterior inside. **How:** a clap or balloon pop recorded at the shooting spot can serve as a rough IR for `afir` [Sound StackExchange, https://sound.stackexchange.com/questions/2263/processing-adr-to-match-interiors-and-exteriors, checked 2026-10-24]
1721. **Dirty up ADR that is too clean** — Thunderbird Sound sometimes adds a little distortion or compression so studio ADR matches a gritty or over-compressed production lav. **How:** `acompressor` or `asoftclip` very lightly, A/B against production [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1722. **Room tone under ADR** — lay the production room tone under ADR so the background never breaks; find it at the head/tail of the take or an alternate take, Ambience Match as a fallback. **How:** `amix=inputs=2:normalize=0` with the scene's fill [Thunderbird Sound, https://www.tbirdsound.com/post/adrmatch, 2021-05-20]
1723. **Prep production around ADR so it can be undone** — Semenoff prepares the surrounding production dialogue so the air doesn't drop out when the ADR line comes in, but in a way that the ADR fill can be muted if the mix goes back to production. **How:** keep ADR fill on its own file/track [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1724. **Keep the untouched ADR copy** — Semenoff sometimes changes pitch or EQ of ADR but always keeps the original for the mixer and adds reverb only temporarily to test a line. **How:** save `adr_raw.wav` next to any processed version [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1725. **ADR usually needs more EQ than production** — a film mixer notes ADR often carries more EQ than production dialogue because scenes may be dubbed in one go; a benefit is that ADR can be panned since no noise moves with it. **How:** budget EQ time for ADR lines [Film Mixing, https://film-mixing.com/2013/12/16/dialogue-mixing-part-1/, 2013-12-16]
1726. **Match acoustics and perspective, not just words** — the classic ADR mistake is dropping clean studio lines in without matching perspective (reverb, EQ), level and breaths, so they sound detached. **How:** EQ, IR reverb, level and room tone, then check in context [IRPR Sound Design, https://sounddesign.irpr.agency/guides/how-to-match-adr-to-production-sound/, 2026-06-18]
1727. **ADR cueing tools** — cues should be prepared in a spotting session before ADR; EdiCue/EdiPrompt (Sounds in Sync) and 3Cue handle cue sheets, streamers and countdown beeps; Semenoff uses ADR Toolbox for cue databases. **How:** for small jobs, a cue list with timecode in/out and line text is enough [Production Expert, https://www.production-expert.com/production-expert-1/tips-for-getting-great-adr-recordings, 2024-01-30] [3Studio, https://www.3studio.co.uk/3cue/, checked 2026-10-24] [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1728. **ADR is the answer when it must be truly clean** — Larry Jordan: if you need an absolutely clean background, re-record in a studio with ADR; most of the time some background is wanted because it feels like the location. **How:** offer a re-record when the owner wants studio-clean speech from a noisy clip [Larry Jordan, https://larryjordan.com/articles/how-to-reduce-background-noise-using-davinci-resolve-20/, 2025-07-24]

## Dialogue editing workflow
1729. **Checkerboard dialogue by character** — split the production clips line by line and move each character's lines to that character's own track, so each has its own volume, EQ and dynamics; add a production-effects (PFX) track for non-dialogue sounds the mics picked up. **How:** locally, one WAV per character (and one PFX WAV) built with `atrim`/`adelay`/`amix` [Fairlight Audio Guide L2, https://www.imaster.org/docs/fairlight-audio-guide-r20/l2-editing-dialogue-tracks, checked 2026-10-24] [REAPER Blog, https://reaper.blog/2017/09/checkerboarding-dialog/, 2017-09-25]
1730. **A/B tracks per mic and character** — a track build checkerboards Jane's boom across two tracks (A/B), the Radio Voice boom across two more, and keeps each radio mic on its own track. **How:** alternate consecutive clips of the same mic between two tracks so fades and fills can overlap [ebrary, "The dialogue editing track build", https://ebrary.net/294464/education/dialogue_editing_track_build, checked 2026-10-24]
1731. **A live-action dialogue track template** — Semenoff's standard: 10-12 PD (production dialogue), 4-6 PFX, 4-6 X tracks (production replaced by ADR), 2-6 Futz (speakers, radios), ADR tracks as needed, 16 loop-group tracks, kept in multiples of 8 for console fader banks. **How:** scale down for small jobs but keep the categories [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1732. **Work tracks and junk tracks** — Semenoff keeps 4-8 empty WORK tracks for temporary edits and inactive "Crap" tracks for clips he doesn't want to lose but that shouldn't feed the mix. **How:** in the scratchpad keep `work/` and `unused/` folders per job [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1733. **Expand the editor's cut to all mics first** — the dialogue assembly takes the AAF or audio EDL and expands the used takes to all microphones recorded, because picture usually cuts with the on-set mix track. **How:** ask clients for the original multi-channel recorder files, not just the camera mix [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1734. **Watch everything before cutting** — first watch the whole film/episode for pacing, scenes that need more work, and breaths/efforts to borrow. **How:** one full listen of the client's clip before any processing [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1735. **Keep a muted unprocessed copy next to every NR clip** — Semenoff's motto is "do no harm to the dialogue": if dialogue quality drops, the noise reduction went too far; he keeps the unprocessed version nearby, since the mixer can add more NR but going back is harder. **How:** always write `*_raw.wav` beside `*_nr.wav` [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1736. **Background music on set is the hardest fix** — Semenoff has no good fix for music playing on set when it is close in level to the dialogue; repo tests found the same: a song with a singer as background stays in any vocal stem. **How:** warn the owner early; try `clean_voice.py`, which removes only instrumental sound [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24] [repo: CLAUDE.md "Voice and songs with words"]
1737. **Classify noise first: steady or sudden** — decide whether a noise is consistent (AC, fridge, crickets: whole-file tools like Dialogue Isolate) or intermittent (creaks, bumps: select and repair only those spots). **How:** steady -> `afftdn`/`arnndn` on the clip; sudden -> patch the spot with room tone [iZotope blog, https://www.izotope.com/community/blog/how-to-remove-background-noise-from-dialogue-recordings, 2024-05-15]
1738. **What a dialogue editor does (and leaves to the mixer)** — April Tucker's list: keep only usable/best mics, fades, crossfades and fills, remove pops, clicks, hums and thumps, repair dropouts, edit ADR and narration; broadband noise is addressed in mixing; volume automation is the mixer's job. **How:** in a client edit, do the cleanup pass before any loudness work [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1739. **Ask before deleting volume automation** — some re-recording mixers want the picture editor's volume automation kept in the AAF, so check with the mixer before stripping it. **How:** keep the editor's gain notes when re-cutting a client's timeline [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1740. **Long fades let ambience come in naturally** — Tucker's basic dialog edit uses long fade-ins and fade-outs so the ambience enters and leaves naturally where it is audible, fills holes with crossfades, and moves a bad mid-word edit. **How:** `afade=t=in:d=0.5` / `afade=t=out` on clip heads and tails with audible ambience [April Tucker, https://apriltucker.com/dialog-editing-part-6/, checked 2026-10-24]
1741. **What Premiere's default AAF gives audio post** — without adjusting settings Premiere often exports stereo as split mono pairs and gives no or too-short handles; on Windows, embedded AAFs over 2 GB fail, so use separate audio. **How:** when sending to an audio editor, set handles and separate audio [Forte, https://www.forte-ai.com/blog/pro-tools-friendly-aaf-from-adobe-premiere, 2026-03-16] [Adobe Premiere Help, https://helpx.adobe.com/premiere/desktop/render-and-export/export-files/export-aaf-files.html, 2026-08-18]
1742. **M&E needs split production effects** — after the final mix the dialogue editor cuts all lines out for the M&E (music and effects) mix; production movement and PFX are lost unless they were split and filled during dialogue editing. **How:** keep PFX on its own file from the start [A Sound Effect interview, https://www.asoundeffect.com/dialogue-editing-tips/, checked 2026-10-24]
1743. **Cleanup first, enhancement second** — Krotos frames dialogue editing as two phases: phase 1 cleanup (sync production audio, label and organise takes, rough comp of best performances), then enhancement; dialogue editing is distinct from mixing. **How:** don't EQ or level before the cleanup pass is done [Krotos Studio, https://krotos.studio/blog/what-is-dialogue-editing, 2026-07-03]
1744. **Noise is "reduced", not "removed"** — Larry Jordan: background noise and speech share frequencies, so removing too much damages the voice; aim to hear the speaker clearly while keeping the feeling of the location. **How:** stop de-noising when the voice starts to change [Larry Jordan, https://larryjordan.com/articles/how-to-reduce-background-noise-using-davinci-resolve-20/, 2025-07-24]

## NLE and editor tools (when the owner has them)
1745. **Resolve Voice Isolation amount** — Larry Jordan finds the default 100 excessive, 70-80 natural for strong isolation, and used 25 on a noisy trade-show clip; use Voice Isolation or Dialogue Leveler's Background Reduction, not both, on one clip. **How:** needs DaVinci Resolve (missing; Voice Isolation is Studio only) [Larry Jordan, https://larryjordan.com/articles/how-to-reduce-background-noise-using-davinci-resolve-20/, 2025-07-24] [DVResolve, https://dvresolve.com/tutorial/voice-isolation-dialogue-leveler-audio-tools/, 2022-12-16]
1746. **Resolve Dialogue Leveler (free and Studio)** — it detects dialogue, rides down loud parts, lifts soft parts and lowers non-dialogue background; Larry Jordan prefers "Allow wider dynamics" and warns against settings that remove the noise completely so it pops in and out. **How:** needs DaVinci Resolve (missing) [Larry Jordan, https://larryjordan.com/articles/how-to-reduce-background-noise-using-davinci-resolve-20/, 2025-07-24] [DVResolve, https://dvresolve.com/tutorial/voice-isolation-dialogue-leveler-audio-tools/, 2022-12-16]
1747. **Premiere Enhance Speech with Mix Amount** — Essential Sound > Dialogue > Enhance runs the AI cleanup; the Mix Amount slider blends raw and enhanced audio so some natural background can return. **How:** needs Adobe Premiere (missing) [Adobe Premiere Help, https://helpx.adobe.com/premiere/desktop/add-audio-effects/adjust-volume-and-levels/enhance-speech.html, 2026-01-07] [Adobe Community, https://community.adobe.com/announcements-732/now-released-enhance-speech-in-premiere-pro-313485/index3.html, 2023-09-13]
1748. **Audition Noise Reduction expectations** — Audition's (Waveform Editor) Noise Reduction can typically raise signal-to-noise by 5-20 dB while keeping high quality; capture a noise print from a noise-only selection (Shift+P) first. **How:** needs Adobe Audition (missing) [Adobe Audition Help, https://helpx.adobe.com/audition/using/noise-reduction-restoration-effects.html, checked 2026-10-24] [Macquarie Univ. Adobe portal, https://adobe.arts.mq.edu.au/support/time-based-media/intro-to-podcasting/, checked 2026-10-24]
1749. **Audition Adaptive Noise Reduction for changing noise** — it removes variable broadband noise (background sounds, rumble, wind) and runs in real time, so it works in the Multitrack Effects Rack, unlike Noise Reduction. **How:** needs Adobe Audition (missing) [Adobe Audition Help, https://helpx.adobe.com/audition/using/noise-reduction-restoration-effects.html, checked 2026-10-24]
1750. **Audacity Noise Reduction controls** — Noise Reduction (dB, default 6: use the lowest that works), Sensitivity (0-24, default 6), Frequency smoothing (bands, default 6; lower favours music, higher spoken word); time smoothing is fixed at 20 ms attack / 100 ms release. **How:** needs Audacity (missing, GPL) [Audacity Manual, https://manual.audacityteam.org/man/noise_reduction.html, 2026-09-02]
1751. **Audacity "Residue" to hear the damage** — Residue plays what would be removed; recognisable bits of speech in it mean Noise Reduction or Sensitivity is too high; artifacts like "tinkly bells" mean Sensitivity is too low or the profile isn't representative. **How:** the ffmpeg equivalent is `afftdn=om=n` or `arnndn=mix=-1` (tested here 2026-10-24) [Audacity Manual, https://manual.audacityteam.org/man/noise_reduction.html, 2026-09-02]
1752. **One noise type at a time** — if different noises sit in different places, Audacity advises profiling and reducing the first, then profiling the next; profiles must match the track's sample rate. **How:** in ffmpeg, process each section with its own `afftdn` profile via `asendcmd` sn start/stop [Audacity Manual, https://manual.audacityteam.org/man/noise_reduction.html, 2026-09-02]

## Spectral de-noise reference (RX)
1753. **Learn the longest pure-noise stretch** — RX Spectral De-noise works best with a profile from the longest noise-only selection (ideally a few seconds), often at the start/end or between words; a learned profile stays fixed, so Adaptive mode suits changing noise (traffic, waves). **How:** same rule for `afftdn` sample-noise [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/spectral-de-noise.html, checked 2026-10-24]
1754. **Separate tonal and broadband reduction** — RX Spectral De-noise splits noise into tonal (hum, buzz) and random (hiss) parts with separate Threshold/Reduction, e.g. remove an unpleasant buzz but leave harmless constant hiss. **How:** needs iZotope RX (missing); in ffmpeg combine `bandreject` for tones with light `afftdn` [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/spectral-de-noise.html, checked 2026-10-24]
1755. **Artifact Control: spectral subtraction vs gating** — low values rely on spectral subtraction (more accurate, can sound chirpy/watery), high values on wide-band gating (fewer musical artifacts, but noise bursts after the signal drops). **How:** needs iZotope RX (missing) [iZotope RX 11 Help, https://docs.izotope.com/rx11/en/spectral-de-noise.html, checked 2026-10-24]
1756. **Voice De-noise: zero-latency adaptive gate** — RX Voice De-noise is a 64-band psychoacoustic multiband gate; Adaptive mode follows a changing floor (set lower to avoid artifacts), Learn needs at least one second of pure noise, Dialogue mode reacts faster than Music, Surgical removes more than Gentle but can add musical noise. **How:** needs iZotope RX (missing) [iZotope RX 10 Help, https://docs.izotope.com/rx10/en/voice-de-noise/index.html, checked 2026-10-24]
