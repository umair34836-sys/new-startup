# Colour looks, film stocks, LUTs and film texture (skills #1041-#1279)

Named creative looks and grading recipes (film stocks, genre and director looks, teal-orange variants, VHS/tape, tints), LUT creation (Hald CLUT, .cube) and grain/halation/bloom/glow, plus the HyperFrames media-treatment presets and recipes. Basic correction is in file 02.

Researched 2026-10-24 via agent-reach (Exa) web search, official docs and local tests. Pages were fetched and read; when Exa was down, WebSearch was used only to find URLs that were then fetched. ffmpeg 6.1.1 commands ran on a 640x360 (and 1280x720) testsrc2 clip; HyperFrames 0.8.188 payloads were validated with `media-treatment --dry-run` in a scratch project. "Tested" means the command ran without error, not that the look was judged by eye.

## HyperFrames treatment recipes and controls

1061. **Product Polish base** — for filmed or photographed products: intensity 0.7 with exposure 0.01, contrast 0.06, highlights -0.10, shadows 0.04, whites 0.02, blacks -0.03, vibrance 0.03, saturation 0.02; temperature/tint stay 0 unless a cast is visible, and no grain, vignette, blur or pixelate for catalogue media. **How:** `npx hyperframes@0.8.188 media-treatment --project . --file index.html --selector '#hero' --grading '<json>' --dry-run --json` with that payload (tested here 2026-10-24) [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1062. **Product Polish rejection rules** — reject a result that clips white packaging, muddies black products, shifts a known brand colour, hides texture or makes labels harder to read; if the source already has accurate colour and clean endpoints, leave pixels unchanged and polish with framing or motion, and report that choice. **How:** compare before/after sheets; skip `--apply` when the source wins [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1063. **UI footage gets no grade** — for literal app, website, dashboard, terminal or slide pixels the default payload is none; a global grade shifts brand colours, status colours, charts and tiny text together. **How:** polish UI with crop, scale, pacing, cursor emphasis or DOM overlays outside the captured pixels; if a stylised UI look is requested, state that exact UI colour is no longer preserved [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1064. **Film Memory flicker** — the Film Memory treatment adds a gentle exposure pulse, not a flash: author `--hf-color-grading-exposure: 0` inline and move it through a finite irregular sequence within -0.03..0.03, in `sine.inOut` segments of about 0.45-0.8 s, returning near the start. **How:** `tl.to("#hero",{"--hf-color-grading-exposure":0.02,duration:0.6,ease:"sine.inOut"},t)` steps on the registered paused timeline; no randomness, timers or onUpdate [repo: .claude/skills/media-use/references/media-treatment-recipes.md] [repo: .claude/skills/media-use/references/grading.md]
1065. **Film Memory gate weave limits** — keep x/y drift within 0.15% of the shorter composition edge, rotation within 0.03 degrees and scale 1.005-1.01 so edges never show; weave is slight mechanical drift, not handheld shake. **How:** for 1080 px height that is at most about 1.6 px of x/y; tween `x`, `y`, `rotation`, `scale` on the media wrapper with finite sine.inOut steps [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1066. **Film Memory is not stock emulation** — the recipe is for warm memories and restrained flashbacks and must be described as an HF film-memory treatment, not camera-stock emulation; don't add dust, scratches, light leaks or halation unless an owned component exists and the story needs it. **How:** report it with that wording; reach for 8mm Home Movie when material artifacts are wanted [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1067. **Creator Camcorder bounds** — tune only inside: intensity 0.55-0.8, contrast 0.03-0.1, saturation -0.12..-0.02, grain 0.04-0.12, chromaBleed 0.35-0.7, vignette 0.03-0.1; blur and pixelate stay 0, and square pixels, scanlines, RGB splitting and tracking noise are other visual languages, not defaults. **How:** `npx hyperframes@0.8.188 media-treatment --project . --file index.html --selector '#hero' --grading '<json>' --dry-run --json` with the recipe payload, then change one value inside its range (tested here 2026-10-24) [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1068. **Camcorder HUD block** — explicit recording-device language comes from the Registry block `camcorder-hud`; its paused timeline derives the counter and REC blink from composition time, so preview, scrub and render agree. **How:** `npx hyperframes@0.8.188 add camcorder-hud --dir . --no-clipboard --json` (installs `compositions/camcorder-hud.html`, default 4 s, 1920x1080); edit date/time/mode there; the installed file loads GSAP from cdn.jsdelivr, so point it at `assets/vendor/gsap-3.14.2.min.js` (tested here 2026-10-24) [repo: .claude/skills/media-use/references/media-treatment-recipes.md] [repo: CLAUDE.md "HyperFrames learnings"]
1069. **Source-to-camera reveal needs two layers** — global grading intensity fades only primary correction and LUT output, not the camcorder effects; for a visible switch from clean to camera, use two synchronized media layers and a finite opacity crossfade on the paused timeline. **How:** duplicate the `<video>` (same src/data-start), grade only the top copy, tween its `opacity` 0 to 1 [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1070. **VHS Playback: use the whole combination** — start from the complete recipe, not `tapeDamage` alone; tapeDamage owns line jitter, time-base wobble, bottom-edge head switching, luma bandwidth loss, ghosting, noise and dropouts, chromaBleed separately cuts horizontal chroma detail. **How:** `npx hyperframes@0.8.188 media-treatment --project . --file index.html --selector '#hero' --grading '<json>' --dry-run --json` with the recipe payload or `{"preset":"vhs-playback"}` (tested here 2026-10-24) [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1071. **VHS digital stage only tears rows** — in the VHS recipe the digital glitch stage is used only for rare horizontal row tears: digitalGlitchColorSplit, Pixelate, BlockAmount, BlockDisplacement and BlockOpacity stay 0; blur, CRT curvature, pixelation and the camera HUD stay off. **How:** keep those keys at 0 when tuning `digitalGlitch` (0.2-0.4) and `digitalGlitchLineTear` (0.04-0.1) [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1072. **VHS rejection checks** — inspect dense consecutive frames and reject hard edge tearing, face smearing, frozen noise, square blocks, blank borders or a bottom disturbance that competes with the subject; global intensity does not fade tape damage. **How:** render a draft and step through frames; for a source-to-tape reveal crossfade two synchronized layers [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1073. **"Old home video" is not automatically VHS** — for "make it feel like an old home video", compare 8mm and VHS language against the source first; never infer that every old-video request means VHS. **How:** build two candidates (`home-movie-8mm` and `vhs-playback`) and pick from before/after evidence [repo: .claude/skills/media-use/references/media-treatments.md]
1074. **8mm filmArtifacts owns only dust and scratches** — in the 8mm recipe `filmArtifacts` (0.35-0.7) adds deterministic sparse dust and short scratches; colour, vignette and grain come from the preset/details, weave from the host timeline (within 0.15% of the short edge, 0.03 deg, scale 1.005-1.015, 0.6-1 s sine.inOut steps). **How:** `npx hyperframes@0.8.188 media-treatment --project . --file index.html --selector '#hero' --grading '<json>' --dry-run --json` with the 8mm payload; reject constant dust, persistent scratches, pumping, exposed edges or muddy highlights (tested here 2026-10-24) [repo: .claude/skills/media-use/references/media-treatment-recipes.md]

## Making and using LUTs (Hald CLUT, .cube, HyperFrames)

1113. **A Hald CLUT is a 3D LUT stored as pixels** — each pixel holds one cube entry (its colour is the output value), laid out row by row across a square image; it is an ordinary PNG. **How:** treat Hald PNGs as LUTs, never as photos (don't resize, re-encode lossy or colour-manage them) [RawCut, https://www.rawcut.art/tools/hald-clut, checked 2026-10-24] [Quelsolaar (Hald author), http://www.quelsolaar.com/technology/clut.html, checked 2026-10-24]
1114. **Identity Hald from ffmpeg** — `haldclutsrc` makes an identity Hald CLUT; level N gives an N*N*N by N*N*N picture, each component coded on a 1/(N*N) scale: level 8 = 512x512 (a 64-point cube), level 6 = 216x216 (36-point). **How:** `ffmpeg -f lavfi -i haldclutsrc=8 -frames:v 1 hald8.png` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#haldclutsrc, checked 2026-10-24]
1115. **Turn any grade into a LUT** — open the identity image in any editor, apply the grade and save; the result is that grade as a LUT, which is how you get a LUT out of software with no LUT export. **How:** grade the identity with an ffmpeg chain: `ffmpeg -i hald8.png -vf "curves=preset=cross_process" -frames:v 1 hald_cp.png` (tested here 2026-10-24) [RawCut, https://www.rawcut.art/tools/hald-clut, checked 2026-10-24] [pixls.us G'MIC thread, https://discuss.pixls.us/t/create-and-save-lut-clut-for-use-in-video-editing/13748, 2019-08-22]
1116. **Keep spatial effects off the Hald** — a LUT can only change colour, contrast, brightness and gamma; grain, noise reduction, vignetting or sharpening applied to the Hald PNG can corrupt the LUT. **How:** grade the Hald with colour-only filters (curves, colorbalance, eq, lut3d); add grain/vignette later on the video [lutCreator.js, https://sirserch.github.io/lut-creator-js/, checked 2026-10-24]
1117. **Apply a Hald to video** — `haldclut` takes the video as first input and the Hald as second; the Hald can be a picture or a whole video stream. **How:** `ffmpeg -i in.mp4 -i hald_cp.png -filter_complex "[0:v][1:v]haldclut" -c:v libx264 -crf 18 out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#haldclut, checked 2026-10-24]
1118. **Prove the Hald round trip** — an untouched identity Hald should give back the source; here identity `haldclut` vs source measured PSNR 50.68 dB average, so differences are interpolation rounding only. **How:** `ffmpeg -i in.mp4 -i hald8.png -filter_complex "[0:v]format=rgb24,split[a][b];[b][1:v]haldclut[c];[c][a]psnr" -f null -` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#haldclut, checked 2026-10-24]
1119. **Animated CLUT stream** — the docs build an identity Hald stream altered over time (`hue=H=2*PI*t...`, `curves=cross_process`) saved with a lossless codec; haldclut applies it frame by frame and, after the CLUT stream ends, keeps applying its last picture (`repeatlast` default 1). **How:** `ffmpeg -f lavfi -i haldclutsrc=8 -vf "hue=H=2*PI*t:s=sin(2*PI*t)+1, curves=cross_process" -t 2 -c:v ffv1 clut.nut` then `[0:v][1:v]haldclut` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#haldclut, checked 2026-10-24]
1120. **Use only the first CLUT frame** — `clut=first` processes only the first frame of the CLUT input (default `all`). **How:** `ffmpeg -i in.mp4 -i clut.nut -filter_complex "[0:v][1:v]haldclut=clut=first" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#haldclut, checked 2026-10-24]
1121. **Hald with a built-in preview** — ffmpeg uses the biggest square from the top-left of the Hald picture and ignores right/bottom padding, so you can pad the Hald with SMPTE bars before/after the effect as a visual label. **How:** the docs' `pad=iw+320 ... smptebars=s=320x256 ... curves=color_negative` example made `clutprev.png`, and that padded file still applied cleanly with `haldclut` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#haldclut, checked 2026-10-24]
1122. **Hald to .cube converter (Python)** — a Hald PNG's pixels in row-major order are the .cube entries (red fastest), so conversion is a relabelling; here a level-8 Hald became `LUT_3D_SIZE 64` and `lut3d` with it matched `haldclut` at 57.75 dB PSNR. **How:** `python3 hald2cube.py hald_cp.png look.cube` (script in this session's scratch folder: reads the PNG with PIL, writes `LUT_3D_SIZE n` then one `r g b` line per pixel) (tested here 2026-10-24) [RawCut converter, https://www.rawcut.art/tools/convert, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lut3d, checked 2026-10-24]
1123. **lut3d formats and interpolation** — `lut3d` reads .3dl (After Effects), .cube (Iridas), .dat (DaVinci), .m3d (Pandora) and .csp (cineSpace); interp can be nearest, trilinear, tetrahedral, pyramid or prism. **How:** `ffmpeg -i in.mp4 -vf "lut3d=file=look.cube:interp=tetrahedral" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lut3d, checked 2026-10-24]
1124. **1D LUT for a pure tone curve** — `lut1d` applies a 1D .cube or .csp with nearest, linear, cosine, cubic or spline interpolation; a 1D LUT changes each channel's curve only. **How:** write `LUT_1D_SIZE 1024` + 1024 `v v v` lines (here a 0.8 gamma lift) and run `ffmpeg -i in.mp4 -vf "lut1d=file=lift.cube:interp=cubic" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lut1d, checked 2026-10-24]
1125. **LUT strength in ffmpeg** — ffmpeg's LUT filters have no intensity option; mixing the LUT result over the original with `blend` opacity gives a partial strength. **How:** `ffmpeg -i in.mp4 -i look.png -filter_complex "[0:v]format=gbrp,split[a][b];[b][1:v]haldclut,format=gbrp[g];[g][a]blend=all_mode=normal:all_opacity=0.6" out.mp4` (command ran; 0.6 is an example) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
1126. **Hald CLUTs on stills with ImageMagick** — IM's `-hald-clut` takes an image and a Hald and returns a new image of the input's size; `hald:8` generates an identity. **How:** `convert hald:8 hald8.png` and `convert frame.png look.png -hald-clut out.png` (tested here 2026-10-24) [snibgo, https://im.snibgo.com/edithald.htm, checked 2026-10-24]
1127. **Ingest your own .cube into HyperFrames** — `media-use resolve --type lut --from` validates a cube before registering it under `.media/luts/`; an ffmpeg-made 64-point cube ingested as `lut_001`. **How:** `npx hyperframes@0.8.188 media-use resolve --type lut --from look.cube --project . --json`, then `{"lut":{"src":".media/luts/lut_001.cube","intensity":0.85}}` (tested here 2026-10-24) [repo: .claude/skills/media-use/references/grading.md]

1135. **Don't bake a LUT for shader controls** — don't generate or hand-edit a LUT merely to combine controls the realtime shader already owns (adjust, wheels, curves, secondaries); keep those as editable JSON. **How:** use a LUT only for transforms outside the preset vocabulary [repo: .claude/skills/media-use/references/grading.md] [repo: .claude/skills/media-use/references/media-treatments.md]

## Film stocks: what each one looks like (reference for matching)

Note for this whole section: these are the stocks' described traits for briefing and matching by eye. HyperFrames' parametric LUTs cannot reproduce a real stock [repo: .claude/skills/media-use/references/grading.md]; a faithful look needs a scanned .cube ingested with `media-use resolve --type lut --from` (tested in the LUT section). The How lines name the repo control that corresponds to each stated trait; they are not verified emulations.

1137. **Kodak Portra 400** — warm and natural; reviews call its saturation restrained (Kodak claims "exceptional"), skin tones are its reputation, one reviewer notes a slight magenta bias in skin, and shadows may lean blue or blue-green; latitude about -1 to +3 stops. **How:** brief it as warm, restrained saturation, cool-leaning shadows; check skin on a real frame with `grade-compare` [The Grain Archive, https://thegrainarchive.com/films/kodak-portra-400/, checked 2026-10-24]
1138. **Portra 400 defining traits** — three things to nail: soft highlight roll-off (highlights fade rather than clip), restrained saturation (warm, not vivid), warm shadows on the orange/amber side. **How:** HF controls that correspond: `adjust.highlights` negative, modest `saturation`, `wheels.shadows` toward a warm hue; compare candidates on a frame [Marien Photography, https://mariengb.com/posts/kodak-portra-400/, 2026-08-18]
1139. **Portra 160** — soft, muted, pastel; less saturated than Portra 400 and 800; Kodak promises neutral skin, reviews find it warm; takes overexposure well, underexposure looks muddy. **How:** treat as the low-saturation member of the Portra family when briefing [The Grain Archive, https://thegrainarchive.com/films/kodak-portra-160/, checked 2026-10-24]
1140. **Portra 800** — warm and more saturated than Portra 400 for most reviews, with vibrant reds, yellows and oranges; Print Grain Index 48 vs 37 for Portra 400. **How:** more grain and saturation than Portra 400 when matching [The Grain Archive, https://thegrainarchive.com/films/kodak-portra-800/, checked 2026-10-24]
1141. **Kodak Ektar 100** — highly saturated with vivid blues, greens and reds; skin is the weak point (faces can look redder); Print Grain Index under 25, below visibility in a 4x6 print. **How:** if matching Ektar on people, watch faces for red shift with a skin secondary (`secondaries` key around the skin hue) [The Grain Archive, https://thegrainarchive.com/films/kodak-ektar-100/, checked 2026-10-24]
1142. **Kodak Gold 200** — warm, golden-to-orange tint and saturated colours by Kodak's account; adds yellow to light greys in cool light and can turn orange when underexposed; Print Grain Index 44. **How:** brief as warm consumer film; don't confuse with Portra's restraint [The Grain Archive, https://thegrainarchive.com/films/kodak-gold-200/, checked 2026-10-24]
1143. **Kodak UltraMax 400** — saturated consumer colour, usually called warm, punchier in colour and contrast than Portra 400 in a lab side-by-side; Print Grain Index 46. **How:** reference for a punchy everyday-snapshot look [The Grain Archive, https://thegrainarchive.com/films/kodak-ultramax-400/, checked 2026-10-24]
1144. **Kodak ColorPlus 200** — warm and fairly muted for most reviews, very close to Gold 200 in a controlled side-by-side; reds and pinks pop slightly more than blues and greens. **How:** reference for budget-film warmth [The Grain Archive, https://thegrainarchive.com/films/kodak-colorplus-200/, checked 2026-10-24]
1145. **Kodak Ektachrome E100** — E-6 slide film: neutral balance and moderately enhanced saturation per Kodak, some reviews find it cool; overexposed areas may shift cooler and shadows warmer; latitude about half a stop either way; RMS 8. **How:** brief as clean, slightly cool, careful highlights [The Grain Archive, https://thegrainarchive.com/films/kodak-ektachrome-e100/, checked 2026-10-24]
1146. **Ektachrome E100 Lightroom recipe** — slightly cool white balance (temp down 300-800 K), highlights -30 to -70, contrast +10 to +25, blacks -10 to -25, vibrance +10 to +20 with saturation 0 to +5, blue hue toward cyan and blue luminance down, mild S-curve, light grain 10-25 (Lightroom units). **How:** the matching HF controls are `adjust.temperature`, `highlights`, `contrast`, `blacks`, `vibrance`, `hueCurves.hueVsHue`/`hueVsLuma` around blue, `curves.master`, `details.grain` — values must be re-chosen by eye, units differ [Legendary Presets, https://legendarypresets.com/kodak-ektachrome-e100-travel-editing-guide-for-lightroom/, 2026-02-06]
1147. **Ektachrome skin needs protection** — E100 pushes warm tones toward magenta, the tone curve does more than the contrast slider, and slide film has almost no latitude above the exposure point. **How:** protect skin with an HSL secondary and set highlights before anything else [Legendary Presets, https://legendarypresets.com/slide-film-look-kodak-ektachrome-e100-tips/, 2025-09-24]
1148. **Kodak Kodachrome 64** — warm with rich reds and deep neutral blacks in photographers' accounts; skies blue, sometimes cyan; contrast slightly higher than Ektachrome; RMS 10; K-14 processing ended in January 2011. **How:** reference for warm-red vintage slides [The Grain Archive, https://thegrainarchive.com/films/kodak-kodachrome-64/, checked 2026-10-24]
1149. **Fujifilm Velvia 50** — extremely saturated with deep blues and a lean toward magenta/purple; high contrast steepening toward the shadows; narrow latitude (about 5 stops); RMS 9. **How:** reference for hyper-saturated landscapes; don't use for skin [The Grain Archive, https://thegrainarchive.com/films/fujifilm-velvia-50/, checked 2026-10-24]
1150. **Fujifilm Provia 100F** — neutral and faithful, slightly cool, saturated but less than Velvia; "Standard" contrast in Fujifilm's chart; RMS 8. **How:** reference for neutral slide film [The Grain Archive, https://thegrainarchive.com/films/fujifilm-provia-100f/, checked 2026-10-24]

## Named creative looks (genres, directors, eras)

Units note: v8eo recipes are in v8eo's own slider units (100 = neutral for contrast/saturation/brightness); they show direction and relative size, not HyperFrames values.

1177. **Matrix look, colourist version** — low saturation of about 30%, green pushed into shadows and (more) midtones, a little yellow in the highlights so it isn't monochrome, then key the skin and bring it back to a normal skin tone on the vectorscope. **How:** HF controls in that order: `adjust.saturation` down, `wheels.shadows`/`midtones` toward green, `wheels.highlights` toward yellow, then a `secondaries` skin key with a correcting `hueShift` [Aaron Williams, https://aaronwilliams.tv/2011/01/colorist-tip-23/, 2011-01-13]
1178. **Matrix green, don't overdo the tint** — the green sits mostly in shadows and midtones and skin should read as "a bit sick", not lime; tint around -15 to -20 (v8eo units), -40 looks like night vision, and raising saturation makes skin radioactive; offices, stairwells and fluorescent light suit it. **How:** keep the green in the split/wheels, not in global saturation [v8eo, https://www.v8eo.com/blogs/matrix-green-tint-look-color-grading, checked 2026-10-24]
1179. **Matrix real-world blue** — the Zion/ship scenes go blue and cold (temperature -20, split shadow `#101c2c`, highlight `#b8c4cc`, grain 20 in v8eo units); cutting between green and blue worlds makes an edit feel like it has a story. **How:** two looks on two scene groups; `wheels` toward blue for the second [v8eo, https://www.v8eo.com/blogs/matrix-green-tint-look-color-grading, checked 2026-10-24]
1180. **Why the Matrix is green** — the green tint nods to the monochrome green of command-line computing, and the film runs against the usual healthy yellow/orange skin rendering. **How:** use green-tinted skin only when the story is "inside a system" [PremiumBeat, https://www.premiumbeat.com/blog/blockbuster-looks-in-davinci-resolve-the-matrix/, 2015-08-03]
1181. **Mexican filter: know the criticism** — a yellow/sepia or overly warm grade used to signal hot, arid places such as Mexico, starting with Traffic (2000); it is criticised for washing out darker-skinned faces and stereotyping the places shown. **How:** don't apply a blanket yellow wash to a real place or client footage; if warmth is wanted, protect skin with a secondary [Wikipedia, https://en.wikipedia.org/wiki/Mexican_filter, 2026-10-06]
1182. **Traffic: one palette per storyline** — Soderbergh gave each thread its own colour: Mexico a desaturated yellow, Judge Wakefield's story icy blue, the DEA storyline bright and multicoloured. **How:** for a multi-thread edit, assign one HF payload per thread and apply it with one selector per thread [StudioBinder, https://www.studiobinder.com/camera-shots/composition/color-in-film/, 2025-09-02]

1200. **Cyberpunk is a restriction** — a narrow palette: cyan-blue shadows, hot magenta-pink highlights and almost nothing warm in between, on a deep blue-black base; reference hexes: shadows `#0a1f3d` to `#123a5e`, midtones `#2b2f3a`, highlights `#d61f8a` to `#ff3fa4`, one sparing amber accent `#ffb347`; avoid orange/yellow elsewhere. **How:** `wheels.shadows` toward cyan, `wheels.highlights` toward magenta, saturation of other hues down with `hueCurves.hueVsSaturation` [DaVinci Resolve 21 blog, https://davinciresolve21.com/blog/davinci-resolve-cyberpunk-neon-color-grading-tutorial, 2026-07-25]
1201. **Cyberpunk safety checks** — isolate practical neon signs with HSL qualifiers, add controlled glow, protect skin on a separate node, and check the vectorscope so saturated cyan and magenta don't clip in Rec.709 delivery. **How:** skin `secondaries` key + `effects.bloom`; render a frame and look at the neon edges [DaVinci Resolve 21 blog, https://davinciresolve21.com/blog/davinci-resolve-cyberpunk-neon-color-grading-tutorial, 2026-07-25]
1202. **Cyan-magenta gradient map** — one Photoshop cyberpunk recipe: B&W conversion with more contrast, then a gradient map from cyan `#00D4FF` (shadows) to magenta `#FF00C8` (highlights) in Soft Light at 55%. **How:** ffmpeg version of that map: `ffmpeg -i in.mp4 -filter_complex "[0:v]format=gbrp,split[a][b];[b]colorchannelmixer=.3:.4:.3:0:.3:.4:.3:0:.3:.4:.3,lutrgb=r='val':g='212*(1-val/255)':b='255-55*val/255'[m];[a][m]blend=all_mode=softlight:all_opacity=0.55" out.mp4` (tested here 2026-10-24) [PSD Vault, https://www.psdvault.com/photo-effect/portrait-cyberpunk-effect-photoshop/, 2026-08-20] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
1203. **Horror: keep a little colour** — horror rarely goes fully monochrome: a sickly green or cold blue-grey cast keeps a scene feeling wrong, while full desaturation removes information. **How:** desaturate partly, never to 0, and add a green or blue-grey cast [Freevisuals, https://www.freevisuals.net/luts/50-horror-thriller-luts-pack, checked 2026-10-24]
1204. **Horror green as decay** — green is also the colour of mold; mottled green makes a whole frame look rotten, as in the squalid settings of the Saw franchise. **How:** green `wheels.midtones` on grimy locations only [No Film School, https://nofilmschool.com/horror-movie-color-theory-explained, 2026-05-10]
1205. **Green as "the colour of fear"** — by 1931 green and horror were linked strongly enough that Universal reportedly marketed Dracula's green tint as "the color of fear"; German expressionist films used green tint for forests, night and dread. **How:** briefing history for a green-tinted horror title [In Transition, https://intransition.openlibhums.org/article/16383/galley/33622/download/, checked 2026-10-24]
1206. **Moody blue** — cool the temperature, push shadows to blue harder than for teal-and-orange, a smaller cool push in midtones, protect the orange band so faces don't die, lift the black point a little (crushed blacks plus heavy blue reads as an error), cut global saturation 10-20%. **How:** HF order: `adjust.temperature`, `wheels.shadows`/`midtones`, skin `secondaries`, `adjust.blacks` up, `saturation` -0.1..-0.2 [Luttie, https://luttie.app/looks/moody-blue, checked 2026-10-24]
1207. **Moody is not dark** — true moody editing keeps visible shadows, warm but restrained highlights, muted greens and blues, balanced midtones and preserved dynamic range; the difference between moody and muddy is always in the highlights and shadows. **How:** check `--analyze` clip risk after a moody grade [The Editing Studio, https://theeditingstudio.co/blog/moody-photo-editing-preset-for-lightroom, 2020-02-21]
1208. **Dark-and-moody in two curve handles** — the Phlearn guide: in Curves, move the bottom-left point up and right and the top-right point in and down, the same two points per R/G/B channel, then a corrective pass. **How:** HF `curves.master` with a lifted first point and lowered last point, e.g. `[[0,0.06],[1,0.92]]` (example values), validated with the dry run (tested here 2026-10-24) [Phlearn, https://phlearn.com/tutorial/dark-moody-color-grading-photoshop/, 2020-12-22]
1209. **Golden hour in post** — warm overall slightly and fix any green cast, push highlights toward yellow-orange (carries most of the look), hold shadows slightly cool (real golden hour has cool shadows; skipping this looks like a sepia filter), lift the red curve's top, soften the highlight roll-off, lift yellow saturation/luminance. **How:** `wheels.highlights` warm + `wheels.shadows` slightly blue + `curves.red` top lifted [Luttie, https://luttie.app/looks/golden-hour, checked 2026-10-24]
1210. **What golden hour can't fake** — post reproduces the colour (warm highlights, cool shadows, soft roll-off) but not the direction and length of shadows, which are geometry; it fights hard midday light and fluorescent interiors. **How:** only fake golden hour on overcast or soft-light footage [Luttie, https://luttie.app/looks/golden-hour, checked 2026-10-24]
1211. **Bright and airy wedding grade** — four moves from neutral: shadows lifted 15-25 IRE above true black, a gentle amber push on highlights, greens and blues pulled to pastels while skin oranges/pinks are kept, exposure 0.5-1 stop brighter than neutral; moody-dark weddings are the opposite (crushed cool shadows, 1-1.5 stops under). **How:** `adjust.exposure` up, `blacks` up, `wheels.highlights` amber, `hueCurves.hueVsSaturation` down around green/blue [MKTRL Production, https://www.mktrlproduction.com/en/blog/bright-airy-wedding-film-style, checked 2026-10-24]
1212. **Pastel base grade** — one node: lift blacks slightly, pull gain down a touch, saturation to about 30-35 (Resolve scale), a cool-to-warm split tone in lift and gain, protect skin with a Hue vs Sat curve, check the vectorscope. **How:** lifted `blacks`, `saturation` well down, `wheels` cool shadows/warm highlights, `hueCurves.hueVsSaturation` lifting the skin hue [DaVinci Resolve 21 blog, https://davinciresolve21.com/blog/davinci-resolve-pastel-aesthetic-color-grading-tutorial, 2026-07-25]
1213. **Pastel is not faded film** — pastel keeps saturation low everywhere and leans to candy colours (pinks, lavenders, mints, butter yellows); faded film lowers contrast and lifts blacks like an old print and can stay saturated; skipping the contrast step gives a foggy, undersaturated mess. **How:** set contrast first, then the pastel colour choice [DaVinci Resolve 21 blog, https://davinciresolve21.com/blog/davinci-resolve-pastel-aesthetic-color-grading-tutorial, 2026-07-25]
1214. **High-contrast look** — S-curve first, bring black and white points just to the limits and back off (watch the waveform, clipping can't be undone), then cut saturation 5-10% because contrast raises perceived saturation, then check skin hue (contrast pushes faces to red). **How:** `curves.master` S, then `adjust.saturation` -0.05..-0.1 [Luttie, https://luttie.app/looks/high-contrast, checked 2026-10-24]
1215. **Teal and orange through the blue curve** — Luttie's order: neutralise white balance, shadows toward cyan/blue (about 5-10% of the wheel), highlights toward orange by about half that, orange saturation up slightly with hue a degree or two toward red, then lift the blue curve's shadow end and pull its highlight end down ("the split that makes the look, more than the wheels"), gentle S-curve last. **How:** `curves.blue` like `[[0,0.05],[1,0.95]]` (example values; ffmpeg `curves=blue='0/0.05 1/0.95'` also ran) (tested here 2026-10-24) [Luttie, https://luttie.app/looks/teal-and-orange, checked 2026-10-24]
1216. **Teal-orange: when to avoid** — skip it when the background is already warm (sunset, wood-panelled interior: the frame turns muddy) and on documentary or product work where accurate colour matters. **How:** check the background colour before choosing it [Luttie, https://luttie.app/looks/teal-and-orange, checked 2026-10-24]
1217. **Modernised teal-orange** — the separation is fine, the intensity dates it: put warmth in the highlights only (highlight hue about 40-50 at low saturation) instead of warming every range. **How:** warm `wheels.highlights` at a small amount, no global temperature [The Editing Studio, https://theeditingstudio.co/blog/why-teal-and-orange-looks-dated, 2026-04-03]
1218. **Split the split-tone** — a colourist's alternative: put the high end and the low end on separate nodes, remove neutrals from the low end so grey/black things don't turn blue, keep neutrals in the high end so whites go creamy. **How:** in HF, use a `secondaries` selection with a minimum saturation for the cool push instead of a global shadow wheel [Reddit r/colorists, https://www.reddit.com/r/colorists/comments/1h1txm0/fed_up_of_orange_and_teal_what_are_some_other/, 2024-11-28]
1219. **Cross-processing look** — developing slide film in C-41 (or negative in E-6) gave a marked colour shift and contrast change; the digital start: red channel shallow S (down about 25% along, up about 75%), blue channel reverse S, optionally green, then an overall S or reverse S for contrast. **How:** `ffmpeg -i in.mp4 -vf "curves=red='0/0 0.25/0.18 0.75/0.82 1/1':blue='0/0.1 0.25/0.3 0.75/0.7 1/0.9'" out.mp4` (example amounts; ffmpeg also has `curves=preset=cross_process`) (tested here 2026-10-24) [Digital Camera World, https://www.digitalcameraworld.com/features/what-is-cross-processing-and-how-does-it-work, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#curves, checked 2026-10-24]
1220. **Bleach bypass via a desaturated overlay** — duplicate the image, desaturate the copy, put it on top in Overlay; strength by the copy's levels or opacity. Alternative: desaturated copy with contrast below, original on top in Color mode. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]format=gbrp,split[a][b];[b]hue=s=0[g];[a][g]blend=all_mode=overlay" out.mp4` (add `:all_opacity=0.5` for less) (tested here 2026-10-24) [OTOY forum, https://render.otoy.com/forum/viewtopic.php?p=116425, 2012-12-23] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
1221. **Bleach bypass in three adjustment layers** — saturation about -40, contrast about +40, then Photoshop's Bleach Bypass colour lookup at about 30% opacity because full strength was overblown (example values for one image). **How:** HF `adjust.saturation`/`contrast` plus the library `bleach-bypass` LUT at low `lut.intensity` [Giggster, https://giggster.com/guide/retouching/bleach-bypass/, checked 2026-10-24]
1222. **Orton glow** — Michael Orton blended a well-exposed and an overexposed slide, the overexposed one blurred; darktable's soften module copies this with size (blur), saturation and brightness of the overexposed copy and a mix where 50% is an equal blend. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]format=gbrp,split[a][b];[b]exposure=exposure=1,gblur=sigma=10[o];[a][o]blend=all_mode=average" out.mp4` (1 EV, sigma 10 are examples) (tested here 2026-10-24) [darktable manual, https://docs.darktable.org/usermanual/5.6/en/module-reference/processing-modules/soften/, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#exposure, checked 2026-10-24]
1223. **Silent-film tint vs tone** — tinting dyes the whole film so what would be white becomes coloured; toning replaces the silver and colours the darkest areas, leaving whites largely untouched. **How:** tint = grey image multiplied by a colour: `ffmpeg -i in.mp4 -f lavfi -i color=c=0x4060c0:s=640x360:d=2 -filter_complex "[0:v]hue=s=0,format=gbrp[g];[1:v]format=gbrp[c];[g][c]blend=all_mode=multiply:shortest=1" out.mp4`; tone-like = same with `all_mode=screen` and a dark colour (both ran) (tested here 2026-10-24) [Wikipedia, https://en.wikipedia.org/wiki/Film_tinting, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
1224. **Silent-film tint meanings** — common tints in order: amber for daylight interiors (night amber for lit night exteriors), orange for night interiors, yellow ("Sunshine") only for daylight exteriors, blue for moonlit night, sepia tone popular in 1930s-50s westerns, red for fire and fury, lavender for romance/dusk/dawn, rose for low-key night interiors, green for mysterious or sea scenes. **How:** pick the tint colour for the multiply pass from this list [Wikipedia, https://en.wikipedia.org/wiki/Film_tinting, checked 2026-10-24]
1225. **Tint names as moods** — a vintage tint ad: Azure = reserve and distance (cold, formal interiors); Nocturne = night, murky interiors, sadness and dark intrigue; Purplehaze = dim, hazy, dreamy; Fleur de Lis = ceremonial, royal. **How:** use as a mood vocabulary when the owner asks for an old-film chapter [Movies Silently, https://moviessilently.com/2019/03/14/what-do-tinting-colors-mean-a-vintage-ad-gives-us-a-clue/, 2019-03-14]
1226. **Nosferatu tint LUTs** — one colourist built three tint LUTs from Nosferatu (1922) stills: yellow for daylight, pink for twilight, green for night, over a B&W dye-density base, mixed so a clip can fade from day to twilight to night. (Wikipedia's caption shows a blue-tinted night scene from the same film, so prints differ.) **How:** three tinted versions of a B&W clip crossfaded on the timeline [Greg Enright, https://www.gregenright.com/joy-of-colourgrading/nosferatu1922-xg83b, 2025-01-09] [Wikipedia, https://en.wikipedia.org/wiki/Film_tinting, checked 2026-10-24]
1227. **Sepia from the ffmpeg docs** — ffmpeg's documented sepia simulation is a colour-channel-mixer matrix. **How:** `ffmpeg -i in.mp4 -vf "colorchannelmixer=.393:.769:.189:0:.349:.686:.168:0:.272:.534:.131" out.mp4` (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#colorchannelmixer, checked 2026-10-24]
1228. **Technicolor three-strip** — made famous by The Wizard of Oz; its quirks delivered posterised primary colours; PremiumBeat recreates it in Resolve by splitting the image into red, green and blue with splitter nodes and recombining. **How:** reference only here; a channel split/recombine needs a node tool (Resolve) that the repo lacks [PremiumBeat, https://www.premiumbeat.com/blog/100-years-of-color-grading/, 2019-05-28]
1229. **Sin City: shot in colour, graded to near-B&W** — Rodriguez shot everything in colour on HDCAM SR 4:4:4 with two monitors on set, one in colour and one desaturated with pushed contrast to make lighting choices; he admitted some greyscale instead of pure black-and-white, which gives more detail and a silvery depth. **How:** keep a colour master; for a single held colour use ffmpeg `colorhold` (keeps one colour, rest grey): `ffmpeg -i in.mp4 -vf "colorhold=color=red:similarity=0.3:blend=0.0" out.mp4` (tested here 2026-10-24) [Post Magazine, https://www.postmagazine.com/Publications/Post-Magazine/2005/April-1-2005/COVER-STORY-SIN-CITY.aspx, 2005-04-01] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#colorhold, checked 2026-10-24]
1230. **B&W virtual colour filters** — film photographers used red filters to darken skies and make clouds pop, orange to smooth skin, green to lighten foliage; digital channel mixing does the same maths, so start at the channel mixer, push contrast further than in colour, and add a real grain pass. **How:** ffmpeg `monochrome` is a "custom colour filter" grey conversion: `ffmpeg -i in.mp4 -vf "monochrome=cb=-0.3:cr=0.3:size=1" out.mp4` (cb/cr set the filter spot, -1..1) (tested here 2026-10-24) [Luttie, https://luttie.app/looks/black-and-white, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#monochrome, checked 2026-10-24]
1231. **Indian skin tones** — Indian skin ranges from very fair to deep brown with warm, neutral or cool undertones (melanin, hemoglobin, carotene); keep skin on the vectorscope skin line without pushing to red or magenta, isolate skin with qualifiers, and avoid LUTs designed for Western skin. **How:** a `secondaries` skin key before any creative LUT on the owner's clients [Indian Film Institute, https://www.indianfilminstitute.org/post/mastering-color-grading-for-indian-skin-tones-techniques-and-challenges-explained, 2026-04-11]
1232. **Build a "digital film stock" first** — Annapurna Studios' supervising colourist spends the first days building highlight roll-off, skin tones, mid-tone contrast and shadow distribution as a base "digital film stock", including a shadow roll-off that holds blacks just above absolute zero, then does the rest in the base grade. **How:** make one shared base payload for the whole film before per-scene looks [FilmLight, https://www.filmlight.ltd.uk/customers/meet-the-colourist/andreas_brueckl.php, checked 2026-10-24]
1233. **Palette from the story setting (Dangal)** — Dangal's DoP and colourist tested skin tones and costumes in pre-production and derived the palette from the setting, shooting mostly in natural light to look raw and real. **How:** for client films, set the palette from place and period before choosing a LUT [Business Standard, https://www.business-standard.com/article/news-ani/this-is-how-blockbuster-dangal-got-its-color-palette-right-117010901395_1.html, 2017-01-09]
1234. **Music videos grade for identity** — films grade for naturalism with sparing departures; music videos grade for identity: a teal-orange wash, a mono treatment, a saturated push in one channel or a film-emulation look. **How:** pick one signature look per music video and keep it across every shot [FXiation Digitals, https://www.fxiationdigitals.com/blog/stylized-compositing-music-videos/, 2026-04-27]
1235. **Music video: two passes** — build a stable image first (organise by camera, lighting setup and scene, correct), then shape its personality, so a creative node never hides an exposure or white-balance problem. **How:** correction payload per clip group, then one shared look [Image Studio, https://imagestudio.com/editorial/post/music-video-color-grading-2/, 2026-09-02]
1236. **Look reference categories** — a practical music-video look reference separates mood, lighting, colour (wardrobe, design, skin, grade direction), camera and texture (grain, halation, haze, diffusion) references. **How:** ask the owner for one reference per category before grading [To The Cut, https://tothecut.com/guides/shot-reference/how-cinematographers-build-a-look-reference-for-a-music-video/, 2026-09-27]

## Bloom, glow, halation and diffusion

1237. **Bloom vs halation** — bloom is a soft, neutral glow from bright areas into neighbouring darks, wider and gentler than halation, mostly from the lens (dust, coating flaws, reflections between elements); halation happens inside the film when light reflects off the base and re-exposes it from behind, so it is red-orange and hugs the highlight. **How:** use a neutral blurred-highlight pass for bloom and a red-only tight pass for halation; don't use one for the other [Silver Halide, https://silverhalide.pro/guides/bloom-effect, checked 2026-10-24]
1238. **Bloom only from real highlights** — Silver Halide finds the real highlights, blurs only those and adds the result back over the sharp image; a pass over the whole frame just looks hazy. **How:** threshold, blur, add: `ffmpeg -i in.mp4 -filter_complex "[0:v]format=gbrp,split[a][b];[b]curves=all='0/0 0.75/0 1/1',gblur=sigma=12[g];[a][g]blend=all_mode=addition" out.mp4` (0.75 threshold and sigma 12 are examples) (tested here 2026-10-24) [Silver Halide, https://silverhalide.pro/guides/bloom-effect, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
1239. **Bloom amount per stock** — Silver Halide's engine values: Vision3 C41 cross 0.25, Kodak 2383/2393 print 0.2, Vision3 500T 0.2, Fuji 3510 print 0.18, Kodachrome 64 0.1, Fuji Sensia 0.08, Fuji Astia 100F and Ilford FP4 0.05; print stocks bloom more than slide/B&W stocks in their library. **How:** keep `effects.bloom` low for slide/B&W looks, higher for print looks (relative use only; their units are not HF's) [Silver Halide, https://silverhalide.pro/guides/bloom-effect, checked 2026-10-24]
1240. **Bloom threshold and amount** — Luttie's bloom: amount 5-20 = subtle believable softness, 40+ = deliberate dreamlike (music video, fashion); threshold default 75 means only the top 25% of tones bloom; lower it to reach into upper midtones, raise it for only speculars and light sources. **How:** in the ffmpeg bloom pass the threshold is the curves knee (`0.75/0`); in HF tune `bloom` and `bloomRadius` and judge a render [Luttie, https://luttie.app/features/bloom, checked 2026-10-24]
1241. **What bloom fixes** — digital highlights clip abruptly; bloom softens hard speculars (jewellery, wet surfaces, windows), waxy bright skin (low bloom at a high threshold) and contained-looking practical lights and neon. **How:** for skin use a high threshold and low amount [Luttie, https://luttie.app/features/bloom, checked 2026-10-24]
1242. **Halation controls** — amount 10-20 is most convincing ("when you're not sure it's there"), 60+ is stylised; radius sets how far down into the highlights the tint reaches; hue default warm red-orange (~10), about 40 for golden amber, about 350 for a pinker Kodak-style halation. **How:** colour the halation pass by the hue you need before screening it back [Luttie, https://luttie.app/features/halation, checked 2026-10-24]
1243. **Where halation shows** — backlit subjects (hair and rim lights, subjects against windows), street and night practicals, golden-hour highlights and bright skin patches; in CineStill 800T it shows most when a light source stands against a dark background. **How:** apply halation only to clips with such sources [Luttie, https://luttie.app/features/halation, checked 2026-10-24] [The Grain Archive, https://thegrainarchive.com/films/cinestill-800t/, checked 2026-10-24]
1244. **Halation is the red layer** — light reflected from the inner camera surfaces is filtered of high frequencies (blue and green) and backlights mostly the red emulsion layer, the closest to that surface; stocks differ with their anti-halation layer. **How:** build halation from the red channel only (`lutrgb=g=0:b=0` on the highlight copy) [No Film School quoting Dehancer, https://nofilmschool.com/four-elements-film-emulation, 2026-01-16]
1245. **Vision3 500T has no red halos** — with its anti-halation protection intact, Vision3 500T showed none of CineStill 800T's red glow; Kodak says its AHU structure controls halation even better than rem-jet. **How:** don't add halation when the brief says "Vision3 500T" as opposed to "CineStill 800T" [The Grain Archive, https://thegrainarchive.com/films/kodak-vision3-500t/, checked 2026-10-24]
1246. **Free halation from edge detect** — the free-Resolve method: a node in Screen composite mode with an Edge Detect effect so only bright edges are picked up and coloured. **How:** ffmpeg equivalent of those two steps: `ffmpeg -i in.mp4 -filter_complex "[0:v]split[a][b];[b]edgedetect=low=0.1:high=0.4,format=gbrp,lutrgb=g=0:b=0,gblur=sigma=4[e];[a]format=gbrp[a2];[a2][e]blend=all_mode=screen" out.mp4` (thresholds/sigma are examples) (tested here 2026-10-24) [EasyEdit, https://easyedit.pro/blog/halation-effect-in-da-vinci-resolve-18-free-and-studio-version-tips, 2024-02-14] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#edgedetect, checked 2026-10-24]
1247. **Two pro halation builds** — Mixing Light describes one method that converts LogC to linear, isolates highlights with a curve and recombines through a Layer Mixer, and another that builds a matte from an edge detect, a grown luma key and a Key Mixer. **How:** for log footage, do the highlight isolation after a linear conversion, not on the display image [Mixing Light, https://mixinglight.com/color-grading-tutorials/emulating-film-halation-in-davinci-resolve/, 2020-01-02]
1248. **Dreamy glow by screen blend** — duplicate the image, blur the bright parts and screen them back over the original; it softens the clinical sharpness of digital sensors for romantic sequences. **How:** `ffmpeg -i in.mp4 -filter_complex "[0:v]format=gbrp,split[a][b];[b]curves=all='0/0 0.6/0 1/1',gblur=sigma=20[g];[a][g]blend=all_mode=screen" out.mp4` (example values) (tested here 2026-10-24) [Cutsio, https://cutsio.com/blog/dreamy-effect-tutorial-in-davinci-resolve-dreamy-glow-effect, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#blend, checked 2026-10-24]
1249. **Glow vs halation sliders** — RapidRAW defines Glow as soft "halation" around bright tones (picks bright pixels, blurs them, blends back) and Halation as a stronger, colour-warm bloom around very bright highlights emulating film's red/orange halo. **How:** use the neutral blurred pass for "glow" requests and the red pass for "halation" requests [RapidRAW docs, https://www.getrapidraw.com/docs/adjustments/effects, checked 2026-10-24]
1250. **Glow by range, spread, warmth** — Adobe Camera Raw's Glow has Range (which tones are targeted), Spread (how far beyond them it goes) and Warmth (blue to orange), plus styles Diffusion, Bloom and Halation. **How:** the same three choices in ffmpeg: threshold knee in `curves`, `gblur` sigma, and the colour of the glow copy [PetaPixel, https://petapixel.com/2026/09/04/im-really-digging-adobe-camera-raws-new-glow-effect/, 2026-09-04]
1251. **Bloom includes diffusion filters** — Dehancer's bloom is light dispersion at contrasting boundaries from the optics, amplified in the emulsion, most prominent with vintage lenses and diffusion filters such as Pro-Mist. **How:** a Pro-Mist request is a bloom/glow request in post [Dehancer, https://www.dehancer.com/learn/articles/bloom-how-it-works, checked 2026-10-24]
1252. **Black Pro-Mist character** — even at its lowest density (1/8) it adds diffusion and a little halation that warms the image without distorting skin tones; it slightly reduces contrast and highlights, smooths wrinkles and blemishes, and becomes more apparent from 1/4 up. **How:** if mimicking it in post, keep bloom low and add a slight contrast drop; bright-and-airy wedding crews use a Black Pro-Mist 1/4 on set [AbelCine, https://www.abelcine.com/buy/lenses-accessories/filters/tiffen-black-pro-mist-1-8-filter-4x565, checked 2026-10-24] [MKTRL Production, https://www.mktrlproduction.com/en/blog/bright-airy-wedding-film-style, checked 2026-10-24]
1253. **Light trails with lagfun** — ffmpeg `lagfun` slowly updates darker pixels so short flashes of light appear longer (decay 0-1, default 0.95). **How:** `ffmpeg -i in.mp4 -vf "lagfun=decay=0.95" out.mp4` for neon/lights streaking on a music beat (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#lagfun, checked 2026-10-24]
1254. **Temporal soft blend with tmix** — `tmix` mixes successive frames with weights; the docs' example averages 7 frames. **How:** `ffmpeg -i in.mp4 -vf "tmix=frames=7:weights='1 1 1 1 1 1 1'" out.mp4` (smears motion; use on short dreamy inserts) (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#tmix, checked 2026-10-24]
1255. **Anamorphic streak flare block** — the Registry's `vfx-anamorphic-flare` draws bright points each throwing the long horizontal blue-violet streak of an anamorphic lens, from measured constants (0.3 high-pass, 80 horizontal taps at quarter resolution, samples/3 gain, tint 0x7a8aff). **How:** `npx hyperframes add vfx-anamorphic-flare --dir . --no-clipboard --json` as an overlay, not a grade [repo: `npx hyperframes@0.8.188 catalog --json`, run 2026-10-24]

## Grain, gate weave and film breath

1256. **Grain scale is set by the 48 µm aperture** — every datasheet granularity is measured through a 48 µm aperture, which projects to about 3.7 px at 1920 wide for Super 35, 7.5 px for Super 16 and 2.6 px for 35 mm stills (7.4 / 14.9 / 5.1 px at 3840). **How:** use those as the target grain feature size in pixels for the delivery raster [Arpit Phillips, https://arpitphillips.com/recipes/knowledge/post-grain-settings/, checked 2026-10-24]
1257. **Grain scale doubles with the raster** — a grain setting dialled in on a 1920 timeline is wrong by a factor of two at 3840, the most common grain mistake; set grain at delivery resolution or scale the size parameter. **How:** in HF re-check `details.grainSize` after changing composition size; in ffmpeg add grain after the final `scale` [Arpit Phillips, https://arpitphillips.com/recipes/knowledge/post-grain-settings/, checked 2026-10-24]
1258. **Super 16 = double grain scale, same intensity** — 16 mm is often the same emulsion enlarged twice as much, so Vision3 500T in Super 16 gets the same intensity and about 2x (24.89/12.35 = 2.02) the grain scale of Super 35. **How:** for a "16mm" brief double the grain size, don't just raise the amount [Arpit Phillips, https://arpitphillips.com/recipes/knowledge/post-grain-settings/, checked 2026-10-24]
1259. **RMS granularity ladder** — published diffuse RMS (48 µm): Pro 400H 4, Acros 100 7, Ektachrome E100 8, Kodachrome 25 9, Kodachrome 64 10, Double-X 5222 14, Kodachrome 200 16; RMS is linear, so ratios between stocks are meaningful, but no absolute plugin value follows from it. **How:** use the ratios to set relative grain amounts between looks; calibrate absolute values by eye [Arpit Phillips, https://arpitphillips.com/recipes/knowledge/post-grain-settings/, checked 2026-10-24]
1260. **Why 8mm looks grainier** — grain particles are roughly the same size in 8, 16 and 35 mm; the smaller frame makes them huge relative to the picture once blown up to a screen. **How:** grain size, not amount, carries the gauge difference [Aprture, https://aprture.com/blogs/news/8mm-vs-16mm-vs-35mm-film-grain, 2026-09-17] [HitFilm manual, https://www.manula.com/manuals/fxhome/hitfilm/14/en/topic/film-grain, checked 2026-10-24]
1261. **Grain follows brightness** — real grain isn't uniform: Luttie's grain is strongest in the midtones and fades toward pure black and white, while v8eo describes Portra's grain as heavier in the shadows and lighter in the highlights; both reject a flat noise overlay. **How:** ffmpeg `noise` has no tone-dependent option (its docs list only strength, seed and flags), so prefer HF `details.grain` (deterministic film grain) for film looks [Luttie, https://luttie.app/features/film-grain, checked 2026-10-24] [v8eo, https://www.v8eo.com/blogs/kodak-portra-400-video-look, checked 2026-10-24]
1262. **Grain goes on top of the grade** — grade first; grain sits on top of the colour work, as in a darkroom. **How:** grain last in the ffmpeg chain; in HF the shader order already puts details after the LUT [Luttie, https://luttie.app/features/film-grain, checked 2026-10-24] [repo: `npx hyperframes@0.8.188 media-treatment --capabilities --all --json`, run 2026-10-24]
1263. **ffmpeg noise options** — `noise` takes strength 0-100 per component (`alls`) and flags `a` (averaged temporal, smoother), `p` (mixed with a semi-regular pattern), `t` (changes every frame), `u` (uniform, otherwise gaussian); the docs' example is `alls=20:allf=t+u`. **How:** `ffmpeg -i in.mp4 -vf "noise=alls=20:allf=t+u" out.mp4`; omit `t` and the pattern freezes (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#noise, checked 2026-10-24]
1264. **Grain in AV1: synthesis instead of encoding** — SVT-AV1 film grain synthesis denoises the input, estimates a grain model in flat areas (autoregressive, from source minus denoised) and signals its parameters so the decoder re-adds grain; adaptive film grain (default on) varies the grain block size with resolution to reduce patterns. **How:** `ffmpeg -i graded.mp4 -c:v libsvtav1 -preset 10 -crf 35 -svtav1-params film-grain=8 out.mkv` ran here (SVT-AV1 1.7.0); check the result on the target player (tested here 2026-10-24) [SVT-AV1 docs, https://gitlab.com/AOMediaCodec/SVT-AV1/-/raw/master/Docs/Appendix-Film-Grain-Synthesis.md, checked 2026-10-24] [SVT-AV1 Parameters, https://gitlab.com/AOMediaCodec/SVT-AV1/-/raw/master/Docs/Parameters.md, checked 2026-10-24]
1265. **Gate weave is mechanical, film breath is exposure** — Dehancer separates gate weave (frame movement in the gate) from film breath (frame-to-frame changes in exposure, contrast and colour from uneven coating, shutter instability and development); film breath is most pronounced on Super 8, even fresh and well developed. **How:** for an 8mm look use both: HF weave on the wrapper plus the Film Memory exposure pulse [repo: .claude/skills/media-use/references/media-treatment-recipes.md] [Dehancer, https://blog.dehancer.com/articles/film-breath-and-gate-weave/, checked 2026-10-24]
1266. **Weave needs a slight scale-up** — to displace the image without revealing frame edges it must be scaled slightly, and that resampling can soften the image a little. **How:** HF recipes keep weave scale at 1.005-1.015 for exactly this reason [Filmbox guide, https://videovillage.com/learn/filmbox/full-guide/negative/gate-weave, checked 2026-10-24] [repo: .claude/skills/media-use/references/media-treatment-recipes.md]
1267. **Weave in fractions of a pixel** — Kdenlive's frei0r Gate Weave moves the frame randomly with an interval and max horizontal/vertical movement up to 10, taking fractions that give subtle pixel colour mixes. **How:** frei0r plugins are not installed here (ffmpeg lists the `frei0r` filter, no plugin dir), so use HF GSAP weave (checked here 2026-10-24: `ffmpeg -filters | grep frei0r`) [Kdenlive manual, https://docs.kdenlive.org/en/effects_and_filters/video_effects/motion/gate_weave.html, checked 2026-10-24]
1268. **Reference-based weave** — The Holdovers' team motion-tracked actual 35 mm film and applied that data to their digital footage for "a little subtle gate weave throughout the show". **How:** if the owner has a real film clip, track its drift and reuse those offsets in GSAP keyframes [No Film School, https://nofilmschool.com/four-elements-film-emulation, 2026-01-16]

## VHS, tape and analog video looks (ffmpeg route)

1269. **What VHS really did** — VHS recorded brightness and colour as separate signals with very different bandwidth (luma about 3 MHz, chroma about 0.4 MHz), so colour had roughly a tenth of the horizontal detail and smeared sideways across edges that stayed fairly crisp; the defining artifact is colour bleed, not static. **How:** degrade chroma more than luma [Jeje Studios, https://boiler.jejestudios.com/guides/vhs-effect-video, 2026-08-17]
1270. **VHS artifacts in order of importance** — 1 horizontal colour bleed (blur chroma only, horizontally), 2 red/blue offset of two or three pixels, 3 slight overall softness (under a pixel), 4 fine tape noise mostly in the darks with a horizontal streak, 5 head-switching noise in a few lines at the bottom. **How:** chroma-only horizontal blur: `ffmpeg -i in.mp4 -vf "format=yuv444p,gblur=sigma=6:sigmaV=0:planes=6,format=yuv420p" out.mp4`; offset: `rgbashift=rh=-3:bh=3`; softness: `gblur=sigma=0.6` (all ran) (tested here 2026-10-24) [Jeje Studios, https://boiler.jejestudios.com/guides/vhs-effect-video, 2026-08-17] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#gblur, checked 2026-10-24] [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#rgbashift, checked 2026-10-24]
1271. **What to leave out of VHS** — scanlines come from a CRT, not the tape (wrong for "tape on a modern screen"); constant rolling/tracking errors mean a broken tape (intermittent is convincing); date stamps belong to the camcorder look, not a commercial tape. **How:** add scanlines/curvature only for "tape on a CRT someone filmed" [Jeje Studios, https://boiler.jejestudios.com/guides/vhs-effect-video, 2026-08-17]
1272. **VHS order of operations** — soften slightly, bleed colour horizontally, offset red and blue, add tape noise, then crop or add head-switching noise; anything imitating the display goes after all of this; a channel offset applied before a displacement gets dragged along and reads as a bad encode. **How:** keep the ffmpeg chain in that order [Jeje Studios, https://boiler.jejestudios.com/guides/vhs-effect-video, 2026-08-17]
1273. **VHS signal-chain recipe** — finish in 4:3 at 29.97 or 25 fps; scale to about 640x480 and back up (detail loss first); blur only the colour channels horizontally (3-6 px) and shift red 1-3 px right; lift blacks, clip highlights, lower saturation except skin and reds; streaky horizontal noise, not film grain; a head-switching strip on the bottom 6-10 lines; a tracking band once or twice per scene; date stamp last in a blocky, slightly soft font. **How:** first steps: `ffmpeg -i in.mp4 -vf "crop=ih*4/3:ih,scale=640:480,format=yuv444p,gblur=sigma=4:sigmaV=0:planes=6,format=yuv420p,rgbashift=rh=2,fps=30000/1001" out.mp4` (ran: 640x480 at 30000/1001) (tested here 2026-10-24) [Flashboards, https://flashboards.yaroflasher.com/learn/post-production/vhs-effect/, 2026-09-25]
1274. **VHS resolution** — the tape stored roughly 240 lines of horizontal detail for brightness and far less for colour, so edges go soft and colours smear sideways, especially reds. **How:** scale down and back up before any artifact: `ffmpeg -i in.mp4 -vf "scale=320:-2:flags=bilinear,scale=640:360:flags=bilinear" out.mp4` (ran; pick the down-size by eye) (tested here 2026-10-24) [Flashboards, https://flashboards.yaroflasher.com/learn/post-production/vhs-effect/, 2026-09-25]
1275. **VHS vs glitch** — the VHS effect is a medium (a whole shot that looks like tape, constant mostly gentle artifacts); a glitch is an event (the image breaks for a moment, often with digital blocks). Scratches, dust and burns belong to damaged film, never to tape. **How:** never add `filmArtifacts` to a VHS look; use `digitalGlitch` only as a short event [Flashboards, https://flashboards.yaroflasher.com/learn/post-production/vhs-effect/, 2026-09-25]
1276. **VHS colour drift and timestamp** — tapes drifted warm toward red and magenta as they aged and VHS clipped highlights aggressively; mute and warm the palette; a period timestamp in a blocky pixel font in orange or yellow is the fastest "camcorder" cue; leaving it too clean or widescreen gives it away. **How:** warm/magenta `wheels`, highlights clipped, 4:3 crop (`crop=ih*4/3:ih` ran: 480x360 from 640x360) (tested here 2026-10-24) [v8eo, https://www.v8eo.com/blogs/vhs-effect-video-authentic-analog, checked 2026-10-24]
1277. **Balance and crop before the VHS style** — a VHS node chain separates degradation from decoration: balance the shot, crop to 4:3, colour-cast look, blur only the chroma for bleed, then scanlines/tracking, tape noise and vignette; skipping balance and crop is the most common reason a VHS grade looks like a sticker. **How:** run correction first, then the VHS chain [DaVinci Resolve 21 blog, https://davinciresolve21.com/blog/davinci-resolve-how-to-create-a-vhs-retro-look, 2026-08-01]
1278. **Why VHS is used in films** — memory (family camcorder = birthdays and living rooms; a cut to tape works like a flashback), evidence (amateur video feels unauthored: found-footage horror), period match (No, 2012, shot on U-matic cameras to cut with real 1988 ads) and unease. **How:** pick the VHS look only when one of these reasons applies [Flashboards, https://flashboards.yaroflasher.com/learn/post-production/vhs-effect/, 2026-09-25]
1279. **Chroma shift without RGB split** — `chromashift` moves only the chroma planes (cb/cr horizontally and vertically, edge smear/warp), unlike `rgbashift` which moves R/G/B. **How:** `ffmpeg -i in.mp4 -vf "chromashift=cbh=3:crh=-3" out.mp4` keeps luma edges in place (tested here 2026-10-24) [ffmpeg docs, https://ffmpeg.org/ffmpeg-filters.html#chromashift, checked 2026-10-24]
